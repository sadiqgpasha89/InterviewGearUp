Explain the backtracking paradigm: Generating all permutations and combinations with pruning.

Software engineer (core) · Gear 2 (Mid-level) · Algorithms · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Backtracking builds a solution one choice at a time, recurses, and undoes the choice when the branch fails or finishes. Permutations and combinations differ in what a "choice" is (any unused element vs only later elements), and pruning cuts branches that cannot lead to valid answers.

Explained in depth

The template

Backtracking is depth first search over a decision tree. Every node holds a partial solution. At each step you choose, recurse, then un-choose so the shared state is clean for the next sibling.

def permutations(nums):
    out, path, used = [], [], [False] * len(nums)
    def go():
        if len(path) == len(nums):
            out.append(path[:])            # copy: path is mutated later
            return
        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True; path.append(x)  # choose
            go()                            # explore
            path.pop(); used[i] = False     # un-choose
    go()
    return out

Combinations versus permutations

  • Permutations: order matters, so each level may pick any unused element. There are n! leaves.
  • Combinations (choose k of n): order does not matter, so you only pick elements with an index greater than the previous pick. That removes reordered duplicates and gives C(n, k) leaves.
def combine(n, k):
    out, path = [], []
    def go(start):
        if len(path) == k:
            out.append(path[:]); return
        for x in range(start, n + 1):
            path.append(x); go(x + 1); path.pop()
    go(1)
    return out

Pruning

Pruning stops a branch as soon as it can no longer succeed:

  • Bound pruning: in combination sum, if the running total exceeds the target, return (sort the input first so you can break instead of continue).
  • Count pruning: for combine(n, k), stop the loop at n - (k - len(path)) + 1, because fewer than the remaining required elements are left.
  • Constraint pruning: in N-Queens, skip a column or diagonal already attacked.

Duplicates in the input

Sort the array. At each level skip nums[i] if i > start (or the first unused) and nums[i] == nums[i-1]. This removes repeated branches without a set of results, which would waste time and memory.

Complexity

Output size dominates: O(n * n!) for permutations (copying each of the n! results) and O(n * 2^n) for subsets. Extra space is the recursion depth O(n) plus the result. Recursion depth can overflow the stack for large n, but results at that size would be astronomically large anyway.

Common mistakes

Forgetting to copy path before storing it, forgetting to undo state, and mixing up start (combinations) with a used array (permutations).

Likely follow-ups

  • How do you avoid duplicate permutations when the input has repeated values?
  • What is the time complexity of generating all permutations versus all subsets?
  • How would you convert the recursion to an iterative version?
