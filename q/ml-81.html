What is Data Leakage in machine learning and how do you ensure preprocessing occurs strictly inside cross-validation folds?

ML / AI engineer · Gear 2 (Mid-level) · Data · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Data leakage happens when information from outside the training data, such as test labels, future data or full-dataset statistics, influences fitting, inflating validation scores that vanish in production. Split first and fit every preprocessing step, including scaling, imputation, encoding and feature selection, only on training folds via a Pipeline inside cross-validation.

Explained in depth

What leakage is

A model "cheats" using information it would not have at prediction time. Cross-validation scores look excellent (AUC 0.99), then performance collapses after deployment. It is one of the most common causes of failed ML projects.

Main types

  1. Train-test contamination (preprocessing leakage): fitting normalisation, imputation values, PCA, target encoding, vocabulary or feature selection on the entire dataset before splitting. Test statistics (mean, variance, selected features that correlate with the test labels) leak into training.
  2. Target leakage: a feature that is a consequence of, or proxy for, the label: "claim_paid_amount" when predicting fraud, "treatment_received" for diagnosing disease, an account closure flag for predicting churn, post-outcome timestamps.
  3. Temporal leakage: random splits on time-dependent data let the model train on the future to predict the past; features aggregated over windows that include the prediction date.
  4. Group and duplicate leakage: rows from the same user, patient, device, image series or near-duplicate documents appear in both train and test, so the model memorises entities.
  5. Label leakage via IDs or ordering: row index, file names, data collection artefacts that encode the class.
  6. Hyperparameter overfitting: repeatedly tuning on the test set, effectively leaking it.
  7. Feature selection before CV: choosing the top features using all labels is a classic mistake that produces spectacular, false results on high-dimensional data.

Doing it right: pipelines inside cross-validation

The rule: split first, then fit every data-dependent step on the training portion only, and apply (transform) the fitted steps to validation data.

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.feature_selection import SelectKBest
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.ensemble import GradientBoostingClassifier

pre = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")), ("sc", StandardScaler())]), num_cols),
    ("cat", OneHotEncoder(handle_unknown="ignore"), cat_cols)])
pipe = Pipeline([("pre", pre), ("select", SelectKBest(k=50)), ("clf", GradientBoostingClassifier())])
scores = cross_val_score(pipe, X, y, cv=StratifiedKFold(5, shuffle=True, random_state=0), scoring="roc_auc")

In each fold, cross_val_score refits the entire pipeline on that fold's training data, so imputation values, scaling parameters, selected features and encoders are learned without seeing the validation fold. The wrong way: X_scaled = StandardScaler().fit_transform(X) then cross_val_score(model, X_scaled, y). Also: nested cross-validation (inner loop for tuning, outer for evaluation) for unbiased estimates when tuning hyperparameters, and a final untouched test set used once.

Correct split strategies

  • Time series: forward chaining (TimeSeriesSplit), train on the past and validate on later periods, with a gap to avoid overlapping windows; build features using only data available at prediction time (point-in-time joins).
  • Grouped data: GroupKFold or StratifiedGroupKFold by user, patient or device.
  • Deduplicate before splitting, and check near duplicates in text and images.
  • Target encoding and embeddings: compute within folds (out-of-fold encoding).
  • Resampling (SMOTE, undersampling): apply only to the training fold, never before the split.

Detection

Suspiciously high scores, a single feature with extreme importance (check SHAP), performance dropping sharply on a time-based holdout or in production, features unavailable at inference time, and train versus serving feature differences. Review each feature with the question "Would I know this at the moment of prediction?" and keep a data timeline diagram.

Pitfalls

Imputing or scaling before splitting, selecting features with all labels, random splits on temporal or grouped data, leaking through duplicates, and tuning repeatedly on the test set.
