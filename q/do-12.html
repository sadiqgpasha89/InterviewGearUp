What are file system inodes, and how can a disk run out of space when `df -h` shows available megabytes?

DevOps / SRE / Cloud · Gear 2 (Mid-level) · Linux · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

An inode stores a file's metadata (owner, permissions, size, block pointers) and each file needs one. A filesystem is created with a fixed number of inodes, so millions of tiny files can use them all while plenty of free space remains. df -h shows block usage, while df -i shows inode usage; at 100 percent you cannot create new files.

Explained in depth

What an inode is

Each file or directory has an inode with its metadata and pointers to data blocks, but not its name. Directory entries map names to inode numbers, so a file can have several names (hard links). The number of inodes is fixed at format time for ext4 (XFS allocates them dynamically, which makes exhaustion rare).

Symptom

$ touch newfile
touch: cannot create 'newfile': No space left on device
$ df -h /var        # shows 40% used, plenty of space
$ df -i /var        # shows IUse% 100%

Finding the culprit

df -i                                          # which filesystem is out of inodes
for d in /var/*; do echo "$(find $d -xdev | wc -l) $d"; done | sort -n | tail    # count entries per directory

Common causes: session or cache files, mail queues, millions of tiny files from a runaway job, and container layers.

Fixes

  • Delete the unneeded files (use find ... -delete; rm * may fail with "argument list too long").
  • Add cleanup jobs (tmpwatch, logrotate, TTL on caches).
  • For a long-term fix, create the filesystem with more inodes (mkfs.ext4 -i bytes-per-inode or -N), or use XFS or Btrfs.

Related disk space puzzle

Deleted files that a process still holds open continue to use space until it closes them. Check with lsof +L1 and restart or truncate the file instead.
