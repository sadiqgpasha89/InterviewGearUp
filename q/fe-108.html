How do map, filter and reduce work, and why do they avoid mutating arrays?

Frontend engineer · Gear 1 (Junior) · JavaScript · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

map transforms every element into a new array of the same length, filter keeps elements that pass a test, and reduce folds the array into a single value using an accumulator. They return new values and leave the original array untouched, which makes code easier to reason about and fits state management in React and Redux, where immutability lets changes be detected cheaply.

Explained in depth

The three methods

const nums = [1, 2, 3, 4, 5];

nums.map(n => n * 2);              // [2, 4, 6, 8, 10]
nums.filter(n => n % 2 === 0);     // [2, 4]
nums.reduce((sum, n) => sum + n, 0); // 15
  • map: returns a new array with each element transformed. Same length.
  • filter: returns a new array containing only elements where the callback returns truthy.
  • reduce: calls a function with an accumulator and the current element and returns one final value (a number, object, or even another array). Always provide an initial value (the 0 above), or an empty array throws.
  • forEach returns nothing and is used for side effects; use map when you want a result.

Chaining

const total = orders
  .filter(o => o.status === 'paid')
  .map(o => o.amount)
  .reduce((a, b) => a + b, 0);

Why avoid mutation

  • Mutating methods (push, splice, sort, reverse) change the original, which creates hidden coupling between parts of the code.
  • In React, state updates must produce new references so the framework can detect changes quickly (=== comparison); mutated arrays may not re-render.
  • Immutable updates:
const added = [...items, newItem];
const removed = items.filter(i => i.id !== id);
const updated = items.map(i => i.id === id ? { ...i, done: true } : i);

Note that sort and reverse mutate, so copy first ([...items].sort(), or toSorted() in newer runtimes).

Trade-offs

Chained methods create intermediate arrays; for very large data or hot paths, a single loop or reduce can be faster. Readability usually wins first.
