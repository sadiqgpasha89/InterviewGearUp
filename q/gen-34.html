How does the two pointers technique solve the Two-Sum problem in a sorted array in $O(N)$ time?

Software engineer (core) · Gear 1 (Junior) · Algorithms · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

With a sorted array, put one pointer at each end. If the sum is too small move the left pointer right; if too large move the right pointer left; stop when the sum equals the target. Each step discards one candidate, so it takes O(N) time and O(1) extra space.

Explained in depth

Algorithm

def two_sum_sorted(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return [lo, hi]
        if s < target:
            lo += 1        # need a bigger sum
        else:
            hi -= 1        # need a smaller sum
    return []

Why it is correct

If nums[lo] + nums[hi] is smaller than the target, nums[lo] cannot pair with any element at or before hi, because those are all no larger than nums[hi]. So lo can be safely discarded. The same argument for hi applies when the sum is too large. Every iteration removes one element from consideration.

Complexity

O(N) time, O(1) space. A hash map solves the unsorted version in O(N) time but needs O(N) space; sorting first costs O(N log N) and loses the original indexes.

Related problems

Three-sum (fix one element, run two pointers on the rest, O(N²)), container with most water, removing duplicates in place and checking palindromes.
