What is the difference between GROUP BY and window functions in SQL?

Data engineer · Gear 1 (Junior) · SQL · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

GROUP BY collapses rows into one row per group, so you lose the individual rows. A window function computes an aggregate or ranking over a set of related rows but keeps every original row, so you can show row detail next to the group total, a running sum or a rank. Use GROUP BY for summaries and windows for per-row analytics.

Explained in depth

GROUP BY: collapse

SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department;

Returns one row per department. Individual employees disappear, and every selected column must be grouped or aggregated.

Window function: keep the rows

SELECT name, department, salary,
       AVG(salary) OVER (PARTITION BY department) AS dept_avg,
       salary - AVG(salary) OVER (PARTITION BY department) AS diff_from_avg
FROM employees;

Every employee remains, with the department average beside them.

The OVER clause

  • PARTITION BY splits rows into groups (like GROUP BY, but without collapsing).
  • ORDER BY defines the order inside each partition (needed for ranking and running totals).
  • An optional frame (ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) selects which neighbouring rows are used.

Common window functions

  • Ranking: ROW_NUMBER() (unique 1,2,3), RANK() (ties share a rank, gaps follow), DENSE_RANK() (ties share, no gaps).
  • Offsets: LAG(x) and LEAD(x) read the previous or next row.
  • Running or moving aggregates: SUM(amount) OVER (ORDER BY day).
  • Others: NTILE(4), FIRST_VALUE, PERCENT_RANK.

Typical uses

Top N per group (ROW_NUMBER then filter rn <= 3 in an outer query), month-over-month change with LAG, deduplicating rows, and running totals. Window functions run after WHERE and GROUP BY, so you cannot filter on them in the same WHERE; wrap in a subquery or CTE.
