Explain Prim's algorithm for Minimum Spanning Trees using priority queues.

Software engineer (core) · Gear 2 (Mid-level) · Graphs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Prim's algorithm grows one tree from a start vertex. It repeatedly takes the cheapest edge that connects the tree to a vertex outside it, using a priority queue of candidate edges. With a binary heap it runs in O(E log V). It suits dense graphs better than Kruskal's because it never sorts all edges.

Explained in depth

Algorithm

  1. Start from any vertex and mark it in the tree.
  2. Push its edges into a min-heap keyed by weight.
  3. Pop the cheapest edge; if its endpoint is already in the tree, skip it, otherwise add the vertex and push its edges.
  4. Stop when all vertices are in the tree.
import heapq

def prim(graph, start=0):               # graph[u] = [(w, v), ...]
    seen = {start}
    heap = list(graph[start])
    heapq.heapify(heap)
    total = 0
    while heap and len(seen) < len(graph):
        w, v = heapq.heappop(heap)
        if v in seen:
            continue
        seen.add(v)
        total += w
        for edge in graph[v]:
            if edge[1] not in seen:
                heapq.heappush(heap, edge)
    return total

Complexity

  • Binary heap and adjacency list: O(E log V).
  • Fibonacci heap: O(E + V log V).
  • Adjacency matrix with no heap (scan for the minimum): O(V^2), which is best for very dense graphs.

Prim's versus Dijkstra

They look alike, but Prim's key is the edge weight connecting a vertex to the tree, while Dijkstra's key is the total distance from the source. Prim's finds a minimum spanning tree, not shortest paths.
