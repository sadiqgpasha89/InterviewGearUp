How do you design reusable React compound components using React Context?

Frontend engineer · Gear 2 (Mid-level) · React · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Compound components are a set of components that share implicit state through Context, such as Tabs, Tabs.List, Tabs.Tab and Tabs.Panel. The parent owns state, children read it from context, giving consumers flexible composition and clean APIs instead of a single component with a dozen props.

Explained in depth

The problem with prop-heavy components

<Tabs tabs={[...]} activeIndex={1} renderPanel={...} tabClassName=... /> accumulates props for every variation and hides structure. Consumers cannot reorder, wrap or insert elements between parts.

The compound API

<Tabs defaultValue="profile" onChange={log}>
  <Tabs.List>
    <Tabs.Tab value="profile">Profile</Tabs.Tab>
    <Tabs.Tab value="billing">Billing</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel value="profile"><ProfileForm /></Tabs.Panel>
  <Tabs.Panel value="billing"><Billing /></Tabs.Panel>
</Tabs>

Implementation with Context

const TabsContext = createContext(null);
function useTabs() {
  const ctx = useContext(TabsContext);
  if (!ctx) throw new Error('Tabs.* must be rendered inside <Tabs>');
  return ctx;
}

function Tabs({ defaultValue, value, onChange, children }) {
  const [inner, setInner] = useState(defaultValue);
  const current = value !== undefined ? value : inner;          // controlled or uncontrolled
  const select = useCallback((v) => { if (value === undefined) setInner(v); onChange?.(v); }, [value, onChange]);
  const ctx = useMemo(() => ({ current, select }), [current, select]);
  return <TabsContext.Provider value={ctx}>{children}</TabsContext.Provider>;
}
Tabs.List = ({ children }) => <div role="tablist">{children}</div>;
Tabs.Tab = ({ value, children }) => {
  const { current, select } = useTabs();
  return <button role="tab" aria-selected={current === value} onClick={() => select(value)}>{children}</button>;
};
Tabs.Panel = ({ value, children }) => {
  const { current } = useTabs();
  return current === value ? <div role="tabpanel">{children}</div> : null;
};

Context replaces React.Children.map + cloneElement, which breaks when children are wrapped in other components or fragments.

Design points

  • Controlled and uncontrolled support (as above) mirrors native inputs.
  • Accessibility is encapsulated: roles, aria-selected, aria-controls/id pairing (generate ids with useId), roving tabindex and arrow key handling in the list. Consumers get correct behaviour for free.
  • Memoise the context value so unrelated parent renders do not re-render all parts.
  • Provide helpful errors when parts are used outside the parent.
  • Offer styling hooks (className, asChild pattern, data attributes like data-state="active").

Where it is used

Radix UI, Reach UI, Headless UI, MUI and Chakra build menus, accordions, selects and dialogs this way.

Trade-offs

More flexible and readable markup, but more internal code, the implicit contract between parts must be documented, TypeScript typing of static members needs care, and Server Components cannot use context directly (parts are client components).

Pitfalls

Relying on children order or cloneElement, recreating the context value each render, hidden state coupling, and exposing too much of the internal state to consumers.
