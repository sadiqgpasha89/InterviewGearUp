Why is AES-GCM preferred over AES-CBC for symmetric encryption (Authenticated Encryption)?

Security engineer · Gear 2 (Mid-level) · Cryptography · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

AES-CBC only provides confidentiality; an attacker can modify ciphertext, and padding errors can leak plaintext (padding oracle attacks) unless you add a separate MAC correctly. AES-GCM is an authenticated encryption mode that encrypts and produces an authentication tag in one operation, so tampering is detected, and it is fast and parallelisable. Never reuse a nonce with the same key in GCM.

Explained in depth

The problem with CBC

CBC encrypts blocks chained with the previous ciphertext block. It provides confidentiality only:

  • Ciphertext is malleable: flipping bits in one block predictably changes the next plaintext block.
  • With padding checks that behave differently on errors, padding oracle attacks (Vaudenay, POODLE, Lucky 13) let an attacker decrypt data byte by byte.
  • To be safe you must add a MAC and verify it before decrypting (encrypt-then-MAC). Many implementations got this wrong.

AES-GCM (AEAD)

Galois/Counter Mode combines counter-mode encryption with a GHASH authentication tag. It is an AEAD (Authenticated Encryption with Associated Data) cipher:

from cryptography.hazmat.primitives.ciphers.aead import AESGCM
key = AESGCM.generate_key(bit_length=256)
aes = AESGCM(key)
nonce = os.urandom(12)                      # 96-bit, unique per message
ct = aes.encrypt(nonce, b'secret', b'header')   # ciphertext plus 16-byte tag
pt = aes.decrypt(nonce, ct, b'header')      # raises InvalidTag if anything changed
  • Any change to the ciphertext, nonce or associated data (such as headers) makes decryption fail.
  • No padding, so no padding oracle; it can be parallelised and is accelerated in hardware.

The key rule

Never reuse a (key, nonce) pair. Reuse in GCM leaks the XOR of plaintexts and lets attackers forge tags. Use random 96-bit nonces with limits on messages per key, a counter, or a nonce-misuse-resistant mode (AES-GCM-SIV).

Guidance

Use an AEAD mode (AES-GCM or ChaCha20-Poly1305) by default; avoid hand-assembled CBC plus HMAC. TLS 1.3 removed CBC suites entirely.
