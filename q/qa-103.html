What are the levels of software testing: unit, integration, system and acceptance testing?

QA / SDET · Gear 1 (Junior) · Fundamentals · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Unit testing checks individual functions or classes in isolation, integration testing checks that modules and services work together, system testing validates the complete application against requirements in a production-like environment, and acceptance testing confirms the software meets business needs and is ready for release. Each level finds different defects and runs at a different cost.

Explained in depth

The four levels

LevelScopeWhoExamples
UnitSmallest piece of code: a function, method or classDevelopersA tax calculation returns 18 for an input of 100 at rate 18 percent
IntegrationInteraction between components: modules, database, APIs, servicesDevelopers and QAThe order service saves to the database and calls the payment API correctly
SystemThe whole application end to end, in an environment resembling productionQAA user registers, searches, adds to cart and pays
Acceptance (UAT)Whether the product meets business needs and acceptance criteriaBusiness users, product owner, customersThe finance team confirms the monthly report matches their expectations

Key points

  • Unit tests are fast and numerous, with dependencies mocked, and they point to the exact failing code.
  • Integration tests find interface problems: wrong data formats, configuration, queries, timeouts. Approaches include big-bang, top-down, bottom-up and incremental integration.
  • System tests cover functional and non-functional requirements (performance, security, usability) on the full stack.
  • Acceptance tests can be UAT by users, alpha (internal) and beta (external pilot) testing, or automated acceptance tests written in BDD style from the acceptance criteria.

Relationship to the test pyramid

Lower levels are cheap and fast, so most tests should live there; fewer slower tests sit at the system and acceptance levels. Defects found earlier cost far less to fix.

Related testing types

Regression testing (re-running tests after changes) and smoke testing (a quick check that the build is stable) apply across levels.
