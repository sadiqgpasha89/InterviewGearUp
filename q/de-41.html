How do dbt incremental models work with merge, delete+insert, and append strategies?

Data engineer · Gear 3 (Senior) · Transformation · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A dbt incremental model builds the full table on the first run and afterwards processes only new or changed rows, using is_incremental() to filter the source. The strategy (append, merge, delete+insert, insert_overwrite) decides how those rows are written, and a unique_key is needed to update existing rows instead of duplicating them.

Explained in depth

{{ config(materialized='incremental', unique_key='order_id', incremental_strategy='merge') }}
select order_id, status, amount, updated_at
from {{ source('shop', 'orders') }}
{% if is_incremental() %}
where updated_at > (select max(updated_at) from {{ this }})
{% endif %}

On the first run, or with --full-refresh, the is_incremental() block is skipped and the whole table is built. On later runs only the filtered rows are processed and written into the existing table ({{ this }}).

Strategies

StrategyHow it writesNotes
appendInserts new rows onlyFast; reprocessed rows become duplicates
mergeMERGE on unique_key (update or insert)Handles updates; supported by Snowflake, BigQuery, Databricks and others
delete+insertDeletes matching keys, then insertsWorks where MERGE is slow or unavailable
insert_overwriteReplaces whole partitionsGood for large date-partitioned tables

Available strategies and defaults depend on the warehouse adapter.

Things to get right

  • Late-arriving data: filter with a lookback window (for example the last 3 days) instead of the strict maximum, and rely on unique_key to avoid duplicates.
  • Schema changes: on_schema_change controls whether new columns are added or the run fails.
  • Correctness over time: periodic full refreshes catch drift; test unique and not_null on the key.
  • Incremental models trade simplicity for cost savings, so use them only when the table is big enough to justify it.

Likely follow-ups

  • How would you handle records that arrive two days late?
  • Why might an append strategy create duplicates?
  • When would you choose insert_overwrite over merge?
