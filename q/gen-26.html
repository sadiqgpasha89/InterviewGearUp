Explain Breadth-First Search (BFS): Queue implementation and finding shortest paths in unweighted graphs.

Software engineer (core) · Gear 1 (Junior) · Graphs · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

BFS explores a graph level by level using a FIFO queue: visit a node, enqueue its unvisited neighbours and mark them visited when enqueued. It reaches nodes in order of edge count, so the first time it reaches a node is a shortest path in an unweighted graph. It runs in O(V + E) time and O(V) space.

Explained in depth

from collections import deque

def shortest_path(graph, start, goal):
    prev = {start: None}
    q = deque([start])
    while q:
        node = q.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = prev[node]
            return path[::-1]
        for nxt in graph[node]:
            if nxt not in prev:
                prev[nxt] = node
                q.append(nxt)
    return None

Mark nodes visited when you enqueue them, not when you dequeue them. Otherwise the same node can be queued many times and the queue can blow up on dense graphs.

Why it finds shortest paths

The queue always holds nodes at distance d followed by nodes at distance d + 1, so nodes are dequeued in non-decreasing distance. This only holds when every edge costs the same; with weights use Dijkstra, and with only 0 and 1 weights use 0-1 BFS with a deque.

Typical uses

Fewest hops in a grid or social graph, level-order traversal of a tree, connected components and word-ladder problems. Memory is the usual limit: the queue can hold a whole level, which is large in wide graphs, whereas DFS holds only one path.
