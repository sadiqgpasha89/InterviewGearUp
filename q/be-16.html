How does database sharding work, and what are the trade-offs between range-based and hash-based sharding?

Backend engineer · Gear 3 (Senior) · Databases · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Sharding splits data across several databases by a shard key so each holds a subset. Range-based sharding assigns contiguous key ranges, which makes range queries efficient but risks hot spots. Hash-based sharding spreads keys evenly but scatters ranges across shards. The shard key choice and resharding strategy are the hardest parts.

Explained in depth

Why shard

One database eventually hits limits in storage, write throughput or memory. Replication scales reads; sharding scales writes and data size by splitting data horizontally.

Strategies

  • Range-based: shard 1 holds user ids 1 to 1M, shard 2 holds 1M to 2M, and so on.
  • Pros: range scans stay on one shard, easy to understand.
  • Cons: hot spots (new users or recent timestamps all land on the last shard) and uneven sizes.
  • Hash-based: shard = hash(key) % N.
  • Pros: even distribution of load and data.
  • Cons: range queries need all shards; changing N remaps most keys unless you use consistent hashing or many virtual buckets.
  • Directory (lookup) based: a mapping service tracks which shard holds what. Flexible, but the directory is a dependency.

Choosing the shard key

It should have high cardinality, even access distribution and match the main query pattern (for example tenant_id so a tenant's data stays together). A bad key (country, status) creates skew.

Costs of sharding

  • Cross-shard queries and joins become scatter-gather, slower and more complex.
  • Distributed transactions need two-phase commit or sagas.
  • Global unique ids need a generator (snowflake ids, UUIDs).
  • Resharding (moving data online) is operationally hard; plan with many logical shards mapped onto fewer physical ones.
  • Schema changes and backups multiply.

Before sharding

Try indexing, caching, read replicas, partitioning inside one database, archiving old data and vertical scaling. Many systems never need sharding.
