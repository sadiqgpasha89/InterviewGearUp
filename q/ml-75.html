Compare Distributed Data Parallel (DDP) with Fully Sharded Data Parallel (FSDP) for multi-GPU training.

ML / AI engineer · Gear 4 (Lead / Staff) · Distributed · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

DDP keeps a full copy of the model, gradients and optimizer states on every GPU and all-reduces gradients each step; it is fast and simple while the model fits in memory. FSDP shards parameters, gradients and optimizer states across GPUs and gathers each layer's parameters just in time, so models far larger than one GPU can train, at the cost of more communication.

Explained in depth

DDPFSDP
Model, gradients, optimizer states per GPUFull copySharded, about 1/N each
Communication per stepAll-reduce of gradientsAll-gather of parameters (forward and backward) plus reduce-scatter of gradients
Relative communication1xAbout 1.5x
Max model sizeMust fit on one GPU, with activationsScales with the number of GPUs
ComplexityLowHigher (wrapping, sharding strategy)

DDP

Each process holds the whole model. During the backward pass, gradients are grouped into buckets and all-reduced while computation continues, so most of the communication is hidden. With mixed precision and Adam, model states take roughly 16 bytes per parameter (weights, gradients, fp32 master weights and two moments), so a 7B model needs about 112 GB for states alone, which does not fit on one 80 GB GPU.

FSDP

Equivalent to ZeRO stage 3. Parameters are split into units (often one transformer block). Before a unit runs forward or backward, FSDP all-gathers its parameters, uses them, then frees them. Gradients are reduce-scattered so each GPU keeps only its shard, and the optimizer updates only that shard. Memory is roughly the sharded states plus the activations and the full parameters of one unit at a time. Prefetching overlaps the next all-gather with the current compute.

Tuning and options

  • Wrapping policy: unit size trades memory against communication efficiency.
  • Activation checkpointing to cut activation memory, CPU offload for even larger models, and mixed precision to halve memory and traffic.
  • Hybrid sharding: shard inside a node (fast NVLink) and replicate across nodes, reducing slow inter-node traffic.

Choosing

If the model fits, use DDP: it is faster and easier to debug. Use FSDP when memory is the limit. A fast interconnect matters much more for FSDP.
