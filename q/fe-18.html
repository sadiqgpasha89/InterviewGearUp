How does `async`/`await` syntactic sugar work under the hood with generators and promises?

Frontend engineer · Gear 2 (Mid-level) · JavaScript · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

async/await is syntax over promises and generators: an async function runs like a generator that yields each awaited promise to a driver, which resumes it with the resolved value or throws the rejection into it. Each await therefore suspends the function and continues in a microtask.

Explained in depth

What the language gives you

An async function always returns a promise. await expr pauses that function, converts expr to a promise (Promise.resolve), and schedules the continuation as a microtask when the promise settles. While paused the call stack is free, so the event loop keeps running.

The generator equivalent

Early transpilers (Babel's regenerator, TypeScript for ES2015) compiled async code into a generator plus a small runner:

function spawn(genFn) {
  return new Promise((resolve, reject) => {
    const gen = genFn();
    function step(method, arg) {
      let r;
      try { r = gen[method](arg); } catch (e) { return reject(e); }
      if (r.done) return resolve(r.value);
      Promise.resolve(r.value).then(v => step('next', v), e => step('throw', e));
    }
    step('next');
  });
}

// async function load() { const u = await getUser(); return u.name; }  is roughly:
const load = () => spawn(function* () { const u = yield getUser(); return u.name; });

yield plays the role of await: the generator hands a promise to the driver, which resumes it later with next(value) or throw(error). A rejection becomes a normal exception at the await, so try/catch works.

Execution order

console.log(1);
(async () => { console.log(2); await null; console.log(4); })();
console.log(3);          // prints 1 2 3 4

Code before the first await runs synchronously; the continuation runs after the current script finishes, in the microtask queue (before timers and rendering).

Error handling

A throw in an async function becomes a rejected promise. Forgetting to await or .catch a promise leads to an unhandled rejection (a warning in browsers, a crash by default in recent Node).

Practical rules

  • Independent calls run in parallel with await Promise.all([a(), b()]), not sequential awaits.
  • await in forEach does not wait; use for...of or Promise.all(array.map(...)).
  • Use Promise.allSettled when partial failure is acceptable, and AbortController to cancel.
  • Stack traces stay readable because modern engines (V8 async stack traces) stitch them together.

Pitfalls

return await is needed inside try/catch if you want the catch to see the rejection; accidentally serialising independent requests; and assuming await yields to rendering (microtasks run before the browser paints, so heavy loops still block UI).
