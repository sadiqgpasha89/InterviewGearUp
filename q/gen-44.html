Compare top-down memoization and bottom-up tabulation in dynamic programming.

Software engineer (core) · Gear 2 (Mid-level) · Dynamic programming · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Top-down memoization writes the natural recursion and caches results by state, so only reachable subproblems are solved. Bottom-up tabulation fills a table iteratively from the base cases. Both give the same time complexity; tabulation avoids recursion depth limits and can reduce memory by keeping only the last rows.

Explained in depth

Example: Fibonacci

Top-down:

from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

Bottom-up:

def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

Both take O(n) time; the plain recursion without caching is exponential.

Comparison

Top-downBottom-up
StyleRecursion plus cacheLoops filling a table
Subproblems solvedOnly those neededAll of them in the table
Stack depthCan overflow on deep recursionNone
Space optimisationHardEasy, keep only the previous row
Ease of writingClose to the recurrenceNeeds the correct fill order

Process

  1. Define the state (what identifies a subproblem).
  2. Write the recurrence and base cases.
  3. Pick top-down for clarity or when many states are unreachable, and bottom-up for speed and memory.

DP applies when the problem has overlapping subproblems and optimal substructure.
