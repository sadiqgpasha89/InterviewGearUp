Design a real-time typeahead (search suggestion) service that answers in under 100 ms.

Software engineer (core) · Gear 4 (Lead / Staff) · System design · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Precompute the most popular completions for each prefix from query logs, store them in a trie or prefix-keyed cache with the top suggestions at each node, serve them from memory behind a CDN and local caches, and refresh the data in batches or near real time. Debounce on the client, personalise lightly, and filter unsafe suggestions.

Explained in depth

Requirements

Return the top 5 to 10 suggestions for a typed prefix in under 100 ms, at very high read volume (every keystroke), with suggestions reflecting popularity and freshness.

Data structure

A trie (prefix tree) where each node stores the top-k completions with scores for the prefix ending there. Lookup is O(length of prefix) plus constant time to read the cached top-k, because we avoid traversing the subtree at query time. Alternatives: a key-value store keyed by prefix ("ca" to ["cat", "car", ...]), or a search engine with edge n-grams, which is simpler to run.

Offline and online pipeline

  1. Log collection: queries from the search service flow through Kafka.
  2. Aggregation: batch jobs (hourly or daily) count queries with time decay and filters (remove spam, adult content, personal data and rare queries).
  3. Trie builder: builds a new trie or prefix map snapshot and publishes it to the serving fleet, which swaps it in atomically.
  4. Trending: a streaming path (Flink or Spark Streaming) updates scores for fast-rising queries within minutes.

Serving

  • In-memory serving nodes, sharded by prefix range (for example by first one or two characters, balanced for load) and replicated.
  • Caching: CDN or edge for common short prefixes, a browser cache, and Redis.
  • Client: debounce requests (wait 100 to 200 ms after typing stops), cancel outdated requests, and prefetch.
  • Handle typos with fuzzy matching on the long tail.

Personalisation and safety

Blend global popularity with the user's recent searches and location, computed from a small profile fetched in parallel. Block offensive suggestions with deny lists, and respect privacy settings.

Metrics

Latency percentiles, suggestion click-through, keystrokes saved, and freshness lag.

Likely follow-ups

  • How do you update suggestions for trending queries quickly?
  • How do you shard a trie across servers?
  • How do you personalise suggestions without hurting latency?
