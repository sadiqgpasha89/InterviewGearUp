What are the core principles of GitOps, and how does pull-based reconciliation differ from push-based CI/CD?

DevOps / SRE / Cloud · Gear 3 (Senior) · GitOps · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

GitOps stores the desired state of infrastructure and applications declaratively in Git, and an agent in the cluster continuously reconciles the live system toward it. In the pull-based model, the in-cluster controller pulls changes from Git, so the CI system needs no cluster credentials; in push-based CI/CD, the pipeline pushes changes into the cluster.

Explained in depth

Core principles (OpenGitOps)

  1. Declarative: the desired state is expressed as manifests, Helm charts or Kustomize.
  2. Versioned and immutable: Git is the single source of truth, giving history, review and audit.
  3. Pulled automatically: software agents fetch the approved state.
  4. Continuously reconciled: agents detect and correct drift.

Push versus pull

Push-based CI/CDPull-based GitOps
Who deploysThe pipeline runs kubectl apply or helm upgradeAn in-cluster controller (Argo CD, Flux)
CredentialsCI needs cluster admin access from outsideCluster only needs read access to Git and registry
DriftNot detected until the next runContinuously detected and corrected
RollbackRe-run a pipelinegit revert and the controller applies it
VisibilityPipeline logsDiff between Git and live state

Typical workflow

  1. Developer merges code; CI builds, tests and pushes an image.
  2. CI updates the image tag in a config repository (or an image-updater does) through a pull request.
  3. After review and merge, the GitOps controller notices the change and syncs the cluster.

Benefits

Audit trail, easy rollbacks, consistent environments, reduced credential exposure and disaster recovery by re-applying from Git.

Cautions

Secrets cannot be stored in plain text (use Sealed Secrets or External Secrets), repository structure for many environments needs design, and sync and health feedback is asynchronous, so teams need good dashboards and alerts.
