When should you use ROC AUC versus precision-recall AUC to evaluate a classifier?

Data scientist · Gear 2 (Mid-level) · Model evaluation · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

ROC AUC measures how well scores rank positives above negatives across all thresholds and is insensitive to class prevalence. PR AUC focuses on precision and recall for the positive class and reflects performance under heavy imbalance. Prefer PR AUC when positives are rare and false positives matter, and ROC AUC for balanced problems or ranking quality.

Explained in depth

ROC curve and AUC

The ROC curve plots the true positive rate (recall) against the false positive rate (FPR = FP / (FP + TN)) as the threshold sweeps from 1 to 0. ROC AUC is the area under it and has a neat meaning: the probability that a random positive receives a higher score than a random negative. 0.5 is random, 1.0 is perfect. Properties: invariant to monotonic score transformations and independent of class prevalence (because TPR and FPR are each conditioned on a true class). It evaluates ranking across all thresholds, not calibration.

Precision-recall curve and AUC

The PR curve plots precision against recall. Average precision (AP) summarises it (a weighted mean of precisions at each recall increase). Precision depends on prevalence because it divides by predicted positives, so PR curves expose how many false alarms accompany each level of recall. A random classifier's PR AUC equals the positive rate (0.5 percent for 0.5 percent prevalence), so values must be read relative to that baseline.

Why they disagree under imbalance

Suppose 100,000 negatives and 100 positives. A model that catches 80 percent of positives with FPR = 1 percent gives:

  • TPR = 0.8, FPR = 0.01, which looks great (ROC AUC maybe above 0.95).
  • But FP = 1,000 and TP = 80, so precision = 80 / 1,080 = 7.4 percent. Reviewers would see 12 false alarms per true case.

FPR uses the huge negative class in its denominator, so large absolute numbers of false positives barely move it. PR analysis shows the problem immediately.

Choosing

SituationPrefer
Rare positive class, interest in the positive class (fraud, disease, defect, retrieval)PR AUC / average precision, precision at k, recall at fixed precision
Balanced classes, care about both classes equallyROC AUC works well
Comparing models across datasets with different prevalenceROC AUC is more comparable (but not decision-relevant)
Ranking quality or scoring system independent of thresholdROC AUC; also gain and lift charts
A specific operating constraint exists ("at least 90 percent precision")read the point from the PR curve or report recall at that precision
Costs of errors knownexpected cost curves or decision-curve analysis

Also report calibration (Brier score, reliability curve) if probabilities are used, and metrics at the chosen threshold (confusion matrix).

from sklearn.metrics import roc_auc_score, average_precision_score, precision_recall_curve
print("ROC AUC", roc_auc_score(y_te, p), "AP", average_precision_score(y_te, p), "baseline", y_te.mean())
prec, rec, thr = precision_recall_curve(y_te, p)
ok = prec[:-1] >= 0.9                     # operating point: best recall with precision >= 90%
print(thr[ok][0] if ok.any() else None, rec[:-1][ok].max() if ok.any() else None)

Cautions

  • Both ignore how scores are calibrated.
  • AUC summarises all thresholds, including ones you will never use; partial AUC or metrics in the relevant region can be more meaningful.
  • Small numbers of positives make PR AUC noisy; use bootstrap intervals.
  • Interpolating PR curves linearly is incorrect; use average precision as implemented.
  • Multi-class: one-vs-rest macro averages.

Pitfalls

Quoting ROC AUC as proof of usefulness for rare events, comparing PR AUC across datasets with different prevalence without the baseline, and treating AUC as a decision rule.

Likely follow-ups

  • Why can ROC AUC stay high while precision is poor when negatives vastly outnumber positives?
  • What is the baseline PR AUC of a random classifier?
  • How do you pick an operating point on either curve for a business decision?
