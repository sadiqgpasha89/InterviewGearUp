How do VPC Peering, Transit Gateways, and PrivateLink connect isolated private cloud networks?

DevOps / SRE / Cloud · Gear 3 (Senior) · Cloud · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

VPC peering is a non-transitive one-to-one private link between two VPCs. Transit Gateway is a regional hub-and-spoke router that connects many VPCs, VPNs and on-premises networks with transitive routing and route tables. PrivateLink exposes a specific service privately through interface endpoints without exposing the whole network, so CIDRs may even overlap.

Explained in depth

The problem

Workloads live in separate VPCs (accounts, environments, regions, vendors). Private IP communication between them without crossing the public internet needs a connectivity construct. The right choice depends on scale, routing needs, and how much of each network you want to expose.

VPC peering

A direct, private network connection between two VPCs (same or different account and region). Traffic uses the provider backbone, not the internet.

  • Setup: request and accept the peering, then add routes in each route table to the other's CIDR, and open security groups and NACLs.
  • Non-transitive: if A peers with B and B with C, A cannot reach C through B; it needs its own peering. A full mesh of N VPCs requires N(N−1)/2 peerings, which becomes unmanageable beyond a handful.
  • CIDRs must not overlap (the route table cannot disambiguate).
  • Low latency, no bandwidth bottleneck (no gateway), no hourly attachment fee (data transfer charges apply cross-AZ and cross-region).
  • Best for small numbers of VPCs and simple topologies.

Transit Gateway (AWS; equivalents: Azure Virtual WAN, GCP Network Connectivity Center)

A regional virtual router hub. Each VPC, VPN or Direct Connect attachment connects once to the gateway; route tables on the gateway control which attachments can reach which (propagation and association).

  • Transitive routing: spokes reach each other via the hub, plus on-premises through VPN and Direct Connect.
  • Segmentation: separate route tables for prod, dev and shared services, with isolation or controlled paths (for example all traffic to an inspection VPC with firewalls via appliance mode).
  • Scales to thousands of attachments, supports inter-region peering, multicast and centralised egress and inspection architectures.
  • Costs: per attachment per hour plus per GB processed; bandwidth limits per VPC attachment (tens of Gbps).
  • Overlapping CIDRs still cannot be routed together.

PrivateLink (interface and gateway endpoints)

Exposes one service (behind a Network Load Balancer, or an AWS service like S3 and Secrets Manager) to consumers as an elastic network interface with a private IP in the consumer's subnet. Traffic is one-directional (consumer initiates), the provider cannot reach into the consumer network, and overlapping CIDRs are fine since the consumer talks to a local IP. Provider approves consumer connections, and consumers use security groups and endpoint policies. Used for SaaS vendors, shared internal platforms, accessing AWS services without NAT or internet gateways. Costs: hourly per endpoint per AZ plus data processing.

Choosing

  • Two or three VPCs, simple: peering.
  • Many VPCs, shared services, hybrid with on-premises, centralised inspection: Transit Gateway.
  • Exposing or consuming a specific API across accounts or organisations, or CIDR overlap: PrivateLink.

Often combined: Transit Gateway for internal connectivity, PrivateLink for third-party and shared SaaS endpoints.

Operations

Plan CIDRs centrally (IPAM) to avoid overlap, use infrastructure as code for route tables, monitor flow logs and attachment metrics, use DNS (Route 53 Resolver rules, private hosted zones associated across VPCs), and apply least-privilege security groups instead of broad CIDR routing.

Pitfalls

Forgetting return routes or security group rules, assuming transitive peering, overlapping address plans discovered late, and hidden data processing costs of centralised inspection.

Likely follow-ups

  • How do you segment traffic with Transit Gateway route tables?
  • When do you choose PrivateLink over peering for service consumption?
