What is the software testing life cycle (STLC), and how does it fit with the development life cycle?

QA / SDET · Gear 1 (Junior) · Process · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

The software testing life cycle is the sequence of testing activities: requirement analysis, test planning, test case design, test environment setup, test execution with defect reporting, and test closure. It runs alongside the development life cycle and is repeated in each iteration in agile teams, with testers involved from the first requirement discussion instead of only at the end.

Explained in depth

Phases

  1. Requirement analysis: understand requirements and acceptance criteria from a test point of view; find ambiguities and untestable statements; identify what can be automated. Output: questions, a requirement traceability matrix (RTM).
  2. Test planning: define scope, approach, tools, roles, schedule, risks, environments and entry and exit criteria. Output: test plan.
  3. Test case design: write test cases and scripts using techniques (equivalence partitioning, boundary values, decision tables), prepare test data, and review them. Output: test cases, data, automation scripts.
  4. Test environment setup: configure servers, builds, data and tools; run a smoke test to confirm the environment and build are ready.
  5. Test execution: run tests, compare actual with expected results, log defects with evidence, retest fixes and run regression. Track progress.
  6. Test closure: evaluate against exit criteria; report metrics (coverage, pass rate, defects by severity, escaped defects); document lessons learned and archive artifacts.

Entry and exit criteria

  • Entry: requirements reviewed, build deployed, environment stable, smoke test passes.
  • Exit: planned tests executed, no open critical defects, coverage and pass-rate targets met, sign-off.

Relationship to the SDLC

  • In waterfall, testing phases follow development (the V-model pairs each development phase with a test level).
  • In agile, testing is continuous: each sprint includes analysis, design, automation, execution and a retrospective. Testers join backlog refinement and define acceptance criteria, in the spirit of shift-left.
  • In DevOps, automated tests run in CI/CD pipelines, with monitoring and testing in production.

Key outputs to remember

Test plan, test cases, RTM, defect reports, test summary report. Adapt the ceremony to the team: keep documents light, but keep the discipline of planning, risk-based coverage and clear exit decisions.
