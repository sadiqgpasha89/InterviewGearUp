Explain the Command pattern: Encapsulating actions as objects for queueing, logging, and undo operations.

Software engineer (core) · Gear 2 (Mid-level) · Design patterns · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

The Command pattern turns a request into an object holding the action, its receiver and its parameters. Because the request is now data, you can queue it, log it, schedule it, send it elsewhere and undo it, decoupling who triggers an operation from who performs it.

Explained in depth

Structure

  • Command: interface with execute() (and optionally undo()).
  • ConcreteCommand: binds a receiver to an action and stores parameters.
  • Receiver: the object that does the real work.
  • Invoker: triggers the command (button, menu, scheduler) and knows nothing about the receiver.
  • Client: creates and wires commands.
interface Command { void execute(); void undo(); }

class InsertText implements Command {
    private final Editor ed; private final int pos; private final String text;
    InsertText(Editor ed, int pos, String text) { this.ed = ed; this.pos = pos; this.text = text; }
    public void execute() { ed.insert(pos, text); }
    public void undo()    { ed.delete(pos, text.length()); }
}

class History {
    private final Deque<Command> undo = new ArrayDeque<>(), redo = new ArrayDeque<>();
    void run(Command c) { c.execute(); undo.push(c); redo.clear(); }
    void undo() { if (!undo.isEmpty()) { Command c = undo.pop(); c.undo(); redo.push(c); } }
    void redo() { if (!redo.isEmpty()) { Command c = redo.pop(); c.execute(); undo.push(c); } }
}

What reifying a request gives you

  • Undo and redo: store inverse operations or a before-snapshot (memento) in each command.
  • Queuing and scheduling: thread pools execute Runnables, which are commands.
  • Logging and replay: persist commands to recover after a crash, or to implement audit logs. This is the seed of event sourcing and CQRS command handlers.
  • Macro commands: a composite command that runs a list of commands as a transaction-like batch.
  • Remote execution: serialise a command and send it to a worker.
  • Decoupled UI: a menu item and a keyboard shortcut trigger the same command object.

Command versus Strategy

Both wrap behaviour. A Strategy is a how (interchangeable algorithm inside an object). A Command is a what and when (one specific request that can be stored, delayed and undone).

Pitfalls

  • Undo requires deterministic inverses; irreversible actions (sending an email) need compensation instead.
  • Commands that capture mutable state by reference may behave differently at replay time, so copy what you need.
  • A large number of small command classes is the cost of the pattern; use lambdas for simple cases.
  • Idempotency matters when commands are retried from a queue.
