How does prototypal inheritance work in JavaScript, and what is the prototype chain?

Frontend engineer · Gear 2 (Mid-level) · JavaScript · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Every JavaScript object has an internal prototype link to another object. When you read a property that is not on the object itself, the engine follows that link, then the next one, up the prototype chain until it finds the property or reaches null. Classes and constructor functions are syntax built on this delegation mechanism.

Explained in depth

The chain

const animal = { eats: true, speak() { return 'generic sound'; } };
const dog = Object.create(animal);   // dog's prototype is animal
dog.barks = true;

dog.barks;     // own property
dog.eats;      // not on dog, found on animal through the chain
dog.toString;  // found on Object.prototype, the end of the chain

Property reads walk the chain. Writes create or update an own property on the object itself (unless a setter exists up the chain).

Constructors and classes

function Person(name) { this.name = name; }
Person.prototype.greet = function () { return 'Hi ' + this.name; };

const p = new Person('Ana');
Object.getPrototypeOf(p) === Person.prototype;   // true

new creates an object whose prototype is Person.prototype. The class syntax is a cleaner way of doing the same: methods are placed on the class's prototype, and extends links the prototypes together.

Terms

  • Object.getPrototypeOf(obj) (or the older obj.__proto__) is an object's actual prototype.
  • Func.prototype is the object that will become the prototype of instances created with new Func().
  • hasOwnProperty or Object.hasOwn distinguishes own properties from inherited ones.

Practical notes

Shared methods live once on the prototype, which saves memory. Long chains slow lookups slightly. Avoid changing built-in prototypes, and use Object.create(null) for a plain dictionary with no inherited keys.
