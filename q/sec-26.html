How do digital signatures guarantee non-repudiation and data integrity using asymmetric key pairs?

Security engineer · Gear 2 (Mid-level) · Cryptography · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

To sign, the sender hashes the message and encrypts or signs the hash with their private key; anyone can verify with the public key by checking the signature against a fresh hash. A valid signature proves integrity (the data was not changed) and authenticity (the private key holder signed it). Non-repudiation follows from the signer being the only holder of the private key.

Explained in depth

How signing and verifying work

  1. Sign: compute digest = SHA-256(message), then produce signature = Sign(private_key, digest) (RSA-PSS, ECDSA or Ed25519).
  2. Send the message and the signature.
  3. Verify: the receiver computes the digest of the received message and checks it against the signature using the signer's public key.
from cryptography.hazmat.primitives.asymmetric import ed25519
key = ed25519.Ed25519PrivateKey.generate()
sig = key.sign(b'pay 100 to Ana')
key.public_key().verify(sig, b'pay 100 to Ana')     # raises InvalidSignature if altered

Guarantees

  • Integrity: changing a single bit of the message changes the digest, so verification fails.
  • Authentication: only the holder of the private key could create a signature that verifies under the matching public key.
  • Non-repudiation: because only the signer holds the private key, they cannot plausibly deny signing, provided the key was protected and the public key is reliably bound to them (through a certificate, time stamping and audit trail).

Signature versus MAC

An HMAC uses a shared secret, so either party could have produced it: it gives integrity and authenticity between two parties, but no non-repudiation. A signature uses an asymmetric pair, so anyone can verify and only one party can sign.

Practical points

  • The binding between a public key and a person or server comes from certificates issued by a CA.
  • Protect private keys (HSM or KMS), rotate them, and have revocation procedures.
  • Used for code signing, software updates, JWTs (RS256 and ES256), TLS, email (S/MIME) and legal e-signatures.
