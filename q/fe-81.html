Design an autocomplete search component with debouncing, request cancellation, and keyboard navigation.

Frontend engineer · Gear 2 (Mid-level) · Architecture · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A robust autocomplete debounces input, cancels stale requests with AbortController, ignores out-of-order responses, and implements the ARIA combobox pattern with arrow, Enter and Escape keyboard handling. Cache recent queries and show loading, empty and error states.

Explained in depth

Requirements

Type-ahead suggestions that feel instant, never show stale results, reduce server load, and work fully by keyboard and screen reader.

Data flow

  1. Input event updates local state immediately (the text box must never lag).
  2. Debounce (150 to 300 ms) before querying; skip queries shorter than 2 characters or equal to the previous one.
  3. Cancel the in-flight request when a newer query starts.
  4. Cache results by normalised query (Map or LRU) so backspacing is instant.
  5. Render the list, tracking an activeIndex for keyboard focus.
function createAutocomplete(fetchSuggestions, render) {
  let timer, controller;
  const cache = new Map();
  return function onInput(raw) {
    const q = raw.trim().toLowerCase();
    clearTimeout(timer);
    controller?.abort();                           // cancel stale request
    if (q.length < 2) return render({ status: 'idle', items: [] });
    if (cache.has(q)) return render({ status: 'ok', items: cache.get(q) });
    timer = setTimeout(async () => {
      controller = new AbortController();
      render({ status: 'loading' });
      try {
        const items = await fetchSuggestions(q, controller.signal);
        cache.set(q, items);
        render({ status: items.length ? 'ok' : 'empty', items });
      } catch (e) {
        if (e.name !== 'AbortError') render({ status: 'error' });
      }
    }, 200);
  };
}

Aborting guarantees only the latest request can update the UI. If the API cannot be aborted, compare a monotonically increasing request id before applying a response.

Keyboard and ARIA (combobox pattern)

  • Input: role="combobox", aria-expanded, aria-controls (listbox id), aria-autocomplete="list", and aria-activedescendant pointing at the highlighted option. DOM focus stays in the input.
  • List: role="listbox", items role="option" with unique ids and aria-selected.
  • Keys: ArrowDown and ArrowUp move (wrap or stop), Enter selects, Escape closes then clears, Tab closes, Home and End move the caret, not the list.
  • Announce the number of results in a polite aria-live region.

Edge cases

Ignore Enter during IME composition (isComposing), keep the highlight in view (scrollIntoView({ block: 'nearest' })), close on blur but allow clicks (use mousedown and preventDefault), highlight matched text safely (escape HTML), and highlight no option by default so Enter submits the typed text.

Production concerns

Server-side rate limiting and caching, request cost (prefix indexes, search engines), highlighting and ranking, recent searches, analytics on selection, and virtualised lists for large result sets. In React, put the logic in a useAutocomplete hook or use Downshift, React Aria or Headless UI Combobox.
