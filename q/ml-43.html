What is QLoRA and how do 4-bit NormalFloat (NF4) and double quantization enable fine-tuning on consumer GPUs?

ML / AI engineer · Gear 3 (Senior) · LLMs · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

QLoRA keeps the frozen base model quantised to 4 bits and trains LoRA adapters in higher precision on top of it. It uses NF4, a 4-bit data type designed for normally distributed weights, double quantisation (quantising the quantisation constants too) and paged optimisers to avoid memory spikes, so a 65B model can be fine-tuned on a single 48 GB GPU.

Explained in depth

Problem

Fine-tuning a large model needs memory for the weights, gradients and optimiser states. LoRA removes gradients and optimiser state for most weights, but the 16-bit base weights still occupy about 2 bytes per parameter (130 GB for 65B parameters).

QLoRA ingredients

  1. 4-bit NormalFloat (NF4): pre-trained weights are roughly normally distributed. NF4 places its 16 quantisation levels at the quantiles of a normal distribution, so each level represents equal probability mass. This gives lower error than uniform 4-bit integers or standard 4-bit floats for such weights. Weights are quantised in small blocks (for example 64 values), each with its own scale.
  2. Double quantisation: the per-block scale constants are themselves quantised (to 8 bits), saving roughly 0.37 bits per parameter.
  3. Paged optimisers: optimiser states use unified memory that pages to CPU RAM when the GPU runs short, avoiding out-of-memory crashes on long sequences.
  4. LoRA adapters in 16-bit (bf16) are the only trained parameters.

Forward and backward

The base weights stay in 4 bits. During each layer's computation they are dequantised on the fly to bf16 for the matrix multiplication; gradients flow through to the LoRA adapters, while the quantised weights are never updated.

Results and trade-offs

  • Memory: about 0.5 bytes per base parameter plus small adapter and activation memory.
  • The paper reports quality matching 16-bit LoRA on benchmarks, though some small degradation can occur on sensitive tasks.
  • Slower per step than 16-bit LoRA because of dequantisation.
  • After training, the adapter can be merged into a dequantised or 16-bit copy, or served on top of the quantised model.
