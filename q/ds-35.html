How does gradient boosting work, and how do XGBoost and LightGBM differ and which parameters matter most?

Data scientist · Gear 3 (Senior) · Machine learning algorithms · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Gradient boosting builds trees sequentially, each fitted to the negative gradient of the loss (residuals for squared error) and added with a small learning rate. XGBoost adds second-order optimisation and regularisation, LightGBM uses histogram binning and leaf-wise growth for speed. Learning rate, number of trees, tree depth or leaves, subsampling and regularisation matter most.

Explained in depth

Idea

Boosting builds a strong model by adding weak learners (shallow trees) that each correct the errors of the ensemble so far. In gradient boosting, the model is F_m(x) = F_{m-1}(x) + eta x h_m(x), where h_m is a tree fit to the negative gradient of the loss with respect to the current predictions (pseudo-residuals). For squared error these are simple residuals; for log loss they are y - p. Steps: initialise with a constant (log-odds for classification), compute pseudo-residuals, fit a small tree, set leaf values (a line search or Newton step), scale by the learning rate eta, add to the model, repeat. Compared with bagging (random forests: independent deep trees averaged to reduce variance), boosting reduces bias by sequentially focusing on hard examples, and can overfit if not regularised.

XGBoost

  • Uses a second-order Taylor approximation (gradients and Hessians) of the loss for split gain and leaf weights.
  • Explicit regularisation in the objective: L1 and L2 on leaf weights, a penalty gamma per leaf (min split loss).
  • Sparsity-aware split finding (learns a default direction for missing values), column and row subsampling, parallel histogram or exact split search, GPU support, built-in early stopping.

LightGBM

  • Histogram-based splitting (bins continuous features), much less memory and faster.
  • Leaf-wise (best-first) growth: always splits the leaf with the largest loss reduction, reaching lower loss than level-wise growth for the same number of leaves but can create deep, unbalanced trees that overfit on small data; control with num_leaves, max_depth, min_data_in_leaf.
  • GOSS (gradient-based one-side sampling) and EFB (exclusive feature bundling) for speed; native handling of categorical features (optimal partition splits).
  • CatBoost (related): ordered boosting and ordered target statistics to reduce target leakage and prediction shift; excellent with categorical features.

Parameters that matter

ParameterEffect
learning_rate (eta)smaller = more robust, needs more trees (0.01 to 0.1)
n_estimatorschoose with early stopping on a validation set
max_depth / num_leavesmodel complexity (depth 3 to 8; leaves 15 to 127)

Practical notes

  • Trees need no scaling and handle non-linear interactions and mixed types; they cannot extrapolate beyond training ranges (poor for trending targets).
  • Handle missing values natively, but understand why they are missing.
  • Use monotonic constraints when the business requires them; custom objectives for asymmetric costs; quantile loss for intervals.
  • Interpret with gain importance cautiously (biased to high-cardinality features) and prefer permutation importance or SHAP.
  • Calibrate probabilities when needed; watch for target leakage and group leakage in cross-validation.

Pitfalls

Tuning on the test set, huge numbers of trees without early stopping, ignoring time-based splits for temporal data, and trusting default feature importance.
