Compare RabbitMQ exchange types: Direct, Fanout, Topic, and Headers.

Backend engineer · Gear 2 (Mid-level) · Messaging · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

RabbitMQ routes messages through exchanges to queues using bindings. A direct exchange routes by exact routing key, fanout broadcasts to all bound queues, topic matches wildcard patterns on dotted keys, and headers exchange matches on message header attributes instead of the routing key.

Explained in depth

Model

Producers publish to an exchange, not directly to a queue. The exchange applies routing rules (bindings) and delivers copies to matching queues, from which consumers read. This decouples producers from consumers.

ExchangeRouting ruleTypical use
Directrouting key equals binding key exactlytask routing (email, sms), log severity (error)
Fanoutignores the key and copies to every bound queuebroadcast: cache invalidation, notifications to many services, live scores
Topickey is dot-separated words; binding patterns use * (one word) and # (zero or more)orders.eu.created, logs.#, selective subscriptions
Headersmatches message headers using x-match: all or anymulti-attribute routing where a key is awkward

Examples

Direct:  binding key "error" -> queue errors; publish key "error" -> only that queue.
Fanout:  every bound queue gets each message, regardless of key.
Topic:   binding "orders.*.created" matches "orders.eu.created" but not "orders.created";
         binding "orders.#" matches every key starting with "orders".
Headers: binding {format: pdf, type: report, x-match: all} requires both headers.
// amqplib
await ch.assertExchange('events', 'topic', { durable: true });
await ch.assertQueue('billing', { durable: true });
await ch.bindQueue('billing', 'events', 'orders.*.paid');
ch.publish('events', 'orders.eu.paid', Buffer.from(JSON.stringify(evt)), { persistent: true });

Also useful

  • The default exchange is a nameless direct exchange where each queue is bound automatically with its own name as the key, so publishing with the queue name sends straight to it.
  • Dead-letter exchanges capture rejected, expired or overflowed messages.
  • Alternate exchanges catch unroutable messages; the mandatory flag and publisher confirms tell the producer about failures.
  • Newer RabbitMQ features: quorum queues (replicated, safe), streams (log-like, replayable), consistent hash exchange for sharding.

Choosing

Use direct for simple categories, topic for flexible hierarchical filtering (most common), fanout for broadcast, and headers when routing depends on several unrelated attributes. Topic is generally clearer and faster than headers.

Pitfalls

Messages published to an exchange with no matching binding are silently dropped, queues must be declared consistently (same arguments), non-durable queues and non-persistent messages lose data on restart, and overly broad topic patterns create fan-out surprises.
