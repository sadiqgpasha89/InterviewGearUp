How do you handle severely imbalanced classes, such as 0.5 percent fraud, in training and evaluation?

Data scientist · Gear 2 (Mid-level) · Modeling · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Keep the evaluation set at the real class distribution, choose metrics like PR AUC and recall at fixed precision instead of accuracy, and address imbalance with class weights, resampling inside training folds, or threshold tuning. Calibrate probabilities, use cost-sensitive decisions, and consider anomaly detection or more labels if positives are very scarce.

Explained in depth

Why imbalance is tricky

With 0.5 percent positives, a model that always predicts "negative" has 99.5 percent accuracy and is useless. Standard loss functions are dominated by the majority class, so minority patterns are under-learned, and metrics such as accuracy or ROC AUC can look good while precision for the rare class is poor.

1. Evaluate correctly

  • Never resample the validation or test set; keep the true class prior so metrics reflect production.
  • Use precision, recall, F1/F-beta, PR AUC (average precision), recall at a fixed precision, precision at top-k (when analysts can review k cases per day), and cost-based metrics. ROC AUC can be overly optimistic with huge numbers of negatives; PR curves show the practical trade-offs.
  • Stratified splits, and enough positives per fold (consider repeated stratified CV). Confidence intervals will be wide; report them.

2. Training-level fixes

TechniqueHow it worksNotes
Class weights / cost-sensitive learningpenalise minority errors more (class_weight="balanced", scale_pos_weight)simple and effective; no data duplication
Random oversampling of the minorityduplicate positivescan overfit; apply only to training folds
Undersampling the majoritydrop negativesfaster, loses information; informed methods (Tomek links, NearMiss)
SMOTE and variants (ADASYN, Borderline-SMOTE)synthesise minority points by interpolating neighboursuseful for low-dimensional numeric data; poor for categorical, high-dimensional or noisy data

Always place resampling inside the cross-validation pipeline (imbalanced-learn Pipeline) so duplicated or synthetic points never leak into validation folds.

from imblearn.pipeline import Pipeline
from imblearn.over_sampling import SMOTE
from sklearn.ensemble import HistGradientBoostingClassifier
pipe = Pipeline([("smote", SMOTE(random_state=0)), ("clf", HistGradientBoostingClassifier(class_weight="balanced"))])

3. Decision threshold and calibration

  • The default 0.5 threshold is rarely right. Choose the threshold that minimises expected cost = cost_FP x FP + cost_FN x FN, or maximises F-beta, or meets an operating constraint (review capacity).
  • Resampling and class weights distort predicted probabilities. If you need real probabilities (risk scores, expected loss), recalibrate with Platt scaling or isotonic regression on an untouched, representatively distributed calibration set, or correct the prior shift.

4. Production considerations

Monitor positive rate and score distribution; labels may be delayed (chargebacks), so evaluate on matured cohorts; retrain as fraud patterns shift (adversarial drift). Use explanations for investigators.

Interview structure

Define costs, evaluate with PR-based metrics on an untouched distribution, start with weighted gradient boosting, try resampling in-fold, tune threshold by cost, calibrate, then monitor.

Pitfalls

Resampling before splitting, reporting accuracy, using SMOTE on categorical encodings, and shipping uncalibrated probabilities as if they were real risks.

Likely follow-ups
