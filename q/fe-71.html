What are React portals (`createPortal`) and why are they used for modal dialogs and tooltips?

Frontend engineer · Gear 2 (Mid-level) · React · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A portal renders children into a DOM node outside the parent component's DOM hierarchy while keeping them in the same React tree. That lets modals, tooltips and dropdowns escape overflow clipping and stacking contexts, yet still receive context and bubble events to React ancestors.

Explained in depth

The problem

A modal rendered inside a card with overflow: hidden, a transform or a low z-index stacking context gets clipped or hidden behind other content. Moving the markup to the end of <body> fixes it, but you still want it written where it logically belongs.

createPortal

import { createPortal } from 'react-dom';

function Modal({ open, onClose, children }) {
  if (!open) return null;
  return createPortal(
    <div className="backdrop" onClick={onClose}>
      <div role="dialog" aria-modal="true" onClick={(e) => e.stopPropagation()}>{children}</div>
    </div>,
    document.body                                // target DOM node
  );
}

The DOM output lives under body, escaping clipping and stacking contexts of the parent.

What stays the same

The portal child is still part of the React tree: it receives context from its logical parents (theme, auth, i18n), state and props flow normally, and synthetic events bubble to React ancestors even though the DOM nodes are elsewhere. That is useful (a click in the modal reaches a parent onClick) but can surprise: add stopPropagation or check e.target when the parent should ignore portal events.

Accessibility checklist

  • role="dialog", aria-modal="true", labelled by a heading (aria-labelledby).
  • Move focus into the dialog on open, trap focus inside while open, close on Escape, and restore focus to the trigger on close.
  • Make the rest of the page inert (inert attribute or aria-hidden on the app root) and lock body scroll.
  • Libraries (Radix Dialog, Headless UI, react-aria) handle this; the native <dialog> element with showModal() provides top layer rendering, focus trapping and ::backdrop without portals.

Common uses

Modals, drawers, tooltips and popovers (positioned with Floating UI), toasts, context menus, and dropdowns inside scrollable containers.

Pitfalls

Server rendering: document does not exist on the server, so render portals after mount (useEffect flag) or use a stable container; multiple modals need ordering; CSS from the parent (inherited fonts, variables set on a container) may not apply in body, so put CSS custom properties on :root or the portal container.
