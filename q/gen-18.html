Explain Binary Search Tree (BST) operations: Insertion, deletion, and finding in-order predecessor/successor.

Software engineer (core) · Gear 2 (Mid-level) · Data structures · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A BST keeps smaller keys in the left subtree and larger keys in the right subtree. Search and insert follow one root-to-leaf path. Delete has three cases: a leaf is removed, a node with one child is replaced by that child, and a node with two children is replaced by its in-order successor (or predecessor). Operations take O(h), which is O(log N) if balanced and O(N) if degenerate.

Explained in depth

Insert and search

def insert(node, key):
    if node is None:
        return Node(key)
    if key < node.key:
        node.left = insert(node.left, key)
    elif key > node.key:
        node.right = insert(node.right, key)
    return node

Search follows the same comparisons. The cost is the height h of the tree.

In-order predecessor and successor

  • Successor (next larger key): if the node has a right child, it is the leftmost node of the right subtree. Otherwise it is the lowest ancestor for which the node lies in the left subtree.
  • Predecessor: the rightmost node of the left subtree, or the lowest ancestor whose right subtree contains the node.

Delete

  1. Leaf: remove it.
  2. One child: replace the node by its child.
  3. Two children: copy the in-order successor's key into the node, then delete the successor from the right subtree (it has at most one child).

Complexity

O(h) for each operation. Inserting sorted keys in order produces a linked-list shape with h = N, so production code uses balanced variants. An in-order traversal of a BST visits keys in sorted order, which is also a way to validate one.
