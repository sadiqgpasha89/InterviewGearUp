Compare recursion and iteration: Call stack frames, memory overhead, and tail call optimization (TCO).

Software engineer (core) · Gear 1 (Junior) · Algorithms · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Recursion expresses a problem in terms of smaller versions of itself and pays for it with one stack frame per call, so memory grows with depth and deep recursion can overflow the stack. Iteration reuses one frame and loops. Tail call optimization lets some languages reuse the frame when the recursive call is the last action, but Python and Java do not do this.

Explained in depth

Costs

  • Recursion: each call pushes a frame holding arguments, locals and a return address. Depth n means O(n) stack space. A stack of typically 1 MB to 8 MB can hold only some thousands to hundreds of thousands of frames, so very deep recursion raises a stack overflow error.
  • Iteration: a loop uses constant extra space and avoids call overhead.

Tail calls

A call is in tail position when nothing remains to do after it returns.

def fact(n, acc=1):
    if n <= 1:
        return acc
    return fact(n - 1, acc * n)   # tail call

A compiler with tail call optimization can jump instead of pushing a new frame, giving O(1) stack. Scheme requires it, and Scala and Kotlin can do it for self-recursive functions with a keyword or annotation. Python and Java do not perform TCO, so convert such code to a loop.

Choosing

Prefer recursion for naturally recursive structures such as trees, divide and conquer and backtracking, where it is clearer. Prefer iteration for simple linear loops, very deep inputs and performance-sensitive code. Any recursion can be turned into iteration with an explicit stack.
