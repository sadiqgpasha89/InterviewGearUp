How does the Bellman-Ford algorithm compute shortest paths and detect negative weight cycles?

Software engineer (core) · Gear 3 (Senior) · Graphs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Bellman-Ford relaxes every edge V-1 times, because a shortest simple path has at most V-1 edges. It handles negative edge weights in O(V*E). If a further pass can still relax an edge, there is a negative cycle reachable from the source.

Explained in depth

def bellman_ford(n, edges, src):          # edges = [(u, v, w), ...]
    INF = float('inf')
    dist = [INF] * n
    dist[src] = 0
    for _ in range(n - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] != INF and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            break                          # early exit
    for u, v, w in edges:                  # one more pass
        if dist[u] != INF and dist[u] + w < dist[v]:
            return None                    # negative cycle reachable
    return dist

Why V-1 rounds

After round k, every vertex whose shortest path uses at most k edges has its correct distance. Without negative cycles, shortest paths are simple and use at most V-1 edges, so V-1 rounds are enough.

Detecting a negative cycle

A negative cycle lets you keep lowering distances forever. If any edge can still be relaxed in round V, a negative cycle is reachable from the source. To list the cycle, follow predecessor links back from that vertex V times to land inside it.

Notes

  • Cost O(V*E), slower than Dijkstra, but it works with negative edges.
  • An undirected edge with negative weight is itself a negative cycle.
  • Uses: currency arbitrage (use the negative log of exchange rates), distance-vector routing, and as a step in Johnson's algorithm. The queue-based variant (SPFA) is often faster in practice but has the same worst case.
