What is defence in depth, and why is relying on a single security control risky?

Security engineer · Gear 1 (Junior) · Fundamentals · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Defence in depth layers independent controls across people, process and technology so that if one fails or is bypassed, others still protect the asset. Layers include network segmentation, authentication, authorisation, input validation, encryption, monitoring and backups. A single control is a single point of failure, since every control has gaps, misconfigurations or bypasses.

Explained in depth

The idea

Like a castle with a moat, walls, gates and guards, an attacker should have to defeat multiple, different controls in sequence. Assume that any single layer can fail because of bugs, misconfiguration, stolen credentials or insider mistakes.

Layers (example for a web application)

LayerControls
Policy and peopleSecurity training, onboarding and offboarding, least privilege, change management
Perimeter and networkFirewalls, WAF, DDoS protection, segmentation into tiers, private subnets, network ACLs
HostPatching, hardened images, EDR, minimal packages, disabled unused services
ApplicationInput validation, output encoding, parameterised queries, secure session handling, dependency scanning, secure code review
Identity and accessStrong authentication, MFA, role-based access, short-lived tokens, secrets management
DataEncryption in transit and at rest, key management, masking, backups with tested restores
Detection and responseLogging, SIEM, alerts, incident response plan, regular exercises

Control types

Combine preventive (stop), detective (notice), corrective (recover) and deterrent controls. For example, a firewall (prevent), IDS and logs (detect), and backups (recover).

Principles

  • Layers should be diverse and independent, so a single flaw does not defeat several at once (avoid all layers depending on the same credential).
  • Fail securely (deny by default) and avoid security through obscurity as the only protection.
  • Apply least privilege at each layer to limit the blast radius.

Why one control is not enough

A WAF can be bypassed, an authenticated user can be phished, patching lags behind exploits. If the app also validates input, the database account has minimal rights and data is encrypted, an attacker's exploit gains little. Defence in depth also supports zero trust, where no network location is automatically trusted.
