How do ES Modules (ESM) differ from CommonJS (CJS) in loading semantics and circular dependencies?

Frontend engineer · Gear 2 (Mid-level) · JavaScript · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

ES Modules are static, asynchronously loaded and export live bindings that are resolved before execution; CommonJS loads synchronously at runtime with require and exports copied values via module.exports. This changes tree shaking, top-level await, strict mode defaults and how circular dependencies resolve.

Explained in depth

ESM phases

  1. Construction: parse, find all import specifiers statically, fetch the whole graph.
  2. Instantiation: allocate memory for exports and connect imports to them (live bindings), before any code runs.
  3. Evaluation: execute module bodies in dependency order.

Because imports are hoisted and static, tools can tree shake and statically verify missing exports.

Live bindings versus copies

// counter.mjs
export let count = 0; export function inc() { count++; }
// main.mjs
import { count, inc } from './counter.mjs'; inc(); console.log(count); // 1  (live view)

In CJS, const { count } = require('./counter') copies the number at that moment, so later changes are not seen.

Circular dependencies

  • CJS: require of a module currently loading returns its partially filled module.exports so far, so you may get undefined for functions defined later.
  • ESM: bindings exist from instantiation, so a function declaration is usable even if the other module has not finished evaluating, but accessing a let/const/class export before its evaluation throws a ReferenceError (temporal dead zone).

Best fix: break the cycle by extracting shared code, or defer access to call time.

Interop in Node

  • A .mjs file or "type": "module" makes files ESM; .cjs or default is CJS.
  • ESM can import CJS (default import receives module.exports; named imports depend on static analysis).
  • CJS cannot require ESM synchronously (newer Node versions allow require(esm) for modules without top-level await). Use await import().
  • No __dirname or require in ESM: use import.meta.url, createRequire.
  • Packages should expose "exports" with import and require conditions, avoiding the dual package hazard (two copies of the module loaded with separate state).

Pitfalls

File extensions are required in ESM specifiers, mixing default and named interop, mutating imported bindings (read-only), and bundlers that transform ESM to CJS and destroy tree shaking.
