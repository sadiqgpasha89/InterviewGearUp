What is Apache Spark, and why use it instead of a single-machine tool such as pandas?

Data engineer · Gear 1 (Junior) · Spark · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Spark is a distributed engine that splits data into partitions and processes them in parallel across a cluster, with in-memory computation, a SQL and DataFrame API, and fault tolerance through lineage. Use it when data or computation exceeds one machine's memory or time budget. For data that fits comfortably on one machine, pandas, DuckDB or Polars are simpler and often faster.

Explained in depth

What Spark does

You write DataFrame or SQL code; Spark builds a logical plan, optimises it (Catalyst), and runs it as tasks on executors across a cluster. Data is divided into partitions processed in parallel.

df = spark.read.parquet("s3://lake/orders/")
result = (df.filter(df.status == "paid")
            .groupBy("country")
            .agg({"amount": "sum"}))
result.write.parquet("s3://lake/revenue_by_country/")

Key concepts

  • Lazy evaluation: transformations (filter, select, join) only build a plan; actions (count, write, collect) trigger execution, which lets Spark optimise the whole job.
  • Shuffle: moving data between partitions (joins, group by) over the network; the most expensive operation.
  • Fault tolerance: lost partitions are recomputed from lineage.
  • Unified engine: batch, SQL, streaming (Structured Streaming), machine learning (MLlib), and graphs.

Choosing

If data fits on a laptop or one large VM, use pandas, Polars or DuckDB; they are simple and quick. Use Spark when data size, parallelism or the need to integrate with a data lake and many jobs justify a cluster. Spark's pandas API helps migrate pandas code, but performance depends on understanding partitioning and shuffles.
