Explain Kruskal's algorithm for finding the Minimum Spanning Tree using a greedy approach and Union-Find.

Software engineer (core) · Gear 2 (Mid-level) · Graphs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Kruskal's algorithm builds a minimum spanning tree by sorting all edges by weight and adding each edge if it connects two different components, which Union-Find checks in nearly constant time. It stops after V-1 edges. Time is O(E log E) from the sort.

Explained in depth

Algorithm

  1. Sort edges by weight, smallest first.
  2. For each edge (u, v): if find(u) != find(v), add it to the tree and union(u, v). Otherwise it would create a cycle, so skip it.
  3. Stop when the tree has V - 1 edges.
def kruskal(n, edges):                  # edges: (w, u, v)
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]   # path halving
            x = parent[x]
        return x
    total, used = 0, 0
    for w, u, v in sorted(edges):
        ru, rv = find(u), find(v)
        if ru != rv:
            parent[ru] = rv
            total += w
            used += 1
            if used == n - 1:
                break
    return total

Why the greedy choice is correct

By the cut property, the lightest edge crossing any cut of the graph belongs to some minimum spanning tree. When Kruskal adds the lightest edge that joins two components, that edge is the lightest across the cut between them.

Complexity

Sorting dominates: O(E log E), which equals O(E log V). Union-Find with path compression and union by rank costs almost O(1) per operation. A disconnected graph yields a minimum spanning forest.
