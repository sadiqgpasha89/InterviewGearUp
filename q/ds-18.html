Compare L1 (lasso) and L2 (ridge) regularisation, and explain when you would use elastic net.

Data scientist · Gear 2 (Mid-level) · Modeling · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Both penalise large coefficients to reduce variance. Ridge adds the squared magnitude and shrinks coefficients smoothly without zeroing them, which helps with correlated features. Lasso adds the absolute value and drives some coefficients exactly to zero, giving feature selection. Elastic net combines the two and is a good default with groups of correlated predictors.

Explained in depth

The idea

Ordinary least squares minimises the loss. Regularisation adds a penalty on coefficient size so the model prefers simpler solutions that generalise better, trading a little bias for a larger drop in variance.

  • Ridge (L2): minimise loss + lambda x sum(beta_j squared).
  • Lasso (L1): minimise loss + lambda x sum(|beta_j|).
  • Elastic net: loss + lambda x [alpha x L1 + (1 - alpha)/2 x L2].

Lambda (called alpha or C-inverse in some libraries) controls strength: larger means more shrinkage; zero means no regularisation.

Geometric intuition

The loss has elliptical contours; the penalty defines a constraint region: a circle (L2) for ridge, a diamond with corners on the axes (L1) for lasso. The optimum is where the contour first touches the region. With a diamond, contact often happens at a corner, where some coordinates are zero, so L1 yields sparsity. A circle has no corners, so coefficients shrink but are rarely zero.

Bayesian view

Ridge corresponds to a Gaussian prior on coefficients (MAP estimate); lasso to a Laplace (double exponential) prior, which has a sharp peak at zero.

Practical steps

  1. Standardise features (zero mean, unit variance) first, because the penalty depends on scale; otherwise variables with small units are penalised unfairly. Do not penalise the intercept.
  2. Choose lambda by cross-validation (RidgeCV, LassoCV, ElasticNetCV, LogisticRegressionCV), often using the one-standard-error rule for a simpler model. Plot the regularisation path of coefficients versus lambda.
  3. Inspect the nonzero coefficients; for selection stability, check across bootstrap samples (stability selection).
from sklearn.linear_model import ElasticNetCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
m = make_pipeline(StandardScaler(), ElasticNetCV(l1_ratio=[.1, .5, .9, 1], cv=5, n_alphas=100)).fit(X_tr, y_tr)
print(dict(zip(cols, m[-1].coef_.round(3))), m[-1].alpha_, m[-1].l1_ratio_)

Beyond linear regression

The same penalties apply to logistic regression, GLMs, neural networks (weight decay is L2), and SVMs. Tree models use other regularisers (depth, leaf size, learning rate, subsampling).

Cautions

Regularised coefficients are biased; do not read them as unbiased effects or use naive p-values (post-selection inference needs special methods). Lasso selection is for prediction, not proof of importance. Highly correlated features make the selected set arbitrary.

Pitfalls

Forgetting to scale, tuning lambda on the test set, comparing coefficients across differently scaled models, and treating zero coefficients as "no effect".
