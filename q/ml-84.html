Compare Hyperparameter Optimization algorithms: Grid Search, Random Search, and Bayesian Optimization (Optuna).

ML / AI engineer · Gear 2 (Mid-level) · Tuning · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Grid search tries every combination on a predefined grid, which is exhaustive but explodes with dimensions. Random search samples configurations from distributions and covers important parameters better for the same budget. Bayesian optimisation such as Optuna's TPE builds a model of past trials to choose promising settings next and prunes bad trials early, usually finding good values in far fewer evaluations.

Explained in depth

The problem

Hyperparameters (learning rate, depth, regularisation, number of layers) are not learned by gradient descent. Each evaluation means training a model, so search efficiency matters.

Grid search

Define a discrete list per hyperparameter and evaluate every combination (3 learning rates × 4 depths × 5 regularisation values = 60 trainings).

  • Pros: simple, reproducible, parallel, fine for 1 or 2 hyperparameters.
  • Cons: cost grows exponentially with dimensions; wastes trials on unimportant parameters (testing 5 values of an irrelevant parameter repeats the same effective values of the important one); limited to the points you chose, with a coarse resolution for continuous values.
from sklearn.model_selection import GridSearchCV
GridSearchCV(model, {"max_depth": [3, 5, 7], "learning_rate": [0.01, 0.1]}, cv=5, scoring="roc_auc").fit(X, y)

Random search

Sample each hyperparameter independently from a distribution (log-uniform for learning rates, uniform for dropout, integers for depth) for a fixed number of trials.

  • Bergstra and Bengio (2012) showed it is more efficient than grid when only a few hyperparameters strongly affect the result (low effective dimensionality): each trial explores a distinct value of every parameter, so the important ones are covered more densely.
  • Easy to parallelise, budget is explicit (n_iter), supports mixed and conditional spaces, and anytime stopping.
from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import loguniform, randint
RandomizedSearchCV(model, {"learning_rate": loguniform(1e-3, 3e-1), "max_depth": randint(3, 12)}, n_iter=50, cv=5).fit(X, y)

Weakness: ignores what previous trials learned.

Bayesian optimisation

Treats the validation metric as an expensive black-box function. It fits a surrogate model to observed (hyperparameters, score) pairs and uses an acquisition function (expected improvement, UCB) to balance exploration (uncertain regions) and exploitation (regions likely good) when choosing the next trial.

  • Gaussian-process BO (Spearmint, BoTorch): good for few continuous dimensions, scales poorly beyond a few hundred trials.
  • TPE (Tree-structured Parzen Estimator), the default in Optuna and Hyperopt: models p(x | good) and p(x | bad) with kernel density estimators (splitting trials at a quantile, for example the best 25 percent) and picks the x maximising p(x|good)/p(x|bad). Handles categorical, conditional and large spaces well.
  • SMAC uses random forests.
import optuna
def objective(trial):
    params = {"learning_rate": trial.suggest_float("lr", 1e-4, 1e-1, log=True),
              "max_depth": trial.suggest_int("max_depth", 3, 12),
              "subsample": trial.suggest_float("subsample", 0.5, 1.0)}
    model = lgb.LGBMClassifier(**params)
    for step in range(100):                     # pruning with intermediate values
        model.fit(...); score = evaluate(model)
        trial.report(score, step)
        if trial.should_prune(): raise optuna.TrialPruned()
    return score
study = optuna.create_study(direction="maximize", sampler=optuna.samplers.TPESampler(seed=0), pruner=optuna.pruners.MedianPruner())
study.optimize(objective, n_trials=100, n_jobs=4)

Pruning (median pruner, Successive Halving, Hyperband) stops unpromising trials early based on intermediate results, saving much compute. Optuna also offers CMA-ES, NSGA-II multi-objective search, distributed studies backed by a database, dashboards and importance analysis.

Practical advice

  • Use log scales for learning rates and regularisation; keep ranges sensible; make conditional parameters conditional.
  • Evaluate with cross-validation or a fixed validation split, with the same pipeline (no leakage); keep a final test set untouched to avoid overfitting to validation noise; use nested CV when estimating generalisation of the tuning procedure.
  • Start with a coarse random or TPE search, then refine around good regions; budget by trials or wall time; seed for reproducibility; log everything (MLflow, W&B).
  • Consider multi-fidelity methods (train on subsets or fewer epochs), population-based training for deep learning, and AutoML.

Pitfalls

Searching over too many parameters at once, tuning on the test set, ignoring noise (same params yield different scores), too narrow ranges, and not repeating the best configuration with different seeds.

Likely follow-ups

  • Why does random search beat grid search when only a few hyperparameters matter?
  • How does TPE choose the next trial and how does pruning work?
  • How do you set search spaces, budgets and cross-validation to avoid overfitting the validation set?
