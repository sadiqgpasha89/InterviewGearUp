Explain how to find the Longest Increasing Subsequence (LIS) in $O(N \log N)$ time using patience sorting.

Software engineer (core) · Gear 3 (Senior) · Dynamic programming · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

To find the longest increasing subsequence in O(N log N), keep an array tails where tails[k] is the smallest possible last value of an increasing subsequence of length k+1. For each number, binary search for the first tail that is at least it and replace it, or append if it is larger than all. The final length of tails is the LIS length.

Explained in depth

Algorithm

from bisect import bisect_left

def lis_length(nums):
    tails = []
    for x in nums:
        i = bisect_left(tails, x)     # first tail >= x
        if i == len(tails):
            tails.append(x)           # extends the longest subsequence
        else:
            tails[i] = x              # a smaller ending is better
    return len(tails)

# [10, 9, 2, 5, 3, 7, 101, 18] -> 4

Why it works

tails is always sorted, so binary search applies. Replacing a tail with a smaller value keeps the same length but makes it easier to extend later. This mirrors patience sorting: each number goes onto the leftmost pile whose top is at least as large, and the number of piles equals the LIS length.

Caveats

  • tails is not the subsequence itself; only its length is meaningful.
  • Use bisect_left for a strictly increasing subsequence and bisect_right for a non-decreasing one.
  • To reconstruct the sequence, store for each element the index of its predecessor and the index that currently ends each length.

Complexity

O(N log N) time and O(N) space, compared with the simple DP, where dp[i] is the best length ending at i, which is O(N^2) and fine for a few thousand elements.
