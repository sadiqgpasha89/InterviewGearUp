Why is Composition favored over Inheritance: Fragile base class problems and tight coupling.

Software engineer (core) · Gear 1 (Junior) · OOP · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Inheritance couples a subclass tightly to its parent's implementation, so changes to the base class can break subclasses (the fragile base class problem). Composition builds behaviour by holding and delegating to other objects behind an interface, which keeps coupling loose, lets you swap behaviour at runtime and avoids deep hierarchies.

Explained in depth

Problems with inheritance

  • Fragile base class: a subclass relies on how the parent works internally. Joshua Bloch's example is an InstrumentedHashSet that overrides add and addAll to count insertions; because HashSet.addAll calls add internally, items are counted twice. A harmless-looking change in the parent can break the child.
  • Tight coupling: the subclass inherits everything, including methods that do not fit. The Square extends Rectangle problem is an example of breaking substitutability.
  • Rigid hierarchies: single inheritance forces you to pick one axis of variation, and combinations cause class explosions (for example FlyingSwimmingDuck).

Composition

class Engine:
    def start(self): ...

class Car:
    def __init__(self, engine):      # has-a, injected
        self.engine = engine
    def start(self):
        self.engine.start()          # delegate
  • Behaviour is replaceable at runtime and in tests (pass a fake engine).
  • Classes stay small and focused, and depend on an interface, not on a concrete parent.

Guidance

"Favor composition over inheritance" is a default, not a ban. Use inheritance for a true is-a relationship with a stable, well-designed base class, or when the base class is built and documented for extension.
