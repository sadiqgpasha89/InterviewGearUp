How does React `memo` perform shallow prop comparisons, and when does it fail to prevent re-renders?

Frontend engineer · Gear 2 (Mid-level) · React · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

React.memo skips re-rendering a component when its props are shallowly equal to the previous props, comparing each prop with Object.is. It fails to help when parents pass new object, array or function identities on every render, or when the component consumes changing context or its own state.

Explained in depth

How the comparison works

React.memo(Component) wraps a component so that React compares the new props object to the previous one key by key using Object.is. If every prop is identical, the previous render result is reused and the component function is not called.

const Row = React.memo(function Row({ item, onSelect }) {
  return <li onClick={() => onSelect(item.id)}>{item.name}</li>;
});

Why it often fails

Shallow comparison treats two different object references as different even if their contents are the same.

function List({ items }) {
  const [sel, setSel] = useState(null);
  return items.map(i => (
    <Row key={i.id}
         item={{ ...i, selected: i.id === sel }}      // new object every render
         onSelect={(id) => setSel(id)} />              // new function every render
  ));
}

Both props are new identities each time, so Row re-renders anyway, and memo only added comparison cost.

Making memo effective

  • Pass primitives (selected={i.id === sel}) instead of freshly built objects.
  • Stabilise callbacks with useCallback and derived objects with useMemo.
  • Move state down or lift content up (children as props) so the parent re-renders less often.
  • Keep data immutable so unchanged items keep the same reference.
const onSelect = useCallback((id) => setSel(id), []);
<Row item={i} selected={i.id === sel} onSelect={onSelect} />

Other cases where memo cannot help

  • Context: a memoised component that calls useContext re-renders whenever that context value changes.
  • Its own state or hooks changing.
  • children props that are JSX elements: <Row><b>x</b></Row> creates a new element object each time.
  • Props that legitimately change.

Custom comparator

React.memo(Comp, (prev, next) => prev.id === next.id) can skip updates using your own rule. It is risky: ignoring a prop that the component uses produces stale UI, and deep comparisons can cost more than rendering.

When to use it

Measure first with React DevTools Profiler ("Why did this render?"). Memoise components that are expensive to render or rendered in large lists, and whose props are stable. Memoising everything adds memory and comparison overhead and clutters the code. The React Compiler (React 19 era) auto-memoises components and values, reducing the need for manual memo, useMemo and useCallback.

Pitfalls

Mutating objects in place (same reference, no re-render, stale UI), memo plus inline functions, and trusting memo as a correctness mechanism: it is only an optimisation and React may still re-render.
