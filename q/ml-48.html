What is the KV Cache in autoregressive LLM decoding and why does it create GPU memory bottlenecks?

ML / AI engineer · Gear 3 (Senior) · LLMs · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

During autoregressive decoding each new token needs the keys and values of all previous tokens in every layer. The KV cache stores them so they are computed once and reused, turning per-token cost from quadratic recomputation into a linear read. The cache grows with batch size, sequence length, layers and heads, so it becomes the main GPU memory bottleneck for long contexts and high concurrency.

Explained in depth

Why it exists

For token t, attention needs the keys K and values V of tokens 1 to t. Without a cache, generating each token would recompute K and V for the whole prefix: O(n^2) work overall for each step. The cache stores K and V per layer; at each step the model computes only the new token's K, V and query, appends K, V to the cache and attends over it.

Two phases

  • Prefill: process the whole prompt in parallel, filling the cache. Compute-bound.
  • Decode: generate one token at a time, reading the entire cache each step. Memory-bandwidth-bound.

Cache size

bytes = 2 (K and V) * layers * kv_heads * head_dim * sequence_length * batch * bytes_per_value Example: a 7B-class model with 32 layers, 32 KV heads of dimension 128 and FP16 (2 bytes) uses 2 * 32 * 32 * 128 * 2 = 524,288 bytes (about 0.5 MB) per token. At 4,096 tokens that is 2 GB per sequence; with 32 concurrent users, 64 GB just for the cache.

Why it limits serving

GPU memory holds the weights plus the cache, so cache size bounds concurrent sequences and context length. Fragmentation from variable-length requests wastes memory.

Mitigations

  • GQA and MQA: share K and V across heads, cutting cache several times.
  • PagedAttention (vLLM): store the cache in fixed-size blocks, like virtual memory pages, to avoid fragmentation and allow sharing of common prefixes.
  • KV cache quantisation (INT8 or FP8), sliding-window or sparse attention, and offloading to CPU.
  • Prefix caching to reuse the cache for shared system prompts.
  • Continuous batching and speculative decoding improve throughput.
