What are the common dimensions of data quality and how do you check them in a pipeline?

Data engineer · Gear 1 (Junior) · Data quality · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Common dimensions are completeness (no missing required values), uniqueness (no duplicates), validity (values match formats and ranges), consistency (agreement across systems), accuracy (matches reality) and timeliness (fresh enough). Check them with automated tests at pipeline stage boundaries, such as not-null, unique and accepted-value tests, row counts and freshness, and alert or block loads when they fail.

Explained in depth

The dimensions

DimensionQuestionExample check
CompletenessIs required data present?customer_id is not null; 99 percent of rows have an email
UniquenessAre there duplicates?order_id is unique
ValidityDoes it match rules and formats?Age between 0 and 120; status in an allowed list; valid email pattern
ConsistencyDo systems agree?Order totals equal the sum of line items; same customer count across tables
AccuracyDoes it reflect reality?Reconcile revenue with the finance system
Timeliness (freshness)Is it recent enough?Latest event is under 2 hours old
IntegrityDo references exist?Every order.customer_id exists in customers

Implementing checks

  • dbt tests: not_null, unique, accepted_values, relationships, plus custom SQL tests; Great Expectations, Soda, or warehouse-native checks.
  • Pipeline level: row count versus the source, schema checks, null-rate and distribution thresholds, and freshness SLAs.
  • Place checks at boundaries: after ingestion (is the source healthy?), after transforms (did logic break?), and before publishing.

Handling failures

  • Block the load for critical checks (a duplicate primary key), warn for softer ones, and quarantine bad records in a separate table for review.
  • Alert the owning team with context, and track data quality scores and incidents.

Beyond fixed rules

Anomaly detection on volumes, null rates and value distributions catches the unexpected (Monte Carlo, Soda, custom statistical checks). Data contracts with producers prevent bad data at the source.
