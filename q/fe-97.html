What is the `:has()` relational pseudo-class and how does it replace JavaScript parent selectors?

Frontend engineer · Gear 2 (Mid-level) · CSS · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

The :has() relational pseudo-class selects an element based on its descendants or following siblings, such as form:has(input:invalid). It is effectively a CSS parent selector, replacing JavaScript that toggled classes on parents, and enables state-driven styling and quantity queries with no scripting.

Explained in depth

Syntax

:has(<relative-selector-list>) matches an element if at least one relative selector matches starting from it.

/* Parent that contains an image */
.card:has(img) { display: grid; grid-template-columns: 120px 1fr; }

/* Form group containing an invalid input */
.field:has(input:invalid) label { color: crimson; }

/* Previous sibling selection: h2 immediately followed by a paragraph */
h2:has(+ p) { margin-block-end: 0; }

/* Page-level state: lock scroll when a dialog is open */
html:has(dialog[open]) { overflow: hidden; }

/* Quantity query: layout changes when a list has 4 or more items */
ul:has(li:nth-child(4)) { columns: 2; }

/* Highlight a label when its checkbox is checked, no JS */
label:has(input:checked) { background: #e0f2fe; }

What it replaces

Previously you needed JavaScript to add a has-image or is-invalid class to ancestors, observers for dialog state, or tricks with sibling combinators (which only look forward). Now CSS reacts to state directly, keeping markup clean, working with server-rendered HTML and avoiding hydration flashes.

Combining

.menu:has(> li.active:not(.disabled)) { ... }
:is(.card, .tile):has(:focus-visible) { outline: 2px solid; }   /* focus-within style on any descendant */
section:not(:has(h2)) { border-top: 1px solid; }                /* sections without a heading */

:has() accepts the child > and sibling + and ~ combinators.

Limitations and notes

  • Specificity is that of the most specific selector in its argument.
  • :has() cannot be nested inside another :has(), and pseudo-elements (::before) are not valid inside it.
  • It is forgiving-free: one invalid selector in the list invalidates the whole rule (unlike :is() and :where()).
  • Performance: browsers optimise it, but selectors like body:has(.x) or :has(*) on a huge, frequently mutating DOM require wider invalidation. Scope to the nearest ancestor (.card:has(...)) and avoid broad universal parts.
  • Support: all current evergreen browsers (Chrome 105, Safari 15.4, Firefox 121 and later). Use @supports selector(:has(a)) for progressive enhancement.

Accessibility

CSS cannot change semantics; do not use :has() to hide or reveal information only visually. Keep state in real elements (inputs, details, dialog) so assistive technology sees the same state.
