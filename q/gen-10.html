Compare singly linked lists and doubly linked lists: Pointer overheads and operation trade-offs.

Software engineer (core) · Gear 1 (Junior) · Data structures · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

A singly linked node stores one next pointer; a doubly linked node adds a prev pointer. Doubly linked lists allow O(1) removal of a known node and backward traversal, at the cost of an extra pointer per node and more pointer updates on every insert or delete.

Explained in depth

Structure

  • Singly linked: each node holds a value and next. You can only walk forward.
  • Doubly linked: each node holds a value, next and prev. You can walk both ways, and usually keep both head and tail.

Operation costs

OperationSinglyDoubly
Insert or delete at headO(1)O(1)
Insert at tail (with tail pointer)O(1)O(1)
Delete at tailO(n), you need the predecessorO(1)
Delete a node you already hold a reference toO(n), find the predecessor firstO(1)
Search by valueO(n)O(n)
Traverse backwardsNot possibleO(n)

Trade-offs

  • Memory: the extra pointer is 8 bytes per node on a 64-bit machine, which is a large share of a small node.
  • Update cost: an insert in a doubly linked list rewrites four pointers instead of two, and mistakes at the boundaries (null head or tail) are easy to make. A sentinel node removes most special cases.
  • Use cases: singly linked suits stacks, simple queues and hash table chains. Doubly linked suits LRU caches (move a node to the front in O(1)), undo history and deques.
  • Both have poor cache locality compared with arrays, because nodes are scattered in memory.
