Explain ZeRO (Zero Redundancy Optimizer) memory stages: Partitioning optimizer states, gradients, and parameters.

ML / AI engineer · Gear 4 (Lead / Staff) · Distributed · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

ZeRO removes the redundancy in data-parallel training by splitting model states across GPUs in three stages: stage 1 partitions optimizer states, stage 2 also partitions gradients, and stage 3 also partitions the parameters themselves. Each stage cuts memory per GPU further, with stage 3 needing extra communication.

Explained in depth

Memory in standard data parallelism

With mixed-precision Adam, each parameter needs about 16 bytes: 2 for the fp16 or bf16 weight, 2 for its gradient, and 12 of optimizer state (fp32 master copy 4, momentum 4, variance 4). Plain data parallelism stores all of it on every GPU. A 7B-parameter model needs roughly 112 GB of model states before counting activations.

The stages (N = number of data-parallel GPUs)

StagePartitioned across GPUsApprox. bytes per parameter per GPU
BaselineNothing16
1Optimizer states4 + 12/N
2+ Gradients2 + 14/N
3+ Parameters16/N

With 64 GPUs, stage 3 brings that 112 GB down to under 2 GB of states per GPU, leaving room for activations.

How it works

  • Stage 1: each GPU updates only its slice of the optimizer states and parameters, then the updated parameters are all-gathered.
  • Stage 2: gradients are reduce-scattered so each GPU keeps only the slice it owns.
  • Stage 3: parameters are gathered on demand for each layer's forward and backward pass and then discarded.

Communication

Stages 1 and 2 use about the same volume as ordinary data parallelism. Stage 3 needs roughly 1.5x more, because parameters are gathered in both passes.

Extensions and limits

ZeRO-Offload and ZeRO-Infinity push states to CPU memory or NVMe, trading speed for capacity. ZeRO does not shard activations, so activation checkpointing is still needed, and it is combined with tensor and pipeline parallelism for the largest models. PyTorch FSDP implements the same ideas as stage 3.
