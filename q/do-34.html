Explain how an Ingress Controller routes external HTTP traffic to internal services using Gateway API.

DevOps / SRE / Cloud · Gear 3 (Senior) · Kubernetes · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

An Ingress Controller is a reverse proxy running in the cluster (nginx, Traefik, Envoy) that watches Ingress or Gateway API resources and routes external HTTP and HTTPS requests to Services by host and path. The Gateway API is the newer, more expressive model that separates infrastructure roles into GatewayClass, Gateway and HTTPRoute.

Explained in depth

Ingress model

An Ingress resource declares rules, and an Ingress Controller implements them. The controller is exposed through a Service of type LoadBalancer or NodePort, watches the API server and reconfigures its proxy.

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata: { name: shop }
spec:
  ingressClassName: nginx
  tls:
    - hosts: [shop.example.com]
      secretName: shop-tls
  rules:
    - host: shop.example.com
      http:
        paths:
          - { path: /api, pathType: Prefix, backend: { service: { name: api, port: { number: 80 } } } }
          - { path: /,    pathType: Prefix, backend: { service: { name: web, port: { number: 80 } } } }

Traffic path: client, cloud load balancer, ingress controller pod, Service, pod.

Limits of Ingress

Only HTTP and HTTPS are in the spec, and advanced features (rewrites, timeouts, header matching) depend on vendor-specific annotations, which are not portable.

Gateway API

A more expressive, role-oriented successor:

  • GatewayClass: the implementation (managed by the infrastructure provider).
  • Gateway: listeners, ports and TLS (managed by cluster operators).
  • HTTPRoute (also GRPCRoute, TCPRoute): routing rules owned by application teams, which attach to a Gateway, even across namespaces with explicit permission.

It supports header matching, traffic splitting by weight (useful for canary releases), request mirroring and redirects as standard fields.

Operational notes

Automate certificates with cert-manager, set timeouts and body size limits, run several controller replicas, and use health checks and rate limiting.
