How does `IntersectionObserver` enable performant lazy loading and infinite scrolling without scroll listeners?

Frontend engineer · Gear 2 (Mid-level) · Browser APIs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

IntersectionObserver reports asynchronously when a target element enters or leaves the viewport or another root by given thresholds, without scroll listeners or layout reads on the main thread. That makes lazy loading, infinite scroll, scroll-linked analytics and sticky effects cheap and simple.

Explained in depth

Why not scroll listeners

A scroll handler fires very frequently and typically calls getBoundingClientRect(), which forces synchronous layout (layout thrashing). Even throttled, it competes with rendering on the main thread. IntersectionObserver (IO) is implemented by the browser: intersection is computed during the rendering pipeline and callbacks are batched, so cost stays low.

API

const io = new IntersectionObserver((entries, observer) => {
  for (const e of entries) {
    if (e.isIntersecting) {
      loadImage(e.target);
      observer.unobserve(e.target);         // lazy load once
    }
  }
}, { root: null, rootMargin: '200px 0px', threshold: 0 });

document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));
  • root: the ancestor used as viewport (null means the browser viewport).
  • rootMargin: grows or shrinks the root box, e.g. 200px to start loading before the element is visible.
  • threshold: ratio (or list) of visibility at which to fire (0 for any pixel, 1 for fully visible, [0, .25, .5, 1] for progress).
  • Entries provide isIntersecting, intersectionRatio, boundingClientRect, time.

Infinite scroll

const sentinel = document.querySelector('#sentinel');          // empty div after the last item
let loading = false;
new IntersectionObserver(async ([e]) => {
  if (!e.isIntersecting || loading) return;
  loading = true;
  const items = await fetchNextPage();
  render(items);
  loading = false;
}, { rootMargin: '600px' }).observe(sentinel);

Keep a cursor, guard against concurrent fetches, stop observing when there is no more data, and consider virtualisation (windowing) for very long lists so the DOM stays small.

Other uses

Impression tracking and ad viewability, auto-playing and pausing video, highlighting the current table of contents section, animating elements on reveal, sticky header detection (observe a sentinel at the top), and pausing expensive off-screen work.

Native alternatives

loading="lazy" on images and iframes covers simple lazy loading with no JavaScript. Use IO when you need custom behaviour, thresholds, background images, components or data loading. content-visibility: auto skips rendering off-screen sections.

Pitfalls

Not unobserving or disconnecting (memory leaks), assuming synchronous results, hidden elements (display: none) never intersect, cross-origin iframes give limited data, and an observer callback that changes layout can cause loops if it moves the sentinel back into view.
