Compare Mutexes, Binary Semaphores, and Counting Semaphores in thread synchronization.

Software engineer (core) · Gear 2 (Mid-level) · Systems · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A mutex provides mutual exclusion and has an owner: only the thread that locked it may unlock it. A binary semaphore is a 0/1 signalling counter without ownership, and a counting semaphore tracks N available resources. Use mutexes to protect data, semaphores to signal or limit concurrency.

Mutex

Guards shared data. Because it has an owner, the system can support recursive locking, detect misuse and apply priority inheritance (a low priority holder temporarily runs at the priority of a high priority waiter), which avoids priority inversion. That is why real-time systems use mutexes, not semaphores, for protection.

pthread_mutex_lock(&m);
balance += amount;          // critical section
pthread_mutex_unlock(&m);

Binary semaphore

Initial value 0 or 1; wait (P) decrements or blocks, post (V) increments and wakes a waiter. It is often used for signalling: thread A does post when an event completes, thread B waits on it. B is not "owning" anything.

sem_t ready;  sem_init(&ready, 0, 0);
// consumer: sem_wait(&ready);   // blocks until the producer signals
// producer: ... prepare data ...; sem_post(&ready);

Using a binary semaphore as a mutex works but loses ownership checks and priority inheritance, and anyone can accidentally release it.

Counting semaphore

Initialised to the number of permits. It models pools:

Semaphore dbPermits = new Semaphore(10);
void query() throws InterruptedException {
    dbPermits.acquire();             // blocks when 10 queries are running
    try { runQuery(); } finally { dbPermits.release(); }
}

Typical uses: connection pools, rate or concurrency limiting, bounded buffers (one semaphore counts empty slots, another counts full slots).

Choosing

  • Protecting a data structure: mutex (or read-write lock).
  • Waiting for an event: condition variable, latch or binary semaphore.
  • Limiting parallelism or modelling a resource pool: counting semaphore.

Pitfalls

Deadlock from wrong acquisition order, releasing a mutex from another thread (undefined behaviour in POSIX), lost wakeups when signalling before anyone waits (a semaphore remembers the post, a plain condition variable does not), and starvation when wake-up order is unfair.
