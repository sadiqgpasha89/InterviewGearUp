How does a Segment Tree support range sum queries and point updates in $O(\log N)$ time?

Software engineer (core) · Gear 3 (Senior) · Data structures · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

A segment tree stores aggregates (sum, min, max) of array ranges in a binary tree, so a range query combines O(log N) nodes and a point update recomputes O(log N) ancestors. It trades O(N) extra memory for logarithmic queries and updates, and extends to lazy range updates.

Explained in depth

Structure

Each node covers a segment [l, r] of the array and stores the aggregate of that segment. The root covers [0, n-1]; each node splits its range at the midpoint into two children. Leaves hold single elements. The tree has 2n - 1 nodes (an array of size 4n is a safe bound for recursive layout).

Build, query, update (sum)

class SegTree:
    def __init__(self, a):
        self.n = len(a); self.t = [0] * (4 * self.n); self._build(a, 1, 0, self.n - 1)
    def _build(self, a, v, l, r):
        if l == r: self.t[v] = a[l]; return
        m = (l + r) // 2
        self._build(a, 2*v, l, m); self._build(a, 2*v+1, m+1, r)
        self.t[v] = self.t[2*v] + self.t[2*v+1]
    def query(self, v, l, r, ql, qr):               # sum of a[ql..qr]
        if ql > r or qr < l: return 0               # disjoint: identity element
        if ql <= l and r <= qr: return self.t[v]    # fully covered
        m = (l + r) // 2
        return self.query(2*v, l, m, ql, qr) + self.query(2*v+1, m+1, r, ql, qr)
    def update(self, v, l, r, pos, val):            # point assignment
        if l == r: self.t[v] = val; return
        m = (l + r) // 2
        if pos <= m: self.update(2*v, l, m, pos, val)
        else: self.update(2*v+1, m+1, r, pos, val)
        self.t[v] = self.t[2*v] + self.t[2*v+1]

Complexity

  • Build O(n), space O(n).
  • A range query visits at most about 4 log n nodes: at each level at most two partially covered nodes are expanded, so O(log n).
  • Point update walks one root-to-leaf path and recomputes parents: O(log n).

Extensions

  • Any associative operation with an identity: min, max, gcd, XOR, matrix product, "(count, max)" tuples.
  • Lazy propagation supports range add or assign by storing pending tags on nodes and pushing them down only when needed, keeping updates O(log n).
  • Iterative bottom-up version (size 2n) is faster and shorter for commutative operations.
  • Persistent and 2D variants, merge sort trees, and sweep line problems (area of union of rectangles).

Pitfalls

Off-by-one errors in the inclusive ranges, wrong identity for disjoint nodes (0 for sum, +infinity for min), too small an array, and forgetting to push lazy tags before descending.
