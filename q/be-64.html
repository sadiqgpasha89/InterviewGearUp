What is Cross-Origin Resource Sharing (CORS), and what triggers an HTTP OPTIONS preflight request?

Backend engineer · Gear 2 (Mid-level) · Security · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

CORS lets a server tell browsers which other origins may read its responses, using Access-Control-Allow-* headers. The browser sends a preflight OPTIONS request first when the actual request is not 'simple': a method like PUT or DELETE, a custom header such as Authorization, or a JSON content type.

Explained in depth

Why it exists

The same-origin policy stops a page on a.com from reading responses from b.com. CORS is a controlled exception: b.com replies with Access-Control-Allow-Origin: https://a.com and the browser then allows the page to read the response.

Simple requests

GET, HEAD or POST with only basic headers and a content type of form-encoded, multipart or plain text are sent straight away. The browser checks the response headers afterwards and hides the response from the script if they do not allow it. (The request may still have reached the server.)

Preflight

For anything else, the browser first sends:

OPTIONS /api/orders
Origin: https://a.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: authorization, content-type

The server must answer with Access-Control-Allow-Origin, Access-Control-Allow-Methods and Access-Control-Allow-Headers. Only then is the real request sent. Access-Control-Max-Age lets the browser cache the answer.

Triggers include methods such as PUT, PATCH and DELETE, custom or Authorization headers, and content types such as application/json.

Credentials

To send cookies, the client sets credentials: 'include' and the server must return Access-Control-Allow-Credentials: true with a specific origin, not *.

Common mistakes

  • CORS is enforced by browsers. It does not protect your API from curl, servers or other non-browser clients, and it is not a CSRF defence.
  • Reflecting any Origin header back with credentials enabled lets any site read your users' data. Use an allow-list and add Vary: Origin.
  • A missing CORS header on an error response (such as 500) shows up in the browser as a misleading CORS error.

Likely follow-ups

  • Why can you not use a wildcard origin together with credentials?
  • Does CORS stop a malicious site from making a POST request to your API?
  • How do you debug a CORS error that appears only on error responses?
