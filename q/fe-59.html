How does `requestAnimationFrame` synchronize animations with the browser refresh rate?

Frontend engineer · Gear 2 (Mid-level) · DOM · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

requestAnimationFrame schedules a callback just before the browser's next repaint, normally 60 or more times per second in step with the display. Doing visual updates there avoids wasted work, tearing and jank that setTimeout or setInterval cause, and it pauses automatically in background tabs.

Explained in depth

Why not timers

setTimeout(fn, 16) is not aligned with the display refresh. The callback may run mid-frame, twice before one paint (wasted work), or miss a frame (visible stutter). Timers keep firing in hidden tabs and drain battery.

rAF behaviour

The browser's frame pipeline is: input events, timers, rAF callbacks, style, layout, paint, composite. Callbacks queued with requestAnimationFrame run right before style and layout for that frame, so all changes made there are rendered together in one pass. It receives a high resolution timestamp.

let start = null;
function tick(now) {
  if (start === null) start = now;
  const t = Math.min((now - start) / 1000, 1);            // 1 second animation, time based
  box.style.transform = `translateX(${easeOut(t) * 300}px)`;
  if (t < 1) id = requestAnimationFrame(tick);            // schedule the next frame
}
let id = requestAnimationFrame(tick);
// cancelAnimationFrame(id) to stop

Using elapsed time (not "add 5px per frame") makes speed independent of the refresh rate (60, 120, 144 Hz) and of dropped frames.

Good practice

  • Animate transform and opacity, which the compositor can handle without layout or paint.
  • Batch reads before writes: reading offsetWidth after writing styles forces synchronous layout (layout thrashing). Pattern: measure in one callback, mutate in the next.
  • Use it to throttle high frequency events: record the latest mouse or scroll position in the event handler and process once per frame in rAF.
  • Cancel on unmount (cancelAnimationFrame) to avoid leaks; in React, store the id in a ref.
  • Do not run heavy computation inside; a callback longer than about 16 ms drops frames. Move work to a Web Worker or chunk it.
  • Hidden tabs pause rAF, which helps battery; do not rely on it for logic that must continue (use timers or workers).

Alternatives

CSS transitions and keyframe animations and the Web Animations API (element.animate) run off the main thread when properties are compositor friendly and are simpler for declarative effects. Use rAF for canvas and WebGL drawing, physics, scroll-linked custom effects and games.

Pitfalls

Scheduling a new rAF when nothing changes (a permanent loop), forgetting that the callback time is a frame-start timestamp (compare with performance.now() only consistently), and animating layout properties (top, width), which triggers layout every frame.
