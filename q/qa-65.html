How do you verify file downloads (PDF, CSV, Excel) and validate their contents in automated browser tests?

QA / SDET · Gear 2 (Mid-level) · UI Automation · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Capture the download event in the browser tool, save the file to a known temporary path, then validate the content with a parser rather than comparing bytes: pdf-parse or pdfplumber for PDF text, a CSV parser, and openpyxl or SheetJS for Excel. Assert filename, MIME type, size, headers, row counts, formulas and key values against expected data from the API or database.

Explained in depth

Capturing the download

Browsers write downloads to disk and may show OS dialogs. Test tools provide an event or a configured download directory.

// Playwright: the download is tied to the page and saved under a temp path
const [download] = await Promise.all([page.waitForEvent('download'), page.click('text=Export CSV')]);
expect(download.suggestedFilename()).toMatch(/^orders-\d{4}-\d{2}-\d{2}\.csv$/);
const path = await download.path();                          // or await download.saveAs('tmp/orders.csv')
// Selenium (Chrome): configure a download directory, then poll for the finished file (ignore .crdownload)
ChromeOptions o = new ChromeOptions();
o.setExperimentalOption("prefs", Map.of("download.default_directory", dir.toString(), "download.prompt_for_download", false,
    "plugins.always_open_pdf_externally", true));
// Cypress: cy.task or readFile with retry
cy.get('#export').click(); cy.readFile('cypress/downloads/report.xlsx', { timeout: 15000 }).should('exist');

On remote grids, the file lands on the browser node, not the test machine; use grid features (Selenium 4 getDownloadableFiles and downloadFile, BrowserStack or Sauce download APIs) or verify through an API download endpoint instead.

Validating content by type

  1. CSV: parse with a real parser (handle quotes, commas, newlines, BOM, encoding UTF-8 or Windows-1252, delimiters).
import csv
rows = list(csv.DictReader(open(path, encoding='utf-8-sig')))
assert rows[0].keys() == {'order_id', 'customer', 'total', 'currency'}
assert len(rows) == expected_count
assert sum(Decimal(r['total']) for r in rows) == expected_total
  1. Excel (.xlsx): openpyxl.load_workbook(path, data_only=True); assert sheet names, headers, number formats, formulas (data_only=False), merged cells, column widths if relevant, and data types (dates are real dates, not text). Node: SheetJS or ExcelJS.
  2. PDF: extract text with pdfplumber, PyMuPDF, pdf-parse or pdftotext; assert invoice number, totals, line items, page count, metadata, fonts embedded, accessibility tags if required. For layout, render pages to images and compare visually (pdftoppm, then image diff or Playwright screenshot comparison with tolerance) and verify tables are not clipped or overlapped; check images and logos are present.
  3. ZIP and other formats: unzip and validate each entry; JSON files via schema; images by dimensions.

Expected values

Compare against the source of truth (API response or database query for the same filter) instead of hard-coded numbers; this validates that the export honours filters, sorting, permissions, and locale. Include edge cases: special characters, unicode, very long text, empty result (headers only), large exports (streaming, memory, time), formula injection prevention (cells starting with =, +, -, @ are escaped), correct timezone and date formats, thousands separators, and localised numbers.

Robustness and hygiene

  • Wait for the download completion, not a fixed sleep; ignore partial files; use a unique per-test download directory and clean up.
  • Mask dynamic parts (generation timestamp, report IDs) with regular expressions, or freeze time.
  • Test headers through API tests too: Content-Disposition: attachment; filename*=UTF-8''..., Content-Type, Content-Length, caching headers, authorisation on download URLs (signed URL expiry, other users cannot fetch).
  • Large file performance and cancellation; error responses (an HTML error page saved as .pdf is a classic defect: check magic bytes %PDF-).
  • Security: files are generated without leaking other tenants' data.

Pitfalls

Hard-coded sleeps, comparing whole binary files (PDF and XLSX contain timestamps), forgetting remote-grid file location, not parsing CSV with a real parser, and validating only that "a file exists".
