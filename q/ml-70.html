Compare Collaborative Filtering (matrix factorization) with Content-Based recommender systems.

ML / AI engineer · Gear 2 (Mid-level) · Recommenders · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Collaborative filtering learns only from user-item interactions, factorising the interaction matrix into user and item latent vectors whose dot product predicts preference. Content-based methods recommend items similar to those a user liked, using item features. CF finds surprising matches but has cold start, while content-based works for new items but over-specialises. Hybrids combine both.

Explained in depth

Content-based filtering

Represent each item by features (genre, tags, text embedding, image embedding, price, category) and each user by a profile aggregated from items they interacted with. Recommend items whose feature vectors are most similar to the profile (cosine similarity).

  • Pros: works for new items with metadata (no interaction history needed), transparent explanations ("because you watched sci-fi"), no need for other users' data (privacy-friendly), no popularity bias.
  • Cons: limited serendipity (over-specialisation), depends on feature quality and engineering, struggles to capture taste not expressed by features, new users still need some history.

Collaborative filtering (CF)

Uses only the user-item interaction matrix R (ratings, clicks, purchases, watch time), assuming people with similar past behaviour like similar things.

  • Neighbourhood methods: user-based or item-based kNN using similarity (cosine, Pearson) on interaction vectors; simple but poor scalability and sparsity issues. Item-item CF is a common production baseline.
  • Matrix factorisation (latent factor models): approximate R ≈ P Qᵀ with user matrix P (m × k) and item matrix Q (n × k), where k is 20 to 500 latent factors (for example "action versus romance" dimensions learned automatically). Predicted score r̂_ui = p_u · q_i (plus biases μ + b_u + b_i).
  • Objective: minimise Σ_{(u,i) observed} (r_ui − p_u·q_i)² + λ(‖p_u‖² + ‖q_i‖²) using SGD or ALS (alternating least squares: fix one matrix, solve a closed-form least-squares for the other; parallelisable in Spark).
  • Implicit feedback (clicks, views): treat observations as confidence-weighted preferences (Hu, Koren, Volinsky), include unobserved entries as weak negatives, or use ranking losses such as BPR (Bayesian Personalized Ranking) and sampled softmax.
  • Extensions: SVD++, factorisation machines, neural collaborative filtering, autoencoders (EASE, Mult-VAE), graph neural networks (LightGCN), sequence models (SASRec).

Hybrids and modern practice

Real systems combine signals: feed content embeddings into factorisation (LightFM, hybrid features), two-tower neural models for retrieval followed by ranking models (gradient boosting or deep) using rich features, context, and business rules; reranking for diversity, freshness and fairness.

Evaluation

Offline: recall@K, precision@K, nDCG, MAP with time-based splits (not random) to avoid leakage; coverage, diversity, novelty. Online: A/B tests on engagement and retention, since offline metrics correlate imperfectly with online outcomes.

Pitfalls

Evaluating with random splits, ignoring exposure bias (users only interact with what was shown), treating missing entries as dislikes, and optimising clicks at the expense of long-term satisfaction.
