How does Inverted File Index with Product Quantization (IVF-PQ) compress billion-scale vector indexes?

ML / AI engineer · Gear 3 (Senior) · RAG · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

IVF-PQ combines two ideas. The inverted file index clusters vectors with k-means into nlist cells and searches only the nprobe nearest cells. Product quantization splits each vector into m sub-vectors, each replaced by a one-byte codebook id, compressing a 768-dimensional float vector from about 3 KB to tens of bytes, with distances computed from lookup tables.

Explained in depth

The scaling problem

One billion 768-dimensional float32 embeddings occupy about 3 TB of RAM, and brute-force search is O(N). Graph indexes such as HNSW need the full vectors plus links in memory. IVF-PQ reduces both compute (searching a small fraction of vectors) and memory (compressed codes).

IVF: inverted file index (coarse quantisation)

  1. Train k-means on a sample to get nlist centroids (for example 4096 to 262,144 for a billion vectors, about √N is a common start).
  2. Assign each vector to its nearest centroid and store it in that centroid's inverted list.
  3. Query: find the nprobe nearest centroids to the query, then scan only the vectors in those lists (about nprobe/nlist of the data).

Higher nprobe raises recall and latency. Vectors close to a cell boundary may fall in a different cell than the query probes, so recall is below 100 percent. Often vectors are stored as residuals (vector minus centroid) to improve quantisation accuracy.

PQ: product quantization (compression)

  1. Split each D-dimensional vector into m sub-vectors of dimension D/m (for example 768 → m = 96 sub-vectors of 8 dims).
  2. For each subspace, run k-means with 2^nbits centroids (typically 256 for 8 bits) to build a codebook.
  3. Encode each sub-vector as the index of its nearest sub-centroid. A vector becomes m bytes (96 bytes versus 3072 bytes: 32x compression), code size = m × nbits / 8.
  4. Asymmetric distance computation (ADC): for a query, precompute a lookup table of distances between each query sub-vector and each of the 256 centroids in that subspace (m × 256 entries). The distance to any encoded vector is the sum of m table lookups, with no decompression. This is very fast and SIMD-friendly (FAISS fast scan with 4-bit codes).

The effective number of representable vectors is 256^m, giving fine granularity from small codebooks.

Putting it together

import faiss
d, nlist, m, nbits = 768, 65536, 96, 8
quantizer = faiss.IndexFlatL2(d)                       # coarse quantizer
index = faiss.IndexIVFPQ(quantizer, d, nlist, m, nbits)
index.train(train_vectors)                              # k-means for nlist + PQ codebooks (e.g. 10-50M samples)
index.add(vectors)
index.nprobe = 64
D, I = index.search(queries, 100)                       # candidate ids, then optionally rerank

Memory per vector ≈ m bytes + id (8 bytes), so 1B vectors ≈ 100 GB instead of 3 TB, which fits on a few machines or even disk-based setups.

Trade-offs and tuning

  • Recall versus compression: PQ introduces quantisation error; more sub-vectors (m) or bits improve accuracy at higher memory. OPQ (rotation before PQ) reduces error.
  • Re-ranking: retrieve a larger candidate set (for example top 1000) with PQ distances, then re-score with full-precision vectors from disk or object storage to restore accuracy (IVF-PQ with refine, IndexRefineFlat).
  • Training data must resemble the production distribution; retrain when distribution drifts. Index build is expensive (k-means on large samples, GPU accelerated).
  • Updates: adding vectors is easy, but deletions and centroid drift need periodic rebuilds.
  • Combine with sharding, GPU search (FAISS GPU, cuVS), and metadata filtering (filter lists or pre-filtering).
  • Alternatives: HNSW (high recall and speed but memory-hungry), DiskANN/Vamana (graph on SSD with PQ in RAM), ScaNN (anisotropic quantisation), binary quantisation (32x with Hamming), scalar quantisation (4x).

Pitfalls

Too few probes for the dataset, training codebooks on non-representative samples, ignoring re-ranking, using inner product with PQ without normalisation consideration, and forgetting memory for the coarse quantiser and inverted lists.
