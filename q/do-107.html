What are the core Kubernetes objects (Pod, ReplicaSet, Deployment, Service, ConfigMap, Secret) and how do they relate?

DevOps / SRE / Cloud · Gear 1 (Junior) · Kubernetes · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

A Pod runs one or more containers. A ReplicaSet keeps a set number of identical Pods alive, and a Deployment manages ReplicaSets to provide rolling updates and rollbacks. A Service gives a stable address and load balancing to matching Pods, while ConfigMaps and Secrets inject configuration and sensitive values without rebuilding images.

Explained in depth

The building blocks

  • Pod: the smallest deployable unit; one or more containers sharing a network namespace (one IP) and volumes. Pods are ephemeral: when one dies it is replaced by a new one with a new IP.
  • ReplicaSet: ensures N replicas of a Pod template are running, replacing failed ones.
  • Deployment: the normal way to run stateless apps. It owns ReplicaSets, performs rolling updates (creating a new ReplicaSet gradually) and supports kubectl rollout undo.
  • Service: a stable virtual IP and DNS name that load-balances to Pods selected by labels. Types: ClusterIP (internal), NodePort, LoadBalancer (cloud load balancer).
  • ConfigMap: non-sensitive configuration (files or environment variables).
  • Secret: sensitive values (passwords, tokens). They are only base64-encoded by default, so enable encryption at rest and tight RBAC, or use an external secrets manager.
  • Also: Namespace (isolation scope), Ingress (HTTP routing), PersistentVolumeClaim (storage), StatefulSet and DaemonSet.

Example

apiVersion: apps/v1
kind: Deployment
metadata: { name: web }
spec:
  replicas: 3
  selector: { matchLabels: { app: web } }
  template:
    metadata: { labels: { app: web } }
    spec:
      containers:
        - name: web
          image: myorg/web:1.4.2
          envFrom: [{ configMapRef: { name: web-config } }]
---
apiVersion: v1
kind: Service
metadata: { name: web }
spec:
  selector: { app: web }
  ports: [{ port: 80, targetPort: 8080 }]

Relationships

Deployment creates ReplicaSet, which creates Pods. The Service selects Pods by label, so it keeps working as Pods come and go. Always declare resource requests and limits and health probes.
