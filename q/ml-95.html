How do you generate high-fidelity synthetic tabular data using CTGANs and Copulas for training data augmentation?

ML / AI engineer · Gear 2 (Mid-level) · Data · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

CTGAN conditions a GAN on a mode-specific normalised discrete column and uses mode-specific normalisation for continuous columns, so it models mixed tabular data with imbalanced categories. Gaussian copulas model each column's marginal distribution and the dependency structure separately. Generate, then validate fidelity, utility and privacy before using the data for augmentation.

Explained in depth

Why synthetic tabular data

Uses: augment small or imbalanced datasets (rare fraud), share data without exposing individuals, create test data, simulate scenarios. Tabular data is hard for generative models: mixed continuous and discrete columns, multimodal and skewed distributions, imbalanced categories, and column dependencies.

Gaussian copula

A copula separates a joint distribution into marginals and dependence.

  1. Fit each column's marginal distribution (parametric or empirical CDF).
  2. Transform each column to uniform via its CDF, then to standard normal via the inverse normal CDF.
  3. Estimate the correlation matrix of the transformed (normal) columns.
  4. Sample: draw multivariate normal vectors with that correlation, map back through the normal CDF and inverse marginal CDFs to get realistic marginals with learned correlations.

Pros: fast, deterministic, interpretable, works on CPU, little data needed, good for numeric correlations. Cons: captures only linear (rank) dependence summarised by a correlation matrix, struggles with complex, nonlinear, multimodal or mixed-type relationships.

CTGAN (Conditional Tabular GAN)

Xu et al., 2019. Architecture and tricks designed for tabular problems:

  • Mode-specific normalisation: a continuous column is modelled with a variational Gaussian mixture; each value is represented by its mode (one-hot) plus a normalised value within that mode, handling multimodal distributions and non-Gaussian shapes.
  • Conditional generator and training-by-sampling: pick a discrete column and a category (sampling categories by log-frequency so minority classes appear often), condition the generator on that choice, and add a loss so the generated row matches the condition; this combats imbalance and mode collapse for rare categories.
  • Fully connected generator with residual connections, PacGAN (discriminator sees groups of samples) to reduce mode collapse, WGAN-GP loss.
  • Variants: TVAE (variational autoencoder, often competitive), CopulaGAN, TabDDPM (diffusion), CTAB-GAN, GReaT (LLM-based).

Validating "high fidelity"

  1. Statistical fidelity: compare marginals (KS or total variation distance), pairwise correlations and contingency tables, column-pair plots; SDMetrics quality report (Column Shapes, Column Pair Trends).
  2. Machine learning utility (TSTR): Train on Synthetic, Test on Real versus train-on-real, test-on-real; performance within a few points indicates utility; also check feature importance agreement.
  3. Detectability: train a classifier to distinguish real from synthetic; AUC near 0.5 is best.
  4. Constraint checks: business rules (age ≥ 0, end date after start, referential integrity across tables), uniqueness, valid categories.
  5. Privacy: nearest-neighbour distance to the closest training record (DCR) to detect copies, membership inference attacks, attribute disclosure, optional differential privacy (DP-CTGAN, PATE-GAN) with accuracy trade-off.

Using synthetic data for augmentation

  • Generate only the training split from the training data (never from test data); keep the real validation and test sets untouched.
  • For imbalance, generate minority-class samples via conditional sampling; compare against SMOTE, class weights, and focal loss, since simple methods often match GANs.
  • Mix real and synthetic, tune the ratio, and monitor for model degradation from artefacts; synthetic data cannot add information not in the real data, it can only regularise or rebalance.

Limitations

Needs enough real rows (thousands) for CTGAN, can memorise rare records, struggles with high-cardinality categories and long-range or temporal dependencies, and hyperparameters matter. Treat synthetic data as derived from sensitive data: apply governance unless privacy guarantees are formally established.

Pitfalls

Assuming synthetic equals anonymous, evaluating only marginal histograms, generating from the full dataset including test rows, and ignoring business constraints.
