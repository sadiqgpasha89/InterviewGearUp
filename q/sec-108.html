What is a man-in-the-middle (MITM) attack, and how do you defend against it?

Security engineer · Gear 1 (Junior) · Network security · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

In a man-in-the-middle attack the attacker secretly sits between two parties, reading or altering their communication. It happens through compromised Wi-Fi, ARP or DNS spoofing, rogue proxies or malicious certificates. Defend with TLS and certificate validation, HSTS, certificate pinning for sensitive apps, VPNs on untrusted networks, secure DNS, and user awareness of certificate warnings.

Explained in depth

How it works

The attacker intercepts traffic between a client and a server and either eavesdrops (passive) or modifies and injects data (active), often impersonating each side to the other.

Common techniques

  • Rogue Wi-Fi or evil twin: a fake access point with a familiar name; all traffic passes through the attacker.
  • ARP spoofing on a local network: the attacker claims to be the gateway so devices send traffic to them.
  • DNS spoofing or poisoning: forged answers send the victim to the attacker's server.
  • SSL stripping: downgrading HTTPS links to HTTP when the first request is plain HTTP.
  • Fake or stolen certificates, or a malicious root CA installed on the device.
  • Compromised routers, proxies or malware on the endpoint.
  • BGP hijacking at the internet routing level.

Defences

  1. Strong TLS everywhere with proper certificate validation: verify chain, hostname and expiry; never disable verification in code ("trust all certificates" is a classic vulnerability).
  2. HSTS (with preload) forces HTTPS and prevents downgrade; redirect HTTP to HTTPS.
  3. Certificate pinning or certificate transparency monitoring for high-risk apps (with care for rotation), and CAA records.
  4. Mutual TLS for service-to-service traffic, and VPN or zero trust access on untrusted networks.
  5. Secure DNS (DNSSEC validation, DNS over HTTPS or TLS).
  6. Network protections: switch features such as dynamic ARP inspection, DHCP snooping and 802.1X; use WPA3 for Wi-Fi.
  7. User habits: avoid public Wi-Fi without a VPN, heed browser warnings, and keep devices and trust stores clean.
  8. Detect with monitoring for unusual certificates, duplicate MAC addresses and DNS anomalies.
