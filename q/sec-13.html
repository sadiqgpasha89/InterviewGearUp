Explain Broken Object-Level Authorization (BOLA/IDOR) and how to enforce object ownership checks.

Security engineer · Gear 2 (Mid-level) · AppSec · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

BOLA (also called IDOR) happens when an API accepts an object identifier from the client, such as /orders/1234, and returns or changes the object without checking that the caller is allowed to access that specific object. Fix it by enforcing an ownership or permission check in the server on every request, not by hiding or randomising ids.

Explained in depth

The vulnerability

GET /api/invoices/1001      (logged in as user A, returns A's invoice)
GET /api/invoices/1002      (belongs to user B, but the server returns it)

The user is authenticated, but the server never asks whether this user may see object 1002. It is the first item in the OWASP API Security Top 10 and a common cause of mass data leaks, because attackers simply iterate identifiers.

Where it hides

Path and query parameters, JSON body fields ("accountId"), headers, GraphQL arguments, and bulk or export endpoints. It applies to reads and also to updates and deletes.

Enforcing ownership

  1. Authorise every object access server-side, using the identity from the session or token, not an id sent by the client.
  2. Scope queries by the owner so the check cannot be forgotten:
SELECT * FROM invoices WHERE id = :id AND account_id = :current_account_id;

A missing row returns 404, which avoids confirming that the object exists.

  1. Centralise policy in middleware or a policy library (for example per-resource can(user, action, object) functions) with tests, instead of ad hoc checks in each handler.
  2. Use row-level security in the database for defence in depth.
  3. Deny by default and review new endpoints for object access.

What does not fix it

Unpredictable ids (UUIDs) reduce guessing but do not authorise anything, since ids leak through links, logs and other API responses. Hiding buttons in the UI does nothing for the API.

Testing

Use two test accounts: call each endpoint with account A's object ids using account B's token, and expect 403 or 404. Automate this in the API test suite.

  • How would you test an API for BOLA?
  • How do you apply the check consistently across many endpoints?
