What are the four Coffman conditions required for deadlocks, and how can breaking one prevent deadlocks?

Software engineer (core) · Gear 3 (Senior) · Systems · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A deadlock needs all four Coffman conditions at once: mutual exclusion, hold and wait, no preemption and circular wait. Removing any one prevents deadlock. The most practical fix is to break circular wait by always acquiring locks in one global order; other fixes use timeouts, try-locks or acquiring everything at once.

Explained in depth

The four conditions

  1. Mutual exclusion: a resource can be held by only one thread at a time.
  2. Hold and wait: a thread holds one resource while waiting for another.
  3. No preemption: a resource can only be released by the holder, not taken away.
  4. Circular wait: there is a cycle of threads, each waiting for a resource held by the next.

Breaking each condition

  • Circular wait (most common fix): define a global lock order and always acquire locks in that order. Thread A locking (X then Y) and thread B locking (Y then X) is the classic deadlock; if both take X first it cannot happen.
  • Hold and wait: acquire all needed locks at once, or release what you hold before waiting.
  • No preemption: use tryLock with a timeout and back off, releasing held locks on failure.
  • Mutual exclusion: use lock-free structures, immutable data or message passing so fewer resources need exclusive access.

Example

# Deadlock risk: transfer(a, b) and transfer(b, a) run at the same time
def transfer(a, b, amount):
    first, second = (a, b) if a.id < b.id else (b, a)   # fixed order by id
    with first.lock:
        with second.lock:
            ...

Detection

Build a wait-for graph and look for cycles, or use a thread dump (for example jstack shows deadlocked threads). Database engines detect cycles and abort one transaction.
