How does the Rabin-Karp string search algorithm use rolling polynomial hashes to find substrings?

Software engineer (core) · Gear 3 (Senior) · Algorithms · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Rabin-Karp compares a rolling polynomial hash of each text window with the pattern hash, updating the hash in O(1) as the window slides. Only hash matches are verified character by character, giving O(n + m) expected time and an easy extension to multi-pattern search.

Explained in depth

Idea

Treat a string of length m as a number in base B, reduced modulo a prime M:

h(s) = (s[0]*B^(m-1) + s[1]*B^(m-2) + ... + s[m-1]) mod M

Computing this for every window from scratch costs O(nm). The trick is to roll the hash: when the window moves one position, remove the leading character and add the new trailing one in O(1).

h(next) = ((h(cur) - s[i]*B^(m-1)) * B + s[i+m]) mod M

Implementation

def rabin_karp(text, pat, B=256, M=1_000_000_007):
    n, m = len(text), len(pat)
    if m > n: return []
    high = pow(B, m - 1, M)
    hp = ht = 0
    for i in range(m):
        hp = (hp * B + ord(pat[i])) % M
        ht = (ht * B + ord(text[i])) % M
    hits = []
    for i in range(n - m + 1):
        if hp == ht and text[i:i + m] == pat:     # verify to rule out collisions
            hits.append(i)
        if i < n - m:
            ht = ((ht - ord(text[i]) * high) * B + ord(text[i + m])) % M
    return hits

Complexity

  • Expected O(n + m) with a good hash: collisions are rare, so few verifications.
  • Worst case O(nm) if many windows collide (adversarial input against a fixed modulus, or a pattern like aaaa in text aaaa... where every window genuinely matches).

Choosing parameters

  • Pick a large prime modulus (around 1e9+7, or a 61 bit Mersenne prime with 128 bit multiplication) so the collision probability per window is about 1/M.
  • Use a randomized base per run to defeat adversarial anti-hash inputs.
  • Double hashing (two moduli) reduces false positives further.
  • Be careful with negative values after subtraction: add M before taking the modulus in languages where % can return negatives.

Where it shines

  • Multiple patterns of equal length: store pattern hashes in a set and check each window once (plagiarism detection, DNA motif search).
  • 2D pattern matching and finding repeated substrings (with binary search on length).
  • Content-defined chunking in deduplicating storage and rsync uses the same rolling hash idea.

Compared to alternatives

KMP and Z-algorithm give deterministic O(n + m) for a single pattern. Boyer-Moore is often fastest in practice. Rabin-Karp wins on simplicity and on multi-pattern or approximate matching variants.

Pitfalls

Overflow when using fixed width integers without a modulus, forgetting to verify on a hash hit, and using a small modulus or a fixed base that tests can attack.
