How do you find the Kth largest element in an unsorted array using Quickselect in $O(N)$ average time?

Software engineer (core) · Gear 2 (Mid-level) · Algorithms · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Quickselect partitions the array around a pivot like quicksort, but recurses into only the side that contains the target rank. The expected cost is N + N/2 + N/4 + ..., which is O(N) on average. A bad pivot sequence gives O(N^2), which a random pivot makes unlikely and median-of-medians removes.

Explained in depth

Idea

The Kth largest element is the element at index N - K in sorted order. Partition so that everything left of the pivot is smaller and everything right is larger; the pivot is then in its final position p.

  • If p equals the target index, done.
  • If p is smaller, search the right part; otherwise search the left part.
import random

def kth_largest(nums, k):
    target = len(nums) - k
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        r = random.randint(lo, hi)
        nums[r], nums[hi] = nums[hi], nums[r]
        pivot, p = nums[hi], lo
        for i in range(lo, hi):
            if nums[i] < pivot:
                nums[i], nums[p] = nums[p], nums[i]
                p += 1
        nums[p], nums[hi] = nums[hi], nums[p]
        if p == target:
            return nums[p]
        if p < target:
            lo = p + 1
        else:
            hi = p - 1

Complexity

  • Average O(N): each partition costs the size of the range and the range roughly halves.
  • Worst O(N^2) with consistently bad pivots; random pivots make this very unlikely. Median-of-medians pivots give a guaranteed O(N) but with a large constant.
  • Space O(1) when iterative. It reorders the input.

Alternatives

A min-heap of size K costs O(N log K), needs O(K) space and works on streams. Sorting costs O(N log N).
