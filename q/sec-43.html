How do you automate Infrastructure as Code (IaC) security scanning using Checkov, tfsec, and Trivy?

Security engineer · Gear 2 (Mid-level) · IaC · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Automate IaC scanning by running Checkov, tfsec (now merged into Trivy) and Trivy config scans in pre-commit hooks and CI on every pull request, scanning Terraform, CloudFormation, Kubernetes manifests and Dockerfiles against policy sets. Fail builds on high severity findings, upload SARIF to the code scanning dashboard, manage justified suppressions with expiry, and add custom policies.

Explained in depth

Why scan IaC

Infrastructure as Code turns cloud configuration into reviewable text, so misconfigurations (public buckets, open security groups, unencrypted disks, wildcard IAM) can be found before deployment, cheaply and with developer-friendly feedback. This is the shift-left complement to runtime CSPM.

The tools

  • Checkov (Prisma Cloud/Bridgecrew): Python, 1000+ built-in policies for Terraform, CloudFormation, ARM and Bicep, Kubernetes, Helm, Dockerfile, Serverless, GitHub Actions, secrets; graph-based checks across resources; custom policies in Python or YAML.
  • tfsec: fast Terraform-focused static analyser, now merged into Trivy, which is the maintained path (trivy config).
  • Trivy: all-in-one scanner (container images, filesystems, SBOM, IaC misconfigurations, secrets, licences) with Rego custom checks.
  • Others: KICS (Checkmarx), Terrascan, Snyk IaC, Conftest/OPA, Semgrep, kube-linter, kubesec, Hadolint (Dockerfile).

Running locally and in CI

checkov -d infra/ --framework terraform --compact --quiet
checkov -d infra/ --soft-fail-on LOW,MEDIUM --hard-fail-on HIGH,CRITICAL
trivy config --severity HIGH,CRITICAL --exit-code 1 infra/
trivy config --format sarif -o trivy-iac.sarif infra/

# scan the plan to include variables and module expansions
terraform init && terraform plan -out tf.plan && terraform show -json tf.plan > tf.json
checkov -f tf.json --framework terraform_plan
# GitHub Actions
name: iac-security
on: [pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    permissions: { contents: read, security-events: write }
    steps:
      - uses: actions/checkout@v4
      - uses: bridgecrewio/checkov-action@v12
        with: { directory: infra, framework: terraform, soft_fail: false, output_format: sarif, download_external_modules: true }
      - uses: aquasecurity/trivy-action@master
        with: { scan-type: config, scan-ref: infra, severity: 'HIGH,CRITICAL', exit-code: '1', format: sarif, output: trivy.sarif }
      - uses: github/codeql-action/upload-sarif@v3
        with: { sarif_file: trivy.sarif }
# .pre-commit-config.yaml: fast feedback before commit
repos:
  - repo: https://github.com/bridgecrewio/checkov
    rev: 3.2.0
    hooks: [{ id: checkov, args: ["--quiet", "--framework", "terraform"] }]
  - repo: https://github.com/aquasecurity/trivy
    rev: v0.50.0
    hooks: [{ id: trivy-config }]

Typical findings caught

acl = "public-read" on buckets, cidr_blocks = ["0.0.0.0/0"] on port 22, RDS without encryption or backups, EBS unencrypted, S3 without versioning or logging, IAM policies with *, Kubernetes pods running as root or privileged, hostNetwork, missing resource limits, containers using latest tags, Dockerfile running as root, secrets in variables.

Making it effective

  1. Gate by severity and age: block new high and critical findings; baseline existing debt so teams are not stopped by legacy issues (Checkov baseline files), then burn down with tracked tickets.
  2. Scan at several points: IDE plugin, pre-commit, PR checks, scheduled full scans of the main branch, and registry/module scanning of shared Terraform modules (fixing a module fixes many stacks).
  3. Suppress responsibly: inline skips with required justification and expiry:
resource "aws_s3_bucket" "site" {
  #checkov:skip=CKV_AWS_18:Access logging not needed for public static assets (ticket SEC-142, review 2027-03-01)
  bucket = "marketing-site-assets"
}

and review suppressions regularly; trivy uses .trivyignore with expiry dates.

  1. Custom policies for organisational standards (required tags, approved regions, mandatory KMS keys, no public IPs):
# Checkov custom check
from checkov.terraform.checks.resource.base_resource_check import BaseResourceCheck
from checkov.common.models.enums import CheckResult, CheckCategories
class RequireOwnerTag(BaseResourceCheck):
    def __init__(self): super().__init__(name="Ensure owner tag", id="CKV_ORG_1", categories=[CheckCategories.GENERAL_SECURITY], supported_resources=["aws_instance", "aws_s3_bucket"])
    def scan_resource_conf(self, conf):
        tags = conf.get("tags", [{}])[0]
        return CheckResult.PASSED if isinstance(tags, dict) and "owner" in tags else CheckResult.FAILED
check = RequireOwnerTag()
  1. Policy as code with OPA/Conftest against Terraform plan JSON for contextual rules (cost, naming, network design); Sentinel in Terraform Cloud.
  2. Report and track: SARIF to GitHub Advanced Security, JUnit and dashboards, metrics (new vs fixed findings, mean time to fix), and send high-risk failures to owners via CODEOWNERS.
  3. Pair with runtime: CSPM verifies what actually deployed, catching console drift and resources outside IaC; keep rule sets aligned.

Limits

Static analysis cannot see runtime state, dynamic values (unknown until apply) or business context; false positives happen on intentional exceptions. Scan the plan for better accuracy and combine with policy at deploy (SCPs, Azure Policy).

Pitfalls

Scanning only on main after merge, disabling noisy checks globally, no ownership for fixes, unversioned tool and policy updates that suddenly break pipelines (pin versions), and treating a clean scan as proof of security.
