Compare client-side storage mechanisms: LocalStorage versus SessionStorage versus IndexedDB versus Cookies.

Frontend engineer · Gear 2 (Mid-level) · Browser APIs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Cookies are small, sent with every HTTP request and can be HttpOnly; localStorage is a synchronous, persistent 5 to 10 MB string store per origin; sessionStorage is the same but per tab and cleared on close; IndexedDB is an asynchronous transactional object database for large structured data, even blobs.

When to use which

  • Cookies: server-managed sessions and anything the server must read on every request. Use HttpOnly; Secure; SameSite so scripts cannot read the session token.
  • localStorage: small, non-sensitive preferences (theme, UI state, feature hints). It blocks the main thread because it is synchronous, so avoid large or frequent writes.
  • sessionStorage: per-tab wizard state, drafts that should not leak across tabs.
  • IndexedDB: offline data, caches of API results, large documents, files and blobs, queued writes for sync (via wrappers such as idb, Dexie, localForage). Works in Web Workers and service workers.
localStorage.setItem('theme', 'dark');                      // strings only: JSON.stringify objects
const db = await openDB('app', 1, { upgrade(db) { db.createObjectStore('notes', { keyPath: 'id' }); } });
await db.put('notes', { id: 1, text: 'hello' });

Security

Anything JavaScript can read is exposed to XSS, so do not store session tokens or secrets in localStorage or sessionStorage. Prefer HttpOnly cookies or short-lived in-memory tokens. Storage is per origin and plain text; do not store personal data unencrypted unless needed. Private browsing and user settings may clear or block storage, and Safari's intelligent tracking prevention limits script-written storage for sites not visited recently.

Operations

  • Handle QuotaExceededError and navigator.storage.estimate(); request persistence with navigator.storage.persist() for important data.
  • Version your schemas and migrate in onupgradeneeded.
  • Listen to the storage event to sync tabs (or use BroadcastChannel).
  • Other options: Cache Storage (request/response pairs for service workers) and the Origin Private File System for file-like high-performance storage.

Pitfalls

Synchronous storage jank, storing large JSON blobs repeatedly, parsing failures on corrupted values, and forgetting that cookies add bytes to every request.
