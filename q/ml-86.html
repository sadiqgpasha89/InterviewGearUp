How do recommender systems resolve the Cold Start problem for brand-new users and items?

ML / AI engineer · Gear 2 (Mid-level) · Recommenders · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Cold start occurs when there is no interaction history for a new user or item. Solve it with content and metadata features, popularity and trending fallbacks, onboarding questions, contextual signals, exploration with bandits, transfer from similar users or items via embeddings, and hybrid models that blend content with collaborative signals as data accumulates.

Explained in depth

The problem

Collaborative filtering relies on past interactions. A new user has none, a new item has none, and a new system has none. Without a strategy, new items never get shown (no data, so no recommendations, so no data: a feedback loop), and new users see poor results and may churn.

New-user strategies

  1. Popularity and trending: recommend globally or regionally popular, recently trending, or editorially curated items as a safe default; segment by country, language, time, device.
  2. Onboarding preferences: ask users to pick interests, genres, artists or rate a few items (choose informative items by entropy or diversity); import from connected accounts.
  3. Context and implicit signals: location, device, referral source, time of day, first search queries, and first clicks within the session (session-based recommenders using sequences with GRU4Rec, transformers).
  4. Demographic or cohort models: map to similar existing users by available attributes.
  5. Rapid learning: update user embeddings online after a handful of interactions; use fast-adapting models.
  6. Exploration (bandits): contextual bandits (LinUCB, Thompson sampling) show diverse candidates to learn preferences quickly while tracking reward.

New-item strategies

  1. Content-based features: represent items with metadata, text, image and audio embeddings, and recommend to users whose profiles match (content tower in a two-tower model).
  2. Feature-to-embedding mapping: train a model that predicts the collaborative embedding of an item from its content (as in DropoutNet, hybrid MF like LightFM), so a new item receives a plausible latent vector immediately; random dropout of interaction features during training teaches the model to rely on content when interactions are missing.
  3. Boost and exploration slots: reserve a share of impressions for new items using bandit or epsilon-greedy allocation with Thompson sampling, upper-confidence bounds, or explicit freshness boosts decaying with exposure; cap exposure to limit risk; ensure creators get initial traffic.
  4. Transfer from similar items (same category, creator, series) and from marketplace seller history.
  5. Editorial and manual curation for launches.

Hybrid systems

Blend content-based scores and collaborative scores with weights depending on data availability (confidence): rely on content when counts are low, shift to collaborative as interactions grow (feature-weighted hybrid, switching hybrid, or learned gating). Modern rankers take both interaction features and content features, with count and recency features so the model can adapt.

Evaluation

Evaluate cold-start separately: construct test sets of users with fewer than k interactions and items first appearing in the test period; metrics recall@K and nDCG for those groups, coverage of new items, time-to-first-engagement, and online A/B tests on activation and retention. Monitor item exposure fairness and diversity.

Practical cautions

Avoid showing irrelevant items that damage trust, handle popularity bias (popular fallback can lock in a rich-get-richer effect), respect privacy when using attributes and external data, and log exposure properly for counterfactual learning (inverse propensity weighting).

Pitfalls

Optimising only for existing users' offline metrics, ignoring exploration, leaking item metadata that encodes popularity, and slow pipelines that delay embedding of new items by days.
