Explain the difference between Data Drift and Concept Drift, and what statistical tests (KS-test, PSI) detect them.

ML / AI engineer · Gear 3 (Senior) · MLOps · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Data drift means the input distribution P(X) changes while the relationship between inputs and the target may stay the same. Concept drift means the relationship P(Y given X) changes, so the same inputs now lead to different outcomes. The Kolmogorov-Smirnov test and Population Stability Index detect input distribution shifts, while concept drift needs labels or performance monitoring.

Explained in depth

Definitions

  • Data (covariate) drift: the distribution of input features P(X) in production differs from training. Example: a new marketing campaign brings younger customers, so the age distribution shifts. The model may still be correct inside the new region or may extrapolate badly.
  • Label (prior) drift: P(Y) changes (fraud rate rises from 0.1 to 0.5 percent).
  • Concept drift: P(Y | X) changes: the meaning of the inputs for the target changes. Example: after a regulation or competitor move, customers with the same features churn at a different rate; fraudsters adapt their behaviour so old patterns stop signalling fraud; a pandemic changes demand patterns. Concept drift always hurts model accuracy unless the model is updated; data drift only hurts if the model is poor in the new region.

Types by speed: sudden, gradual, incremental, recurring (seasonal).

Detecting data drift (needs no labels)

Compare a reference window (training or a stable baseline) with a current window (last day or week) feature by feature, and for the prediction distribution.

  1. Kolmogorov-Smirnov (KS) test (continuous features): measures the maximum distance between two empirical CDFs; the p-value tests the null hypothesis that samples come from the same distribution.
from scipy.stats import ks_2samp
stat, p = ks_2samp(reference["age"], current["age"])
drift = p < 0.01 and stat > 0.1          # consider effect size too: with large n, tiny shifts give tiny p-values

For categorical features use chi-square or Jensen-Shannon / total variation distance.

  1. Population Stability Index (PSI): bin the feature (deciles of the reference), then

PSI = Σ (cur_i − ref_i) · ln(cur_i / ref_i) where ref_i and cur_i are the proportions in bin i.

import numpy as np
def psi(ref, cur, bins=10):
    edges = np.quantile(ref, np.linspace(0, 1, bins + 1)); edges[0], edges[-1] = -np.inf, np.inf
    r = np.histogram(ref, edges)[0] / len(ref); c = np.histogram(cur, edges)[0] / len(cur)
    r, c = np.clip(r, 1e-6, None), np.clip(c, 1e-6, None)
    return np.sum((c - r) * np.log(c / r))

Rule of thumb: < 0.1 stable, 0.1 to 0.25 moderate shift (investigate), > 0.25 significant drift. PSI is symmetric-ish, works for scores and categories, and is popular in credit risk.

  1. Other: Wasserstein distance, KL and Jensen-Shannon divergence, Hellinger distance, classifier-based drift detection (train a model to distinguish reference from current; AUC near 0.5 means no drift), multivariate methods (MMD, PCA reconstruction error), embedding drift for text and images.

Statistical caveats

With huge samples, tests flag trivial differences, so combine p-values with effect-size thresholds; apply multiple-testing correction across hundreds of features; prioritise important features (by SHAP or importance); watch seasonality (compare to the same weekday), and monitor missing-value rates and data quality separately.

Detecting concept drift

Requires ground truth or proxies:

  • Track performance metrics (AUC, precision, recall, error) over time on labelled data, accounting for label delay (fraud chargebacks arrive weeks later, loans months): use cohort-based evaluation and proxy metrics (approval rate, score distribution, business KPIs) in the meantime.
  • Error-based detectors on streams: DDM, EDDM, ADWIN, Page-Hinkley monitor the error rate for significant change.
  • Compare model predictions with a challenger or shadow model trained on recent data.
  • Monitor calibration (predicted probabilities versus observed frequencies).

Responses

Alert and investigate, check upstream pipeline bugs first (many "drifts" are broken data), retrain on recent data or with sample weighting, adaptive or online learning, use rolling training windows, fall back to rules, add features that capture the change, and automate retraining triggers with validation gates.

Tools

Evidently, WhyLabs, Arize, Fiddler, NannyML (performance estimation without labels), Alibi Detect, Great Expectations for data checks.

Pitfalls

Equating data drift with model failure, ignoring label delay, using only p-values, drift checks on raw ids or timestamps, and thresholds that cause alert fatigue.
