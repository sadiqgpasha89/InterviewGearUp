What is Privileged Access Management (PAM) and how do Bastion Hosts secure administrative access?

Security engineer · Gear 3 (Senior) · IAM · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Privileged Access Management controls, brokers, records and audits the use of powerful accounts through credential vaulting, session management, just-in-time elevation and analytics. Bastion hosts are hardened jump servers that act as the single audited entry point to private networks, so admins never connect directly to production systems.

Explained in depth

Why privileged access is special

Privileged accounts (domain admins, root, cloud admins, database owners, service accounts, API keys with write power) can change security controls, read all data and erase logs. Most major breaches involve privilege escalation or stolen privileged credentials. PAM reduces the risk with control, visibility and accountability.

PAM capabilities

  1. Discovery and inventory of privileged accounts (human, service, application, cloud, SSH keys, API tokens) including hidden or orphaned ones.
  2. Credential vaulting and rotation: secrets stored in an encrypted vault; checked out for a session; rotated automatically after use or on a schedule; users never see or reuse the password (credential injection).
  3. Least privilege and JIT elevation: request, approve, time-box; remove standing admin; command filtering and sudo delegation (privilege elevation and delegation management, PEDM).
  4. Session brokering and recording: access through a gateway/proxy that records keystrokes, commands and video (SSH, RDP, database, Kubernetes), with live monitoring and the ability to terminate sessions; tamper-resistant storage.
  5. Strong authentication: MFA and device checks on each privileged session; integration with SSO and ITSM approval workflows.
  6. Analytics and alerting: behaviour baselines, anomalous commands, access outside windows, mass data export; forward to SIEM.
  7. Third-party and vendor access: scoped, time-limited, recorded access without VPN credentials.
  8. Secrets management for applications and DevOps (Vault, CyberArk Conjur), eliminating hard-coded passwords.

Products: CyberArk, BeyondTrust, Delinea (Thycotic), HashiCorp Vault and Boundary, Teleport, StrongDM, AWS Systems Manager Session Manager and IAM Identity Center, Azure PIM, GCP PAM.

Bastion hosts (jump servers)

A bastion is a hardened host on a public or management network that is the only path into private networks.

Admin -> (MFA, SSH certificate) -> Bastion in public subnet -> private subnet instances (SG allows 22 only from bastion)

Design and hardening:

  • Security groups: bastion accepts SSH or RDP only from corporate IPs or via a zero trust proxy; private hosts accept admin ports only from the bastion.
  • No password auth; SSH keys or short-lived SSH certificates from an SSH CA; MFA (PAM modules, Duo); restrict users and commands; disable agent forwarding risks (use ProxyJump instead of forwarding the agent: ssh -J bastion target).
  • Minimal OS and software, automatic patching, host intrusion detection, auditd and session recording (tlog, script), central log shipping to SIEM, immutable images rebuilt regularly, no data stored.
  • High availability (multiple bastions per zone) and auto-scaling groups started on demand; ephemeral bastions destroyed after use.
  • Network: private subnets for targets, no direct internet routes, egress restrictions, VPC flow logs.

Modern alternatives to classic bastions

Public inbound ports are an exposure. Session-based access removes them:

  • AWS Systems Manager Session Manager or EC2 Instance Connect Endpoint: no inbound ports, IAM-based authorisation, CloudTrail audit, session logs to S3 or CloudWatch.
  • Google IAP TCP forwarding, Azure Bastion: managed, no public IP on targets.
  • Teleport, StrongDM, Boundary: identity-aware proxies with short-lived certificates, per-session recording, role-based access to servers, databases and Kubernetes.
  • Zero trust network access (ZTNA) applying device posture and continuous verification.

Operational policies

Separate admin accounts from daily accounts; enforce break-glass accounts with monitoring; tier model (control plane, server, workstation) preventing credential exposure across tiers (privileged access workstations for domain admin); quarterly access reviews; log retention aligned with compliance (PCI: at least 1 year); periodic penetration tests of the PAM path itself; protect the vault with HSM, quorum and DR plans.

Metrics

Percentage of privileged accounts vaulted, standing admins count, average session duration, unmanaged service accounts, recorded session coverage, time to revoke leavers, and policy exceptions.

Pitfalls

Using a bastion as an unmonitored shared account, agent forwarding to untrusted hosts, leaving other paths (direct SSH, VPN) open, storing vault recovery keys carelessly, and treating PAM as only a tool rather than a process with ownership and reviews.

Likely follow-ups

  • How does modern session-based access such as Teleport or SSM Session Manager improve on classic bastions?
  • How do you handle credential vaulting and automatic rotation for shared privileged accounts?
  • How do you detect misuse of privileged sessions?
