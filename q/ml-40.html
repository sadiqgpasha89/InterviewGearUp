Explain subword tokenization algorithms: Byte-Pair Encoding (BPE), WordPiece, and SentencePiece.

ML / AI engineer · Gear 2 (Mid-level) · NLP · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Subword tokenizers split text into frequent pieces so the vocabulary stays fixed while rare words are still representable. BPE repeatedly merges the most frequent adjacent symbol pair, WordPiece picks merges that maximise training-data likelihood, and SentencePiece is a language-independent toolkit that works on raw text, treating spaces as symbols, and implements BPE or Unigram.

Explained in depth

Why subwords

Word-level vocabularies explode in size and cannot handle unseen words (out-of-vocabulary), while character-level sequences are very long and lose word-level structure. Subword units balance both: common words are single tokens (the), rare words split into pieces (token + ization), and any string is representable.

Byte-Pair Encoding (BPE)

Training:

  1. Start with a vocabulary of single characters (or bytes) and a corpus split into words with counts.
  2. Count all adjacent symbol pairs, merge the most frequent pair into a new symbol, and add it to the vocabulary.
  3. Repeat until the target vocabulary size is reached (for example 32k to 100k merges).

Encoding applies the learned merges in order to new text. GPT-2 and later use byte-level BPE: the base alphabet is the 256 bytes, so any Unicode text can be encoded with no unknown token.

"low lower lowest": start l o w | l o w e r | l o w e s t
merge (l,o)→lo, (lo,w)→low, (low,e)→lowe, ...

WordPiece (BERT)

Similar to BPE but chooses merges by likelihood gain rather than raw frequency: pick the pair maximising count(ab) / (count(a) × count(b)), which favours pairs that co-occur more than chance. Inference uses greedy longest-match-first; continuation pieces carry a ## prefix (play, ##ing). Unmatched words become [UNK].

Unigram language model (SentencePiece option)

Start with a large candidate vocabulary and a probabilistic model where each piece has a probability. Iteratively remove pieces that least reduce the corpus likelihood (EM to estimate probabilities, prune the lowest-loss pieces) until the target size. Encoding finds the most probable segmentation (Viterbi), and it can sample alternative segmentations (subword regularisation) for robustness.

SentencePiece

A library (not a single algorithm) that trains BPE or Unigram directly on raw text without pre-tokenisation, treating whitespace as a normal symbol (▁). Benefits: language-independent (works for Chinese, Japanese, Thai without spaces), reversible and lossless detokenisation, built-in normalisation, reproducible. Used by T5, LLaMA, ALBERT, and many multilingual models.

Practical implications

  • Vocabulary size trade-off: larger vocabularies shorten sequences (cheaper attention) but enlarge embedding matrices and make rare tokens poorly trained.
  • Cost and latency: API pricing and context limits are in tokens; languages underrepresented in training are split into more tokens (higher cost, worse quality).
  • Tokenizer artefacts affect spelling, arithmetic and code (numbers split inconsistently); mitigations include digit-level tokenisation.
  • The tokenizer must match the model exactly; changing it requires retraining or embedding resizing.
  • Pre-tokenisation rules (regex splitting, normalisation, special tokens like <bos>) matter and should be versioned.

Pitfalls

Using the wrong tokenizer version, truncating mid-token in custom code, ignoring whitespace handling, and assuming token count equals word count (about 1.3 tokens per English word, much higher for some languages).
