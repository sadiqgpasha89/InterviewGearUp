How does Brotli compression compare to Gzip for text assets (HTML, CSS, JS)?

Frontend engineer · Gear 2 (Mid-level) · Performance · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Brotli compresses text assets about 15 to 25 percent smaller than Gzip at comparable or higher levels, thanks to a built-in static dictionary and better modelling. It needs HTTPS in browsers. Precompress static files at max level (11) and use moderate levels (4 to 5) for dynamic responses.

Explained in depth

How they work

Gzip (DEFLATE) uses LZ77 and Huffman coding with a 32 KB window. Brotli (RFC 7932) uses LZ77, a larger window (up to 16 MB), context modelling, and a pre-built 120 KB dictionary of common web strings (HTML tags, CSS properties, JS keywords), which especially helps small files.

Best practice

  • Static assets: compress at build time with Brotli level 11 (and keep a Gzip fallback), store app.js.br and app.js.gz, and let the server or CDN pick the matching file. Slow compression does not matter because it happens once.
  • Dynamic responses (HTML, JSON APIs): use Brotli at levels 4 to 5 (or Gzip 6); level 11 would add latency and CPU per request.
  • Compress only compressible types: HTML, CSS, JS, JSON, SVG, XML, fonts like TTF and OTF. Do not recompress images, video, WOFF2 (already Brotli) or PDFs.
  • Skip tiny responses (under about 1 KB) where headers outweigh savings.

Negotiation

The browser sends Accept-Encoding: gzip, deflate, br, zstd; the server picks one and replies with Content-Encoding. Always add Vary: Accept-Encoding so shared caches store each variant correctly.

brotli on;  brotli_comp_level 5;  brotli_types text/css application/javascript application/json image/svg+xml;
brotli_static on;                 # serve precompressed .br files
gzip on;    gzip_static on;

Results in practice

A 300 KB JavaScript bundle might be about 90 KB with Gzip and about 78 KB with Brotli 11. The benefit is largest on slow mobile networks and for many small files. Measure with curl -H 'Accept-Encoding: br' -I and Lighthouse.

Alternatives

Zstandard (zstd) is now supported in browsers, with fast compression and good ratios at lower CPU cost, so it is attractive for dynamic content. Minification and tree shaking reduce the input size before compression.

Pitfalls

Double compression, missing Vary, serving Brotli over HTTP (ignored by browsers), and compressing responses that contain secrets mixed with attacker input over TLS (BREACH), which needs CSRF token masking or per-response randomisation.
