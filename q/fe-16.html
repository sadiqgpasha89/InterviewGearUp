How does the JavaScript Event Loop coordinate the Call Stack, Microtask Queue, and Macrotask Queue?

Frontend engineer · Gear 2 (Mid-level) · JavaScript · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

JavaScript runs one thing at a time on the call stack. Finished timers, network responses and UI events queue callbacks as macrotasks, and promise reactions queue microtasks. The event loop runs one macrotask, then drains the whole microtask queue, then may render, then takes the next macrotask, so promise callbacks always run before setTimeout callbacks.

Explained in depth

The pieces

  • Call stack: where synchronous code runs, to completion.
  • Web APIs / host: timers, fetch, DOM events do their waiting outside the stack.
  • Macrotask (task) queue: setTimeout, setInterval, UI events, I/O and MessageChannel callbacks.
  • Microtask queue: promise reactions (then, catch, finally, and code after await), queueMicrotask, MutationObserver.

The loop

  1. Run one macrotask (such as the main script) until the stack is empty.
  2. Run all microtasks, including ones queued by other microtasks, until the queue is empty.
  3. If it is time, render: run requestAnimationFrame callbacks, style, layout and paint.
  4. Pick the next macrotask.
console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
console.log('4');
// prints 1, 4, 3, 2

The synchronous logs run first (1, 4). The promise callback is a microtask, so it runs before the timer, which is a macrotask (3, then 2).

Consequences

  • A long synchronous task blocks rendering and input, so the page freezes. Break up work or move it to a Web Worker.
  • A microtask that keeps queuing more microtasks can starve rendering and timers.
  • setTimeout(fn, 0) is not instant: it waits for the stack and microtasks to clear, and browsers clamp very small nested delays.
  • async functions run synchronously until the first await; the rest is scheduled as a microtask.
  • Node.js has its own phases and also process.nextTick, which runs before promise microtasks.
