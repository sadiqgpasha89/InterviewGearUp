Explain garbage collection pause phases in modern runtimes (e.g. G1GC, ZGC, Go GC) and how to tune them.

Backend engineer · Gear 4 (Lead / Staff) · Performance · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Modern collectors reduce pauses by doing most work concurrently with the application. G1 collects regions in short, mostly stop-the-world evacuation pauses plus concurrent marking; ZGC and Shenandoah do marking and relocation concurrently with pauses in the sub-millisecond to few-millisecond range; Go uses a concurrent mark-sweep collector tuned with GOGC and a memory limit.

Explained in depth

Why pauses happen

A collector must find live objects. Some phases need all application threads stopped (a safepoint) so object graphs do not change during critical steps. Longer pauses mean higher tail latency.

G1 (default in modern JVMs)

  • Heap divided into regions; collects the regions with the most garbage first.
  • Young collections are stop-the-world but short; concurrent marking finds live data in old regions; mixed collections reclaim old regions.
  • Key knob: -XX:MaxGCPauseMillis (a goal, not a guarantee). Also heap size (-Xms, -Xmx) and region size.
  • Failure mode: a full GC when it cannot keep up (evacuation failure), which causes long pauses.

ZGC and Shenandoah

Concurrent compaction using load barriers (ZGC uses coloured pointers), so pauses stay in the low milliseconds regardless of heap size, at the cost of some throughput and extra CPU and memory headroom. Suitable for large heaps and strict latency targets.

Go

A concurrent, non-moving mark-sweep collector with very short stop-the-world phases. GOGC (default 100) controls how much the heap may grow between collections; GOMEMLIMIT sets a soft memory cap. Reduce allocations and reuse buffers (sync.Pool) to lower GC work.

Tuning approach

  1. Enable GC logging and look at pause times, frequency and heap after collection.
  2. Reduce allocation rate first, because it drives GC frequency.
  3. Right-size the heap; too small causes frequent collections, too large lengthens some pauses.
  4. Change only one setting at a time, and measure with realistic load.
