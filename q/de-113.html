Why use a workflow orchestrator such as Airflow instead of cron jobs for data pipelines?

Data engineer · Gear 1 (Junior) · Orchestration · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Cron only starts commands at times. An orchestrator models dependencies between tasks as a graph, retries and alerts on failure, tracks run history and state, supports backfills and parameterised runs, scales workers, and provides a UI and logs. This makes multi-step pipelines reliable, observable and re-runnable, which cron scripts cannot provide.

Explained in depth

Limits of cron

  • Runs a command at a time; knows nothing about whether upstream jobs finished or succeeded.
  • No retries, dependency handling, alerts or central history; logs are scattered across machines.
  • Hard to re-run a past date, to see what is running, or to scale and share load.
  • A host failure silently stops jobs.

What an orchestrator adds

  1. Dependencies as a DAG: task B runs only after A succeeds; independent tasks run in parallel.
  2. Retries and timeouts with backoff, alerts on failure or SLA misses, and failure callbacks.
  3. State and history: every run, task and attempt is recorded with logs and duration, visible in a UI.
  4. Scheduling with data intervals: a run is tied to a logical date, so you can process "the data for 2025-01-05" and re-run or backfill a range deterministically.
  5. Parameters and templating, connections and secrets management, and sensors that wait for files or upstream data.
  6. Scalability: distribute tasks across workers (Celery, Kubernetes).
with DAG("daily_sales", schedule="@daily", start_date=datetime(2025, 1, 1), catchup=False) as dag:
    extract = PythonOperator(task_id="extract", python_callable=extract_orders)
    transform = PythonOperator(task_id="transform", python_callable=build_sales)
    quality = PythonOperator(task_id="quality_check", python_callable=run_checks)
    extract >> transform >> quality

Good practices

Make tasks idempotent (overwrite the partition for the run date), keep tasks small, avoid heavy work in the orchestrator itself (trigger Spark or SQL jobs), and keep business logic in versioned code. Alternatives: Dagster, Prefect, Argo Workflows, and cloud services (Step Functions, Cloud Composer, Data Factory).
