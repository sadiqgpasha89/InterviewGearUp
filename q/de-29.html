How does Apache Iceberg guarantee ACID transactions and snapshot isolation on cloud object storage?

Data engineer · Gear 3 (Senior) · Lakehouse · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Iceberg tracks a table as a tree: a catalog points to the current metadata file, which lists snapshots; each snapshot points to manifest lists and manifests that list the data files. A commit writes new files and then atomically swaps the catalog pointer using compare-and-swap. Readers use a fixed snapshot, which gives snapshot isolation without locking.

Explained in depth

Metadata tree

Catalog (pointer to current metadata file)
  -> metadata.json  (schema, partition spec, list of snapshots, current snapshot id)
      -> snapshot  -> manifest list  -> manifests  -> data files (Parquet) with stats
  • A manifest lists data files with partition values and column min and max statistics.
  • A snapshot is the complete set of files for the table at one commit.
  • All files are immutable; changes create new files and new metadata.

How a write commits

  1. The writer writes new data files (and delete files) to object storage.
  2. It writes new manifests, a manifest list and a new metadata.json that adds a snapshot.
  3. It asks the catalog to atomically change the table pointer from the old metadata file to the new one (compare-and-swap).

If another writer committed first, the swap fails, and the writer re-reads the latest metadata, checks for conflicts and retries (optimistic concurrency). Object stores lack atomic rename, so the catalog provides this atomicity.

Isolation and consistency

  • Atomicity: until the pointer changes, readers do not see any new files; partial writes are invisible.
  • Snapshot isolation: a query pins one snapshot id at the start, so concurrent commits cannot change what it sees.
  • Consistency: schema and partition specs are in metadata, validated at commit.
  • Durability: immutable files in object storage.

Row-level changes

Deletes are recorded as delete files (positional or equality deletes, merge-on-read) or by rewriting affected files (copy-on-write), depending on the table configuration.

Maintenance

Compact files, expire snapshots (which limits time travel) and remove orphan files left by failed writers.
