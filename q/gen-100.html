How does a Monotonic Queue find sliding window maximums in $O(N)$ amortized time?

Software engineer (core) · Gear 3 (Senior) · Data structures · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

A monotonic deque keeps indices of the current window in order of decreasing value, so the front is always the maximum. Each element is pushed once and popped once, giving O(N) total time for all sliding window maxima, instead of O(N log k) with a heap or O(Nk) with scanning.

Explained in depth

Problem

For an array a and window size k, output max(a[i..i+k-1]) for every i. Brute force costs O(nk). A max-heap costs O(n log n) (with lazy removal of expired items).

Key observation

When a new element x enters the window, every earlier element smaller than x can never be the maximum again: x is larger and will leave the window later than those earlier elements. So they can be discarded immediately.

Algorithm

Keep a deque of indices, whose values are strictly decreasing from front to back.

from collections import deque

def sliding_max(a, k):
    dq, out = deque(), []                       # dq holds indices, a[dq] is decreasing
    for i, x in enumerate(a):
        while dq and a[dq[-1]] <= x:            # drop smaller or equal values from the back
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:                      # front index has left the window
            dq.popleft()
        if i >= k - 1:
            out.append(a[dq[0]])                # front is the window maximum
    return out

Example: a = [1, 3, -1, -3, 5, 3, 6, 7], k = 3 gives [3, 3, 5, 5, 6, 7].

Why it is O(n)

Every index is appended exactly once and removed at most once, either from the back (dominated by a larger value) or from the front (expired). Total deque operations are at most 2n, so the amortized cost per element is O(1).

Invariants

  1. Deque values are decreasing, so front is the maximum.
  2. All indices in the deque lie within the current window (i - k, i] after the expiry check.
  3. Any element not in the deque is either expired or dominated by a later, larger element.

Variations

  • Minimum: reverse the comparison (increasing deque).
  • Constrained DP: dp[i] = a[i] + max(dp[i-k..i-1]) (jump game with a limit, constrained subsequence sum) becomes O(n) with a monotonic deque.
  • Shortest subarray with sum at least K uses a monotonic deque over prefix sums.
  • The one-sided relatives: monotonic stack for next greater element, largest rectangle in a histogram and trapping rain water.

Pitfalls

Storing values instead of indices (you cannot detect expiry), popping with < versus <= (both work for the maximum, but equal values decide which index stays), and off-by-one when checking expiry (i - k). Handle k > n, k = 1 and empty input.
