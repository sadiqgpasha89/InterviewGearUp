How do JavaScript Proxy and Reflect APIs enable reactive state tracking in modern frameworks?

Frontend engineer · Gear 3 (Senior) · JavaScript · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

A Proxy wraps an object and intercepts operations such as get, set, has and deleteProperty through traps, while Reflect provides the matching default operations with correct receiver semantics. Frameworks like Vue 3 use them to track which properties an effect reads and to trigger re-runs when those properties change.

Explained in depth

The mechanism

const handler = {
  get(target, key, receiver) {
    track(target, key);                          // record that the running effect read this key
    return Reflect.get(target, key, receiver);
  },
  set(target, key, value, receiver) {
    const old = target[key];
    const ok = Reflect.set(target, key, value, receiver);
    if (old !== value) trigger(target, key);     // re-run effects that depend on this key
    return ok;
  },
};
const state = new Proxy({ count: 0 }, handler);

Other traps: has (the in operator), deleteProperty, ownKeys (for Object.keys and for...in), getOwnPropertyDescriptor, defineProperty, apply and construct for functions.

Why Reflect

Reflect methods mirror the proxy traps and return booleans instead of throwing in many cases. Using Reflect.get(target, key, receiver) preserves the correct this when properties are getters or the object is inherited, which avoids subtle bugs, and Reflect.set returns a success flag the set trap must return (in strict mode a falsy return throws a TypeError).

A tiny reactive system

const deps = new WeakMap();            // target -> Map(key -> Set(effects))
let activeEffect = null;
function track(t, k) {
  if (!activeEffect) return;
  let m = deps.get(t); if (!m) deps.set(t, m = new Map());
  let s = m.get(k);   if (!s) m.set(k, s = new Set());
  s.add(activeEffect);
}
function trigger(t, k) { deps.get(t)?.get(k)?.forEach((fn) => fn()); }
function effect(fn) { activeEffect = fn; fn(); activeEffect = null; }

const s = reactive({ n: 1 });
effect(() => console.log('n is', s.n));    // runs once and subscribes to n
s.n = 2;                                   // trap triggers the effect again

Real implementations add nesting (return proxies lazily for nested objects, cached in a WeakMap), cleanup of stale dependencies per run, batching and scheduling, array and collection handling (length, push), and guards against recursive triggers.

Why Proxy beat Object.defineProperty (Vue 2)

  • Detects added and deleted properties and array index changes without Vue.set.
  • Wraps objects lazily, with no upfront deep traversal.
  • Supports Map and Set via method wrappers.

Limitations

  • Cannot be polyfilled fully (no IE11).
  • Identity: proxy !== target, so use raw/toRaw escape hatches and avoid mixing the two in sets and comparisons.
  • Internal slots (Map, Date, private #fields) break when the method is called with the proxy as this, so frameworks bind methods to the target.
  • Overhead on hot paths; use shallowReactive or frozen data for huge structures.
  • Other uses: validation, default values, logging, negative array indices, API clients (api.users.get()), and immutable updates (Immer drafts).

Signals-based frameworks (Solid, Preact Signals, Angular signals) avoid proxies by making reads explicit, trading some ergonomics for predictability.
