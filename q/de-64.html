How do you handle late-arriving dimensions and early-arriving facts in data pipelines?

Data engineer · Gear 3 (Senior) · Data Modeling · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Late-arriving dimensions occur when a fact references a dimension row not yet loaded, so insert an inferred placeholder member (unknown attributes, flagged as inferred) with the natural key and update it when the real record arrives. Early-arriving facts are handled the same way, or held in a quarantine and reprocessed. For SCD2, rejoin late-arriving history by effective dates.

Explained in depth

Definitions

In dimensional models, facts reference dimensions through surrogate keys. The pipeline normally loads dimensions first, then facts, looking up each natural key to find the surrogate key. Real systems break the ordering:

  • Early-arriving fact (also called late-arriving dimension): a fact (an order, click or payment) arrives before its dimension row (customer, product) exists in the warehouse. Causes: independent source feeds, CDC lag, event streams outrunning master data, or customers created in a different system.
  • Late-arriving fact: a fact arrives late relative to its event date (for example yesterday's sale), and must be tied to the dimension version valid at the event time (SCD Type 2), not the current version.
  • Late-arriving dimension attribute changes: an update with an effective date in the past (a corrected address), forcing history revision.

Strategies for missing dimension rows

  1. Inferred member (placeholder) pattern (Kimball): when the fact lookup fails, insert a new dimension row with the natural key, default attributes ("Unknown"), and a flag is_inferred = true. The fact gets a valid surrogate key, so referential integrity and counts are preserved. When the real dimension record arrives, update the inferred row in place (for SCD1) or fill it as the first version (SCD2), clearing the flag, without changing the surrogate key, so no fact rewrite is needed.
-- 1. Create inferred members for unknown keys
INSERT INTO dim_customer (customer_nk, name, segment, is_inferred, valid_from, valid_to, is_current)
SELECT DISTINCT s.customer_id, 'Unknown', 'Unknown', TRUE, '1900-01-01', '9999-12-31', TRUE
FROM staging.orders s LEFT JOIN dim_customer d ON d.customer_nk = s.customer_id AND d.is_current
WHERE d.customer_nk IS NULL;
-- 2. Load facts with surrogate key lookup
-- 3. When real data arrives, MERGE into dim_customer updating inferred rows
  1. Default "Unknown" member (surrogate key -1): simple, but loses the link, so facts need repair when the dimension arrives (re-key by a later reconciliation job).
  2. Quarantine and retry: hold unmatched facts in a suspense or error table and reprocess on later runs when dimensions land (works for batch, adds latency, risk of unbounded backlog).
  3. Reorder or synchronise sources (extract dimensions first, use the same snapshot time, CDC with transactional ordering, outbox pattern) to reduce occurrence.
  4. Late-binding views or store natural keys in the fact and resolve to the surrogate at query time (flexible but slower).

SCD Type 2 and effective dating

For history, the lookup is a range join: match the natural key and fact_event_time BETWEEN valid_from AND valid_to. For late-arriving facts, the correct dimension version is the one active at the event time. For late-arriving dimension changes, close and reopen version intervals (split history), then re-point affected facts if their surrogate keys change.

SELECT f.*, d.customer_sk FROM staging.orders f
JOIN dim_customer d ON d.customer_nk = f.customer_id AND f.order_ts >= d.valid_from AND f.order_ts < d.valid_to;

Monitoring

Track the count of inferred members and age (alert if not resolved within N days), orphan facts (surrogate keys without dimension rows must be zero), percentage of facts mapped to unknown, referential integrity tests (relationships in dbt), and freshness of source feeds.

Pitfalls

Dropping unmatched facts silently, creating duplicate dimension rows for the same natural key, forgetting to flip is_inferred, mixing event time and load time in SCD joins, and ignoring dimension corrections that require fact re-keying.
