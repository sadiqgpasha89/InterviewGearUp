How do you use pandas groupby, merge and pivot operations to answer a business question efficiently and correctly?

Data scientist · Gear 1 (Junior) · Python and pandas · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Frame the question and the grain of the result, then join tables on validated keys, aggregate with groupby and named aggregations, reshape with pivot_table or unstack, and sanity-check row counts at every step. Prefer vectorised operations over loops, watch for join fan-out and duplicate keys, and keep the logic in a readable chain.

Explained in depth

A worked example

Question: "What was monthly revenue and repeat-purchase rate by acquisition channel in 2025?" Tables: orders(order_id, customer_id, order_date, amount) and customers(customer_id, channel, signup_date).

import pandas as pd

orders = pd.read_parquet("orders.parquet", columns=["order_id", "customer_id", "order_date", "amount"])
cust = pd.read_parquet("customers.parquet")

# 1. validate keys before joining
assert cust["customer_id"].is_unique, "customers must be one row per customer"
orders = orders.drop_duplicates("order_id")

# 2. merge: many orders to one customer; validate prevents silent fan-out
df = orders.merge(cust[["customer_id", "channel"]], on="customer_id", how="left", validate="m:1")
assert len(df) == len(orders)
print("orders without channel:", df["channel"].isna().sum())

# 3. derive features
df["month"] = df["order_date"].dt.to_period("M")
df["order_rank"] = df.groupby("customer_id")["order_date"].rank(method="first")

# 4. aggregate with named aggregations
monthly = (df[df["order_date"].dt.year == 2025]
           .groupby(["channel", "month"], observed=True)
           .agg(revenue=("amount", "sum"), orders=("order_id", "nunique"), customers=("customer_id", "nunique"))
           .reset_index())

# 5. reshape for reporting
wide = monthly.pivot_table(index="month", columns="channel", values="revenue", aggfunc="sum", fill_value=0)

Key operations

  • groupby: split-apply-combine. agg reduces each group to one row; transform returns a result aligned to the original rows (for example group mean to compute share or z-score); apply runs arbitrary Python (flexible but slow).
df["share_of_channel"] = df["amount"] / df.groupby("channel")["amount"].transform("sum")
  • merge: how in inner, left, right, outer; use validate="1:1", "m:1" and indicator=True to expose unmatched rows. Know your grain (one row per what?).
  • pivot_table / melt / unstack / stack: pivot to wide, melt to long. crosstab for counts.
  • Window-like operations: rolling, expanding, shift, rank, cumsum, diff.
  • Time handling: parse dates, use dt accessors, resample("M"), time zones.

Correctness checklist

  1. Check row counts and uniqueness before and after each join.
  2. Be explicit about NaN handling (dropna, fillna); groupby drops NaN keys by default (dropna=False keeps them).
  3. Beware fan-out: joining on non-unique keys multiplies rows and inflates sums.
  4. Validate against a known total (finance report) or a SQL query.
  5. Avoid chained assignment warnings: use .loc, or assign in a method chain.
  6. Use categorical dtype and observed=True to avoid empty groups.

Performance

  • Vectorise (column operations, np.where) instead of iterrows or row-wise apply.
  • Read only needed columns, use Parquet, downcast dtypes, convert strings to category.
  • Filter early; sort and merge on indexed keys; avoid repeated copies.
  • For larger-than-memory or heavy workloads, push aggregation to SQL, use Polars or DuckDB for fast single-machine processing, or Spark for distributed data.

Pitfalls

Averaging averages instead of weighting, merging on non-unique keys, silently dropping NaN group keys, and writing a long unreviewable notebook cell instead of testable functions.
