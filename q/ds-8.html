Write SQL to return the top three earners per department, and explain how window functions such as ROW_NUMBER, RANK and DENSE_RANK differ.

Data scientist · Gear 1 (Junior) · SQL for data science · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Use a window function that ranks salaries within each department using PARTITION BY and ORDER BY, then filter the rank in an outer query or CTE. ROW_NUMBER gives unique positions, RANK leaves gaps after ties, and DENSE_RANK has no gaps, so the choice decides how ties are handled.

Explained in depth

The query

WITH ranked AS (
  SELECT
    employee_id,
    department_id,
    salary,
    DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS salary_rank
  FROM employees
)
SELECT department_id, employee_id, salary, salary_rank
FROM ranked
WHERE salary_rank <= 3
ORDER BY department_id, salary_rank, employee_id;

PARTITION BY restarts the ranking per department; ORDER BY defines the order inside each partition. Window functions are evaluated after WHERE, GROUP BY and HAVING, so you cannot filter on them in the same SELECT. Wrap in a CTE or subquery (some engines such as Snowflake, BigQuery and Teradata support QUALIFY salary_rank <= 3).

  • ROW_NUMBER: always unique, ties broken arbitrarily (add a tiebreaker like employee_id for determinism). Use it to pick exactly N rows or to deduplicate (keep the latest record per key).
  • RANK: ties share a rank and the next rank skips.
  • DENSE_RANK: ties share a rank and no gaps. "Top 3 salaries" with ties usually means DENSE_RANK; "top 3 people" means ROW_NUMBER.

Other useful functions: NTILE(4) for quartiles, LAG and LEAD for previous and next rows, FIRST_VALUE, PERCENT_RANK, CUME_DIST.

Aggregates as windows and frames

SELECT order_date,
       revenue,
       SUM(revenue) OVER (ORDER BY order_date)                                  AS running_total,
       AVG(revenue) OVER (ORDER BY order_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS moving_avg_7d,
       revenue - LAG(revenue, 7) OVER (ORDER BY order_date)                      AS wow_change
FROM daily_revenue;

ROWS counts physical rows; RANGE groups peers with equal ORDER BY values. For calendar windows with gaps in dates, first generate a date spine or use RANGE with intervals where supported.

Alternatives

  • Correlated subquery: WHERE (SELECT COUNT(DISTINCT salary) FROM employees e2 WHERE e2.department_id = e1.department_id AND e2.salary > e1.salary) < 3. Works everywhere but is often slower (quadratic).
  • Self-join with counts, or LATERAL / CROSS APPLY with ORDER BY ... LIMIT 3 per department, which can use an index well.
  • Window functions are usually clearer and efficient: one sort per partition.

Performance and correctness tips

  • Index or cluster on (department_id, salary DESC) for large tables.
  • Beware NULLs: ORDER BY salary DESC NULLS LAST so missing salaries do not rank first (PostgreSQL puts NULLs first for DESC by default).
  • Define ties explicitly in the spec; ask the interviewer.
  • Check results on a small example, including departments with fewer than three employees.

Pitfalls

Using WHERE on a window alias, relying on ROW_NUMBER with ties without a tiebreaker, and forgetting PARTITION BY (ranking the whole table).
