What is the difference between Spatial Locality and Temporal Locality in array processing?

Software engineer (core) · Gear 2 (Mid-level) · Systems · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Spatial locality means that after touching an address you will soon touch nearby addresses, so cache lines that fetch neighbours pay off; temporal locality means a recently used address will be used again soon, so keeping it cached pays off. Good array code exploits both.

Explained in depth

The two kinds

  • Spatial locality: references cluster in address space. The CPU loads a full 64 byte cache line, so touching a[i] brings a[i+1], a[i+2], ... into the cache at no extra cost.
  • Temporal locality: a location used now is likely to be used again soon, so it stays in the cache (LRU-like replacement) and avoids another trip to DRAM.

Array traversal

// Row-major order in C: a[i][j] and a[i][j+1] are adjacent.
long sum_rows(int a[N][N]) {          // good spatial locality
    long s = 0;
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++) s += a[i][j];
    return s;
}
long sum_cols(int a[N][N]) {          // stride of N ints: new cache line almost every access
    long s = 0;
    for (int j = 0; j < N; j++)
        for (int i = 0; i < N; i++) s += a[i][j];
    return s;
}

For a large N the column version can be 5x to 20x slower, although both do the same arithmetic. In Fortran, MATLAB and Julia the layout is column-major, so the better loop order flips.

The accumulator s and the loop counters show temporal locality: they are used on every iteration and live in registers or L1.

Improving locality

  • Loop interchange to match the memory layout.
  • Blocking (tiling): process small tiles that fit in cache so each loaded element is reused many times before eviction (the key idea behind fast matrix multiplication).
  • Struct of arrays instead of array of structs when a loop uses only one field.
  • Contiguous containers (vector, ArrayList of primitives) over pointer-based ones; avoid chasing pointers.
  • Process data in batches, sort keys to make accesses sequential, and prefetch where the access pattern is predictable (hardware prefetchers detect constant strides).

Why this explains linked lists

Each node is a separate allocation, so traversal causes cache misses and defeats the prefetcher. An array of 1 million ints scans several times faster than a list of the same elements, even when the algorithmic cost is O(n) for both.

Pitfalls

Big-O ignores constant factors that caches dominate. Do not guess: measure with a profiler and hardware counters (perf stat -e cache-misses).
