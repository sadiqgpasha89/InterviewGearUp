How do you test cookie consent banners and verify that tracking scripts are blocked before consent?

QA / SDET · Gear 2 (Mid-level) · Compliance · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Test cookie consent by loading the site in a clean browser context and asserting that no non-essential cookies are set and no tracker requests are sent before the user acts. Then accept, reject and customise choices, and verify cookies, network calls and tags match the chosen categories, that the choice persists and can be withdrawn, and that the banner follows regional rules.

Explained in depth

Rules being tested

Under GDPR and ePrivacy, non-essential cookies and trackers (analytics, advertising, social pixels) need prior, informed, specific, freely given consent; strictly necessary cookies (session, security, load balancing) do not. Rejecting must be as easy as accepting, with no pre-ticked boxes, and consent must be withdrawable and recorded. CCPA and CPRA use an opt-out model (Do Not Sell or Share, Global Privacy Control signals). Test for the regulations that apply to your markets with legal input.

Baseline test: nothing fires before consent

test('no trackers or non-essential cookies before consent', async ({ browser }) => {
  const context = await browser.newContext();           // fresh: no cookies, no storage
  const page = await context.newPage();
  const blocked = [/google-analytics\.com/, /googletagmanager\.com\/gtag/, /facebook\.net/, /doubleclick\.net/, /hotjar\.com/, /linkedin\.com\/px/];
  const trackerCalls: string[] = [];
  page.on('request', r => { if (blocked.some(rx => rx.test(r.url()))) trackerCalls.push(r.url()); });
  await page.goto('/');
  await expect(page.locator('#cookie-banner')).toBeVisible();
  await page.waitForLoadState('networkidle');
  expect(trackerCalls).toEqual([]);
  const names = (await context.cookies()).map(c => c.name);
  expect(names).not.toEqual(expect.arrayContaining(['_ga', '_fbp', '_gid']));
  const ls = await page.evaluate(() => Object.keys(localStorage));
  expect(ls.filter(k => /^(_ga|ajs_|amplitude)/.test(k))).toEqual([]);
});

Also scroll, click and navigate: some scripts fire on interaction, and consent must also be honoured on subsequent pages, iframes (YouTube, maps), and tag-manager containers.

Banner behaviour scenarios

  1. Accept all: banner closes, consent stored (cookie or localStorage and a server-side record with timestamp, version and choices), trackers now load, analytics events fire.
  2. Reject all / Decline: banner closes, still no non-essential cookies or trackers; rejection button is equally prominent.
  3. Customise (granular categories): enable only analytics; marketing remains blocked; verify each category toggles the right scripts and cookies.
  4. Persistence: reload and revisit; banner stays hidden; consent respected across subdomains if designed; re-prompt after expiry (typically 6 to 12 months) or when the policy or vendor list changes (consent version bump).
  5. Withdrawal: a persistent "Cookie settings" link reopens preferences; withdrawing removes the corresponding cookies, stops tracking calls, and informs vendors (consent management platform APIs).
  6. Accessibility: keyboard focus trap, screen reader labels, focus returns after close, readable at zoom, not blocking content unfairly (no cookie wall unless allowed).
  7. Localisation: language by locale, links to privacy and cookie policy, vendor lists.

Region logic

Set the geolocation through proxy or header mocking (context.setGeolocation does not change IP geolocation; use CDN test headers such as CF-IPCountry, a staging flag, or a geo-IP stub) and verify: EU or UK users see the opt-in banner, California users see the opt-out and "Do Not Sell" link, and Global Privacy Control (Sec-GPC: 1 header, navigator.globalPrivacyControl) is honoured automatically.

Consent signals and tag managers

  • Google Consent Mode v2: assert dataLayer entries gtag('consent','default',{ad_storage:'denied',analytics_storage:'denied',ad_user_data:'denied',ad_personalization:'denied'}) before tags and an update after choice; verify pings carry gcs parameters.
  • IAB TCF string (__tcfapi('getTCData')) reflects choices.
  • Tag manager triggers are conditioned on consent state; no hard-coded tags bypass the manager (scan HTML and scripts).

Auditing

Run periodic scans with tools (Cookiebot scanner, OneTrust, Ketch, cookie-audit scripts, Lighthouse, Blacklight) comparing actual cookies and trackers to the declared cookie policy; include third-party iframes and new marketing tags added by non-engineers. Store evidence (HAR files, screenshots) for compliance audits.

Pitfalls

Testing with a browser profile that already has consent, only checking the banner's presence, ignoring server-side set cookies and first-party analytics, missing tags added later by marketing, and assuming accept-all coverage equals compliance.
