How do Kubernetes NetworkPolicies enforce default-deny ingress and egress rules between namespaces?

Security engineer · Gear 3 (Senior) · Kubernetes · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

By default all pods in a Kubernetes cluster can talk to each other. A NetworkPolicy selects pods and lists allowed ingress and egress traffic; once a pod is selected by any policy for a direction, everything not explicitly allowed is denied. A default-deny policy per namespace plus explicit allow rules (including DNS egress) implements zero-trust segmentation, but it needs a CNI plugin that enforces policies.

Explained in depth

Key facts

  • NetworkPolicies are namespaced and are implemented by the CNI plugin (Calico, Cilium, Antrea, Weave). If the CNI does not support them (such as basic flannel), they are accepted by the API but have no effect.
  • Policies are additive allow lists. A pod not selected by any policy accepts all traffic. Once selected for ingress (or egress), only matching allowed traffic works.

Default deny for a namespace

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: default-deny-all, namespace: payments }
spec:
  podSelector: {}            # every pod in the namespace
  policyTypes: [Ingress, Egress]

Allow specific traffic

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: api-from-web, namespace: payments }
spec:
  podSelector: { matchLabels: { app: api } }
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector: { matchLabels: { app: web } }
        - namespaceSelector: { matchLabels: { name: ingress-nginx } }
      ports: [{ protocol: TCP, port: 8080 }]

After default deny on egress, add rules to allow DNS (UDP and TCP 53 to kube-dns in kube-system) and any required external destinations, otherwise name resolution fails.

Design approach

  1. Apply default deny in each namespace (ingress and egress).
  2. Add least-privilege allow rules per application, based on observed flows.
  3. Label namespaces so namespaceSelector works reliably.
  4. Test with a debug pod, and monitor drops (Cilium Hubble, Calico flow logs).

Limits

The standard API is L3 and L4 only; it has no deny rules, no FQDN or L7 filtering and no cluster-wide defaults. CNI-specific policies (Calico GlobalNetworkPolicy, CiliumNetworkPolicy) or a service mesh add those. Combine with mTLS and RBAC.
