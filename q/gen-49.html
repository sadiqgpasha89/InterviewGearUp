Explain the interval scheduling maximization problem and why sorting by end time is optimal.

Software engineer (core) · Gear 2 (Mid-level) · Algorithms · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

To schedule the maximum number of non-overlapping intervals, sort by end time and greedily take each interval whose start is at or after the last chosen end. Finishing earliest leaves the most room, which an exchange argument proves is optimal.

Explained in depth

Problem

Given intervals [start, end), choose the largest subset in which no two overlap. Typical forms: maximum meetings in one room, or minimum intervals to remove so the rest do not overlap (n - max_kept).

Algorithm

def max_non_overlapping(intervals):
    intervals.sort(key=lambda iv: iv[1])        # earliest finish first
    count, last_end = 0, float('-inf')
    for s, e in intervals:
        if s >= last_end:                        # touching ends are allowed
            count += 1
            last_end = e
    return count

Time O(n log n) for the sort, O(1) extra space after it.

Why earliest end time is optimal (exchange argument)

Let g be the greedy choice (the interval that ends first) and let O be any optimal schedule whose first interval is o. Because g ends no later than o, replacing o with g keeps O valid (nothing after o can start before o ends, hence not before g ends) and keeps its size. So some optimal schedule contains g. Repeat the argument on the remaining intervals that start at or after g ends: greedy is optimal by induction.

Why other orderings fail

  • Earliest start: one long interval starting first can block many short ones.
  • Shortest duration: a short interval in the middle can overlap two long, otherwise compatible ones ([1,5], [4,6], [5,9]: shortest picks [4,6] and gets 1, optimum is 2).
  • Fewest conflicts: also has counterexamples.

Boundary handling

Decide whether intervals that touch (end == next start) conflict. For half-open meetings they do not, so use >=. Break ties on equal end times by start time only if your problem needs a stable choice; the count is the same.

Related problems

  • Weighted interval scheduling is no longer greedy: sort by end, then dp[i] = max(dp[i-1], w[i] + dp[p(i)]) where p(i) is found by binary search.
  • Minimum meeting rooms uses a sweep line or a min-heap of end times.
  • Minimum arrows to burst balloons is the same greedy on the overlap structure.

Pitfalls

Sorting by the wrong key, treating inclusive and exclusive endpoints inconsistently, and forgetting that the answer for "intervals to remove" is n - kept.
