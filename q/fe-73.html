How do Resource Hints (`preconnect`, `dns-prefetch`, `preload`, `prefetch`) optimize network waterfalls?

Frontend engineer · Gear 2 (Mid-level) · Performance · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Resource hints let the browser start network work earlier. preconnect opens connections to an origin ahead of time, dns-prefetch only resolves DNS, preload fetches a resource needed on this page with high priority, and prefetch fetches a resource likely needed on a future navigation at low priority.

Explained in depth

The waterfall problem

The browser discovers resources as it parses HTML, CSS and JavaScript. A font referenced in CSS, or a hero image set by JS, is found late, so requests queue behind each other. Hints tell the browser about important resources early.

The hints

HintWhat it doesUse for
dns-prefetchresolves DNS onlythird-party origins used later, as a cheap fallback

<link rel="preconnect" href="https://cdn.example.com" crossorigin>
<link rel="dns-prefetch" href="https://analytics.example.com">
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>
<link rel="preload" as="image" href="/hero.avif" imagesrcset="hero-480.avif 480w, hero-960.avif 960w" imagesizes="100vw" fetchpriority="high">
<link rel="prefetch" href="/js/checkout.chunk.js" as="script">

Rules of thumb

  • Limit preconnect to about 2 to 4 origins; each open connection costs CPU and battery, and idle connections close.
  • Use crossorigin where the actual request is CORS (fonts always; fetch to APIs), otherwise the connection or preload is wasted and the resource is fetched twice.
  • preload must match the later request's as, type, crossorigin and URL, or it is ignored. An unused preload triggers a console warning ("preloaded but not used within a few seconds").
  • Over-preloading competes with truly critical resources and delays them. Preload only what is discovered late and on the critical path.
  • Prefer fetchpriority="high" on an <img> in the HTML over preload when the tag is already visible to the parser.

Earlier delivery

103 Early Hints: the server sends Link: <...>; rel=preload headers before the full response is ready (while it builds HTML), so the browser can start fetches during server think time. Supported on major CDNs.

Verification

Lighthouse and DevTools Network waterfall show request start times, priority and "initiator"; test with throttled networks. Track LCP and TTFB in RUM.

Pitfalls

Preloading everything, forgetting as, using prefetch for current-page resources (low priority will delay them), and caching issues when hinted URLs have hashed names that change between deploys.
