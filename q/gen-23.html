Explain the Trie (Prefix Tree) data structure: Insert, search, and prefix matching complexities.

Software engineer (core) · Gear 2 (Mid-level) · Data structures · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A trie stores strings character by character along tree edges, so insert, exact search and prefix search all take O(L) for a string of length L, independent of how many words are stored. It supports prefix queries that a hash set cannot, at the cost of more memory per key.

Explained in depth

Each node has children keyed by character and a flag that says whether a word ends here.

class Trie {
  constructor() { this.root = { kids: new Map(), end: false }; }
  insert(word) {
    let n = this.root;
    for (const ch of word) {
      if (!n.kids.has(ch)) n.kids.set(ch, { kids: new Map(), end: false });
      n = n.kids.get(ch);
    }
    n.end = true;
  }
  walk(s) { let n = this.root; for (const ch of s) { n = n.kids.get(ch); if (!n) return null; } return n; }
  search(w) { const n = this.walk(w); return !!n && n.end; }
  startsWith(p) { return this.walk(p) !== null; }
}

Complexity

  • Insert, search, startsWith: O(L).
  • Space: up to O(total characters), and more if every node holds a fixed array (for example 26 pointers). A map per node uses less when the alphabet is large or sparse.

Compared with a hash set

A hash set also gives O(L) exact lookup (hashing reads the whole string), but it cannot answer 'which words start with ca' without scanning everything. A trie can list all completions by walking the subtree.

Variants and uses

Compressed (radix) tries merge single-child chains to save memory. Common uses: autocomplete, spell checking, longest-prefix matching in IP routing tables, and word games. For very large dictionaries consider a DAWG or a sorted array with binary search as a lighter alternative.

  • How do you delete a word from a trie without breaking other words?
  • When would a radix tree be better than a plain trie?
