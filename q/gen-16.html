Compare collision resolution strategies: Separate chaining versus open addressing (linear/quadratic probing).

Software engineer (core) · Gear 2 (Mid-level) · Data structures · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Separate chaining keeps a list (or tree) of entries in each bucket, so it degrades gracefully as the load factor passes 1. Open addressing stores entries in the table itself and probes for another slot on collision; it is cache-friendly but needs a load factor below 1, tombstones for deletes and care about clustering.

Probing strategies

  • Linear probing: try i, i+1, i+2. Very cache-friendly but suffers primary clustering: runs of occupied slots grow and make later probes longer.
  • Quadratic probing: try i + 1, i + 4, i + 9. Breaks up primary clusters but keys with the same start follow the same path (secondary clustering). It only visits every slot for suitable table sizes, so pick the size and load factor carefully.
  • Double hashing: the step comes from a second hash, which spreads keys with the same first hash.
def find(table, key):
    i = hash(key) % len(table)
    while table[i] is not EMPTY:          # a tombstone keeps the probe going
        if table[i] is not TOMBSTONE and table[i].key == key:
            return table[i]
        i = (i + 1) % len(table)           # linear probing
    return None

Choosing

Chaining is simple and tolerant of bad hash functions. Open addressing wins on speed for small keys and values because of cache locality, and many modern tables (Python dicts, SwissTable-style maps) use it. Java's HashMap uses chaining and converts long chains into trees to bound the worst case.
