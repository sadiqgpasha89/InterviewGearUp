Explain binary heap array representation: Parent-child index arithmetic and $O(N)$ bottom-up heapify.

Software engineer (core) · Gear 2 (Mid-level) · Data structures · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A binary heap is a complete binary tree stored in an array: with 0-based indexes the parent of i is (i-1)/2 and the children are 2i+1 and 2i+2. Building a heap by sifting down from the last non-leaf node to the root takes O(N), while N separate inserts would take O(N log N).

Explained in depth

Index arithmetic (0-based)

  • parent(i) = (i - 1) / 2 (integer division)
  • left(i) = 2i + 1, right(i) = 2i + 2
  • With 1-based indexing: i / 2, 2i, 2i + 1. A complete tree has no gaps, so no pointers are needed.

Core operations

  • Insert: append at the end, then sift up while it beats its parent. O(log N).
  • Extract min or max: swap the root with the last element, remove the last, then sift down. O(log N).

Why bottom-up heapify is O(N)

def heapify(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):   # last non-leaf down to the root
        sift_down(a, i, n)

Half of the nodes are leaves and need no work. A node at height h can sink at most h levels, and there are about N / 2^(h+1) nodes at height h. The total work is the sum over h of h * N / 2^(h+1), which converges to a constant times N. Inserting N items one by one costs up to log N each, so O(N log N). Most nodes are near the bottom, and that is why the bottom-up approach is cheaper.

Uses

Priority queues, heap sort (build a heap, then repeatedly extract), top-K problems, Dijkstra, and merging K sorted lists.
