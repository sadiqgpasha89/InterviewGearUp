How do you configure Airflow SLA (Service Level Agreement) callbacks and alerts on delayed pipelines?

Data engineer · Gear 2 (Mid-level) · Orchestration · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Set an sla (timedelta) on tasks or default_args, and a sla_miss_callback on the DAG that runs when a task has not finished within the SLA relative to the scheduled data interval end. In Airflow 2.x this works, but SLAs are limited and have been deprecated. Airflow 3 replaces them with Deadline Alerts, and many teams use callbacks, execution timeouts and external monitoring.

Explained in depth

What an SLA means in Airflow

An SLA is a deadline by which a task (or DAG) should have completed, measured relative to the logical schedule of the run (the end of the data interval), not the actual start time. If a task is not finished by schedule time + sla, an SLA miss is recorded and sla_miss_callback fires. The task is not stopped: SLA only notifies. (execution_timeout kills the task; they solve different problems.)

Configuration (Airflow 2.x)

from datetime import timedelta
def notify_sla(dag, task_list, blocking_task_list, slas, blocking_tis):
    msg = f"SLA missed in {dag.dag_id}: {task_list}"
    slack_alert(msg)                                   # your Slack or PagerDuty function

default_args = {
    "owner": "data-platform",
    "retries": 2,
    "sla": timedelta(hours=1),              # applies to every task unless overridden
    "email": ["data-oncall@corp.com"], "email_on_failure": True,
}
with DAG("daily_sales", start_date=datetime(2026, 1, 1), schedule="0 2 * * *",
         default_args=default_args, sla_miss_callback=notify_sla, catchup=False) as dag:
    load = PythonOperator(task_id="load", python_callable=load_fn, sla=timedelta(minutes=45),
                          execution_timeout=timedelta(hours=2))

Flow: the scheduler checks SLAs when processing DAG runs (every scheduler loop), records misses in the sla_miss table, shows them under Browse > SLA Misses, and calls the DAG-level callback with the list of late tasks (and tasks blocking them).

Limitations of classic SLAs

  • Evaluated only if a DAG run exists and the scheduler processes it; a DAG that never starts (upstream outage, paused, scheduler down) does not report a miss.
  • SLA on a task depends on the schedule time, so catch-up and manual runs behave strangely.
  • Not supported for dataset-triggered DAGs and some modes; accuracy problems; callback granularity at DAG level; known bugs. SLAs are deprecated in Airflow 2.x documentation and removed in Airflow 3.

Modern alternatives

  1. Deadline Alerts (Airflow 3): define a deadline for a DAG run relative to a reference such as queued time, logical date or a fixed time, with a callback (notifier) triggered when exceeded, and options to proceed or interrupt.
  2. Task and DAG callbacks: on_failure_callback, on_retry_callback, on_success_callback, dagrun_timeout with on_failure_callback, plus execution_timeout, to detect hung tasks.
  3. Notifiers: SlackNotifier, PagerdutyNotifier, EmailNotifier classes.
  4. Freshness monitoring outside Airflow: query the destination table's max timestamp in a scheduled check (dbt source freshness, Monte Carlo, Soda, Elementary) and alert if stale. This catches the "DAG never ran" case.
  5. Metrics and alerts: export dagrun.duration and ti.finish metrics (StatsD, OpenTelemetry, Prometheus) and alert in Grafana, Datadog or CloudWatch; heartbeat alert for scheduler health.
  6. A watcher task: a final sensor or short-circuit that checks time of day and fails or alerts if data not ready by 7 AM.

Design practices

Alert to on-call rotations with clear ownership and runbooks, distinguish warning (approaching SLA) from critical, avoid alert fatigue by routing by criticality, include run id and logs link in messages, and test callbacks. Define business SLOs (data ready by 7 AM) and measure them end to end, not only inside Airflow.

Pitfalls

Assuming SLA kills long tasks, relying on SLA when the scheduler is down, alert storms during catch-up, and callbacks that throw exceptions or block.
