How does Kafka achieve exactly-once semantics (EOS) across producer and consumer streams?

Backend engineer · Gear 4 (Lead / Staff) · Messaging · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Kafka's exactly-once semantics combine an idempotent producer (sequence numbers let brokers drop retried duplicates), transactions that write to several partitions and commit consumer offsets atomically, and consumers reading with read_committed isolation. It makes a consume-process-produce loop atomic within Kafka, but side effects outside Kafka still need idempotency.

Explained in depth

Building blocks

  1. Idempotent producer (enable.idempotence=true): each producer has an id and a per-partition sequence number. The broker rejects a retried batch it already wrote, so retries do not create duplicates within a partition.
  2. Transactions (transactional.id): a producer can write to multiple partitions and topics atomically, and include the consumer's offset commit in the same transaction (sendOffsetsToTransaction). Either the output records and the input offsets commit together, or neither does.
  3. read_committed consumers (isolation.level=read_committed): they skip records from aborted or still-open transactions.
poll() -> process -> beginTransaction -> send(output) -> sendOffsetsToTransaction -> commitTransaction

Zombie fencing

The transaction coordinator tracks an epoch per transactional.id. If a stalled instance comes back after its replacement started, its writes are rejected, so two copies of a task cannot both commit.

Kafka Streams enables all of this with processing.guarantee=exactly_once_v2.

Limits

  • Guarantees hold inside Kafka. If processing writes to a database or calls an API, a retry can repeat that side effect. Use idempotent writes, or a transactional sink with its own mechanism.
  • Transactions add latency, and a long-open transaction delays read_committed consumers behind it.
  • It is best described as effectively once: the processing may run more than once after a failure, but its visible effects are applied once.
