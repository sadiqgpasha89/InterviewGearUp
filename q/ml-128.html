Using Google's Agent Development Kit, how would you route multi-line insurance questions between specialised sub-agents?

ML / AI engineer · Gear 3 (Senior) · Agents · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Build a coordinator agent with specialised sub-agents (auto, property, life, billing), each with its own instruction, tools and permissions. The coordinator classifies intent and delegates; shared session state carries identifiers like policy number so the user is not asked twice. Questions spanning lines go back to the coordinator, which runs the specialists in sequence or parallel and combines the results.

Explained in depth

Structure in ADK

  • An LlmAgent coordinator lists the specialists as sub_agents. The model can transfer control to the sub-agent whose description fits the request; clear, distinct descriptions make routing reliable.
  • Alternatively wrap a specialist as a tool (AgentTool) when the coordinator should call it and keep control, which is easier to reason about for combined answers.
  • Workflow agents (SequentialAgent, ParallelAgent, LoopAgent) give deterministic orchestration where the steps are known.
auto = LlmAgent(name='auto_claims', description='Auto policy coverage and claims', tools=[...])
home = LlmAgent(name='property', description='Home and property coverage', tools=[...])
coordinator = LlmAgent(name='coordinator', model='gemini-...',
    instruction='Identify the policy line and delegate. Ask for the policy number once.',
    sub_agents=[auto, home, life, billing])

Sharing context

  • Store resolved entities (policy number, claimant id, verified identity) in session state; sub-agents read them instead of asking again.
  • Long-term facts about the customer can come from a memory service (on Google's Gemini Enterprise Agent Platform, Memory Bank).

Cross-line requests

  • 'I reversed into my own garage door' touches auto and home. The coordinator splits the request, calls both specialists (in parallel if independent), and composes one answer that explains which policy covers what and whether one or two claims are needed.

Guardrails

  • Each specialist gets only its own tools and data scopes.
  • Low-confidence routing asks a clarifying question rather than guessing; repeated failure hands off to a person.
  • Evaluate routing accuracy on a labelled set of real questions, including ambiguous ones, and deploy and trace through a managed runtime with logging.

Likely follow-ups

  • When would you use AgentTool instead of sub-agent transfer?
  • How do you evaluate routing accuracy?
  • How do you stop a sub-agent from seeing data from another line of business?
