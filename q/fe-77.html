What are the security implications of `rel="noopener noreferrer"` on external anchor tags?

Frontend engineer · Gear 1 (Junior) · Security · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Links with target="_blank" used to give the new page access to the opener through window.opener, so a malicious page could redirect the original tab to a phishing site (reverse tabnabbing). rel="noopener" cuts that link, and noreferrer additionally hides the Referer header. Modern browsers imply noopener for _blank, but adding it is still good practice.

Explained in depth

The problem

When a page opens another page in a new tab with target="_blank", the new page historically received window.opener, a reference to the original window. A malicious or compromised destination could run:

window.opener.location = 'https://evil.example/fake-login';

The user returns to the original tab, which now shows a look-alike login page. This is reverse tabnabbing.

The fix

<a href="https://external.example" target="_blank" rel="noopener noreferrer">External</a>
  • noopener: the new page gets window.opener = null, and it may run in a separate process, which also helps performance isolation.
  • noreferrer: the browser does not send the Referer header, and it also implies noopener. Use it for privacy when you do not want the destination to learn which page or URL the user came from.

Current behaviour

Modern browsers (Chrome 88+, Firefox 79+, Safari 12.1+) treat target="_blank" as noopener by default, but older browsers do not, so many linters and security checklists still require the attribute. User-generated links should always have it, and you should also restrict URL schemes (no javascript:).

Trade-off

noreferrer removes referrer data that analytics or affiliate programs may need. In that case use rel="noopener" alone.
