How do you fine-tune embedding models using contrastive InfoNCE loss over positive and negative pairs?

ML / AI engineer · Gear 3 (Senior) · Embeddings · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Contrastive fine-tuning teaches an embedding model to place related texts close and unrelated texts far apart. With InfoNCE loss, each query is scored against its positive and many negatives, and a temperature-scaled softmax cross-entropy pushes the positive's similarity above all negatives. In-batch negatives make this efficient, and hard negatives sharpen domain-specific distinctions.

Explained in depth

Goal

Generic embedding models may rank domain-specific content poorly (legal clauses, internal product docs, medical codes). Fine-tuning on in-domain pairs (query, relevant passage) improves retrieval recall noticeably, often with only thousands of examples.

InfoNCE loss

For a query q, its positive passage p⁺, and a set of negatives {p⁻ⱼ}: L = − log [ exp(sim(q, p⁺)/τ) / ( exp(sim(q, p⁺)/τ) + Σⱼ exp(sim(q, p⁻ⱼ)/τ) ) ]

  • sim is cosine similarity (embeddings L2-normalised) or dot product.
  • τ (temperature, for example 0.02 to 0.1) controls sharpness: small τ focuses the gradient on the hardest negatives; large τ treats all negatives more equally.
  • It is a (K+1)-way softmax classification that identifies the positive among negatives, and it maximises a lower bound on mutual information between query and positive (hence "noise contrastive estimation").

Symmetric versions also compute passage-to-query loss.

In-batch negatives

Batch of B pairs (q_i, p_i). Embed all queries and passages, compute the B × B similarity matrix; the diagonal holds positives and every off-diagonal entry in row i serves as a negative for q_i. This is MultipleNegativesRankingLoss in sentence-transformers.

from sentence_transformers import SentenceTransformer, losses, InputExample
from torch.utils.data import DataLoader
model = SentenceTransformer("BAAI/bge-base-en-v1.5")
train = [InputExample(texts=[q, pos, hard_neg]) for q, pos, hard_neg in triples]      # optional hard negative as third text
loader = DataLoader(train, shuffle=True, batch_size=128)
loss = losses.MultipleNegativesRankingLoss(model, scale=20.0)                          # scale = 1/temperature
model.fit(train_objectives=[(loader, loss)], epochs=2, warmup_steps=100, optimizer_params={"lr": 2e-5})

Bigger batches provide more negatives per step and generally improve quality (use gradient caching, GradCache, to simulate large batches within memory).

Building training data

  • Positives: human-labelled relevance, click logs, FAQ question to answer, title to body, doc section to heading, and synthetic queries: an LLM generates questions for each chunk (GPL, InPars, Promptagator style), filtered by a cross-encoder or consistency check.
  • Negatives: random in-batch (easy), hard negatives mined by retrieving top results with BM25 or the base embedding model and excluding true positives (ranks 10 to 100 work well; too-close items may be false negatives), plus cross-encoder-scored negatives with margin filtering.
  • Include instructions or prefixes if the base model requires them (query: and passage: in E5).
  • Hold out an evaluation set (queries with relevant docs from a different time period or documents) to avoid leakage.

Issues and tips

  • False negatives: unlabelled relevant passages treated as negatives hurt training; use deduplication, cluster-aware batching, and denoising with a reranker.
  • Keep batch composition diverse (avoid many same-topic items) or use topic-aware hard-negative batches deliberately.
  • Matryoshka representation learning trains embeddings that remain useful when truncated to smaller dimensions.
  • Prevent catastrophic forgetting: low learning rate, few epochs, mix some general data, LoRA adapters, evaluate on general benchmarks (MTEB subset).
  • Match training and inference similarity function, normalisation, max length and prefixes.
  • Distillation from a cross-encoder (margin-MSE) can add quality.
  • Re-embed the entire corpus after fine-tuning and rebuild the index.

Evaluation

Recall@k, MRR@10, nDCG@10 on the held-out set versus the base model and a BM25 baseline; end-to-end RAG answer quality; latency and index size. Expect the largest gains where domain vocabulary differs from web text.

Pitfalls

Training on test queries, too-high learning rate wrecking pretrained knowledge, hard negatives that are actually relevant, forgetting normalisation, and not re-indexing.
