Explain the difference between narrow transformations and wide transformations in Spark.

Data engineer · Gear 2 (Mid-level) · Spark · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A narrow transformation computes each output partition from a single input partition (map, filter, select), so it needs no data movement and is pipelined within a stage. A wide transformation (groupBy, join, distinct, repartition) needs data from many partitions, causes a shuffle across the network and starts a new stage.

Explained in depth

Narrow

map, filter, select, withColumn, union. Every output partition depends on at most one input partition, so Spark chains them in one task with no data exchange. If a partition is lost, only that partition's lineage is recomputed.

Wide

groupBy, reduceByKey, distinct, orderBy, repartition, and most joins. Rows with the same key must end up in the same partition, so every task writes shuffle files to local disk, and the next stage reads the relevant pieces from all of them over the network. That is the expensive part: disk, network and serialisation.

Stages

Spark splits the job graph into stages at shuffle boundaries. In the Spark UI (or df.explain()) an Exchange node marks a shuffle.

df.filter('amount > 0').select('user', 'amount')     # narrow, one stage
  .groupBy('user').sum('amount')                      # wide, shuffle, new stage

Reducing shuffle cost

  • Filter and project early so less data is shuffled.
  • Prefer reduceByKey or DataFrame aggregations, which combine map-side, over groupByKey on RDDs.
  • Use a broadcast join when one side is small, so the large side is not shuffled.
  • Tune spark.sql.shuffle.partitions and rely on adaptive query execution to coalesce small post-shuffle partitions.
  • Watch for skew, where one key makes a single shuffle partition huge.

  • How can you tell from explain() where the shuffles happen?
  • Is a join always a wide transformation?
