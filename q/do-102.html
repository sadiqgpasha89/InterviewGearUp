How do you write a Dockerfile that builds quickly and produces a small image?

DevOps / SRE / Cloud · Gear 1 (Junior) · Containers · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Order instructions from least to most frequently changing so Docker can reuse cached layers (copy dependency manifests and install before copying source), use a small base image, put cleanup in the same layer as the install, and use a multi-stage build so build tools do not end up in the final image.

Explained in depth

# build stage
FROM node:22 AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# runtime stage
FROM node:22-slim
WORKDIR /app
COPY --from=build /app/dist ./dist
USER node
CMD ["node", "dist/server.js"]
  • Layer cache: each instruction creates a layer, and Docker reuses it if the instruction and its inputs are unchanged. Copying package*.json first means dependencies are only reinstalled when they change.
  • Multi-stage builds keep compilers and dev dependencies out of the runtime image.
  • Use a .dockerignore (excluding .git and node_modules) to shrink the build context.
  • Pin base image versions, run as a non-root user, and clean package-manager caches in the same RUN that created them. Deleting files in a later layer does not shrink the image.
  • Rebuild regularly to pick up base-image security patches.
