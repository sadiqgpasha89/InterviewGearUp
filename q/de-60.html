What is Change Data Capture (CDC) and how does Debezium stream database changes into Kafka?

Data engineer · Gear 3 (Senior) · Ingestion · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Change data capture streams a database's row-level inserts, updates and deletes to other systems. Log-based CDC reads the transaction log, so it is low-impact and sees deletes and every change in order. Debezium runs as Kafka Connect source connectors, takes an initial snapshot and then publishes before and after images of each row to a Kafka topic per table.

Explained in depth

Approaches

  • Query-based (poll an updated_at column): simple, but misses deletes and intermediate updates and adds load.
  • Trigger-based: captures everything but adds write overhead to the source.
  • Log-based: reads the MySQL binlog, the PostgreSQL write-ahead log (via logical decoding) or the SQL Server and Oracle change logs. It has little impact on the source and preserves commit order.

Debezium

A Kafka Connect source connector per database. It performs an initial snapshot of existing rows, then streams changes. Each event carries the primary key, the before and after row state, an operation code (create, update, delete, read for snapshot), source metadata such as the log position, and a timestamp. Offsets are stored in Kafka so the connector resumes where it stopped.

{ 'op': 'u', 'before': {'id': 7, 'status': 'NEW'}, 'after': {'id': 7, 'status': 'PAID'}, 'source': {'table': 'orders', 'lsn': 53829104} }

Operational concerns

  • On PostgreSQL a replication slot keeps WAL until the connector reads it. A stopped connector can fill the database's disk.
  • Using the primary key as the Kafka message key keeps each row's changes in order within a partition.
  • Delivery is at least once, so consumers should be idempotent (upsert by key).
  • Schema changes need a schema registry and compatible evolution; very large initial snapshots need planning.
  • Deletes arrive as an event plus an optional tombstone, which matters for compacted topics.

The outbox pattern uses CDC to publish events reliably from a service without dual writes.
