How do you configure synthetic monitoring to continuously probe critical user journeys from the outside?

DevOps / SRE / Cloud · Gear 2 (Mid-level) · Observability · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Synthetic monitoring runs scripted checks against production from outside, on a schedule and from multiple regions, to verify critical user journeys such as login, search and checkout. It detects outages, slowness and third-party failures before users report them, measures availability and latency as seen by customers, and feeds alerts and SLOs.

Explained in depth

Why probe from outside

Internal metrics can look healthy while users fail: DNS, CDN, TLS certificates, load balancers, routing, third-party scripts and regional network problems are invisible to the app. Synthetic probes act like a user at the edge, giving a clear up or down signal and an end-to-end latency baseline even at 3 a.m. with no real traffic.

Types of checks

  • Uptime (ping, TCP, HTTP): status code, response time, body assertion, redirects, TLS expiry (certificate days remaining), DNS resolution.
  • API checks: multi-step flows with authentication tokens, assertions on JSON, schema and latency.
  • Browser checks (journeys): real browser automation (Playwright) for login, add to cart, checkout in a test account, with screenshots, traces and Web Vitals.
  • Heartbeat or dead man's switch: expects pings from cron jobs and batch processes.
  • Multi-location: run every 1 to 5 minutes from several regions and networks; alert only when several locations fail (to avoid single-probe false positives).

Example tools

Blackbox Exporter with Prometheus, Grafana Synthetic Monitoring (k6 and Playwright based), Datadog Synthetics, Checkly (monitoring as code), New Relic, Pingdom, UptimeRobot, AWS CloudWatch Synthetics canaries, Google Cloud Uptime checks, Azure Application Insights availability tests.

# Prometheus blackbox exporter module and probe
modules:
  http_2xx:
    prober: http
    http: { valid_status_codes: [200], fail_if_body_not_matches_regexp: ["Add to cart"], preferred_ip_protocol: ip4 }
# prometheus.yml scrape config targets https://shop.example.com/ via /probe, alert on probe_success == 0 for 5m, probe_ssl_earliest_cert_expiry
// Playwright journey run as a monitor (Checkly style)
test('checkout journey', async ({ page }) => {
  await page.goto('https://shop.example.com');
  await page.getByRole('link', { name: 'Shoes' }).click();
  await page.getByRole('button', { name: 'Add to cart' }).first().click();
  await expect(page.getByTestId('cart-count')).toHaveText('1');
});

Design principles

  • Cover the money paths and key dependencies first (login, search, payment, API gateway), not every page.
  • Isolate test data: dedicated synthetic accounts, test payment modes, tagging requests with a header so analytics, fraud systems and inventory ignore them; clean up created records; avoid actions with real-world effects (emails, orders).
  • Stable selectors and assertions (roles, data-testid), explicit timeouts, retries (one quick retry before alerting) and tolerance for expected variance.
  • Measure SLIs: availability (percent of successful checks), latency percentiles per location and step, correlate with deploys. Use for SLO dashboards and error budgets, and alert on symptoms with runbook links.
  • Secure credentials in a secrets store; rotate test passwords; avoid hitting rate limiters and WAF bot protection (allowlist probe IPs or headers).
  • Keep check suites in version control, review them like code, and run them against staging and after deployments (smoke tests in CD).

Complement with RUM

Real user monitoring shows actual device and network diversity and rare issues but needs traffic and cannot detect outages with no users. Synthetic gives controlled, repeatable measurements and proactive detection. Use both, plus internal metrics and tracing for diagnosis.

Pitfalls

Single-location alerts causing false pages, brittle UI scripts breaking on every release, probes polluting business metrics, and monitoring only the home page.
