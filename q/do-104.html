A Linux server feels slow. What commands do you run in the first few minutes to find out why?

DevOps / SRE / Cloud · Gear 1 (Junior) · Linux · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Check load and uptime, then CPU with top or htop, memory and swap with free, disk space and inodes with df, disk I/O with iostat, network sockets with ss, and recent errors in dmesg and logs. Work through CPU, memory, disk and network in order, find the process responsible, and change one thing at a time.

Explained in depth

A quick checklist

  1. uptime: load averages for 1, 5, 15 minutes. Compare against the number of CPU cores (nproc). Load far above core count means waiting work (CPU or I/O).
  2. top or htop: which processes use CPU and memory? Look at %us (user), %sy (kernel), %wa (I/O wait), %st (steal, noisy neighbours on virtual machines).
  3. free -h: memory. Look at available, not just free, and at swap use. Heavy swapping (vmstat 1, columns si/so) makes everything slow.
  4. df -h and df -i: a full disk or no free inodes causes strange failures.
  5. iostat -xz 1: disk utilisation, queue length and latency (await). iotop shows which process does I/O.
  6. ss -s and ss -tulpn: socket counts, listening ports, many connections in odd states.
  7. dmesg -T | tail and journalctl -p err -n 50: out-of-memory kills, disk errors, network resets.
  8. Application logs and recent changes (deploys, cron jobs, config).

USE method

For each resource (CPU, memory, disk, network) check Utilisation, Saturation and Errors. This stops guessing.

Next steps

  • High CPU: which process, perf top or a profiler, then why (traffic, a runaway loop).
  • High I/O wait: find the heavy reader or writer, check for backups or log storms.
  • Memory pressure: look for leaks, check cgroup limits, and the OOM killer.
  • Remember to record what you found, and avoid restarting before capturing evidence (thread dumps, top output).

Likely follow-ups

  • What is the difference between load average and CPU utilisation?
  • How do you tell if the system is swapping heavily?
  • How do you find which process is using the most disk I/O?
