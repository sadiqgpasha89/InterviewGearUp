What telemetry and evaluation do you need to run AI agents in production, and how is it different from testing deterministic code?

ML / AI engineer · Gear 3 (Senior) · MLOps · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Trace every run end to end (each LLM call, tool call, latency, tokens, cost, errors) under one trace id. Evaluate both the trajectory (right tools, right order, no loops) and the outcome (correct, grounded, compliant) with golden datasets, deterministic checks and calibrated LLM judges. Unlike deterministic code, outputs vary, so you test statistically on many cases and keep monitoring after release.

Explained in depth

Telemetry

  • Tracing with OpenTelemetry or an agent observability tool (LangSmith, a cloud platform's tracing): spans for each node, model call and tool call, linked by a trace id and tagged with model and prompt versions.
  • Performance: latency per step and end to end (p50, p95, p99), time to first token, tokens and cost per run.
  • Tool health: call error rate, schema validation failures, retries, and invalid arguments.
  • Trajectory stats: steps per run, loops detected, recursion-limit hits, human handoff rate.
  • Safety: guardrail triggers, PII redactions, prompt-injection detections, policy violations.
  • Business outcomes: task completion, escalation rate, reviewer override rate, customer satisfaction.

Evaluation

LayerWhat to checkHow
Deterministic rulesHard rules always hold (suspended licence is always flagged; payout arithmetic)Unit tests, 100% pass
Tool useRight tool, right arguments, right orderCompare with expected trajectories on a golden set
RetrievalRelevant policy clauses foundRecall at k, context relevance

Why it differs from deterministic testing

  • The same input can produce different but acceptable outputs, so exact-match assertions fail. Test properties (fields, cited clause, decision) and score distributions over hundreds of cases.
  • Run each case several times to measure consistency, and gate releases on pass rates per category, not on one run.
  • Model or prompt changes from providers can shift behaviour, so evaluation continues in production: sample live traces, score them, and alert on drops.
