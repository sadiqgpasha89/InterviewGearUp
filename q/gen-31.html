Explain the Floyd-Warshall dynamic programming algorithm for all-pairs shortest paths.

Software engineer (core) · Gear 3 (Senior) · Graphs · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Floyd-Warshall computes shortest paths between all pairs of vertices with dynamic programming: for each intermediate vertex k, it checks whether going through k improves the distance from i to j. It uses three nested loops, so it runs in O(V^3) time and O(V^2) space, and it handles negative edges but not negative cycles.

Explained in depth

Idea

Let dist[i][j] be the best known distance from i to j using only vertices from the first k as intermediates. Adding vertex k as an allowed intermediate gives:

dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])

def floyd_warshall(dist):              # dist[i][j]: edge weight, inf if none, 0 on the diagonal
    n = len(dist)
    for k in range(n):                 # the intermediate vertex must be the OUTER loop
        for i in range(n):
            for j in range(n):
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist

Key points

  • Loop order matters: k must be the outermost loop, because the recurrence builds on results for smaller sets of intermediates.
  • Negative cycles: after the run, if any dist[i][i] < 0, a negative cycle exists.
  • Path reconstruction: keep a next[i][j] matrix that is updated whenever a distance improves.
  • Complexity: O(V^3) time and O(V^2) space; it can run in place.

Choosing it

Use it for dense graphs with a few hundred vertices, transitive closure (with booleans) and simple code. For sparse graphs, running Dijkstra from every vertex costs O(V * E log V), which is faster; with negative edges use Johnson's algorithm.

Likely follow-ups

  • How do you detect a negative cycle with it?
  • How do you reconstruct the actual path, not just the distance?
  • When is running Dijkstra from every vertex better?
