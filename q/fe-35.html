Explain React 18 Concurrent Features: `useTransition`, `useDeferredValue`, and Suspense.

Frontend engineer · Gear 3 (Senior) · React · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

React 18 concurrent features let rendering be interruptible and prioritised. useTransition marks a state update as non-urgent so the UI stays responsive while it renders; useDeferredValue gives a lagging copy of a value for expensive children; and Suspense lets components wait for data or code and show a fallback, now also on the server with streaming.

Explained in depth

useTransition

const [isPending, startTransition] = useTransition();

function onChange(e) {
  setQuery(e.target.value);                  // urgent: keep the input responsive
  startTransition(() => setFilter(e.target.value));   // non-urgent: heavy list can wait
}

React renders the transition update in the background, and it can be interrupted by a new keystroke. isPending lets you show a subtle loading hint. Unlike a debounce, there is no artificial delay and the work is cancelled when superseded.

useDeferredValue

const deferred = useDeferredValue(query);
return <HeavyList filter={deferred} />;      // lags behind, uses the old value during urgent updates

Useful when you do not control the code that sets the state (props from a parent).

Suspense

<Suspense fallback={<Spinner />}>
  <Profile />       {/* may suspend while loading data or lazy code */}
</Suspense>

When a child suspends, React shows the nearest fallback. With transitions, React keeps the previous UI visible instead of replacing it with a spinner. On the server, streaming SSR sends the shell first and fills in suspended parts as they resolve, with selective hydration.

Other 18 changes

Automatic batching of updates in promises and timeouts, createRoot, and Strict Mode that remounts components once in development to expose effect bugs.
