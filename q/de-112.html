How do NULLs behave in SQL comparisons, aggregates and joins, and how do you handle them?

Data engineer · Gear 1 (Junior) · SQL · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

NULL means unknown, so any comparison with it using = or <> yields unknown rather than true, which means rows are filtered out unexpectedly. Use IS NULL and IS NOT NULL, COALESCE to supply defaults, and remember that aggregates like SUM and AVG ignore NULLs while COUNT of a column skips them but COUNT star counts all rows. NULLs also never match in joins on equality.

Explained in depth

Three-valued logic

A comparison can be TRUE, FALSE or UNKNOWN. Anything compared with NULL is unknown:

SELECT NULL = NULL;     -- NULL (unknown), not TRUE
SELECT 5 <> NULL;       -- NULL
SELECT * FROM users WHERE phone = NULL;     -- returns nothing
SELECT * FROM users WHERE phone IS NULL;    -- correct

WHERE and ON keep only rows evaluating to TRUE, so rows with unknown results disappear.

Operators and functions

  • Arithmetic with NULL gives NULL (1 + NULL). String concatenation with NULL often gives NULL (except in Oracle and a few others).
  • AND and OR follow rules: FALSE AND NULL is false, TRUE OR NULL is true, TRUE AND NULL is NULL.
  • COALESCE(a, b, 0) returns the first non-NULL; NULLIF(a, b) returns NULL when equal (useful to avoid division by zero: x / NULLIF(y, 0)). IS DISTINCT FROM compares treating NULLs as equal.

Aggregates

  • SUM, AVG, MIN, MAX ignore NULLs. An average over (10, NULL, 20) is 15, not 10.
  • COUNT(column) counts non-NULL values; COUNT(*) counts rows.
  • A group of all NULLs gives a NULL sum (use COALESCE(SUM(x), 0)).
  • GROUP BY and DISTINCT treat NULLs as one group.

Joins and sets

  • Join on a.key = b.key never matches NULL keys; in a LEFT JOIN, unmatched rows produce NULLs, so be careful distinguishing "no match" from "matched with a NULL value".
  • NOT IN with a NULL in the list returns no rows (every comparison becomes unknown); use NOT EXISTS instead.

Practices

Declare NOT NULL where a value is required, use defaults, document the meaning of NULL (unknown, not applicable, not yet provided), and test for unexpected NULL rates in pipelines.

Likely follow-ups

  • How do NULLs sort and group?
