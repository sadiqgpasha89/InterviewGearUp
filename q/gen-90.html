How does the IEEE 754 floating-point standard represent numbers, and why does `0.1 + 0.2 != 0.3` occur?

Software engineer (core) · Gear 2 (Mid-level) · Systems · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

IEEE 754 stores a float as sign, exponent and mantissa in binary, so most decimal fractions such as 0.1 and 0.2 cannot be represented exactly. Their rounded binary approximations add up to 0.30000000000000004, which is not the nearest double to 0.3, so the equality test fails.

Explained in depth

Representation

A 64 bit double has 1 sign bit, 11 exponent bits (bias 1023) and 52 fraction bits. A normal value is:

(-1)^s * 1.fraction * 2^(exponent - 1023)

A 32 bit float uses 1, 8 and 23 bits. A double provides about 15 to 17 significant decimal digits, a float about 6 to 9.

Why 0.1 is inexact

Decimal fractions are exact only if their denominator is a power of two. 0.1 = 1/10 has an infinitely repeating binary expansion (0.0001100110011...), so it is rounded to the nearest 53 bit mantissa:

0.1 -> 0.1000000000000000055511151231257827...
0.2 -> 0.2000000000000000111022302462515654...
sum -> 0.3000000000000000166533453693773481...  rounds to 0.30000000000000004
0.3 -> 0.2999999999999999888977697537484346...

The exact sum of the two stored values falls between two representable doubles and rounds to a number different from the one 0.3 rounds to, so 0.1 + 0.2 != 0.3. In Python 0.1 + 0.2 prints 0.30000000000000004.

Comparing floats

Never rely on == for computed values. Use a tolerance:

import math
math.isclose(a, b, rel_tol=1e-9, abs_tol=1e-12)

Use a relative tolerance for large magnitudes and an absolute tolerance near zero. Test libraries provide assertAlmostEqual, pytest.approx, toBeCloseTo.

Other hazards

  • Absorption and cancellation: 1e16 + 1 == 1e16; subtracting nearly equal numbers loses significant digits.
  • Non-associativity: (a + b) + c may differ from a + (b + c), so parallel reductions give slightly different results; use Kahan summation for accuracy.
  • Special values: NaN (never equal to itself), +/-Infinity, signed zero (-0.0 == 0.0 but they differ in sign), subnormal numbers near zero with reduced precision.
  • Integers above 2^53 are not all representable as doubles (a JavaScript Number trap for 64 bit ids).

Money

Use integer minor units (cents) or decimal types (BigDecimal, Python decimal, NUMERIC in SQL), with an explicit rounding mode. Store currency alongside the amount.

Pitfalls

Printing with limited digits hides errors, float vs double mixing causes unexpected widening, and fast-math compiler flags change results. Deterministic simulations or distributed systems should avoid depending on exact floating point results across platforms.
