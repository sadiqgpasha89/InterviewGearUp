What is middleware in a web framework, and what are typical uses?

Backend engineer · Gear 1 (Junior) · Architecture · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Middleware is a chain of functions that wrap request handling: each can inspect or modify the request, short-circuit with a response, call the next function, then process the response on the way back. It keeps cross-cutting concerns such as logging, authentication, CORS, compression, rate limiting and error handling out of business handlers.

Explained in depth

The pipeline model

A request passes through an ordered list of middleware before reaching the handler, and the response travels back through them in reverse.

// Express example
app.use((req, res, next) => {
  const start = Date.now();
  res.on('finish', () => console.log(req.method, req.url, res.statusCode, Date.now() - start + 'ms'));
  next();                       // pass control to the next middleware
});

app.use(authenticate);          // may respond 401 and stop the chain
app.use(express.json());        // parse the body
app.get('/orders', handler);
app.use(errorHandler);          // error-handling middleware at the end

Each middleware chooses to continue (next()), respond itself, or fail with an error.

Typical uses

  • Request logging, request IDs and tracing context.
  • Authentication and authorisation (verify the token, attach req.user).
  • Body parsing, validation and sanitising.
  • CORS headers, security headers (Helmet), HTTPS redirects.
  • Rate limiting, compression, caching headers.
  • Centralised error handling that converts exceptions to consistent responses.
  • Metrics and timing.

Order matters

Security and logging usually come first, parsing before validation, authentication before handlers, and the error handler last. For example, a rate limiter placed after an expensive step does not protect it.

Same idea elsewhere

ASP.NET Core middleware, Django middleware, Koa, Rack (Ruby), Go http.Handler wrappers, and interceptors or filters in Spring and NestJS.

Cautions

Keep middleware small and focused; avoid heavy synchronous work; handle async errors properly (unhandled promise rejections can hang requests); and do not put business logic in middleware, since it makes behaviour hard to find and test.
