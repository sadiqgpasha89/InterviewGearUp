How do you monitor a deployed machine learning model for data drift, concept drift and performance decay, and when do you retrain?

Data scientist · Gear 3 (Senior) · ML monitoring · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Monitor data quality, input and prediction distributions using PSI or KS tests, and business and model metrics once labels arrive, with segment breakdowns and alerting. Distinguish covariate shift from concept drift, track label delay with proxies, define retraining triggers and a champion-challenger process, and keep rollback and logging in place.

Explained in depth

Why models decay

The world changes: customer behaviour, seasonality, new products, fraud tactics, upstream pipeline changes, and feedback loops (the model's decisions alter future data). A model with excellent offline metrics can quietly degrade.

Types of change

TypeMeaningExample
Covariate shift (data drift)P(X) changes, P(y given X) stablenew user demographics
Label (prior) shiftP(y) changesfraud rate rises in holidays
Concept driftP(y given X) changescustomer sensitivity to price after a recession
Data quality / pipeline issueschema, units, nulls, delayed feedsa feature silently filled with zeros
Training-serving skewfeatures computed differently online and offlinetimezone or rounding difference

What to monitor

  1. Data quality: schema validation, null rates, ranges, categorical cardinality, freshness and volume (Great Expectations, Deequ, Evidently).
  2. Input drift: compare production feature distributions with the training reference: Population Stability Index (PSI) (rule of thumb: below 0.1 stable, 0.1 to 0.25 moderate, above 0.25 major), KS test, Jensen-Shannon divergence, chi-square for categoricals. Prioritise features by importance, and beware that large samples make tiny shifts "significant".
  3. Prediction drift: distribution of scores, share above threshold, calibration of mean prediction.
  4. Model performance: precision, recall, AUC, calibration, error metrics, once labels arrive; also by segment (region, device, new vs old users) and for fairness.
  5. Business outcomes and proxies: conversion, approval rate, manual review load, complaints, revenue per decision.
  6. Operational health: latency, throughput, errors, resource use, fallback rates.
import numpy as np
def psi(expected, actual, bins=10):
    cuts = np.quantile(expected, np.linspace(0, 1, bins + 1)); cuts[0], cuts[-1] = -np.inf, np.inf
    e = np.histogram(expected, cuts)[0] / len(expected) + 1e-6
    a = np.histogram(actual, cuts)[0] / len(actual) + 1e-6
    return np.sum((a - e) * np.log(a / e))

Delayed labels

Use leading indicators: drift metrics, proxy outcomes (early repayment behaviour, chargeback flags, user feedback), partial labels, estimated performance methods (CBPE, confidence-based), human-labelled samples of recent traffic, and shadow deployments. Backfill true performance when labels mature.

Response playbook

  • Alerts with thresholds and severity, owners and runbooks; avoid alert fatigue by tuning.
  • Diagnose: pipeline bug, data source change, or real-world shift? Fix pipeline issues first.
  • Retrain with recent data (windowing or weighting), re-validate, and deploy with champion-challenger, shadow mode, canary or A/B tests; keep rollback to the previous version.
  • Retraining policy: scheduled (weekly, monthly) for steady domains, triggered (drift or performance breaches) for volatile ones, or continuous learning with safeguards. Weigh retraining cost, risk of learning from biased feedback, and governance requirements.
  • Maintain model registry, versioned data and code, reproducible training, and an audit trail of predictions (inputs, model version, outputs) for debugging and compliance.

Feedback loops

Decisions can censor labels (loans you reject never show whether they would default). Use exploration, randomised holdouts, and reject inference to keep learning unbiased.

Pitfalls

Monitoring only infrastructure, alerting on every statistically significant drift, retraining blindly on contaminated data, and having no ground truth strategy.
