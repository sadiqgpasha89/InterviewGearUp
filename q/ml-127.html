In LangGraph, how would you require an underwriter or adjuster to approve high-value or high-risk cases before the agent continues?

ML / AI engineer · Gear 3 (Senior) · Agents · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Route with a conditional edge (for example coverage above a limit or risk score above a threshold) to a review node that calls interrupt() with a summary. With a persistent checkpointer, the run pauses under its thread id; your API shows the case in a review queue, and the reviewer's decision resumes the run with Command(resume=...). Make steps before the pause idempotent: the node restarts on resume.

Explained in depth

Graph

extract_application -> evaluate_rules -> (human_review | decide) -> bind_or_decline

from langgraph.types import interrupt, Command

def route(state):
    if state['requested_coverage'] > 500_000 or state['risk_score'] > 70:
        return 'human_review'
    return 'decide'

def human_review(state):
    decision = interrupt({                    # pauses here; payload goes to the caller
        'case_id': state['case_id'],
        'summary': state['summary'],
        'flags': state['flags'],
    })
    return {'review': decision}               # runs after resume

graph = builder.compile(checkpointer=PostgresSaver(conn))

Runtime flow

  1. The API runs the graph with config={'configurable': {'thread_id': case_id}}. When it reaches interrupt, the run stops and the state is saved; the caller receives the interrupt payload.
  2. The case appears in the reviewer's queue with the extracted data, rule results and cited evidence.
  3. The reviewer approves, edits or declines. The backend resumes: graph.invoke(Command(resume={'action': 'approve', 'notes': '...'}), config=same_config).
  4. human_review returns the decision into state and the graph continues to the next node.

Details that matter in production

  • The interrupted node restarts from its beginning on resume. Put side effects (sending an email, writing to the policy system) in a later node or make them idempotent.
  • Validate the resume payload (allowed actions, the reviewer's authority for that amount) before using it.
  • Record who approved, when, what they saw and what they changed, for audit.
  • Handle timeouts: a scheduled job escalates cases waiting longer than the service level.
  • Thresholds are business rules: keep them in configuration owned by underwriting, not in a prompt.
  • Older code may use interrupt_before=['node'] at compile time; the interrupt() function is more flexible because it can pause conditionally and pass data to the reviewer.

Likely follow-ups

  • Why must the code before interrupt() be idempotent?
  • How would you let the reviewer edit extracted fields before resuming?
  • How do you handle a review that never comes back?
