Explain Multi-Head Attention and how multiple heads learn diverse representation subspaces.

ML / AI engineer · Gear 3 (Senior) · Transformers · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Multi-head attention projects the input into several smaller query, key and value subspaces, runs scaled dot-product attention in each head in parallel, then concatenates the heads and applies an output projection. Each head can attend to different relationships (syntax, position, coreference), so the model captures several kinds of dependencies at once at about the same cost as one big head.

Explained in depth

Scaled dot-product attention

For queries Q, keys K and values V: Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V Each token's query is compared with every key; the softmax weights decide how much of each value is mixed into the output. Dividing by sqrt(d_k) keeps the dot products from growing with dimension and pushing the softmax into saturation (tiny gradients).

Multiple heads

With model dimension d_model and h heads, each head uses dimension d_k = d_model / h (for example 512 / 8 = 64):

head_i = Attention(X W_Q_i, X W_K_i, X W_V_i)
MultiHead(X) = Concat(head_1, ..., head_h) W_O

Because each head has its own learned projections, it works in a different representation subspace. Analyses of trained models show heads specialising: one attends to the previous token, another to syntactic dependents, another to rare matching words. A single head would average these into one pattern.

Cost

  • Total computation is similar to one full-width head, since each head is smaller.
  • Self-attention costs **O(n^2 * d)** time and O(n^2) memory in sequence length n for the attention matrix, which limits long contexts (FlashAttention reduces memory traffic; sparse and linear variants change the complexity).

Variants for efficient inference

  • Multi-query attention (MQA): all heads share one key and value projection.
  • Grouped-query attention (GQA): groups of heads share keys and values; used in many modern LLMs.

Both shrink the KV cache, which dominates memory during generation.

Masking

Decoder self-attention uses a causal mask so a token cannot see future tokens, and encoder-decoder models add cross-attention from decoder queries to encoder keys and values.
