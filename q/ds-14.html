Explain the bias-variance trade-off and how model complexity, data size and regularisation affect it.

Data scientist · Gear 1 (Junior) · ML fundamentals · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Expected prediction error splits into bias (error from overly simple assumptions), variance (sensitivity to the particular training sample) and irreducible noise. Simple models have high bias and low variance, flexible models the reverse. Regularisation, ensembling and more data lower variance, while richer models and better features lower bias.

Explained in depth

The decomposition

For squared loss, the expected error at a point decomposes into Error = Bias squared + Variance + Irreducible noise.

  • Bias: how far the average prediction (over many training sets) is from the truth. High bias means the model class cannot represent the pattern (a straight line for a curve): underfitting.
  • Variance: how much predictions change when trained on different samples. High variance means the model chases noise: overfitting.
  • Irreducible noise: randomness in the target that no model can explain; it sets the floor.

The classical picture: as complexity rises, bias falls and variance rises, so test error is U-shaped with a sweet spot in the middle.

Examples

ModelTypical behaviour
Linear regression on non-linear datahigh bias, low variance
Deep decision tree (no limit)low bias, high variance
KNN with k = 1low bias, high variance; large k raises bias
Random foresteach tree high variance; averaging lowers variance
Gradient boostingsequentially fits residuals, lowers bias; too many rounds raises variance
Ridge or lassoadds bias on purpose to reduce variance

Levers

  • Reduce variance: more training data, regularisation (L1, L2, dropout, early stopping), fewer or simpler features, bagging and random forests, ensembling, pruning, data augmentation, larger k in KNN.
  • Reduce bias: more expressive model, richer features and interactions, longer training, lower regularisation, boosting.
  • More data mainly helps variance; it does little for a model that is structurally too simple.

Diagnosis

  • Training error high and validation error similar and high: bias problem (underfit).
  • Training error low and validation error much higher: variance problem (overfit).
  • Learning curves and validation curves visualise both; cross-validation variance across folds is another hint.
from sklearn.model_selection import validation_curve
import numpy as np
depths = np.arange(1, 20)

# plot -tr.mean(1) and -va.mean(1): the minimum of validation error marks the sweet spot

Modern nuance

Large over-parameterised models (deep networks, very wide models) can show double descent: test error rises near the point where the model just fits the training data, then falls again as capacity grows further, helped by implicit regularisation from optimisation. Practitioners therefore rely on empirical validation, not only the textbook curve. Also, in boosting and deep learning, early stopping and regularisation remain essential.

Practical workflow

Start with a simple, interpretable baseline, add complexity while validation performance improves, apply regularisation, evaluate on held-out data, and compare against the noise level you believe exists (inter-annotator agreement, repeated measurement variation).

Pitfalls

Equating complexity only with parameter count, assuming more data always fixes a bad model, and tuning on the test set while chasing the sweet spot.
