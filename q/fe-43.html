How do you optimize image delivery using modern formats (AVIF, WebP), responsive `srcset`, and lazy loading?

Frontend engineer · Gear 2 (Mid-level) · Performance · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Deliver the smallest correctly sized image the browser can display: use AVIF or WebP with a fallback through picture, provide srcset and sizes so devices choose the right width, set width and height to prevent layout shift, lazy-load below-the-fold images, and prioritise the LCP image.

Explained in depth

Modern formats

FormatTypical saving vs JPEGNotes
WebP25 to 35%wide support, lossy and lossless, animation
AVIF40 to 50%best compression, slower to encode, wide modern support
JPEG XLvariablelimited browser support

Serve the best format the browser supports using <picture>:

<picture>
  <source type="image/avif" srcset="hero-480.avif 480w, hero-960.avif 960w, hero-1600.avif 1600w" sizes="(min-width: 900px) 50vw, 100vw">
  <source type="image/webp" srcset="hero-480.webp 480w, hero-960.webp 960w, hero-1600.webp 1600w" sizes="(min-width: 900px) 50vw, 100vw">
  <img src="hero-960.jpg" srcset="hero-480.jpg 480w, hero-960.jpg 960w, hero-1600.jpg 1600w"
       sizes="(min-width: 900px) 50vw, 100vw" width="960" height="540" alt="Team at work" fetchpriority="high">
</picture>

Responsive sizing

  • srcset with width descriptors (480w) lists candidate files; sizes tells the browser how wide the image will be in the layout, so it can choose before CSS loads. The browser multiplies by device pixel ratio and picks the smallest sufficient file.
  • Use srcset with 1x, 2x descriptors for fixed-size images (logos, avatars).
  • Use <picture> with media for art direction (different crops).

Loading behaviour

  • loading="lazy" defers off-screen images and iframes. Do not lazy-load the LCP image or anything above the fold.
  • decoding="async" avoids blocking the main thread.
  • fetchpriority="high" on the LCP image, with a <link rel="preload" as="image" imagesrcset=... imagesizes=...> if it is discovered late (CSS background).
  • Always set width and height (or CSS aspect-ratio) so the browser reserves space and CLS stays near zero.

Delivery

  • Use an image CDN or optimiser (Cloudflare, Cloudinary, imgix, Next.js <Image>, Astro assets) to resize and convert on demand, and negotiate format with the Accept header.
  • Set long immutable cache headers on hashed filenames.
  • Compress thoughtfully: quality 60 to 80 for photos, SVG for icons (minified with SVGO), CSS or inline SVG for simple shapes, and strip metadata.

Pitfalls

Serving a 4000 px photo into a 300 px slot, lazy-loading the hero (hurts LCP), missing sizes (the browser assumes 100vw and overfetches), upscaled blurry assets, and CSS background images that the preload scanner cannot discover.
