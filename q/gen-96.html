Explain the Fenwick Tree (Binary Indexed Tree) for computing dynamic prefix sums in $O(\log N)$ time.

Software engineer (core) · Gear 3 (Senior) · Data structures · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

A Fenwick tree (binary indexed tree) stores partial sums in a flat array where index i covers a block of length equal to its lowest set bit. Prefix sums and point updates both walk O(log N) indices by adding or subtracting i & -i, using one array and very little code.

Explained in depth

Idea

Use a 1-indexed array bit[1..n]. Position i stores the sum of the lowbit(i) elements ending at i, where lowbit(i) = i & -i.

index i : 1  2  3  4  5  6  7  8
lowbit  : 1  2  1  4  1  2  1  8
bit[i] covers: [1] [1..2] [3] [1..4] [5] [5..6] [7] [1..8]

Operations

class Fenwick:
    def __init__(self, n): self.n = n; self.t = [0] * (n + 1)
    def add(self, i, delta):            # point update: a[i] += delta
        while i <= self.n:
            self.t[i] += delta
            i += i & -i                 # jump to the next block that includes i
    def prefix(self, i):                # sum of a[1..i]
        s = 0
        while i > 0:
            s += self.t[i]
            i -= i & -i                 # drop the lowest set bit
        return s
    def range_sum(self, l, r):          # a[l..r]
        return self.prefix(r) - self.prefix(l - 1)

Both loops run at most log2(n) iterations because each step changes the lowest set bit. Memory is n + 1 numbers, and constants are tiny compared to a segment tree.

Building in O(n)

Instead of n updates, copy the array in and for each i add t[i] into its parent i + (i & -i).

Useful variations

  • Range update, point query: store differences, so add(l, v) and add(r + 1, -v); the value at i is prefix(i).
  • Range update, range query: two Fenwick trees (B1, B2) using the identity for prefix sums of a difference array.
  • Order statistics: a Fenwick tree over counts finds the k-th smallest by binary lifting on the tree in O(log n); counting inversions uses it with coordinate compression.
  • 2D Fenwick for submatrix sums with point updates.

Limits

It requires an invertible operation for range queries (sum, XOR). Min and max are not invertible, so use a segment tree. Prefix-only monotone updates can still work for prefix max, with update that only increases values.

Comparison with a segment tree

Simpler, faster and half the memory for sum-like problems, but less flexible (no lazy propagation of arbitrary operations).

Pitfalls

Using 0-based indexes (i & -i is 0 at i = 0, causing an infinite loop), forgetting l - 1 for range sums, integer overflow in sums, and mixing difference-array versions without the second tree.

  • How would you find the k-th smallest element or the lower bound with a Fenwick tree?
