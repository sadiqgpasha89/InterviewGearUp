Compare Kubernetes Liveness, Readiness, and Startup probes and the impact of incorrect probe configurations.

DevOps / SRE / Cloud · Gear 2 (Mid-level) · Kubernetes · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A liveness probe tells Kubernetes when to restart a stuck container, a readiness probe decides whether a pod receives traffic, and a startup probe holds off the other two while a slow application boots. Wrong settings cause restart loops, traffic sent to pods that are not ready, or cascading failures.

Explained in depth

ProbeQuestionOn failure
LivenessIs the process stuck beyond recovery (deadlock)?Container is restarted
ReadinessCan it serve requests right now?Pod is removed from Service endpoints, not restarted
StartupHas the application finished starting?Delays liveness and readiness until it passes; restarts if it never does
readinessProbe:
  httpGet: { path: /ready, port: 8080 }
  periodSeconds: 5
  failureThreshold: 3
livenessProbe:
  httpGet: { path: /healthz, port: 8080 }
  periodSeconds: 10
  timeoutSeconds: 2
startupProbe:
  httpGet: { path: /healthz, port: 8080 }
  periodSeconds: 5
  failureThreshold: 30        # up to 150 s to start

Common mistakes

  • Liveness checks that depend on other services. If the database is down, every pod fails liveness and restarts together, turning an outage into a bigger one. Keep liveness to the process's own health; put dependency checks in readiness, carefully.
  • Timeouts too tight or no startup probe: a slow-starting app is killed before it is ready and loops in CrashLoopBackOff. Use a startup probe rather than a large initialDelaySeconds.
  • No readiness probe: traffic reaches pods before they can serve, causing errors during deploys.
  • Probes that are expensive, or that share a thread pool with real traffic, so that load makes them fail.

Probe types are HTTP, TCP, exec and gRPC. Make the readiness check fail during graceful shutdown so the pod drains traffic before it stops.

Likely follow-ups

  • Why can a liveness probe that checks the database cause a cascading outage?
  • When would you add a startup probe instead of increasing initialDelaySeconds?
  • How do readiness probes help during a rolling update?
