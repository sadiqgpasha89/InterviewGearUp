Define Big-O, Big-Omega, and Big-Theta asymptotic notations with mathematical bounds.

Software engineer (core) · Gear 1 (Junior) · Complexity · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Big-O gives an upper bound on growth, Big-Omega a lower bound and Big-Theta a tight bound where both hold. Formally f(n) = O(g(n)) if f(n) is at most c times g(n) for all n beyond some n0. They describe growth rates, not best or worst cases, although people often use Big-O for the worst case.

Explained in depth

Definitions

  • O(g(n)): there exist constants c > 0 and n0 such that f(n) <= c * g(n) for all n >= n0. It is an upper bound.
  • Omega(g(n)): f(n) >= c * g(n) for all n >= n0. It is a lower bound.
  • Theta(g(n)): f(n) is both O(g(n)) and Omega(g(n)). It is a tight bound.

Example

For f(n) = 3n^2 + 5n + 7: it is Theta(n^2), because with c = 4 and n0 = 8 we have f(n) <= 4n^2, and f(n) >= 3n^2 always. It is also technically O(n^3), which is true but not tight.

Clearing up common confusion

  • These notations bound a function. Which function (best, average or worst case running time) is a separate choice. Quicksort's worst case is Theta(n^2) and its average case is Theta(n log n).
  • Saying "the algorithm is O(n)" only promises it grows no faster than linear; it might be much faster. Use Theta when you mean exactly.
  • Constants and lower-order terms are dropped because they stop mattering as n grows, but they still matter in practice for small inputs.

Common growth order

O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(2^n) < O(n!).
