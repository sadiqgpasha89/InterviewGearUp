How does Speculative Decoding accelerate LLM token generation using a small draft model and verification?

ML / AI engineer · Gear 3 (Senior) · LLMs · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Speculative decoding speeds up generation without changing the output distribution. A small draft model quickly proposes several tokens, then the large target model verifies all of them in one parallel forward pass, accepting the longest valid prefix by a rejection-sampling rule and sampling one correction token. Because decoding is memory-bound, verifying k tokens costs about the same as generating one.

Explained in depth

The bottleneck

Autoregressive decoding generates one token per forward pass of the large model. For each token the GPU must read all model weights from memory (hundreds of GB/s needed) while doing relatively little compute: decoding is memory-bandwidth-bound, leaving compute units idle. Generating 500 tokens needs 500 sequential passes.

Idea

Use spare compute: a cheap draft model M_q (for example a 1B model, or a smaller variant) proposes γ tokens autoregressively; the expensive target model M_p scores all γ proposals in a single parallel forward pass (like processing a prompt), which costs only slightly more than one decoding step. Then accept or reject the proposals.

Algorithm (Leviathan et al.; Chen et al., 2023)

  1. Draft model generates x_1..x_γ with probabilities q(x_i | prefix).
  2. Target model computes p(· | prefix, x_1..x_{i-1}) for all positions in one pass.
  3. For i = 1..γ: accept x_i with probability min(1, p(x_i) / q(x_i)). If rejected, resample a replacement token from the residual distribution norm(max(0, p − q)) and stop; discard later drafts.
  4. If all γ are accepted, sample one bonus token from the target's distribution at the next position.

Each iteration yields at least one token (the correction or bonus) and up to γ + 1 tokens. Correctness: this rejection-sampling scheme guarantees that the emitted tokens follow exactly the target model's distribution (lossless), for any sampling temperature (greedy: accept when the target's argmax equals the draft token).

# conceptual loop
while len(out) < max_new:
    draft = draft_model.generate(prefix, n=gamma, return_probs=True)
    p = target_model.forward(prefix + draft.tokens)            # one pass gives distributions for all positions
    n_acc = 0
    for i, (tok, q) in enumerate(zip(draft.tokens, draft.probs)):
        if random() < min(1, p[i][tok] / q[tok]): n_acc += 1
        else: break
    out += draft.tokens[:n_acc]
    out.append(sample(p[n_acc]) if n_acc == gamma else sample(residual(p[n_acc], q_at(n_acc))))

Speedup

Let α be the average acceptance rate and γ the draft length: expected tokens per target pass = (1 − α^(γ+1)) / (1 − α). With α = 0.8 and γ = 5, about 3.7 tokens per target step. Overall speedup also depends on the draft cost ratio c = cost(draft)/cost(target); typical real-world gains are 2x to 3x with no quality loss, higher for predictable text (code, structured output, translation) and lower at high temperatures or with mismatched drafts. Acceptance rises when the draft is well aligned with the target (same family and tokenizer, distilled from the target).

Variants

  • Separate small model: needs same vocabulary and tokenizer; extra memory and a second model to serve.
  • Self-speculation / extra heads: Medusa adds multiple decoding heads to the target that predict future tokens, verified using tree attention; EAGLE/EAGLE-2/3 predicts features autoregressively with a lightweight head for higher acceptance; Lookahead decoding (Jacobi iteration).
  • Prompt lookup / n-gram speculation: copy likely continuations from the prompt (useful for summarisation, editing, RAG), no model needed.
  • Tree-based speculation (SpecInfer, Sequoia) verifies multiple candidate branches at once.
  • Layer-skip and early-exit self-speculation (draft = shallow layers of the same model).
  • Supported in vLLM, TensorRT-LLM, TGI, llama.cpp, SGLang, Hugging Face (assisted_generation).

When it helps and limits

Helps latency-sensitive, small-batch serving where the GPU is underutilised. At large batch sizes, decoding becomes compute-bound and speculation gives less benefit (and wasted verification compute can hurt throughput). Costs: extra memory for the draft model or heads and KV cache, implementation complexity, tuning γ dynamically, and batching mixed acceptance lengths.

Pitfalls

Using a draft with a different tokenizer, mismatched domain (low acceptance), choosing γ too large (wasted verification), evaluating speedups only at batch size 1, and assuming speculative sampling changes output quality (it does not, when implemented correctly).
