In UAT, business users complain the agent gives slightly different answers to the same policy question. How do you handle it?

ML / AI engineer · Gear 2 (Mid-level) · Agents · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Separate wording from substance. Agree with users that phrasing can vary but the coverage decision, cited clause and numbers must not, and test against a golden set on those facts. Technically, lower temperature on decision steps, produce schema-validated structured output (status, clause, deductible), compute numbers in code, and render customer text from a template or check it against that result.

Explained in depth

With stakeholders

  • Explain that language models sample text, so wording varies even with identical inputs, and that setting temperature to zero reduces but does not guarantee identical output.
  • Agree what must be consistent: coverage status, the policy clause cited, amounts, required disclosures. Make those the UAT acceptance criteria, measured on a golden set, rather than word-for-word matching.
  • Show the evidence: run each golden question several times and report consistency on those fields.

Technical fixes

  • Decoding: temperature 0 to 0.2 for decision and extraction steps.
  • Structured output: the model returns validated JSON, for example:
{ "coverage_status": "COVERED", "policy_clause": "4.1.A", "deductible": 500, "explanation": "..." }
  • Deterministic sources: deductibles and limits come from the policy system or rules engine, never from generated text.
  • Templates: regulated wording and disclosures come from fixed templates filled with the structured fields; free text is limited to the explanation, and a check confirms it does not contradict the fields.
  • Grounding: retrieve the exact clause and require it to be cited, so different runs anchor on the same source.
  • Pin versions: fix the model version and prompt version so behaviour does not change between test and production.

Keep checking

  • Add the reported questions to the regression suite and track a consistency metric on every release.

Likely follow-ups

  • Why does temperature 0 not guarantee identical outputs?
  • Which fields would you require to be identical across runs?
  • How do you check that free-text explanations do not contradict the structured result?
