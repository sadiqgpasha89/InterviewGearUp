How does LightGBM use histogram-based algorithms and Exclusive Feature Bundling for speed?

ML / AI engineer · Gear 3 (Senior) · Tree Models · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

LightGBM speeds up gradient boosting by bucketing feature values into histograms so split search scans a few hundred bins instead of sorting all values, and by growing trees leaf-wise. Gradient-based one-side sampling keeps the large-gradient rows, and exclusive feature bundling merges sparse features that are rarely non-zero together.

Explained in depth

Histogram-based splits

Each continuous feature is bucketed into at most max_bin bins (255 by default). Split finding scans bin statistics (sum of gradients and hessians) instead of sorting raw values, so it costs O(bins) per feature rather than O(rows). Bins use little memory, and the histogram subtraction trick gets a sibling's histogram as parent minus the other child, so only the smaller child needs computing.

Leaf-wise growth

Most libraries grow trees level by level. LightGBM repeatedly splits the leaf with the largest loss reduction, regardless of depth. It reaches a lower loss with the same number of leaves but can build deep, lopsided trees that overfit small datasets. Control it with num_leaves, max_depth and min_data_in_leaf.

GOSS (gradient-based one-side sampling)

Rows with large gradients are under-trained and informative. GOSS keeps all of the top fraction by gradient size, randomly samples from the rest and up-weights that sample to keep the gradient estimate approximately unbiased. This uses far fewer rows per iteration.

EFB (exclusive feature bundling)

In high-dimensional sparse data, many features are almost never non-zero at the same time (such as one-hot columns). EFB bundles these mutually exclusive features into one by offsetting their bin ranges, so histograms are built for far fewer features. Finding the best bundling is NP-hard, so a greedy graph-colouring approach is used, allowing a small conflict rate.

Other points

Native handling of categorical features, and parallel training modes (feature, data and voting parallel). XGBoost and CatBoost have since added histogram-based modes, so the gap is smaller than it was at first.
