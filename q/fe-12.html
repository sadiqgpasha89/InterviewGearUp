What is the Shadow DOM and how does it provide style and DOM encapsulation?

Frontend engineer · Gear 2 (Mid-level) · DOM · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Shadow DOM attaches a separate, isolated DOM tree to an element. Its internal markup is hidden from the main document's selectors and queries, and its styles do not leak out or in, apart from inherited properties and CSS custom properties. It is the encapsulation mechanism behind Web Components such as custom elements.

Explained in depth

Creating one

class UserCard extends HTMLElement {
  constructor() {
    super();
    const root = this.attachShadow({ mode: 'open' });
    root.innerHTML = `
      <style>p { color: teal; }</style>   <!-- scoped to this shadow tree -->
      <p><slot></slot></p>`;
  }
}
customElements.define('user-card', UserCard);

What is encapsulated

  • DOM: document.querySelector('p') does not see the component's inner <p>. Events cross the boundary but are retargeted so the outside sees the host element.
  • Styles: page CSS does not apply inside, and the component's CSS does not affect the page.

How it still connects to the page

  • Slots let the user project their own children into marked places (<slot name="title">).
  • Inheritable properties (color, font) and CSS custom properties pass through, so --brand-color can theme a component.
  • ::part() lets a component expose named elements for outside styling, and :host styles the host element from inside.

Modes

open allows element.shadowRoot access; closed hides it (but is not a security boundary).

Benefits and costs

Strong isolation avoids global CSS collisions. Costs: global styles and some form or accessibility behaviours need extra work, and server-side rendering needs declarative shadow DOM.
