Explain RAG evaluation metrics using the RAGAS framework: Faithfulness, Answer Relevance, and Context Precision.

ML / AI engineer · Gear 3 (Senior) · RAG · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

RAGAS evaluates RAG pipelines with LLM-judged, mostly reference-free metrics. Faithfulness checks that answer claims are supported by the retrieved context, answer relevance that the answer addresses the question, and context precision that relevant chunks rank high. Context recall and correctness use ground truth. Together they separate retrieval from generation failures.

Explained in depth

Why RAG needs component-level metrics

A wrong answer can come from bad retrieval (missing or noisy context) or bad generation (ignoring context, hallucinating). End-to-end accuracy alone cannot tell which. RAGAS (Retrieval Augmented Generation Assessment) provides metrics for each stage using an LLM as judge and embeddings, with minimal human labelling.

Core metrics

  1. Faithfulness (groundedness): are the claims in the answer supported by the retrieved context?
  • The judge LLM decomposes the answer into atomic statements, then checks each against the context (supported or not).
  • faithfulness = supported statements / total statements (0 to 1).
  • Detects hallucination: statements not inferable from the retrieved context, even if true in the world.
  1. Answer relevance (response relevancy): does the answer address the question, without redundancy or evasion?
  • The LLM generates several questions that the answer could be answering; compute the cosine similarity between each generated question embedding and the original question embedding; average.
  • High if the answer is on topic and complete; penalises noncommittal ("I don't know") or off-topic content. It does not check correctness.
  1. Context precision: are the relevant chunks ranked near the top of the retrieved list? Using the question (and reference answer or the final answer), a judge labels each retrieved chunk as relevant or not; the metric is a precision@k averaged over ranks, so relevant chunks at rank 1 score higher than at rank 5. Measures retrieval ranking and noise.
  2. Context recall: what fraction of the information needed (from the ground-truth answer) is present in the retrieved context? Each ground-truth sentence is attributed to the context or not. Measures whether retrieval found everything needed.
  3. Others: context entity recall, answer correctness (semantic and factual similarity to the reference), answer similarity, noise sensitivity, aspect critiques, and agent or tool-call metrics.
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy, context_precision, context_recall
from datasets import Dataset
ds = Dataset.from_dict({"question": qs, "answer": answers, "contexts": ctxs, "ground_truth": refs})
result = evaluate(ds, metrics=[faithfulness, answer_relevancy, context_precision, context_recall])
print(result)

Using RAGAS in practice

  • Build a golden dataset of 100 to 500 representative questions with reference answers and supporting passages (from domain experts or synthetic generation by an LLM, then reviewed). RAGAS can synthesise test sets from documents.
  • Run evals on every pipeline change (chunking, embedding model, prompt, retriever settings) and in CI, tracking trends and regressions; sample production traces for ongoing monitoring (with feedback signals).
  • Use a strong, fixed judge model and pin versions for reproducibility.

Limitations

LLM judges are noisy, biased (prefer verbose answers, own-model outputs, position), cost tokens, and can disagree with humans. Metrics are only as good as the reference data. Faithfulness cannot verify truth, only support by context. Calibrate against human labels on a sample, report confidence intervals, and combine with human review, user feedback, task success metrics, latency and cost. Alternatives and complements: TruLens, DeepEval, ARES, LangSmith, Phoenix, OpenAI evals.

Pitfalls

Treating scores as absolute truth, changing judge models between runs, evaluating without ground truth for recall, ignoring safety and refusal behaviour, and optimising metrics while user satisfaction falls.
