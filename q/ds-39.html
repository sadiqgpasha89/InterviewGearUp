How would you design an anomaly detection system for metrics or transactions, and how do you evaluate it without many labels?

Data scientist · Gear 3 (Senior) · Anomaly detection · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Define what an anomaly means for the business, start with statistical baselines that handle seasonality such as robust z-scores on residuals, add unsupervised models like isolation forest or autoencoders for multivariate data, combine with rules and a supervised model when labels exist, and tune thresholds to analyst capacity using precision at k and feedback loops.

Explained in depth

Clarify the problem

  • What is an anomaly? Point (one weird value), contextual (a normal value at the wrong time: 3 am traffic spike), or collective (a pattern of values). Is it a business metric monitoring problem (revenue drop), fraud or abuse (transactions, accounts), operational (latency, sensors), or data quality?
  • Cost of misses versus false alarms, latency requirements (real time versus daily), and analyst capacity (50 alerts a day is the budget).

Methods

ScenarioApproach
Univariate metrics with seasonalityforecast the expected value (STL, Prophet, seasonal ETS, gradient boosting with calendar features) and flag when the residual exceeds a threshold using a robust z-score (median and MAD) or prediction intervals
Simple distributionspercentile, IQR rule, Grubbs, CUSUM or EWMA control charts for shifts
Multivariate tabularIsolation Forest (isolates anomalies with fewer random splits), Local Outlier Factor, one-class SVM, Mahalanobis distance, Gaussian mixtures
High-dimensional or sequentialautoencoders (large reconstruction error), variational autoencoders, LSTM or transformer forecasters, matrix profile for time-series discords
Graph and entity relationshipsgraph features, community detection (fraud rings)
With some labelssupervised classifier (gradient boosting) plus an unsupervised score as a feature; semi-supervised (train on normal only); active learning
Business rulesvelocity checks, blacklists, limits; combine with models
from sklearn.ensemble import IsolationForest
import numpy as np
iso = IsolationForest(n_estimators=300, contamination="auto", random_state=0).fit(X_train)
score = -iso.score_samples(X_new)                  # higher = more anomalous
alerts = score > np.quantile(-iso.score_samples(X_train), 0.995)

Metric monitoring example: residual = actual - forecast; z = (residual - median) / (1.4826 x MAD); alert if |z| > 4 for 2 consecutive intervals.

Handling real-world messiness

  • Seasonality and trend: model them or compare to the same hour last week; otherwise daily cycles trigger alarms.
  • Drift (growth, new product): retrain or use adaptive baselines; distinguish a level shift (genuine change) from an anomaly.
  • Contamination: training data contain anomalies; use robust statistics and iterative cleaning.
  • Data pipeline failures look like anomalies; separate data-quality checks (freshness, volume, nulls) from business alerts.
  • Many metrics and dimensions (country x device): hierarchical alerting, multiple-testing control, and root-cause drill-down (which segment explains the drop).

Evaluation without many labels

  • Build a small labelled set from past incidents, injected synthetic anomalies, and analyst reviews; report precision at k, recall of known incidents, time-to-detect, and alert volume.
  • Use back-testing: replay historical data and see whether known incidents would have been caught and how many false alarms there would be.
  • Track analyst feedback (true positive, benign, duplicate) and feed it into thresholds, suppression rules and supervised models.
  • ROC AUC is misleading with extreme imbalance; prefer PR metrics and operational metrics (alerts per day, % actionable).

Operations

Tiered severity, alert grouping and deduplication, cool-down windows, explanations (which features or segments contributed), dashboards, runbooks, and periodic review of thresholds. For fraud, balance friction on genuine customers against losses, and expect adversaries to adapt.

Pitfalls

Using one global threshold, ignoring seasonality, evaluating with accuracy, and shipping a detector nobody has capacity to triage.
