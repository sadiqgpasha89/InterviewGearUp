Overview of SOC 2 Type II, ISO 27001, and PCI-DSS compliance frameworks for enterprise software.

Security engineer · Gear 3 (Senior) · Compliance · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

SOC 2 Type II is an auditor's attestation that controls against the AICPA Trust Services Criteria operated effectively over a period. ISO 27001 certifies an information security management system with a risk-based Annex A control set. PCI-DSS is a prescriptive standard for protecting payment card data. They overlap heavily, so a unified control framework avoids repeating work.

Explained in depth

Why they matter

Enterprise customers, partners and regulators ask for proof that a vendor protects data. Frameworks provide a common language, structure for security programs and independent assurance. Compliance is not the same as security, but a well-run programme improves both.

SOC 2 (System and Organization Controls 2)

  • Issuer and nature: AICPA standard; an attestation report issued by an independent CPA firm. Not a certification; no pass or fail but an opinion with possible exceptions.
  • Trust Services Criteria (TSC): Security (common criteria, mandatory), plus optional Availability, Processing Integrity, Confidentiality, Privacy.
  • Type I: design of controls at a point in time. Type II: design and operating effectiveness over a period (typically 3, 6 or 12 months), with evidence samples (access reviews, change tickets, incident handling). Type II is what customers demand.
  • Scope: the system boundary you define (product, infrastructure, people, procedures, data) and complementary subservice organisations (AWS, GCP) treated carve-out or inclusive.
  • Typical controls: access management and MFA, onboarding and offboarding, change management with peer review, vulnerability scanning and patching, logging and monitoring, incident response, risk assessment, vendor management, encryption, backups and DR tests, security training, policies, background checks.
  • Output: report with management's assertion, auditor opinion, system description, control matrix, test results and exceptions; shared under NDA.
  • Cadence: annual renewal, continuous evidence collection (Vanta, Drata, Secureframe, Sprinto automate).

ISO/IEC 27001

  • A certifiable international standard for an Information Security Management System (ISMS): management commitment, scope, risk assessment and treatment, Statement of Applicability (SoA), internal audits, management review, continual improvement (PDCA).
  • Annex A (2022 version, 93 controls in four themes): Organisational, People, Physical, Technological (e.g., access control, cryptography, secure development, supplier relationships, logging, threat intelligence, cloud services security, data masking).
  • Certification process: Stage 1 (documentation review) and Stage 2 (implementation audit) by an accredited certification body, certificate valid 3 years with annual surveillance audits and recertification.
  • Companion standards: 27002 (control guidance), 27017 (cloud), 27018 (PII in cloud), 27701 (privacy information management).
  • Strength: risk-driven and holistic management system, globally recognised, especially in Europe and Asia.

PCI-DSS (Payment Card Industry Data Security Standard)

  • Prescriptive standard by PCI SSC for any entity that stores, processes or transmits cardholder data (CHD) or affects its security. Current version 4.0.1 (future-dated requirements became mandatory in March 2025).
  • 12 requirements in six goals: secure network (firewalls, secure configuration), protect account data (minimise storage, never store CVV/PIN after authorisation, encrypt PAN, mask display), vulnerability management (anti-malware, secure SDLC, patching, WAF or code reviews for public web apps), strong access control (least privilege, MFA for all access to the CDE in v4), monitor and test (logging, daily log review, quarterly vulnerability scans by ASV, annual penetration tests, file integrity monitoring), and information security policy.
  • Levels by transaction volume; validation via Report on Compliance (ROC) by a QSA or Self-Assessment Questionnaires (SAQ A, A-EP, D), and Attestation of Compliance (AOC).
  • Scope reduction is the main lever: outsource card handling (hosted fields, redirects, iFrames from PSPs like Stripe or Adyen qualify for SAQ A), tokenisation, point-to-point encryption (P2PE), network segmentation of the Cardholder Data Environment (CDE), and not storing PAN at all.

Doing it efficiently

  1. Decide scope and drivers (customer asks, payment handling, geography).
  2. Build a common control framework (CCF): one set of controls mapped to all frameworks (using GRC platforms or tools like Unified Compliance, SCF).
  3. Automate evidence (cloud config, identity, ticketing, HR, code review) with compliance platforms; keep policies concise and operational.
  4. Run gap assessment, remediate, perform internal audit and management review, then engage auditor.
  5. Maintain continuously: access reviews, risk register, vendor assessments, incident exercises, backup restores, awareness training, change logs.
  6. Include third parties: obtain subprocessors' reports (AWS SOC 2, ISO and PCI AOC) and map responsibilities (shared responsibility matrix).

Pitfalls

Treating compliance as an annual scramble, scope creep or scope too narrow, policies that do not match practice, over-reliance on tooling without ownership, paper controls with no operating evidence, and assuming certification equals being secure.
