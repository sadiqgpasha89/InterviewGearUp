How do you detect and treat outliers, and when should you keep them?

Data scientist · Gear 1 (Junior) · Data preparation · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Detect outliers with plots, z-scores, the IQR rule, robust statistics and model-based methods, then investigate each cause. Remove data errors, cap or transform genuine extremes if they distort the model, use robust methods, and keep true rare events when they carry the signal such as fraud or equipment failure.

Explained in depth

First, ask what the outlier is

An outlier is an observation far from the bulk of the data. Before treating it, determine its origin:

  1. Data error: entry typo (age 250), unit mix-up, sensor glitch, default or sentinel value (-999), duplicate or join bug. Fix or remove.
  2. Genuine rare value: a whale customer, a viral day, a legitimate large transaction. It is real information about the process.
  3. Different population: test accounts, bots, employees, another region. Segment or exclude according to the analysis scope.
  4. Signal of interest: fraud, defects, intrusions, failures.

Detection methods

MethodHowNotes
Visualbox plots, histograms, scatter plots, time-series plotsalways start here
Z-scoreabsolute (x - mean) / std > 3assumes roughly normal data; the outlier inflates the mean and std (masking)
Modified z-score0.6745 (x - median) / MAD > 3.5based on median absolute deviation; robust
IQR rule (Tukey fences)below Q1 - 1.5 IQR or above Q3 + 1.5 IQRsimple, non-parametric; use 3 IQR for "far out" values
Percentile capsbelow 1st or above 99th percentileeasy, but forces a fixed fraction of "outliers"
MultivariateMahalanobis distance, Cook's distance and leverage in regressionunusual combinations can be outliers even if each value is normal
Model-basedisolation forest, local outlier factor, DBSCAN noise points, autoencoder reconstruction errorfor high dimensions and anomaly detection
Residual analysislarge standardised residuals after a fitshows points the model cannot explain
import numpy as np, pandas as pd
q1, q3 = df.x.quantile([.25, .75]); iqr = q3 - q1
mask = (df.x < q1 - 1.5*iqr) | (df.x > q3 + 1.5*iqr)
from sklearn.ensemble import IsolationForest
df["iso"] = IsolationForest(contamination="auto", random_state=0).fit_predict(df[["x", "y"]])

Treatment options

  • Correct errors using source systems or rules; remove only with justification and documentation (record how many).
  • Winsorise or cap at percentiles (keeps the row, limits influence).
  • Transform skewed variables (log, square root, Box-Cox) to reduce the pull of extremes.
  • Use robust methods: median, MAD, Huber or quantile regression, tree models (insensitive to extremes in features), rank-based tests.
  • Model separately: segment whales versus regular users.
  • Keep them when they are the target, or when removing them would misrepresent the business (total revenue is dominated by them).
  • Run a sensitivity analysis: report results with and without outliers.

Cautions

Do not remove points just because they hurt the fit; this is data dredging. Fit any caps or thresholds on training data only. In production, decide how the model handles extreme inputs (clipping, fallbacks, alerts) and monitor them.

Pitfalls

Applying the IQR rule to every column blindly, deleting rare but valid events, and forgetting that the same outlier handling must run at inference time.

Likely follow-ups

  • Why is the z-score rule unreliable on skewed data and what is a better alternative?
  • How would you treat extreme but valid values in revenue per customer?
  • When is an outlier the thing you are trying to predict?
