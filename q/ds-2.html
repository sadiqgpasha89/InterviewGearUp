What is overfitting and how do you detect it using training and validation performance?

Data scientist · Gear 1 (Junior) · ML fundamentals · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Overfitting means a model memorises noise and quirks in the training data, so it scores well on training data but poorly on unseen data. Detect it by a large gap between training and validation metrics, learning curves where validation error rises or plateaus while training error keeps falling, and unstable cross-validation scores.

Explained in depth

The idea

A model should learn signal that generalises, not noise specific to the sample. A model with too much capacity relative to the data (deep trees, many features, high-degree polynomials, huge networks) can fit the training set almost perfectly while failing on new data. The opposite is underfitting: both training and validation performance are poor because the model is too simple or poorly specified.

How to detect it

  1. Compare metrics: hold out a validation set (or use cross-validation) and compare. For example training accuracy 99 percent versus validation 78 percent signals overfitting. The metric should match the task (RMSE, AUC, F1).
  2. Learning curves: plot training and validation score against training-set size.
  • Large gap that does not close: high variance (overfitting); more data or regularisation helps.
  • Both curves low and close: high bias (underfitting); need a richer model or better features.
  1. Validation curves against a complexity parameter (tree depth, polynomial degree, regularisation strength): validation score peaks and then falls while training score keeps rising.
  2. Epoch curves for iterative models: validation loss begins to rise while training loss still falls (the point for early stopping).
  3. Cross-validation variance: a high spread of fold scores suggests the model depends heavily on the particular sample.
  4. Sanity checks: very high accuracy on a hard problem often means data leakage, not a great model.
from sklearn.model_selection import learning_curve
import numpy as np
sizes, train_s, val_s = learning_curve(model, X, y, cv=5, scoring="roc_auc", train_sizes=np.linspace(.1, 1, 8))
gap = train_s.mean(1) - val_s.mean(1)      # a persistent large gap means variance problem

Remedies

Model typeTechniques
Anymore data, simpler model, fewer or better features (feature selection), cross-validation for model choice, ensembling (bagging)
Linear modelsL2 or L1 regularisation, feature selection, fewer polynomial terms
Decision trees and boostinglimit depth, minimum samples per leaf, pruning, learning rate and number of trees with early stopping, subsampling
Neural networksdropout, weight decay, data augmentation, early stopping, smaller architecture, batch normalisation
KNNlarger k

Subtle cases

  • You can overfit the validation set by tuning hyperparameters against it many times. Keep a final untouched test set, or use nested cross-validation.
  • Time series needs time-ordered splits; random splits leak the future and hide overfitting.
  • Distribution shift in production looks like overfitting but is a data problem; monitor it.

Interview tip

Describe the whole loop: split correctly, compare train and validation, diagnose with learning curves, apply regularisation or more data, confirm on a clean test set once.
