How does the Horizontal Pod Autoscaler (HPA) scale pods based on metrics, and how does KEDA extend it?

DevOps / SRE / Cloud · Gear 3 (Senior) · Kubernetes · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

The Horizontal Pod Autoscaler periodically compares an observed metric (CPU, memory, custom or external) with a target and computes desiredReplicas = ceil(currentReplicas x current / target), within min and max bounds and with stabilisation windows. KEDA extends this by scaling on event sources such as queue depth, and can scale to and from zero.

Explained in depth

How the HPA works

A controller loop (every 15 seconds by default) reads metrics from the metrics API (metrics-server for CPU and memory, adapters for custom metrics) and calculates:

desiredReplicas = ceil( currentReplicas * currentMetric / targetMetric )

Example: 4 pods at 90% CPU with a target of 60% gives ceil(4 * 90 / 60) = 6 replicas.

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: api }
  minReplicas: 2
  maxReplicas: 20
  metrics:
    - type: Resource
      resource: { name: cpu, target: { type: Utilization, averageUtilization: 60 } }
  behavior:
    scaleDown: { stabilizationWindowSeconds: 300 }

Details

  • CPU utilisation is relative to the pod's request, so requests must be set.
  • A stabilisation window (longer for scale-down) and rate policies prevent flapping.
  • New pods need time to become ready; readiness and startup probes matter.
  • HPA cannot scale to zero, and it works with a Deployment or StatefulSet.

KEDA (Kubernetes Event-driven Autoscaling)

Adds scalers for many sources (Kafka lag, SQS or RabbitMQ queue length, Prometheus query, cron). It feeds the HPA with external metrics and can activate from zero replicas when events arrive and scale back to zero when idle, saving cost for bursty workers.

Related autoscalers

The Vertical Pod Autoscaler adjusts requests per pod, and the Cluster Autoscaler (or Karpenter) adds nodes when pods cannot be scheduled. They work together: HPA creates pods, and the node autoscaler provides capacity.
