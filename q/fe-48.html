What is Content Security Policy (CSP) and what directives prevent unauthorized script execution?

Frontend engineer · Gear 3 (Senior) · Security · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Content Security Policy is a response header that tells the browser which sources it may load scripts, styles, frames and connections from. To limit XSS, avoid 'unsafe-inline' and 'unsafe-eval' in script-src, use per-response nonces or hashes (optionally with 'strict-dynamic'), and set object-src 'none' and base-uri restrictions.

Explained in depth

Directives that matter for script execution

  • script-src: where scripts may come from. The strongest form is a nonce (a random value per response, copied onto each legitimate <script nonce=...>) or a hash of an inline script. 'strict-dynamic' lets nonce-trusted scripts load further scripts.
  • default-src: fallback for other fetch directives. Start with 'self' or 'none'.
  • object-src 'none' and base-uri 'none' (or 'self'): close plugin and base-tag tricks.
  • connect-src, img-src, style-src, form-action: limit where data can be sent.
  • frame-ancestors: who may embed the page (clickjacking). It only works as a header, not in a <meta> tag.
Content-Security-Policy: default-src 'self'; script-src 'nonce-r4nd0m' 'strict-dynamic'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'

Rolling it out

Start with Content-Security-Policy-Report-Only and a reporting endpoint, fix violations, then enforce. Inline event handlers and inline scripts must be moved to files or nonced.

Limits

  • CSP is defence in depth, not a replacement for output encoding. If an attacker can inject markup, a weak policy may still be bypassed.
  • Allow-lists of hosts are often bypassable (a trusted CDN or JSONP endpoint can serve attacker-controlled code), which is why nonce or hash policies are recommended.
  • unsafe-inline in script-src removes most XSS protection. Trusted Types (require-trusted-types-for 'script') additionally locks down dangerous DOM sinks such as innerHTML.

Likely follow-ups

  • Why is a nonce-based policy stronger than a host allow-list?
  • How would you deploy CSP on a large site that uses many inline scripts?
  • What does Trusted Types add beyond CSP?
