What is semantic HTML and why does it matter for accessibility and SEO?

Frontend engineer · Gear 1 (Junior) · HTML · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Semantic HTML uses elements that describe meaning, such as header, nav, main, article, button and label, instead of generic divs. It gives browsers, screen readers and search engines the page structure for free, provides keyboard behaviour and roles by default, and makes code easier to maintain. Use ARIA only when no native element fits.

Explained in depth

What it means

Choose the element that matches the purpose of the content:

  • Page regions: <header>, <nav>, <main>, <aside>, <footer>, <section>, <article>.
  • Text: headings <h1> to <h6> in order, <p>, <ul> and <ol> for lists, <table> for tabular data, <time>, <figure> with <figcaption>.
  • Interaction: <button> for actions, <a href> for navigation, <label> linked to <input>, <fieldset> and <legend> for groups.

Benefits

  • Accessibility: assistive technologies read the role, name and state from native elements. A <button> is focusable, activated by Enter and Space, and announced as a button. A <div onclick> has none of this unless you add role, tabindex and key handlers.
  • Navigation: screen reader users jump by landmarks and headings; a logical heading outline is essential.
  • SEO: crawlers understand the structure, main content and headings, and can show rich results.
  • Maintainability and defaults: forms, native validation, built-in styles and browser features such as reader mode work without extra code.

ARIA

ARIA adds semantics when HTML cannot express them (tabs, comboboxes, live regions). The first rule of ARIA is: do not use ARIA if a native element does the job. Incorrect ARIA is worse than none.

Quick checks

Use real buttons and links, add alt text to meaningful images, associate labels with inputs, keep one <h1>, and test by tabbing through the page and with a screen reader.

Likely follow-ups

  • When would you use ARIA attributes?
  • Why is a clickable div a poor substitute for a button?
  • How do headings affect screen reader navigation?
