What are React Server Components (RSC) and how do they differ from traditional Server-Side Rendering?

Frontend engineer · Gear 3 (Senior) · React · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

React Server Components run only on the server and send a serialised result to the client, with no component JavaScript shipped. They can read databases or files directly and keep large dependencies off the bundle. Traditional SSR renders HTML on the server for first load, but still sends and hydrates all component code on the client.

Explained in depth

Traditional SSR

The server renders components to HTML for fast first paint and SEO. The browser then downloads all the component JavaScript and hydrates the page, running every component again on the client. The code size and hydration cost remain.

Server Components

  • Server Components execute only on the server (at request time or build time). Their output is a special serialised tree (the RSC payload) that React merges into the client's tree.
  • Their code and dependencies never reach the browser: a markdown parser or date library used only there adds zero bytes to the bundle.
  • They can be async, and access the database, file system or secrets directly.
// Server Component (default in the Next.js app router)
export default async function Posts() {
  const posts = await db.posts.findMany();
  return posts.map((p) => <PostCard key={p.id} post={p} />);
}

Client Components

Marked with 'use client'. They hold state, effects, event handlers and browser APIs. They are still pre-rendered to HTML on the server, then hydrated.

Rules and boundaries

  • Server components cannot use useState, effects or browser-only APIs; client components cannot import server-only code.
  • Props passed across the boundary must be serialisable (no functions, apart from server actions).
  • A server component can render client components as children, so interactivity is added in small islands.

Relationship

RSC does not replace SSR; frameworks use both: RSC reduces what is sent and hydrated, and SSR gives the first HTML.
