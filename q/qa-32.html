Explain performance testing categories: Load, Stress, Soak, Spike, and Breakpoint testing.

QA / SDET · Gear 2 (Mid-level) · Performance · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Load testing checks behaviour at expected traffic, stress testing pushes beyond capacity to find the breaking point and recovery, soak (endurance) testing runs for hours to expose leaks, spike testing applies a sudden surge, and breakpoint testing steadily raises load until the system fails. Each answers a different question about capacity and resilience.

Explained in depth

Types

  • Load test: expected and peak normal traffic (for example 500 requests per second). Question: does it meet the service level objectives, such as p95 latency under 300 ms?
  • Stress test: load beyond the design limit. Questions: how does it fail (gracefully or with data loss), and does it recover when load drops?
  • Soak (endurance) test: moderate load for a long time (4 to 24 hours). It finds memory leaks, connection leaks, disk growth and degradation over time.
  • Spike test: sudden jump, such as from 100 to 2,000 users in seconds. It checks autoscaling, queues and rate limits.
  • Breakpoint (capacity) test: increase load in steps until a threshold is crossed. It finds the maximum sustainable throughput.
  • Scalability test: measure how performance changes as you add instances.

Planning tips

  • Define goals first (SLOs) and a realistic workload model from production logs: user mix, think time and data volume.
  • Use a production-like environment and data size; a tiny database hides problems.
  • Monitor the system under test (CPU, memory, garbage collection, database, queue depth), not just the client.
  • Ramp up gradually, keep each run reproducible and compare results with a baseline over time.
  • Avoid testing a shared production system without safeguards.

Tools

k6, JMeter, Gatling and Locust generate load; pair them with dashboards (Grafana, APM) for diagnosis.

Likely follow-ups

  • Which metrics would you watch during each test?
  • How do you design a realistic workload model?
  • How is a performance test environment different from production?
