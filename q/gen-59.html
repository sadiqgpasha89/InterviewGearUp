Explain the Knuth-Morris-Pratt (KMP) string matching algorithm and how the Longest Prefix Suffix (LPS) array works.

Software engineer (core) · Gear 3 (Senior) · Algorithms · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

KMP searches for a pattern in a text in O(N+M) by never moving backwards in the text. It precomputes an LPS array, where lps[i] is the length of the longest proper prefix of the pattern that is also a suffix of pattern[0..i]. On a mismatch it uses lps to shift the pattern, reusing the characters already matched.

Explained in depth

LPS array

For the pattern ABABCABAB, lps = [0,0,1,2,0,1,2,3,4]. At index 8 the string ABAB is both a prefix and a suffix, so its length 4 is stored.

def build_lps(p):
    lps = [0] * len(p)
    k = 0                          # length of the current matching prefix
    for i in range(1, len(p)):
        while k and p[i] != p[k]:
            k = lps[k - 1]         # fall back to a shorter border
        if p[i] == p[k]:
            k += 1
        lps[i] = k
    return lps

def kmp_search(text, p):
    lps, k, hits = build_lps(p), 0, []
    for i, ch in enumerate(text):
        while k and ch != p[k]:
            k = lps[k - 1]         # keep what already matched
        if ch == p[k]:
            k += 1
        if k == len(p):
            hits.append(i - k + 1)
            k = lps[k - 1]
    return hits

Why it is linear

The text pointer never goes back. The pattern pointer k increases by at most one per character and each fallback decreases it, so the total number of fallbacks is bounded by the increases: O(N + M) overall, including O(M) to build the table.

Comparison

The naive method is O(N*M) in the worst case. Rabin-Karp is O(N+M) on average using hashes but can degrade on collisions. KMP gives a guaranteed linear bound and needs O(M) extra space.
