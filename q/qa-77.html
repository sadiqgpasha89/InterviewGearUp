How do you automate interaction with dynamic iframes, shadow DOM elements, and multi-window popups?

QA / SDET · Gear 2 (Mid-level) · UI Automation · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Interact with iframes through frame handles or frameLocator, with shadow DOM through piercing selectors or open shadowRoot access, and with popups by waiting for the new page or window handle event. Playwright pierces open shadow roots and offers frameLocator and popup events by default, while Selenium needs explicit switchTo and shadowRoot calls.

Explained in depth

Why they are tricky

  • iframes are separate documents; locators in the main page cannot see inside, and frames can be added, reloaded, or removed dynamically (ads, payment fields, embedded widgets, rich text editors).
  • Shadow DOM encapsulates a component's internals (web components, Salesforce, Ionic, Material Web); normal CSS and XPath selectors do not cross the boundary in some tools.
  • Popups and new windows are different browsing contexts (OAuth, payment confirmation, print preview, target=_blank).

iframes

// Playwright: locators auto-wait and re-resolve, no manual switching
const card = page.frameLocator('iframe[title="Secure card number"]');
await card.locator('input[name="cardnumber"]').fill('4242 4242 4242 4242');
await page.frameLocator('#editor-frame').locator('body').fill('Hello');
// nested
page.frameLocator('#outer').frameLocator('#inner').getByRole('button', { name: 'Pay' }).click();
// wait for a dynamically added frame
const frame = await page.waitForEvent('frameattached');
// Selenium: switch context explicitly, and switch back
wait.until(ExpectedConditions.frameToBeAvailableAndSwitchToIt(By.cssSelector("iframe[title='Secure card number']")));
driver.findElement(By.name("cardnumber")).sendKeys("4242424242424242");
driver.switchTo().defaultContent();                 // always return to the main document

Tips: select frames by stable attributes (title, name, src pattern), not index; wait for frame load; after navigation or re-render the frame element is stale, so re-acquire it; in Cypress, use cy.get('iframe').its('0.contentDocument.body') or the cypress-iframe plugin (cross-origin iframes need cy.origin or Chrome security flags and are limited). Cross-origin iframes (Stripe Elements, reCAPTCHA) cannot be scripted from page JavaScript, but WebDriver and Playwright can drive them through the browser protocol; for third-party widgets prefer test modes or mocking.

Shadow DOM

// Playwright CSS and text locators pierce OPEN shadow roots automatically
await page.locator('my-date-picker input.day-3').click();
await page.getByRole('button', { name: 'Save' }).click();        // role locators also pierce
// Selenium 4: access shadowRoot, then search within it
SearchContext root = driver.findElement(By.cssSelector("my-component")).getShadowRoot();
root.findElement(By.cssSelector("button.primary")).click();
// Cypress: includeShadowDom config or .shadow()
cy.get('my-component').shadow().find('button.primary').click();   // or { includeShadowDom: true } in config

Limits: closed shadow roots are not reachable by design; ask developers for test hooks (data-testid on the host, exposed attributes, a test-only mode with open roots), or interact via the host element and public API. XPath does not pierce shadow roots. Prefer accessible roles and visible text over implementation selectors so tests survive refactors.

Popups and multiple windows

// Playwright: wait for the popup event while clicking
const [popup] = await Promise.all([page.waitForEvent('popup'), page.click('text=Sign in with Google')]);
await popup.waitForLoadState();
await popup.fill('#email', user); await popup.click('#next');
await popup.waitForEvent('close');                          // popup closes after authentication
await expect(page.locator('#profile-name')).toHaveText('Ada');
// Selenium: track handles
String main = driver.getWindowHandle();
driver.findElement(By.id("open")).click();
wait.until(d -> d.getWindowHandles().size() > 1);
for (String h : driver.getWindowHandles()) if (!h.equals(main)) driver.switchTo().window(h);
// ...interact...; driver.close(); driver.switchTo().window(main);

Handle JavaScript dialogs (alert, confirm, prompt, beforeunload) with page.on('dialog') or switchTo().alert(), and OS-level dialogs separately (file chooser events, basic-auth via httpCredentials in the context).

Robustness

Use auto-waiting locators instead of sleeps, assert the popup URL and title, close extra windows in teardown so they do not leak into the next test, prefer API-based authentication for most tests and keep popup flows in dedicated tests, and run on all target browsers because popup blockers and iframe cookie policies (third-party cookie restrictions, SameSite) behave differently.

Pitfalls

Forgetting to switch back to the default content, indexing frames by position, trying to pierce closed shadow roots with scripts, missing the popup event because the listener is registered after the click, and testing third-party widgets live instead of mocking.
