Why do we split data into training, validation and test sets, and how do you do it correctly?

Data scientist · Gear 1 (Junior) · Model evaluation · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Training data fits the model, validation data is used to tune hyperparameters and choose between models, and the test set is touched once at the end to estimate real-world performance. Split in a way that matches deployment: random for iid data, stratified for imbalance, grouped by entity and ordered by time for temporal data, to avoid leakage.

Explained in depth

Purpose of each set

  • Training set: parameters are learned from it.
  • Validation set (or cross-validation folds): used repeatedly to compare models and tune hyperparameters. Every decision made using it leaks a little information, so it becomes optimistic.
  • Test set: a final, untouched estimate of generalisation. Use it once, after all choices are made. If you keep tweaking until the test score improves, it becomes a second validation set.

Typical proportions: 60/20/20 or 70/15/15; with small data use k-fold cross-validation and keep a small final test set.

Splitting correctly

Data typeRight split
iid tabular datarandom split with a fixed seed
Imbalanced classesstratified split so each set has similar class proportions
Multiple rows per customer, patient or devicegroup split (GroupKFold) so one entity never appears in both train and test
Time series or anything where the future must be predictedchronological split and rolling or expanding window validation (TimeSeriesSplit); never shuffle
Spatial datablock or spatial cross-validation to prevent neighbour leakage
Duplicates or near-duplicates (images, text)deduplicate before splitting

Mirror deployment: if the model will score new customers next month, validate on later periods and unseen customers.

Data leakage

Leakage means information unavailable at prediction time influences training or evaluation, producing inflated scores that collapse in production. Common sources:

  • Target leakage: a feature derived from the outcome (a "refund issued" flag when predicting churn, a post-diagnosis lab test).
  • Preprocessing leakage: fitting scalers, imputers, encoders, PCA or feature selection on the whole dataset before splitting.
  • Duplicate or related rows across splits.
  • Temporal leakage: using future information (features aggregated over windows that extend past the prediction date).
  • Hyperparameter tuning on the test set.

Fix with Pipeline objects that fit preprocessing inside each training fold.

from sklearn.model_selection import train_test_split, GroupKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)
model = make_pipeline(StandardScaler(), clf)
scores = cross_val_score(model, X_tr, y_tr, cv=GroupKFold(5), groups=customer_id_tr, scoring="roc_auc")

Cross-validation versus a single split

Single hold-out is fine with large data and expensive models. k-fold (5 or 10) gives a more stable estimate and a measure of variance with limited data. Use nested cross-validation when tuning and estimating performance simultaneously on small datasets.

After deployment

Compare offline estimates with online results; shifts between training and live data (drift) explain gaps. Keep a time-based holdout representing the most recent data.

Pitfalls

Random splits on time-dependent data, scaling before splitting, reusing the test set, and reporting the best fold.
