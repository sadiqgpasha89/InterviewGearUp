Explain the Apache Spark driver, executor, and cluster manager architecture.

Data engineer · Gear 2 (Mid-level) · Spark · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A Spark application has a driver that runs the main program, builds the execution plan, and schedules tasks; executors are processes on worker nodes that run tasks and cache data; and a cluster manager (YARN, Kubernetes, standalone) allocates resources for the driver and executors. Work is split into jobs, stages and tasks.

Explained in depth

Components

  • Driver: runs your main, creates the SparkSession, converts transformations into a DAG, plans and optimises it, and schedules tasks on executors. It also collects results (for actions like collect()), so it needs enough memory.
  • Executors: JVM processes on worker nodes. They run tasks in parallel (one task per core slot), hold cached partitions, and write shuffle files. They live for the application's duration unless dynamic allocation is on.
  • Cluster manager: provides resources. Options are Standalone, YARN, Kubernetes or Mesos (deprecated). It launches executors but does not understand Spark's logic.

Execution hierarchy

  1. An action (count, write) triggers a job.
  2. The job is split into stages at shuffle boundaries (wide dependencies such as groupBy and join).
  3. Each stage has one task per partition, and tasks run on executors.
Driver  --requests resources-->  Cluster manager
Driver  --schedules tasks---->   Executors (on worker nodes)  <--shuffle data-->  Executors

Deploy modes

  • Client mode: the driver runs where you submit (a laptop or edge node), good for interactive work.
  • Cluster mode: the driver runs inside the cluster, better for production jobs, because it survives the submitting machine going away.

Common issues

Driver out-of-memory from collect() or large broadcast variables, executor out-of-memory from skewed partitions, and too few or too many partitions for the cores available.

Likely follow-ups

  • What decides the number of tasks in a stage?
  • What happens if the driver runs out of memory?
  • What is the difference between client and cluster deploy modes?
