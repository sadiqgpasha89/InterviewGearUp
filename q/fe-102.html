What is the difference between var, let and const in JavaScript, and what is hoisting?

Frontend engineer · Gear 1 (Junior) · JavaScript · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

var is function-scoped and hoisted with an initial value of undefined, while let and const are block-scoped and sit in the temporal dead zone until their declaration runs. const prevents reassigning the binding but not mutating an object it points to. Prefer const by default, let when you must reassign, and avoid var.

Explained in depth

Scope

  • var is scoped to the nearest function (or global), ignoring blocks such as if and for.
  • let and const are scoped to the nearest block { ... }.
if (true) { var a = 1; let b = 2; }
console.log(a); // 1
console.log(b); // ReferenceError

Hoisting

Declarations are processed before code runs.

  • var x is hoisted and initialised to undefined, so reading it early gives undefined.
  • let, const and class are hoisted too, but stay uninitialised in the temporal dead zone (TDZ) until the line that declares them, and reading them early throws a ReferenceError.
  • Function declarations are hoisted completely, so you can call them before they appear.

Reassignment

let can be reassigned; const cannot be rebound, but an object or array it refers to can still be changed (const list = []; list.push(1) works). Use Object.freeze for shallow immutability.

Classic loop example

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i));  // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j));  // 0 1 2

let creates a new binding per iteration, so each callback keeps its own value.

Recommendation

Use const by default, let when the value changes, and avoid var. Redeclaring a var in the same scope is allowed (and bug-prone), while redeclaring let or const is a syntax error.
