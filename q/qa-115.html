How do you test features powered by machine learning or LLMs, where outputs are non-deterministic?

QA / SDET · Gear 4 (Lead / Staff) · AI · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Replace exact-match assertions with evaluation: build curated datasets of inputs with expected properties or reference answers, score outputs with metrics, rules and rubric-based judges, test safety, format and groundedness, compare versions statistically against thresholds, red-team adversarial cases, and monitor production. Treat prompts and models as versioned code.

Explained in depth

Why traditional tests fall short

The same input may produce different valid outputs; quality is a matter of degree (a helpful answer), and behaviour changes when the model, prompt, data or retrieval changes. You test distributions and properties, not single outputs.

Test layers

  1. Component tests: deterministic parts around the model: input validation, prompt templates, parsers, retrieval, tool calls, caching, guardrails. Use mocked model responses to test the surrounding logic and error handling (timeouts, malformed output).
  2. Model evaluation with datasets: a golden dataset of representative and edge-case inputs with labels or reference answers, versioned. Compute metrics: accuracy, precision and recall, F1, calibration for classifiers; for generation, rubric scores, semantic similarity, factuality, citation accuracy, or task success.
  3. Property-based and rule checks: output matches a schema; no prohibited content or personal data; length limits; the answer cites sources from provided context; the refusal behaviour for unsafe requests.
  4. LLM-as-judge: a model scores outputs against criteria. Calibrate it against human labels, guard against position and verbosity bias, use clear rubrics, and spot-check.
  5. Human evaluation on samples for subjective quality, with guidelines and agreement tracking.

Specific risks

  • Robustness: paraphrases, typos, languages, long inputs, adversarial and prompt injection inputs.
  • Bias and fairness: compare performance across groups and slices.
  • Safety and security: jailbreaks, data leakage, harmful content; red-team sessions.
  • Non-functional: latency, cost per request, rate limits.

Handling non-determinism

Set temperature to zero where determinism helps, fix seeds when available, run each case several times and assert pass-rate thresholds (for example 95 percent of 20 samples meet the rubric), and compare versions with statistical tests and confidence intervals rather than single runs.

Regression and release process

Treat prompts, retrieval settings, tools and model versions as versioned artifacts: run the evaluation suite in CI, block on regressions in critical categories, and use shadow mode, canaries and A/B tests. Add failures found in production to the dataset.

Production monitoring

Sample and review outputs, collect user feedback, track drift in input and output distributions, refusal and error rates, and quality scores over time, with alerts and a rollback option.
