What are controlled versus uncontrolled components in React forms, and when is each preferred?

Frontend engineer · Gear 1 (Junior) · React · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

A controlled component keeps the form value in React state and updates it through onChange, so React is the single source of truth. An uncontrolled component lets the DOM hold the value and you read it with a ref or on submit. Controlled suits live validation and dependent fields; uncontrolled is simpler and cheaper for basic forms and file inputs.

Explained in depth

Controlled

function Name() {
  const [name, setName] = useState('');
  return <input value={name} onChange={(e) => setName(e.target.value)} />;
}

The input always shows name. Every keystroke triggers a state update and a re-render, which lets you format, validate or block input immediately and keep other UI in sync (for example enabling a submit button).

Uncontrolled

function Name() {
  const ref = useRef(null);
  return (
    <form onSubmit={(e) => { e.preventDefault(); save(ref.current.value); }}>
      <input defaultValue="" ref={ref} />
    </form>
  );
}

The DOM owns the value; React reads it when needed. There are fewer re-renders and less code.

Choosing

NeedPrefer
Live validation, masks, dependent fieldsControlled
Resetting or setting values from codeControlled
Simple form read on submit, very large formsUncontrolled
File inputs (type="file")Uncontrolled (the value is read-only)

Pitfalls

  • Setting value without onChange makes a read-only field.
  • Starting with undefined and later providing a value switches modes and triggers a warning; initialise with an empty string.
  • Libraries such as React Hook Form use uncontrolled inputs with refs to avoid re-rendering the whole form on each keystroke.

Likely follow-ups

  • Why does React warn when an input switches from uncontrolled to controlled?
  • How do form libraries such as React Hook Form reduce re-renders?
  • How do you handle a file input?
