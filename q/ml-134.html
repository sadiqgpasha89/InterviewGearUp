Your claims triage agent loops calling the OCR tool when a customer uploads a blurry repair estimate. How do you debug and fix it?

ML / AI engineer · Gear 3 (Senior) · Agents · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Read the trace: the OCR tool returns low-confidence or empty fields, and the prompt tells the agent to get the repair total, so it keeps retrying. Fix it in the graph, not only the prompt: return explicit status and confidence from the tool, count attempts in state, route to a fallback after N failures (clearer upload, manual entry or a person), set a recursion limit, and alert on the failure rate.

Explained in depth

Diagnose

  • Open the traces for affected runs: the same tool call repeats with near-identical arguments, each result has empty or low-confidence fields, and the model's next step is 'try extracting again'.
  • Root cause: the tool's output does not say clearly that it failed, the instruction makes the total mandatory, and nothing in the graph limits retries.

Fix

  1. Make the tool honest: return { status: 'LOW_QUALITY', confidence: 0.32, fields: {...} } instead of empty JSON, and add an image-quality check (resolution, blur) before OCR.
  2. Track attempts in state: attempts['ocr'] += 1.
  3. Route deterministically: a conditional edge sends the run to a fallback node when attempts >= 2 or confidence < 0.6.
  4. Graceful fallback: ask the customer for a clearer photo or PDF, or to type the total; if that fails, hand the claim to a person with the reason.
  5. Global safety net: a recursion_limit on the run and handling of the resulting error, so no run can spin forever.
  6. Prompt: tell the model that missing data is acceptable and how to report it.

Prevent regressions

  • Add blurry, rotated, cropped and handwritten estimates to the evaluation set.
  • Emit a metric for OCR fallbacks and alert on spikes, which may also reveal a degraded OCR service or a new document format.
  • Monitor steps per run and tool repetition across all tools, not just this one.

Likely follow-ups

  • Why is a recursion limit alone not a good fix?
  • How would you detect loops automatically in production?
  • What should the customer see when extraction fails?
