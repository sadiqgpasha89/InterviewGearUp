How do you architect client-side state in a large application, separating server state from client state?

Frontend engineer · Gear 4 (Lead / Staff) · State management · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Treat server data as a cache owned by the server and manage it with a dedicated library such as TanStack Query or SWR, keep only genuinely client-side state (UI state, form drafts, preferences) in local component state, context or a small store, derive instead of duplicating, put URL state in the router, and avoid one global store for everything.

Explained in depth

Kinds of state

KindExamplesBest home
Server stateUsers, orders, search resultsA server-cache library (TanStack Query, SWR, RTK Query, Apollo)
URL stateFilters, pagination, selected tabRouter and search params, so links and refresh work
Local UI stateOpen modal, hover, input draftuseState or useReducer in the component
Shared client stateTheme, auth session, wizard progressContext, or a small store (Zustand, Redux Toolkit, Jotai)
Form stateField values, validationA form library (React Hook Form)
Derived stateTotals, filtered listsComputed during render or with selectors, not stored

Why separate server state

Server data is asynchronous, shared, and can become stale. A cache library gives deduplicated requests, caching with keys, background refetching, retries, invalidation after mutations, pagination, and loading and error states. Copying server responses into a global store means rebuilding all this by hand and creating two sources of truth.

Practices

  • Co-locate state as close as possible to where it is used; lift it only when needed.
  • Normalise when the same entity appears in many views, or rely on cache keys and invalidation by entity.
  • Optimistic updates: update the cache immediately, send the mutation, and roll back on failure, then refetch to reconcile.
  • Define a clear data access layer (typed API client, query key factory) so components do not scatter fetch calls.
  • Keep stores small and typed, with actions that describe events, and use selectors to limit re-renders.
  • Avoid putting non-serialisable objects or derived data in state.

Governance

Document which tool is used for which kind of state, review new global stores, and measure re-render performance with the profiler.
