How do you verify client-side storage states (LocalStorage, SessionStorage, Cookies) during automated tests?

QA / SDET · Gear 2 (Mid-level) · Browser APIs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Verify client-side storage by reading it in the test and asserting values and attributes: page.evaluate or cy.getAllLocalStorage for localStorage and sessionStorage, context.cookies or getCookies for cookies including HttpOnly, Secure, SameSite and expiry. Also test persistence across reloads and tabs, clearing on logout, and that no sensitive data is stored in plain text.

Reading and asserting in tests

// Playwright
const ls = await page.evaluate(() => JSON.stringify(window.localStorage));
expect(JSON.parse(ls)).toMatchObject({ theme: 'dark' });
const token = await page.evaluate(() => sessionStorage.getItem('cartId'));
expect(token).toBeTruthy();
// cookies (include HttpOnly ones, which JS cannot read)
const cookies = await context.cookies();
const session = cookies.find(c => c.name === 'session');
expect(session).toMatchObject({ httpOnly: true, secure: true, sameSite: 'Lax' });
expect(session!.expires).toBeGreaterThan(Date.now() / 1000);
// set state before the page loads
await context.addCookies([{ name: 'consent', value: 'accepted', domain: 'example.com', path: '/' }]);
await context.addInitScript(() => localStorage.setItem('onboardingDone', 'true'));
// Cypress
cy.getCookie('session').should('have.property', 'httpOnly', true);
cy.window().then(win => expect(win.localStorage.getItem('theme')).to.eq('dark'));
cy.clearAllLocalStorage(); cy.clearCookies();
// Selenium
Cookie c = driver.manage().getCookieNamed("session"); assertTrue(c.isHttpOnly() && c.isSecure());
String v = (String) ((JavascriptExecutor) driver).executeScript("return window.localStorage.getItem('theme');");

What to test

  1. Correct values written at the right time: preferences saved on change, cart or draft stored, consent recorded, feature flags, auth tokens, language choice.
  2. Persistence: survives reload and new tab (localStorage, cookies); sessionStorage survives reload but not new tabs or windows (open a second page and assert it is empty).
  3. Expiry and clearing: cookie Max-Age and Expires, session cookies removed on browser close (new context), logout clears tokens, user data and caches; switching accounts does not leak previous user's data.
  4. Security attributes on cookies: HttpOnly for session ids, Secure, SameSite (Lax or Strict), scoped Domain and Path, __Host- prefix; no sensitive data (passwords, PII, long-lived tokens, card numbers) in localStorage or cookies in plain text; tokens are the right type and length.
  5. Behaviour when storage is unavailable or full: block cookies and storage (browser setting, page.addInitScript overriding Storage.prototype.setItem to throw QuotaExceededError), private browsing, third-party cookie restrictions (Safari ITP, Chrome changes); the app should degrade gracefully with clear messaging.
  6. Cross-tab synchronisation: storage events update other tabs (logout in one tab logs out others); concurrent writes.
  7. Consent and privacy: no non-essential cookies before consent, removed after withdrawal (see consent banner tests), cookie inventory matches documentation.
  8. Tampering: edit stored values (role flags, prices, tokens) and assert the server does not trust client-side state; corrupted JSON handled without crashing; schema migrations of stored data between app versions.
  9. Storage and session reuse in test infrastructure: save authenticated state once (context.storageState({ path })) and load it in other tests to skip UI login; keep state files out of Git and per-environment.

Pitfalls

Asserting on storage before the app finishes writing (wait for the event or expectation), forgetting that each browser context starts empty, stale storageState files with expired tokens, testing HttpOnly cookies via JavaScript (impossible), and leaving sensitive tokens in artifacts and logs.
