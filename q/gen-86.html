What are atomic operations and Compare-And-Swap (CAS) instructions in lock-free programming?

Software engineer (core) · Gear 3 (Senior) · Systems · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

An atomic operation completes as a single indivisible step that other threads cannot observe half done. Compare-And-Swap (CAS) is a hardware instruction that sets a memory location to a new value only if it still holds the expected value, returning whether it succeeded. Lock-free algorithms retry CAS in a loop instead of holding a lock.

Explained in depth

Atomics

An increment like counter += 1 is really read, add, write. Two threads can interleave and lose an update. Atomic types (AtomicInteger, C++ std::atomic) make the read-modify-write one indivisible step, using CPU instructions such as LOCK XADD or a CAS loop.

CAS

CAS(address, expected, new) does the following atomically: if *address == expected then *address = new and return true; else return false.

AtomicInteger counter = new AtomicInteger();
int old, next;
do {
    old = counter.get();
    next = old + 1;
} while (!counter.compareAndSet(old, next));   // retry if another thread changed it

Lock-free stack push

Read the head, set node.next = head, then CAS the head from the old value to the new node; on failure, someone else pushed first, so retry. No thread can block others by being suspended while holding a lock.

ABA problem

A location changes from A to B and back to A; a CAS sees A and succeeds although the structure changed in between (for example a node was popped, freed and reused). Fixes are version tags (a counter paired with the pointer), hazard pointers or garbage collection.

Trade-offs

Lock-free code avoids deadlock and priority inversion and scales on moderate contention. It is difficult to design and verify, and under heavy contention many failed CAS retries waste CPU. Use well-tested library structures rather than writing your own.
