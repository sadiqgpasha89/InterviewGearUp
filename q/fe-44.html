How does virtualized list rendering (DOM windowing) enable smooth scrolling over 100,000 items?

Frontend engineer · Gear 3 (Senior) · Performance · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Virtualization (windowing) renders only the rows that are visible in the viewport plus a small buffer, inside a container whose scroll height is set to the full list size. As the user scrolls, it reuses and repositions a few dozen DOM nodes, so 100,000 items cost as little as 30 elements instead of 100,000.

Explained in depth

Why it is needed

Each DOM node costs memory and layout time. Rendering 100,000 rows makes the page slow to load, scroll and update. Browsers only show a screenful at a time, so rendering the rest is wasted work.

How it works

  1. The scroll container has a fixed height and an inner spacer whose height is itemCount * itemHeight, so the scrollbar looks correct.
  2. On scroll, compute the visible range: start = floor(scrollTop / itemHeight) and end = start + visibleCount, plus overscan rows above and below to avoid blank flashes.
  3. Render only those items, each positioned absolutely with transform: translateY(index * itemHeight) (or use padding above and below).
// react-window
<FixedSizeList height={600} itemCount={100000} itemSize={40} width="100%">
  {({ index, style }) => <div style={style}>Row {index}</div>}
</FixedSizeList>

Harder cases

  • Variable heights: measure rows after rendering and cache sizes (react-virtuoso, TanStack Virtual), or estimate then correct.
  • Grids and two-dimensional lists use the same idea in both axes.
  • Keep row components cheap, memoised and keyed by id.

Costs

  • Native find-in-page cannot see unrendered rows, and screen readers may not know the list size unless you set aria-rowcount, aria-setsize and aria-posinset.
  • Keyboard focus and scroll-to-item need extra logic, and fast scrolling can show blank areas.

Alternatives

Pagination, infinite scroll with a cap, or CSS content-visibility: auto, which skips rendering of off-screen sections without JavaScript but still keeps all nodes in the DOM.
