Explain Maximum Transmission Unit (MTU), Path MTU Discovery (PMTUD), and packet fragmentation issues.

DevOps / SRE / Cloud · Gear 2 (Mid-level) · Networking · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

MTU is the largest packet a link can carry (1500 bytes on Ethernet). Path MTU Discovery finds the smallest MTU along a route by sending packets with the Don't Fragment bit and reacting to ICMP Fragmentation Needed replies. When ICMP is filtered, large packets silently vanish (black holes), causing hangs that small packets avoid.

Explained in depth

Definitions

  • MTU (Maximum Transmission Unit): maximum IP packet size, including headers, per interface. Ethernet 1500, jumbo frames 9000 (AWS inside a VPC supports 9001), PPPoE 1492, many VPNs 1400 or less.
  • MSS (TCP Maximum Segment Size): payload per TCP segment, negotiated in SYN: MTU − 20 (IP) − 20 (TCP) = 1460 for a 1500 MTU.

Fragmentation

If an IPv4 packet is larger than a link's MTU and DF is not set, routers fragment it; the destination reassembles. Fragmentation is costly: extra CPU, loss of any fragment loses the whole packet, firewalls and load balancers often drop fragments, and it enables attacks. IPv6 routers never fragment; only the sender can, so PMTUD is essential.

Path MTU Discovery (PMTUD)

  1. The sender sets the DF (Don't Fragment) bit and sends packets at its interface MTU.
  2. A router that cannot forward a packet that large drops it and sends ICMP Type 3 Code 4 (Fragmentation Needed, with the next-hop MTU) (ICMPv6 Packet Too Big).
  3. The sender lowers its path MTU for that destination and retransmits smaller segments.

The black hole problem

Firewalls, security groups and some network devices block all ICMP. The "need to fragment" message never arrives, so large packets are dropped forever. Symptoms: TCP handshake works (small packets), small requests succeed, but transfers hang on larger responses, TLS handshakes stall at the certificate, SSH connects but freezes on large output, VPNs work for ping but not for downloads. Fixes: allow ICMP type 3 code 4 (and ICMPv6 type 2), or enable PLPMTUD (packetization layer PMTUD, net.ipv4.tcp_mtu_probing=1), which probes using TCP itself.

Common causes of reduced MTU

Encapsulation adds headers: IPsec (50 to 70 bytes), GRE (24), VXLAN (50), WireGuard (60 to 80), Geneve, Kubernetes overlay CNIs (Flannel VXLAN, Calico IPIP), cloud transit gateways, PPPoE. Pod MTU must be set below the node MTU minus the overhead (for example 1450 on VXLAN over 1500).

Testing and tools

ping -M do -s 1472 example.com       # 1472 + 28 (ICMP+IP) = 1500; fails if the path MTU is smaller
ping -M do -s 1372 example.com       # binary-search the largest size that works
tracepath example.com                # reports MTU per hop
ip link show eth0 | grep mtu
ip route get <dst>                   # shows cached path MTU
sudo tcpdump -ni any 'icmp[0]==3 and icmp[1]==4'

Mitigations

  • MSS clamping on routers or firewalls: iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu, so TCP endpoints never send oversized segments even if ICMP is blocked. Useful on VPN and tunnel gateways.
  • Set consistent MTU across the path (jumbo frames only when every hop supports it, including storage networks), configure CNI and VPN MTU correctly, and document it in Infrastructure as Code.
  • UDP applications (DNS over large responses, QUIC, VoIP) need application-level size limits; QUIC uses a conservative 1200-byte minimum. DNS EDNS buffer sizes around 1232 avoid fragmentation.

Pitfalls

Blocking all ICMP "for security", mixing jumbo and standard MTUs without PMTUD, and misdiagnosing hangs as application bugs.
