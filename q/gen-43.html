How do you solve the N-Queens problem using backtracking with column and diagonal constraint bitsets?

Software engineer (core) · Gear 3 (Senior) · Algorithms · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

N-Queens places N queens so none attack each other. Backtracking places one queen per row, and for each column it checks whether the column and both diagonals are free. Encoding those three sets as bitmasks makes the check and update O(1), and a solution is counted when all N rows are filled.

Explained in depth

Constraint sets

Queens at (r, c) conflict if they share a column, a main diagonal (r - c equal) or an anti-diagonal (r + c equal). Place one queen per row, so rows never conflict.

Bitmask version

Track three bitmasks: occupied columns, and occupied diagonals shifted one step per row.

def total_n_queens(n):
    full = (1 << n) - 1
    def solve(cols, d1, d2):
        if cols == full:
            return 1
        count = 0
        free = full & ~(cols | d1 | d2)         # columns still safe in this row
        while free:
            bit = free & -free                  # lowest free column
            free ^= bit
            count += solve(cols | bit,
                           ((d1 | bit) << 1) & full,
                           (d2 | bit) >> 1)
        return count
    return solve(0, 0, 0)

# n = 8 -> 92 solutions

Why it is fast

  • The bit operations test and update all columns at once in O(1).
  • Pruning stops a branch as soon as a row has no safe column.
  • The search visits far fewer than N^N nodes; the exact growth is roughly factorial but heavily pruned.

Extras

Mirror symmetry halves the work (search only half of the first row and double). The pattern is a template for backtracking problems such as Sudoku and permutations with constraints.

Likely follow-ups
