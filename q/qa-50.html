How do you automate testing of file uploads, drag-and-drop, and multipart form submissions?

QA / SDET · Gear 2 (Mid-level) · UI Automation · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Automate uploads by setting the file on the input element directly instead of driving the OS dialog, such as setInputFiles in Playwright or sendKeys with a path in Selenium. For drag-and-drop use the framework's drag APIs or dispatch drag events for custom widgets, and verify multipart requests by asserting on the network call or the server-side result such as stored file, size and checksum.

Explained in depth

File uploads

Native file pickers are operating system dialogs that browser automation cannot control reliably. Instead, set the file path directly on the <input type="file"> element (even if it is hidden), which triggers the same change event.

// Playwright
await page.setInputFiles('input[type=file]', 'fixtures/invoice.pdf');                  // single
await page.setInputFiles('input[type=file]', ['fixtures/a.png', 'fixtures/b.png']);    // multiple
await page.setInputFiles('input[type=file]', { name: 'note.txt', mimeType: 'text/plain', buffer: Buffer.from('hello') });   // in-memory
await page.setInputFiles('input[type=file]', []);                                      // clear
// when the app opens the chooser via a button:
const [chooser] = await Promise.all([page.waitForEvent('filechooser'), page.click('#upload-button')]);
await chooser.setFiles('fixtures/invoice.pdf');
// Selenium: send the absolute path to the input (make it visible if hidden via JS)
driver.findElement(By.cssSelector("input[type=file]")).sendKeys(new File("src/test/resources/invoice.pdf").getAbsolutePath());
// Cypress with cypress-file-upload or built-in selectFile
cy.get('input[type=file]').selectFile('cypress/fixtures/invoice.pdf', { force: true });

Remote Selenium grids need setFileDetector(new LocalFileDetector()) so the file is transferred to the node.

What to verify

  • Success state, filename and size shown, progress bar reaching 100 percent, thumbnail previews.
  • Validation: allowed and blocked types (extension and MIME sniffing: rename .exe to .jpg), maximum size (just below, at, above the limit), empty files, long or unicode filenames, duplicate names, many files, path traversal names (../../x), zero-byte and corrupt files, and server-side virus scanning responses.
  • Backend result: call the API or storage to confirm the file exists with the correct size, content type and checksum (SHA-256 of fixture equals stored object), and metadata and permissions.
  • Errors and resilience: network interruption (route abort or offline mode), server 413, 415, 500, retries and resumable or chunked uploads, cancellation, large files (generate on the fly instead of storing in the repo).
  • Multipart assertions: intercept the request (page.waitForRequest), check method, Content-Type: multipart/form-data; boundary=..., part names, filename, and fields; in API tests send multipart directly (requests.post(files=...), REST Assured .multiPart(...)).
const [req] = await Promise.all([page.waitForRequest(r => r.url().includes('/upload') && r.method() === 'POST'),
                                 page.setInputFiles('#file', 'fixtures/invoice.pdf')]);
expect(req.headers()['content-type']).toContain('multipart/form-data');

Drag and drop

  1. Native HTML5 drag and drop or file drop zones: Playwright locator.dragTo(target) or page.dragAndDrop(source, target); to drop files on a zone, dispatch a drop event with a DataTransfer built in the page:
const dt = await page.evaluateHandle(() => { const d = new DataTransfer(); d.items.add(new File(['x'], 'a.txt', { type: 'text/plain' })); return d; });
await page.dispatchEvent('#dropzone', 'drop', { dataTransfer: dt });
  1. Libraries using mouse events (react-beautiful-dnd, SortableJS, dnd-kit): simulate low-level actions with small steps: mouse.move, mouse.down, several mouse.move calls (with steps), mouse.up; Selenium Actions().clickAndHold().moveToElement().release(); add small pauses so animations settle.
  2. Assert the resulting order or state (DOM order, API call, persisted value) rather than animation details; reload to confirm persistence; test keyboard alternatives (accessibility).

Practices

Keep fixtures small and deterministic; generate large files in temp directories; clean uploaded test objects by tag; avoid tests that depend on external storage latency (use waits for completion indicators); run on all browsers since drag events differ.

Pitfalls

Trying to automate the OS file dialog, using relative paths that fail on CI, not testing server-side validation (client-side only), flaky drags without intermediate mouse moves, and leaving test files in buckets.
