What is the danger of Target Encoding, and how do you prevent target leakage during training?

ML / AI engineer · Gear 2 (Mid-level) · Preprocessing · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Target encoding replaces a category with the average target value for that category, which is powerful for high-cardinality features but leaks the label: a row's own target is included in its encoding, so rare categories encode their own answer and the model overfits. Prevent it with out-of-fold encoding, smoothing toward the global mean and noise, and fitting encoders only on training folds.

Explained in depth

What it does

For a categorical feature like zip_code, replace each value with the mean target of rows that have it (for classification, the positive rate). It gives one dense numeric column even for thousands of categories, unlike one-hot encoding.

The leakage problem

If you compute the means on the full training set and then train on those same rows, each row's own label contributes to its feature. For a category with only one row, the encoding equals that row's label, so the model learns "this feature perfectly predicts the target" and fails on new data. Validation scores look great and production results collapse.

Safeguards

  1. K-fold (out-of-fold) encoding: split training data into folds; encode each fold using statistics computed from the other folds. The row's own label never affects its feature.
  2. Smoothing (shrinkage): blend category mean with the global mean by size:

enc = (n * cat_mean + m * global_mean) / (n + m) Rare categories move toward the global average.

  1. Noise: add small random noise to the training encodings.
  2. Fit on training data only and apply the learned mapping to validation and test (inside a pipeline); unseen categories get the global mean.
  3. Use ordered target statistics (CatBoost), where each row is encoded using only rows before it in a random permutation.

Alternatives

One-hot for few categories, hashing, frequency encoding, learned embeddings, or leave-one-out encoding (which still leaks unless carefully handled).
