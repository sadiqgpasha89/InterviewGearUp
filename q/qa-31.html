How do you automate testing of OAuth 2.0 and JWT token authentication, refreshes, and expirations?

QA / SDET · Gear 2 (Mid-level) · API Testing · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Automate OAuth 2.0 and JWT testing by obtaining tokens through the real grant flow against a test authorization server, then asserting claims, scopes, signature, expiry and audience. Cover refresh token rotation, expired and tampered tokens, wrong audience or scope, revoked tokens, and that protected endpoints return 401 or 403 correctly without relying on the UI.

Explained in depth

Test environment

Use a dedicated test tenant or realm (Keycloak, Auth0 test tenant, Okta dev org, Cognito pool, or a local mock like mock-oauth2-server) with test clients and users, short token lifetimes configurable for tests, and secrets in CI vault. Avoid driving the login UI for every test: use direct grants where allowed in test (client credentials, resource owner password, token exchange) or API-based auth helpers, and keep one or two end-to-end browser flows for the authorization code with PKCE.

Obtaining tokens in tests

def get_token(scope="read:orders"):
    r = requests.post(f"{AUTH}/oauth/token", data={"grant_type": "client_credentials", "client_id": ID,
                      "client_secret": SECRET, "audience": "https://api.example.com", "scope": scope})
    r.raise_for_status(); return r.json()

Cache tokens per scope for the run (until near expiry) to avoid hammering the server.

What to assert

  1. Happy path: valid access token → 200; response respects the user's identity.
  2. Missing or malformed token → 401 with WWW-Authenticate: Bearer header; no data leakage.
  3. Insufficient scope or role → 403 Forbidden (token valid but not authorised).
  4. Expired token → 401 (invalid_token, "expired"). Generate expired tokens by signing with the test key and a past exp, using a very short lifetime (5 seconds) configured on the test auth server, or a controllable clock.
  5. JWT validation: decode and assert claims (iss, aud, sub, exp, iat, scope/scp, custom claims); verify the signature algorithm (RS256 with JWKS), kid handling, JWKS rotation.
  6. Tampering and attacks: payload edited without re-signing; alg: none; algorithm confusion (HS256 signed with the public key); wrong issuer or audience; nbf in the future; clock skew limits; token reuse across tenants; very large tokens.
def test_rejects_wrong_audience(api):
    t = make_jwt(claims={"aud": "https://other-api", "sub": "u1", "exp": now()+300}, key=TEST_PRIVATE_KEY)
    assert api.get("/orders", headers=bearer(t)).status_code == 401
def test_rejects_alg_none(api):
    t = b64({"alg": "none"}) + "." + b64({"sub": "admin", "exp": now()+300}) + "."
    assert api.get("/admin", headers=bearer(t)).status_code == 401
  1. Refresh flow: use the refresh token to get a new access token; assert new exp; test refresh token rotation (the old refresh token becomes invalid; reuse of a rotated token triggers revocation of the token family); expired or revoked refresh token → invalid_grant; client authentication errors; scope downgrade on refresh not upgrade.
  2. Revocation and logout: after revoking a token (RFC 7009) or logging out, protected endpoints reject it (immediately for introspection-based, eventually for stateless JWT based on design), session invalidation after password change.
  3. Authorization code with PKCE: wrong code_verifier, reused authorization code, wrong redirect_uri, missing state (CSRF) must fail.
  4. Token storage and transport: HTTPS only, tokens not logged, not in URLs, cookies flags (HttpOnly, Secure, SameSite) if cookie-based.
  5. Rate limits and brute force on token endpoints.
  6. Concurrency: simultaneous refresh requests from several tabs handled safely.

Time control

Prefer injecting time: configure the service to use a clock the test can advance (Clock abstraction), use libraries like freezegun, or create tokens with explicit iat/exp. Avoid sleeps.

Tools

Postman/Newman with pre-request scripts, REST Assured OAuth2 helpers, Playwright API request contexts, k6 for load on token endpoints, jwt.io/jose/PyJWT for crafting tokens, OWASP ZAP and JWT_Tool for security tests.

Pitfalls

Using production identity providers, hardcoding long-lived tokens in repos, only testing happy paths, trusting exp checks in tests without verifying signature validation, and ignoring refresh token reuse.
