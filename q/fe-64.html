How does `AbortController` cancel inflight fetch requests and async operations?

Frontend engineer · Gear 2 (Mid-level) · JavaScript · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

AbortController creates a signal that you pass to fetch and other APIs; calling abort() rejects the pending operation with an AbortError and lets the browser stop the network work. It prevents stale responses overwriting newer state, wasted bandwidth and updates after unmount.

Explained in depth

Basic usage

const controller = new AbortController();
fetch('/api/search?q=react', { signal: controller.signal })
  .then(r => r.json())
  .then(render)
  .catch(err => { if (err.name !== 'AbortError') showError(err); });   // abort is not an error

controller.abort();                    // cancels the request; promise rejects with AbortError

signal is an AbortSignal with aborted, reason and an abort event. A signal can be aborted only once. abort(reason) lets you attach a custom reason (signal.reason).

Race conditions in search-as-you-type

Without cancellation, response order is not guaranteed: the answer for "rea" can arrive after "react" and overwrite the right results.

useEffect(() => {
  const c = new AbortController();
  (async () => {
    try {
      const res = await fetch(`/api/search?q=${q}`, { signal: c.signal });
      setResults(await res.json());
    } catch (e) { if (e.name !== 'AbortError') setError(e); }
  })();
  return () => c.abort();               // cleanup: runs on re-run and unmount
}, [q]);

Timeouts and combining signals

fetch(url, { signal: AbortSignal.timeout(5000) });                         // aborts with TimeoutError
fetch(url, { signal: AbortSignal.any([userSignal, AbortSignal.timeout(5000)]) });

Making your own function abortable

function sleep(ms, signal) {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) return reject(signal.reason);
    const id = setTimeout(resolve, ms);
    signal?.addEventListener('abort', () => { clearTimeout(id); reject(signal.reason); }, { once: true });
  });
}

Also used with addEventListener(..., { signal }) to remove many listeners at once, with streams, Request, and Node APIs.

What cancellation does and does not do

Aborting a fetch closes the connection from the client side. The server may still have processed the request, so abort is not rollback: non-idempotent writes need idempotency keys. It also frees browser connection slots (a limit of about six per host on HTTP/1.1).

Pitfalls

Treating AbortError as a failure, reusing an aborted controller, not aborting on route change or unmount, forgetting that awaiting an already resolved promise ignores later aborts, and aborting while reading the body stream (it rejects the body read).
