Explain the rules of `this` binding in JavaScript: default, implicit, explicit, and arrow functions.

Frontend engineer · Gear 2 (Mid-level) · JavaScript · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

What this refers to depends on how a function is called, not where it is written. The rules in priority order: new binding, explicit binding with call, apply or bind, implicit binding as the object before the dot, then default binding (undefined in strict mode, the global object otherwise). Arrow functions have no this of their own and use the one from where they are defined.

Explained in depth

The rules

  1. new: new Foo() makes this the newly created object.
  2. Explicit: fn.call(obj, a), fn.apply(obj, [a]) or fn.bind(obj) set this to obj.
  3. Implicit: obj.method() sets this to obj.
  4. Default: a plain call fn() gives this as undefined in strict mode (modules and classes are strict) or the global object in sloppy mode.

Losing this

const user = { name: 'Ana', hi() { return this.name; } };
user.hi();                  // 'Ana'
const f = user.hi;
f();                        // undefined: plain call, this is lost
setTimeout(user.hi, 0);     // same problem
setTimeout(() => user.hi(), 0);   // fine, or use user.hi.bind(user)

Arrow functions

They do not have their own this, arguments or new behaviour. They capture this lexically from the surrounding scope, which makes them good for callbacks inside methods:

class Timer {
  start() { setInterval(() => this.tick(), 1000); }   // this is the Timer
  tick() {}
}

But do not use arrows for object methods that need dynamic this, nor as constructors. call, apply and bind cannot change an arrow function's this.

Class methods as handlers

Methods lose this when passed as handlers; fix with an arrow function class field or bind in the constructor.
