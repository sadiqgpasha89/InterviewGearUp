How does `ResizeObserver` observe element dimension changes without triggering infinite layout loops?

Frontend engineer · Gear 2 (Mid-level) · Browser APIs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

ResizeObserver notifies you when an element's content or border box size changes, from any cause, so you can respond without polling or window resize listeners. The browser delivers notifications after layout and before paint, and stops infinite loops by only processing deeper elements in each pass and reporting an error if they continue.

Explained in depth

Why it exists

window.resize only covers the viewport. Components often need to react to their own size, which changes with sidebar toggles, font loading, content changes, CSS animations or layout shifts. Polling offsetWidth every frame forces layout and wastes battery.

API

const ro = new ResizeObserver((entries) => {
  for (const entry of entries) {
    const { width, height } = entry.contentRect;                 // content box
    const box = entry.borderBoxSize?.[0];                        // { inlineSize, blockSize }
    chart.resize(width, height);
  }
});
ro.observe(document.querySelector('#chart-container'));
// later: ro.unobserve(el) or ro.disconnect() on cleanup

The box option (content-box default, border-box, device-pixel-content-box) picks which size is observed.

When the callback runs

Observations are gathered after layout and before paint in each frame. If a callback changes the size of an observed element at a shallower or equal depth (so earlier results are invalidated), the browser would loop forever. The spec avoids that: each pass processes only elements deeper in the DOM than those handled in the previous pass; if more notifications remain, it defers them to the next frame and fires an error event with the message "ResizeObserver loop completed with undelivered notifications". This message is usually benign but signals a feedback loop in your logic.

Avoiding loops

  • Do not resize an element that you also observe, based on its own size (for example setting height from width repeatedly).
  • Observe the container and change the child.
  • Defer layout-changing writes to requestAnimationFrame.
  • Batch reads then writes; avoid forcing synchronous layout inside the callback.
  • Guard with comparisons (if (newWidth !== lastWidth)).

Typical uses

Responsive charts and canvases (re-rendering at correct pixel ratio), virtualised lists measuring row heights, auto-growing textareas, truncating text with "show more", editors, and custom layout libraries.

Container queries

For purely visual changes, CSS container queries (container-type: inline-size; @container (min-width: 400px) { ... }) respond to container size with no JavaScript. Use ResizeObserver when the logic must run in JS (canvas redraw, measurement, analytics).

Pitfalls

Forgetting to disconnect in React effects (use cleanup), assuming the first callback is after a resize (it also fires initially on observe), expensive work on every pixel of a drag (throttle with rAF), and observing too many elements.
