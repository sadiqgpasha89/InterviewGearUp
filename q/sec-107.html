What is HTTPS, and what does the padlock in the browser actually guarantee?

Security engineer · Gear 1 (Junior) · Web security · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

HTTPS is HTTP carried over TLS, which encrypts traffic, detects tampering and authenticates the server using a certificate issued by a trusted authority. The padlock means the connection to that domain is private and the domain's identity was verified, not that the website itself is trustworthy, safe or free of malware. Phishing sites can have valid certificates.

Explained in depth

What HTTPS provides

  1. Confidentiality: data between browser and server is encrypted, so someone on the same Wi-Fi or an ISP cannot read passwords or content.
  2. Integrity: modifications in transit are detected (no injected ads or malware).
  3. Server authentication: the certificate proves that the server holds a key for the domain, issued by a certificate authority (CA) the browser trusts.

How it works in brief

The client connects and the TLS handshake negotiates a version and cipher, the server presents its certificate chain, the client verifies the signature chain up to a trusted root, checks the domain name and validity dates, and the two sides derive shared session keys (with ephemeral key exchange for forward secrecy). Then HTTP data flows encrypted.

What the padlock does not mean

  • The site is honest: attackers obtain free certificates for paypa1-login.example easily. Always check the domain.
  • The server is free of vulnerabilities or malware.
  • Your data is safe once it reaches the server (storage and handling are separate).
  • The connection hides which domain you visit (the hostname is usually visible via SNI and DNS, although encrypted ClientHello and DoH are improving this), or the amount of traffic.

Developer checklist

  • Use HTTPS everywhere, redirect HTTP to HTTPS, and enable HSTS so browsers refuse plain HTTP.
  • Use TLS 1.2 or 1.3 with modern ciphers; disable old SSL and TLS 1.0 and 1.1.
  • Renew certificates automatically (ACME, Let's Encrypt) and monitor expiry.
  • Avoid mixed content (HTTP resources on HTTPS pages), and set Secure on cookies.
  • Protect private keys and consider CAA DNS records and certificate transparency monitoring.
