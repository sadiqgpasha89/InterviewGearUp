Explain the difference between `==` loose equality and `===` strict equality, and how `Object.is()` differs.

Frontend engineer · Gear 1 (Junior) · JavaScript · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

=== compares without type conversion: values of different types are never equal. == first coerces both sides to a common type using complicated rules, which gives surprises such as 0 == '' being true. Object.is is like === except that NaN equals NaN and +0 differs from -0. Use === by default.

Explained in depth

Examples

0 == ''               // true  (both coerce to 0)
null == undefined     // true  (a special rule)
null == 0             // false (null only equals undefined)
'1' == 1              // true
[] == false           // true  ([] -> '' -> 0, false -> 0)
NaN === NaN           // false
Object.is(NaN, NaN)   // true
Object.is(0, -0)      // false, while 0 === -0 is true

Rules of thumb: use === for almost everything. The one common deliberate use of == is x == null, which is true for both null and undefined. Use Number.isNaN(x) to test for NaN, and Object.is when you must tell -0 from 0. React uses Object.is to compare state and dependency values.

Objects are compared by reference with every operator: {} === {} is false.
