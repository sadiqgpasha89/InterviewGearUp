How do you create a single source of truth for company KPIs and prevent metric definitions from drifting?

Data engineer · Gear 4 (Lead / Staff) · Metrics · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Define each KPI once in version-controlled code, in a semantic or metrics layer with an owner, description and tests, expose it to every tool through that layer, and certify the datasets behind it. Review definition changes like code, show lineage and documentation in a catalog, and reconcile against finance sources so executives see the same number everywhere.

Explained in depth

The problem

Revenue, active users or churn are calculated differently in each dashboard, spreadsheet and notebook. Executives see conflicting numbers, and trust in data drops.

Solution: define once, reuse everywhere

  1. Governance: for each KPI assign an owner, a precise definition (numerator, denominator, filters, time grain, timezone, currency handling, treatment of refunds and test accounts), and grain and dimensions allowed. Keep a business glossary.
  2. Metrics as code: implement them in a semantic layer or metrics store: dbt Semantic Layer (MetricFlow), Cube, LookML, AtScale, or warehouse-native semantic views. Definitions live in Git, with pull-request review by the owner and data team, tests, and versioning.
  3. Single access path: BI tools, notebooks, reverse ETL and APIs query the layer rather than writing their own SQL for core metrics, so every consumer receives the same calculation.
  4. Certified datasets: gold-layer tables for the metric's inputs, built with tested pipelines, data contracts from source systems, and freshness SLAs. Mark them "certified" in the catalog.
  5. Reconciliation: automated checks comparing key numbers with systems of record (finance ledger, billing), with alerts on variance beyond a threshold.
  6. Change management: when a definition changes, version it, backfill history, annotate dashboards, and announce. Keep old versions for audit.

Handling disagreement

If two teams legitimately need different definitions, give them different names ("gross revenue" and "net revenue", "monthly active users (login)" and "(any event)") and document how they relate, rather than having one name with two meanings.

Adoption

Make the governed metrics the easiest to use (fast, documented, discoverable in the BI tool), deprecate duplicates, monitor usage of uncertified calculations, and train analysts. Track the number of conflicting definitions and incidents of mismatched numbers.
