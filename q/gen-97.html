How does Tarjan's algorithm find bridges and articulation points in an undirected graph in $O(V+E)$ time?

Software engineer (core) · Gear 3 (Senior) · Graphs · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Tarjan's bridge-finding DFS records each vertex's discovery time and the lowest discovery time reachable through its subtree using at most one back edge. A tree edge (u, v) is a bridge if low[v] > disc[u]; a non-root u is an articulation point if some child has low[v] >= disc[u].

Explained in depth

Definitions

In an undirected connected graph:

  • A bridge is an edge whose removal disconnects the graph.
  • An articulation point (cut vertex) is a vertex whose removal disconnects the graph.

A naive solution removes each edge or vertex and re-runs DFS: O(V * (V + E)). Tarjan does everything in one DFS in O(V + E).

Key quantities

  • disc[v]: DFS discovery time.
  • low[v]: the smallest disc reachable from the subtree of v using any number of tree edges and at most one back edge.
low[v] = min( disc[v],
              disc[w] for each back edge (v, w),          // w already visited, not v's parent edge
              low[c]  for each DFS child c of v )

Conditions

  • Tree edge (u, v) (u parent of v) is a bridge iff low[v] > disc[u]: no edge from v's subtree climbs back to u or above, so the subtree hangs only by this edge.
  • Vertex u is an articulation point iff:
  • u is the root and has two or more DFS children, or
  • u is not the root and has a child v with low[v] >= disc[u] (the subtree cannot escape without passing through u).

Note the strict > for bridges versus >= for articulation points: a back edge to u itself saves the edge but not the vertex.

Code

def bridges_and_cuts(n, adj):
    disc = [-1] * n; low = [0] * n; t = 0
    bridges, cuts = [], set()
    def dfs(u, parent_edge):
        nonlocal t
        disc[u] = low[u] = t; t += 1; children = 0
        for v, eid in adj[u]:                      # adjacency holds (neighbour, edge id)
            if eid == parent_edge: continue        # skip the edge we came by (handles multi-edges)
            if disc[v] != -1:                      # back edge
                low[u] = min(low[u], disc[v])
            else:
                children += 1
                dfs(v, eid)
                low[u] = min(low[u], low[v])
                if low[v] > disc[u]: bridges.append((u, v))
                if parent_edge != -1 and low[v] >= disc[u]: cuts.add(u)
        if parent_edge == -1 and children > 1: cuts.add(u)
    for s in range(n):
        if disc[s] == -1: dfs(s, -1)
    return bridges, cuts

Notes

  • Skip the parent edge id, not the parent vertex, so that parallel edges correctly make a connection a non-bridge.
  • Handle disconnected graphs by starting DFS from every unvisited vertex.
  • Recursion depth can reach V; use an iterative DFS or raise the limit for large graphs.

Applications

Network and road resilience (critical links), 2-edge-connected components and biconnected components, building the bridge tree for LCA queries, and finding single points of failure in service dependency graphs.
