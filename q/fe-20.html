How do WeakMap and WeakSet assist with garbage collection and memory leak prevention?

Frontend engineer · Gear 3 (Senior) · JavaScript · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

WeakMap and WeakSet hold their keys (or members) weakly: if nothing else references the object, it can be garbage collected and its entry disappears. This lets you attach metadata or track membership for objects without extending their lifetime, preventing leaks that a normal Map or Set would cause by keeping every key alive.

Explained in depth

The problem with Map

const cache = new Map();
function remember(node, data) { cache.set(node, data); }
// If node is removed from the page, cache still references it, so it is never collected.

WeakMap

const meta = new WeakMap();
function remember(node, data) { meta.set(node, data); }
// Once nothing else references node, both the node and its entry can be collected.

Rules

  • Keys must be objects (or non-registered symbols), not primitives.
  • The references to keys are weak; the values are held as long as the key is alive.
  • You cannot enumerate, clear or get the size of a WeakMap or WeakSet, because the contents depend on when the garbage collector runs. That would make behaviour non-deterministic.
  • Only get, set, has and delete exist.

Use cases

  • Private data per instance without a property on the object.
  • Caches of computed results keyed by an object, such as memoising by DOM node or by request object.
  • Tracking that an object was already processed (WeakSet), for example avoiding double initialisation.
  • Libraries attach metadata to DOM elements without leaks.

Related

WeakRef holds a weak reference to a single object you can try to dereference later; FinalizationRegistry runs a callback after collection. Both are advanced, and their timing is not guaranteed, so do not rely on them for logic.
