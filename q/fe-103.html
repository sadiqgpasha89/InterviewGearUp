How does the this keyword work in JavaScript?

Frontend engineer · Gear 1 (Junior) · JavaScript · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

The value of this depends on how a function is called, not where it is defined: a method call uses the object before the dot, a plain call gives undefined in strict mode, new creates a fresh object, call, apply and bind set it explicitly, and arrow functions take this from the surrounding scope. Losing this when passing methods as callbacks is the classic bug.

Explained in depth

The rules (in order of priority)

  1. new Foo(): this is the newly created object.
  2. Explicit binding: fn.call(obj, a, b), fn.apply(obj, [a, b]), or fn.bind(obj) set this to obj. bind returns a new function with this fixed.
  3. Method call: user.greet() sets this to user (the object before the dot).
  4. Plain function call: greet() gives undefined in strict mode and modules (the global object in sloppy mode).
  5. Arrow functions have no own this; they use the this of the enclosing scope at definition time, and call or bind cannot change it.

Example of losing this

const user = { name: 'Asha', greet() { return 'Hi ' + this.name; } };
const f = user.greet;
f();               // this is undefined, so this.name throws (strict mode)
setTimeout(user.greet, 0);                 // same problem
setTimeout(() => user.greet(), 0);         // fine
setTimeout(user.greet.bind(user), 0);      // fine

Arrow functions in practice

Great for callbacks inside methods because they keep the outer this:

class Timer {
  start() { setInterval(() => this.tick(), 1000); }
}

Avoid arrow functions as object methods or prototype methods, where you want this to be the receiver.

In React and the DOM

Event handlers called by the browser set this to the element for regular functions; in class components, bind handlers or use class fields with arrow functions. Modern function components with hooks avoid the issue.
