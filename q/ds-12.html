What is feature scaling, which algorithms need it, and what is the difference between standardisation and normalisation?

Data scientist · Gear 1 (Junior) · Data preparation · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Feature scaling puts numeric features on comparable ranges. Standardisation rescales to mean 0 and standard deviation 1, while min-max normalisation maps to a fixed range such as 0 to 1. Distance-based and gradient-based models like KNN, SVM, k-means, PCA, regularised regression and neural networks need it; tree-based models mostly do not.

Explained in depth

Why scale

Features measured in different units dominate each other when an algorithm uses distances, dot products, gradients or penalties: income (tens of thousands) overwhelms age (tens) in Euclidean distance. Scaling also speeds up and stabilises gradient descent and makes regularisation penalise coefficients fairly.

Common methods

MethodFormulaNotes
Standardisation (z-score)(x - mean) / stdzero mean, unit variance; not bounded; good default for linear models, SVM, PCA, neural nets; works fine with roughly symmetric data
Min-max normalisation(x - min) / (max - min)bounded 0 to 1; sensitive to outliers (one extreme value squashes the rest); used for image pixels and when bounds matter
Robust scaling(x - median) / IQRresists outliers
Max-abs scalingx / max(abs(x))preserves sparsity, good for sparse features
Log or power transform (Box-Cox, Yeo-Johnson)log(1 + x)tames right skew (counts, money) before scaling
L2 normalisation of rowsx divided by its L2 normscales each sample, used for text vectors and cosine similarity

Terminology: "normalisation" is used loosely for min-max or row normalisation; say exactly what you did.

Which models need it

  • Need it: k-nearest neighbours, k-means and other distance-based clustering, SVM (RBF), PCA, LDA, linear and logistic regression with regularisation (L1, L2), neural networks, gradient descent methods, t-SNE and UMAP.
  • Mostly invariant: decision trees, random forests, gradient boosting (XGBoost, LightGBM), because splits depend on feature order, not scale. Scaling does no harm but is unnecessary.
  • Plain OLS without regularisation is invariant for predictions but coefficients become comparable only after scaling.
  • Naive Bayes and some probabilistic models depend on distributions, not scale.

Doing it correctly

Fit the scaler on training data only and apply the learned mean and standard deviation to validation, test and production data. Fitting on all data leaks information. Use a pipeline.

from sklearn.preprocessing import StandardScaler, RobustScaler, PowerTransformer
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import Ridge
model = make_pipeline(PowerTransformer(), StandardScaler(), Ridge(alpha=1.0))
model.fit(X_train, y_train)          # scaler statistics come from X_train only
model.predict(X_test)

Persist the fitted scaler with the model so inference uses identical parameters. For streaming data, update statistics carefully and monitor drift.

Special cases

  • One-hot encoded or binary columns usually need no scaling.
  • Target scaling (for regression with neural nets) must be inverted when predicting.
  • Scaling affects interpretation: coefficients refer to standard deviation changes.
  • Sparse matrices: avoid centring (it makes them dense); use MaxAbsScaler or with_mean=False.

Pitfalls

Scaling before the train and test split, scaling categorical codes, assuming trees need scaling, and min-max scaling data with extreme outliers.
