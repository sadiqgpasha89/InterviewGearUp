How do you verify that HTTP caching headers (`Cache-Control`, `ETag`) are correctly honored by browsers and CDNs?

QA / SDET · Gear 2 (Mid-level) · Performance · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Verify caching by inspecting response headers and then proving behaviour: assert Cache-Control, ETag, Last-Modified and Vary on each resource class, repeat requests with If-None-Match to expect 304, check that browsers reuse cached responses without network calls, and confirm CDN behaviour through cache status headers such as X-Cache or CF-Cache-Status across origin changes and purges.

Explained in depth

What you are verifying

Correct caching makes sites fast and cheap; incorrect caching leaks private data (a CDN storing a logged-in page) or serves stale content (users see old prices after a deploy). Tests should check policy per resource type and the observable behaviour in browsers and CDNs.

Key headers

API-level tests (fast, deterministic)

def test_static_asset_is_immutable(client):
    r = client.get("/assets/app.3f9a1c.js")
    assert "max-age=31536000" in r.headers["Cache-Control"] and "immutable" in r.headers["Cache-Control"]
    assert "ETag" in r.headers

def test_conditional_request_returns_304(client):
    first = client.get("/api/products/42")
    second = client.get("/api/products/42", headers={"If-None-Match": first.headers["ETag"]})
    assert second.status_code == 304 and second.content == b""

def test_private_data_not_cacheable_by_cdn(client, auth):
    r = client.get("/api/me", headers=auth)
    cc = r.headers["Cache-Control"]
    assert "no-store" in cc or ("private" in cc and "public" not in cc)

def test_vary_on_compression(client):
    assert "Accept-Encoding" in client.get("/", headers={"Accept-Encoding": "gzip"}).headers.get("Vary", "")

Policy matrix to assert: HTML (short TTL or no-cache with ETag), fingerprinted JS, CSS and images (long TTL, immutable), unversioned assets (revalidate), API GET responses (explicit policy), authenticated and personalised responses (private or no-store), error responses (short TTL or none), redirects, and Set-Cookie responses not cached publicly.

Browser behaviour tests

Use Playwright or Puppeteer to load a page twice and inspect network events: second load should show fromCache or disk cache or memory cache (response.fromServiceWorker(), CDP Network.responseReceived.fromDiskCache) for static assets, a 304 for validated resources, and no request for immutable assets within the TTL.

await page.goto('/'); const reqs = [];
page.on('requestfinished', r => reqs.push({ url: r.url(), cached: r.response()?.fromCache?.() }));  // via CDP session for fromDiskCache
await page.reload();

Check hard reload and normal reload semantics (reload revalidates; navigation reuses cache), back/forward cache behaviour, and service worker interaction. DevTools "Disable cache" must be off in tests.

CDN tests

  • Determine cache status headers (X-Cache: HIT/MISS, CF-Cache-Status, X-Served-By, Age, x-amz-cf-pop). First request MISS, second HIT, Age increases.
  • Cache key correctness: query-string handling (ignore tracking params, respect meaningful ones), cookies and headers in the key (avoid fragmentation), device or language variants via Vary, and no cross-user leakage (request with cookie A, then without, ensure private content is never served from cache).
  • Purge and invalidation: deploy a change, purge by URL or surrogate key/tag, and assert users get new content within the SLA; test stale-while-revalidate and stale-if-error by taking the origin down.
  • Range requests, compression variants (gzip, br), TLS and HTTP/2 or 3, redirects at edge, and security headers present on cached responses.
  • Test multiple regions or PoPs (synthetic monitors from several locations).

Release safety

After deployments verify HTML points to new fingerprinted assets, old assets remain available for users with open tabs (do not delete previous versions immediately), and index.html is not cached long enough to strand users.

Pitfalls

Using no-cache and thinking it means "do not store", caching authenticated pages with public, forgetting Vary, caching error responses, testing only through a browser with dev tools cache disabled, and relying on manual CDN purges.
