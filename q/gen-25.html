Compare graph representations: Adjacency list versus adjacency matrix space and traversal trade-offs.

Software engineer (core) · Gear 2 (Mid-level) · Graphs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

An adjacency list stores each vertex's neighbours, using O(V+E) space and letting you iterate neighbours in time proportional to the degree. An adjacency matrix is a V by V grid using O(V^2) space but answers "is there an edge between u and v" in O(1). Lists suit sparse graphs; matrices suit dense graphs and small vertex counts.

Explained in depth

Comparison

AspectAdjacency listAdjacency matrix
SpaceO(V + E)O(V^2)
Check edge (u, v)O(degree of u), or O(1) with hash setsO(1)
List neighbours of uO(degree of u)O(V)
Add or remove an edgeO(1) to add; removal needs a searchO(1)
Traverse the whole graph (BFS or DFS)O(V + E)O(V^2)
Best forSparse graphs (E much smaller than V^2)Dense graphs, fast edge lookups

Details

  • A sparse graph such as a road network or social graph has few edges per vertex, so a matrix would waste memory. A million vertices would need a trillion cells.
  • A matrix is simple, cache-friendly for small V, and supports algorithms like Floyd-Warshall naturally. It also holds edge weights directly (use infinity or a sentinel for no edge).
  • Undirected graphs store each edge twice (both directions) in both forms.

Edge list

A flat list of (u, v, weight) tuples is compact and is what Kruskal's algorithm and Bellman-Ford iterate over.

Rule of thumb

Default to an adjacency list. Use a matrix when V is small (a few thousand at most), the graph is dense, or you need constant-time edge checks.
