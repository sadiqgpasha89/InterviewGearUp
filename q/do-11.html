Explain Linux virtual memory, Resident Set Size (RSS), swap space, and what triggers the OOM Killer.

DevOps / SRE / Cloud · Gear 2 (Mid-level) · Linux · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Each process sees virtual memory that the kernel maps to physical RAM in pages on demand. RSS is the part of a process currently resident in RAM, while swap holds pages moved to disk. When the system cannot reclaim enough memory, the kernel's OOM killer picks a process with a high oom score and kills it to free memory.

Explained in depth

Virtual memory

Every process has its own address space. The kernel maps virtual pages to physical frames lazily: pages are allocated when first touched. This gives isolation, memory-mapped files, copy-on-write after fork and overcommit (promising more than exists, hoping not everything is used).

Key measures

  • VSZ: total virtual size, including unmapped or untouched areas, so it is often huge and misleading.
  • RSS: resident set size, the pages actually in RAM (including shared libraries counted in full in each process).
  • PSS: proportional share, dividing shared pages among users; better for totals.
  • Page cache and buffers use spare RAM for files and are reclaimed when needed; free -h shows "available".

Swap

Swap is disk space for pages that are not currently used, which lets the kernel reclaim RAM. Heavy swapping (thrashing) makes the system extremely slow. vm.swappiness controls how eagerly the kernel swaps.

The OOM killer

When allocations cannot be satisfied and reclaim fails, the kernel chooses a victim by oom_score (mostly memory use, adjusted by oom_score_adj) and sends SIGKILL.

dmesg -T | grep -i 'killed process'      # evidence of an OOM kill
cat /proc/<pid>/oom_score

In containers, cgroup memory limits trigger a cgroup-level OOM kill when the container exceeds its limit, even when the host has free memory (Kubernetes shows OOMKilled).

Diagnosis

Check free, vmstat 1 (swap in and out), top sorted by RES, and application memory growth. Fix leaks, raise limits or add memory; do not simply disable the OOM killer.
