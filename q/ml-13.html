When is PR-AUC (Precision-Recall AUC) preferred over ROC-AUC for imbalanced datasets?

ML / AI engineer · Gear 2 (Mid-level) · Metrics · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

With rare positives, ROC-AUC can look excellent because the false positive rate divides by the huge number of negatives, so many false alarms barely move it. PR-AUC uses precision, which counts those false alarms directly, so it reflects how useful the positive predictions are. Prefer PR-AUC when positives are rare and matter most.

Explained in depth

The difference

  • ROC plots true positive rate against false positive rate, where FPR = FP / (FP + TN). With a million negatives, 1,000 false positives give an FPR of only 0.001.
  • A PR curve plots precision = TP / (TP + FP) against recall. If there are only 100 positives and the model finds 80 of them, those 1,000 false positives give a precision of 80 / 1,080, about 7%, which shows the practical cost.

Baselines

A random classifier scores ROC-AUC of 0.5 whatever the class balance. The random baseline for PR-AUC equals the positive rate (for example 0.01 for 1% positives), so a PR-AUC of 0.3 can be a big improvement even though it looks low.

When to use which

  • PR-AUC (average precision): fraud, disease screening, anomaly detection, retrieval, anywhere the positive class is rare and false alarms are costly.
  • ROC-AUC: roughly balanced classes, or when you care equally about both classes. It does not depend on the class ratio, which makes it useful for comparing across datasets.

Cautions

  • PR-AUC depends on prevalence, so values are not comparable between datasets with different positive rates.
  • Use average precision rather than the trapezoid rule on a PR curve, because linear interpolation between points is misleading.
  • Neither metric picks the operating threshold. Choose it from business costs, precision at a fixed recall, or recall at a fixed precision.
  • Report confidence intervals; with very few positives, both metrics are noisy.
