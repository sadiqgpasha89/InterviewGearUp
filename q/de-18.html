Compare Resilient Distributed Datasets (RDD), DataFrames, and Datasets in Apache Spark.

Data engineer · Gear 2 (Mid-level) · Spark · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

RDDs are the low-level distributed collections of objects with no schema, offering full control but no query optimisation. DataFrames add named columns and a schema and run through the Catalyst optimiser and Tungsten engine, making them much faster. Datasets add compile-time type safety for JVM languages (Scala and Java) on top of the same engine. Python and R use DataFrames.

Explained in depth

RDD (Resilient Distributed Dataset)

An immutable, partitioned collection of arbitrary objects with transformations (map, filter) and lineage for fault tolerance. Spark does not know what is inside, so it cannot optimise column access or push down filters, and serialisation is heavier. Use it for unstructured data, custom partitioning and fine-grained control.

DataFrame

A distributed table with a schema (named, typed columns). Operations are expressed as declarative expressions, which lets the Catalyst optimiser reorder, prune columns and push predicates down, and Tungsten use compact binary memory and generated code.

df = spark.read.parquet('events')
df.filter(df.country == 'IN').groupBy('day').count()

Dataset (Scala and Java)

A DataFrame with a compile-time type: Dataset[Order]. You get type-checked lambdas (ds.map(o => o.amount)) and encoders, but typed lambdas are opaque to Catalyst, so some optimisations are lost. In Scala, DataFrame is just Dataset[Row].

Guidance

Prefer DataFrames and Spark SQL with built-in functions. Python UDFs move rows between the JVM and Python, which is slow; use built-ins, SQL expressions or pandas UDFs (vectorised with Arrow) instead.
