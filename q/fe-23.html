What triggers a Block Formatting Context (BFC) and how does it prevent margin collapse?

Frontend engineer · Gear 2 (Mid-level) · CSS · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A Block Formatting Context is an isolated layout region in which block boxes lay out vertically and floats are contained. It is created by overflow other than visible, display flow-root, floats, absolute positioning, flex or grid items and similar properties, and margins do not collapse across its boundary.

Explained in depth

What a BFC is

A BFC is a region of the page where block-level boxes are laid out according to normal flow rules, independently of the outside. The root element always forms one. Within a BFC, boxes stack vertically, each touching the left edge of the container, and vertical distances are determined by margins.

What creates a new BFC

  • The root <html> element
  • float other than none
  • position: absolute or fixed
  • display: inline-block, table-cell, table-caption, flow-root
  • overflow other than visible (such as hidden, auto, scroll)
  • Flex items and grid items (they establish independent formatting contexts), flex and grid containers for their children
  • contain: layout, content or paint, and elements with column-span: all

The cleanest modern way is display: flow-root, which exists only to create a BFC.

What a BFC changes

  1. Contains floats: a parent whose children are all floated normally collapses to zero height; a BFC parent grows to enclose them (the old "clearfix" problem).
  2. Prevents margin collapse between the BFC's box and its children or siblings outside.
  3. Does not overlap floats: a BFC box next to a float is placed beside it, not underneath, which is how the "media object" layout works.

Margin collapse in practice

Adjacent vertical margins of block boxes in the same BFC combine into the larger one (20px over 30px gives 30px). A parent and its first child collapse if nothing (padding, border, inline content or a BFC) separates them, causing the notorious bug where a child's margin-top pushes the whole parent down.

.card { display: flow-root; }      /* child margins stay inside the card, floats are contained */
.clear::after { content: ""; display: block; clear: both; }  /* legacy approach */

Margins that never collapse

Horizontal margins, margins of floats, absolutely positioned boxes, inline-blocks, and flex or grid items.

Debugging tip

If a gap appears or disappears unexpectedly, check whether a parent is a BFC. Adding padding, border or display: flow-root stops the collapse; switching a parent to flex or grid also stops the child's margin from collapsing through it.

Pitfalls

overflow: hidden creates a BFC but also clips shadows and focus outlines and can create scrollbars. Prefer flow-root when the goal is only containment.
