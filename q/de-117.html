How do you control the cost of a petabyte-scale data platform without hurting users?

Data engineer · Gear 4 (Lead / Staff) · Cost · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Attribute cost to teams, then attack the largest drivers in order: storage lifecycle and file formats, compute rightsizing and autoscaling with workload isolation, query optimisation through partitioning and clustering, pruning unused tables and pipelines, and commitment discounts. Set budgets and guardrails, report unit costs, and make teams accountable with showback.

Explained in depth

Make cost visible

  • Tag compute and storage by team, project and pipeline; use warehouse query tags and resource monitors. Build a cost dashboard: spend by team, by job, by dataset, and trends.
  • Define unit metrics: cost per terabyte processed, per pipeline run, per active user, per business metric produced.
  • Set budgets and alerts, with anomaly detection for sudden spikes (a runaway query or a loop of retries).

Storage

  • Lifecycle policies: move cold data to cheaper tiers (infrequent access, archive), delete temporary and intermediate data, expire old snapshots and time travel retention, and clean up orphaned files.
  • Use columnar compressed formats (Parquet with Zstd), compaction of small files, and avoid storing duplicate copies and unneeded raw copies.
  • Delete or archive unused tables: usage logs often show a large share of tables never queried.

Compute

  • Right-size clusters and warehouses; use autoscaling and auto-suspend, spot or preemptible instances for fault-tolerant batch jobs, and separate workloads (ETL, BI, ad hoc) so one cannot starve or inflate another.
  • Schedule heavy jobs off-peak, avoid unnecessary full refreshes (use incremental models), and cache results.
  • Tune Spark: partition sizes, avoid skew and excessive shuffles, broadcast small tables, and select needed columns only.

Query and modelling practices

  • Partition and cluster large tables on common filters so queries scan less, avoid SELECT *, use pre-aggregated tables and materialised views for repeated heavy queries, and set per-query byte limits.
  • Review top costly queries weekly and coach authors, using query profiles.

Pricing

Move steady baseline usage to commitments (reserved capacity, slot reservations, savings plans) while keeping on-demand for spikes. Negotiate enterprise agreements, and evaluate whether another engine is cheaper for specific workloads.

Governance

Showback or chargeback, guardrails (default limits, approval for large clusters), and make optimisation part of team goals. Balance savings with engineering effort and user productivity: remove obvious waste first, then target big recurring costs.
