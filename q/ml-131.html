How would you design short-term, episodic and long-term memory for an insurance assistant without overflowing the context window?

ML / AI engineer · Gear 3 (Senior) · Agents · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Working memory is the current session (recent turns, tool results, slot values). Episodic memory holds summaries of past interactions per customer. Semantic memory is the knowledge base (policy wording, guidelines) plus extracted customer facts, retrieved on demand. Keep context small with a sliding window, summarisation at a token threshold, offloaded tool outputs and retrieval of only relevant memories.

Writing memory well

  • Do not dump raw transcripts into long-term storage. At session end, extract facts (preferred repair shop, has a teen driver, open claim id) and a short summary, with source and timestamp.
  • Update or supersede facts rather than adding contradictory copies.
  • Apply privacy rules: purpose limitation, retention limits, deletion on request, and no sensitive data the assistant does not need.

Keeping the context window under control

  • Sliding window: keep the last few turns verbatim.
  • Progressive summarisation: when usage passes a threshold (for example 60 to 70 percent of the budget), a background step folds older turns into a summary held in state.
  • Offload large tool results: a 40-page policy schedule goes to storage; the context gets a handle plus the relevant extract.
  • Retrieve, do not preload: fetch policy clauses and past episodes relevant to the current question, filtered by metadata (jurisdiction, product, effective date).
  • Reserve tokens for the system prompt, tools and the answer.

Managed options

  • Frameworks and platforms provide memory services (for example LangGraph stores, or Memory Bank on Google's Gemini Enterprise Agent Platform) that extract and retrieve memories; you still decide what is worth remembering and how long.

Likely follow-ups

  • How do you resolve a new fact that contradicts a stored one?
  • What should never be written to long-term memory?
  • How do you test that summarisation did not drop a key detail?
