What is the CSS `content-visibility: auto` property and how does it boost initial render speed?

Frontend engineer · Gear 2 (Mid-level) · CSS · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

content-visibility: auto lets the browser skip rendering work, including style, layout and paint, for off-screen elements until they are near the viewport. With contain-intrinsic-size reserving placeholder space, it can cut initial render time dramatically on long pages.

Explained in depth

What it does

Large pages (feeds, documentation, long dashboards) force the browser to compute style, layout and paint for thousands of elements the user cannot yet see. content-visibility: auto tells the browser to skip rendering the subtree of an element while it is off-screen, doing the work only as it approaches the viewport. It is a built-in form of virtualisation for rendering cost (not for DOM size or memory).

.section {
  content-visibility: auto;
  contain-intrinsic-size: auto 600px;     /* placeholder height until rendered */
}

Behind the scenes

auto applies contain: layout style paint (and size containment while skipped). An element that is skipped renders no children, but they remain in the DOM, accessibility tree and find-in-page. When it nears the viewport, the browser renders it normally, and remembers the last real size when you use the auto keyword in contain-intrinsic-size.

Why contain-intrinsic-size matters

While content is skipped, the element is treated as having size containment and would collapse to zero height. That makes the scrollbar jump as sections render and causes layout shift. Provide an estimated size:

  • contain-intrinsic-size: 0 500px; fixed guess
  • contain-intrinsic-size: auto 500px; use the remembered rendered size once known, else 500 px

Good estimates keep the scrollbar thumb stable and reduce CLS.

Benefits

Google's case studies reported rendering-time reductions of several-fold on long pages; for typical article lists the initial render drops noticeably, improving LCP and interactivity. Updates inside off-screen sections are cheap too, because their layout is deferred.

Values

  • visible: default, render always.
  • auto: skip when off-screen (relevant to the user), also hidden is similar to display: none but preserves rendered state.
  • hidden: always skipped (cache rendering state for tabs or off-screen panels you toggle often).

Caveats

  • Anchor links, scrollIntoView, find in page and focus navigation work because the browser renders the target on demand, but there can be a brief layout adjustment.
  • Containment means children cannot paint outside or affect outside layout (position: fixed descendants and overflowing shadows get clipped).
  • Do not apply it to elements that are above the fold, or to tiny elements (overhead exceeds benefit).
  • Browser support is wide in Chromium and Safari; Firefox added it later, so use it as progressive enhancement.
  • Semantic content stays available, but verify with screen readers for custom widgets.

Measurement

Use the Performance panel to compare "Recalculate Style" and "Layout" times, run Lighthouse, and enable the Rendering panel's paint flashing to see lazily rendered regions.

  • How does it interact with find-in-page, accessibility and anchor links?
