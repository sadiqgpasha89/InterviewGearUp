How do Web Workers offload CPU-intensive computations from the main browser UI thread?

Frontend engineer · Gear 3 (Senior) · Performance · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A Web Worker runs JavaScript on a separate thread, so heavy work such as parsing, image processing or searching does not block the main thread and freeze the UI. Workers cannot touch the DOM; they communicate by postMessage, which copies data using the structured clone algorithm, or transfers ownership of buffers without copying.

Explained in depth

Why

The main thread handles input, layout and painting. A task that takes more than about 50 ms creates a long task and makes the page feel unresponsive. A worker moves that computation elsewhere.

Using one

// main.js
const worker = new Worker('worker.js');
worker.postMessage({ numbers: bigArray });
worker.onmessage = (e) => render(e.data);

// worker.js
self.onmessage = (e) => {
  const result = heavyCompute(e.data.numbers);
  self.postMessage(result);
};

Constraints

  • No access to document, window or the DOM. APIs like fetch, timers, IndexedDB and WebSocket are available.
  • Messages are copied (structured clone). For large buffers, transfer them (postMessage(buf, [buf])), which moves ownership in O(1) and leaves the sender with an empty buffer.
  • SharedArrayBuffer plus Atomics give truly shared memory, but require cross-origin isolation headers.
  • Starting a worker has a cost, so reuse them or use a pool sized near the number of CPU cores (navigator.hardwareConcurrency).

Kinds

  • Dedicated: owned by one page.
  • Shared: shared by several tabs of the same origin.
  • Service workers: a proxy for network requests, caching and push, not for computation.

Good uses

Parsing large JSON or CSV, image and video processing, compression, search indexes, cryptography and WebAssembly modules. Libraries such as Comlink make the messaging look like function calls. The worker's code must be served from a same-origin URL that is allowed by your Content Security Policy.
