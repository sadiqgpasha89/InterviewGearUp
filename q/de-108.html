Compare CSV, JSON and Parquet as data file formats.

Data engineer · Gear 1 (Junior) · Fundamentals · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

CSV is simple, human-readable and universal but has no types or nesting and is slow and large at scale. JSON supports nested, flexible structures and is the standard for APIs but is verbose and slow to scan. Parquet is a compressed, typed, columnar binary format that makes analytical queries much faster and cheaper, and is the default choice for data lakes.

Why Parquet wins for analytics

Data is stored by column: a query that needs 3 of 100 columns reads only those. Similar values compress well (dictionary and run-length encoding, Snappy or Zstandard). Row groups store min and max statistics so engines skip chunks (predicate pushdown). Splittable for parallel reads in Spark, Trino and others.

Pitfalls of CSV

Delimiters and quoting inside values, encodings, missing headers, no way to tell "007" from 7, dates in different formats, and no null convention. Define the schema explicitly when reading.

JSON tips

Use JSON Lines (one record per line) for big datasets so files can be split and streamed. Flatten or convert to Parquet for analysis.

Related formats

Avro (row-based with schema, good for streaming and Kafka and schema evolution), ORC (columnar, Hive ecosystem), and table formats on top of Parquet (Delta Lake, Iceberg).
