What are Linux process states (Running, Sleeping, Zombie, Stopped, Disk Sleep) and how do you handle zombies?

DevOps / SRE / Cloud · Gear 2 (Mid-level) · Linux · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A Linux process is running or runnable (R), sleeping (S, interruptible, or D, uninterruptible disk wait), stopped (T) or a zombie (Z). A zombie has already exited but its parent has not called wait() to collect its exit status, so only a process table entry remains. You cannot kill a zombie; fix or terminate the parent so init adopts and reaps it.

Explained in depth

States (shown by ps and top)

CodeStateMeaning
RRunning or runnableOn a CPU or in the run queue
SInterruptible sleepWaiting for an event (input, timer), wakes on signals
DUninterruptible sleepWaiting on I/O (disk, NFS); signals are not delivered until it finishes
TStoppedPaused by SIGSTOP or a debugger
ZZombieExited, waiting for the parent to read its exit status

Zombies

When a process exits, the kernel keeps a small entry (PID and exit code) until the parent calls wait() or waitpid(). If the parent never does, the child stays as <defunct>. A zombie uses no CPU or memory apart from the entry, but a flood of them can exhaust the PID table.

Handling them

ps -eo pid,ppid,stat,cmd | awk '$3 ~ /Z/'       # list zombies and their parents
kill -SIGCHLD <parent_pid>                       # sometimes prompts the parent to reap
kill <parent_pid>                                # if the parent is buggy; init (PID 1) then reaps the orphans

kill -9 on a zombie does nothing, because it is already dead. The real fix is correcting the parent to wait on children (or handle SIGCHLD).

In containers

The first process in a container is PID 1 and often does not reap orphans, so zombies accumulate. Run a small init (docker run --init, tini) or make the application handle SIGCHLD.

D state

Processes stuck in D usually point to storage trouble (hung NFS mount, failing disk). Investigate the I/O path; killing will not help.
