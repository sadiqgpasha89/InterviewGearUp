How does custom hook extraction promote logic reuse without component hierarchy nesting?

Frontend engineer · Gear 2 (Mid-level) · React · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A custom hook extracts stateful logic (state, effects, subscriptions) into a reusable function that any component can call. Unlike HOCs or render props it adds no extra wrapper components, keeps the tree flat, and composes naturally because hooks can call other hooks.

Explained in depth

The problem

Before hooks, sharing logic meant higher-order components (wrapper hell, prop name collisions) or render props (nested callbacks). Logic was tied to component structure.

A custom hook

A function whose name starts with use and which may call other hooks. Each call gets its own independent state.

function useDebouncedValue(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);               // cleanup when value changes or unmounts
  }, [value, delay]);
  return debounced;
}

function useFetch(url) {
  const [state, setState] = useState({ data: null, error: null, loading: true });
  useEffect(() => {
    const c = new AbortController();
    setState(s => ({ ...s, loading: true }));
    fetch(url, { signal: c.signal }).then(r => r.json())
      .then(data => setState({ data, error: null, loading: false }))
      .catch(error => { if (error.name !== 'AbortError') setState({ data: null, error, loading: false }); });
    return () => c.abort();
  }, [url]);
  return state;
}

Why it promotes reuse without nesting

  • Components stay at the same tree level; no wrappers appear in DevTools.
  • Hooks compose: useFetch uses useState, useEffect; your useSearch can combine useFetch and useDebouncedValue.
  • The logic is separated from presentation: UI components become short and declarative.
  • Typed, explicit inputs and outputs replace implicit prop injection.

Rules

Call hooks only at the top level (no conditions, loops or nested functions) and only from React functions or other hooks. React relies on call order to associate state with each hook. The eslint-plugin-react-hooks rules enforce this and check dependency arrays.

Custom hook versus utility function

If the code needs useState, useEffect, context or refs, it must be a hook. Pure computations (formatting, math) should remain plain functions that are easier to test and call anywhere.

Testing

Use renderHook from React Testing Library, wrapping providers when needed, and drive updates with act. Test the observable behaviour, not the internals.

Pitfalls

Hooks that return unstable objects and functions (memoise when passed to memoised children), stale closures from missing dependencies, hidden global state shared by module variables, and hooks that do too much. Prefer a battle-tested library (TanStack Query, SWR, VueUse-like collections) for data fetching.
