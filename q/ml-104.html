What is feature engineering and what are common techniques?

ML / AI engineer · Gear 1 (Junior) · Preprocessing · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Feature engineering transforms raw data into inputs that make patterns easier for a model to learn. Common techniques include encoding categories, scaling numbers, creating ratios and aggregations, extracting date and text features, handling missing values and outliers, and selecting features. Good features often beat switching algorithms, but every step must be fit on training data only.

Explained in depth

Why it matters

Models learn from the representation you give them. A raw timestamp means little, while "hour of day", "is weekend" and "days since last purchase" expose real signals.

Common techniques

  • Categorical encoding: one-hot (few categories), ordinal (ordered categories), target or frequency encoding (many categories, with cross-validated fitting to avoid leakage), and embeddings for high-cardinality IDs.
  • Numeric transformations: log or square-root for skewed values, binning into ranges, scaling (standardisation, min-max) for distance-based and gradient-based models, and clipping or winsorising outliers.
  • Missing values: impute (median, mode, model-based) and add a missing indicator feature, since missingness can be informative.
  • Interactions and ratios: price per square metre, clicks divided by impressions, products and differences of features.
  • Date and time: hour, day of week, month, holiday flags, cyclical encoding with sine and cosine, and elapsed time.
  • Aggregations: per-user counts, averages and recency over windows (last 7 and 30 days) from event data.
  • Text: TF-IDF, n-grams, or embeddings; images and audio use learned or extracted features.
  • Feature selection: remove constant, highly correlated or low-importance features using filters, regularisation (L1), or model-based importance.

Rules to avoid mistakes

  1. Split data first and fit every transform on the training set only (use pipelines), to prevent leakage.
  2. Build time-based features using only information available at prediction time.
  3. Apply exactly the same transformations in training and serving (a feature store or shared code avoids training-serving skew).
  4. Validate each new feature with cross-validation and ablation, and keep features documented and monitored for drift.

Deep learning learns many representations automatically, but on tabular data, careful feature engineering with gradient boosting remains very competitive.
