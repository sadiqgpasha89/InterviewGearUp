How does Isolation Forest isolate anomalous points using random binary partitioning trees?

ML / AI engineer · Gear 2 (Mid-level) · Anomaly · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Isolation Forest isolates observations by randomly picking a feature and a random split value between its min and max, building many random binary trees. Anomalies are few and different, so they are separated from the rest in fewer splits, giving shorter average path lengths. The anomaly score converts path length to a value near 1 for anomalies and well below 0.5 for normal points.

Explained in depth

Intuition

Normal points sit in dense regions and need many random cuts to be separated from neighbours. An outlier lies far away or in a sparse region, so a few random cuts isolate it. Instead of profiling normal data and flagging deviations (distance, density, reconstruction methods), Isolation Forest explicitly isolates anomalies.

Algorithm

Training (building iTrees):

  1. Draw a subsample of size ψ (default 256) from the data; this controls swamping and masking and keeps trees small.
  2. Build a binary tree recursively: choose a random feature, choose a random split value uniformly between the feature's min and max in the node; send points left or right; stop when a node has one point, all points are identical, or depth reaches ceil(log2 ψ).
  3. Repeat for t trees (default 100).

Scoring a point x:

  • Compute the path length h(x) in each tree (number of edges from root to the leaf, plus an adjustment c(size) for leaves that were not fully isolated).
  • Average over trees: E[h(x)].
  • Anomaly score: s(x, ψ) = 2^(−E[h(x)] / c(ψ)), where c(ψ) = 2H(ψ−1) − 2(ψ−1)/ψ is the average path length of an unsuccessful search in a binary search tree (normalisation).

Interpretation: s close to 1 means very short path (anomaly); s much smaller than 0.5 means long paths (normal); s about 0.5 for all points means no clear anomalies.

from sklearn.ensemble import IsolationForest
iso = IsolationForest(n_estimators=200, max_samples=256, contamination="auto", random_state=0).fit(X_train)
scores = -iso.score_samples(X_test)            # higher means more anomalous
labels = iso.predict(X_test)                    # -1 anomaly, 1 normal

Properties

  • Linear time and low memory: O(t · ψ · log ψ) to train and O(t · log ψ) per point to score, independent of dataset size because of subsampling; handles millions of rows quickly.
  • No distance or density computation, no normalisation of features needed (splits are per feature), handles mixed scales, works unsupervised (no labels).
  • Parallelisable and easy to deploy; supports streaming variants (Robust Random Cut Forest, Extended Isolation Forest).
  • Sub-sampling actually improves detection by reducing swamping (normal points near anomalies) and masking (clusters of anomalies).

Choosing the threshold

contamination is the expected proportion of anomalies used to set the decision threshold on scores. Unknown in practice: use domain knowledge, review the top-ranked items with experts, set a threshold from a score distribution or percentile, or tune on any labelled anomalies using precision-recall at K. Treat output as a ranking feeding human review or downstream rules.

Limitations

  • Axis-parallel splits create artefacts (score bands along axes); Extended Isolation Forest uses random hyperplanes.
  • Struggles with local anomalies inside dense regions of different densities (use LOF), clustered anomalies larger than the sample size, and high-dimensional data with many irrelevant features (random feature choice dilutes signal); apply feature selection.
  • Categorical features need encoding; scores are not calibrated probabilities; no explanation by default (use SHAP's TreeExplainer on isolation trees or path analysis).
  • Time series need engineered features (rolling stats, seasonality-adjusted residuals).

Applications

Fraud and payment anomalies, network intrusion, sensor and predictive maintenance, data quality monitoring, log analysis.

Pitfalls

Setting contamination arbitrarily, interpreting scores as probabilities, ignoring drift in what "normal" means (retrain periodically), and not validating with domain experts.

Likely follow-ups

  • Why does it not need distance or density computation and why is it fast?
  • How do you set the contamination parameter and threshold?
  • What are its blind spots, such as clustered anomalies and high-dimensional noise?
