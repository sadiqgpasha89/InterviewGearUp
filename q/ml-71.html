Explain Two-Tower Neural Network architecture for candidate retrieval in large-scale recommender systems.

ML / AI engineer · Gear 3 (Senior) · Recommenders · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

A two-tower model learns separate neural encoders for users (and context) and for items, each producing an embedding in a shared space, and scores relevance by the dot product or cosine of the two. Item embeddings are precomputed and indexed for approximate nearest neighbour search, so candidate retrieval over millions of items takes milliseconds, before a heavier ranker refines the shortlist.

Explained in depth

Where it fits: multi-stage recommender

  1. Candidate retrieval (millions to billions of items → hundreds to thousands): must be extremely fast, so it uses a two-tower model plus ANN.
  2. Ranking (hundreds → tens): a rich model scoring user-item pairs with cross features (wide and deep, DCN, transformers).
  3. Re-ranking (business rules, diversity, freshness, fairness).

Architecture

user features (id embedding, history sequence, demographics, context)  → user tower (MLP / transformer) → u ∈ R^d
item features (id embedding, text/image embeddings, category, price)    → item tower (MLP)               → v ∈ R^d
score(u, v) = <u, v>   (or cosine, with a learned temperature)
  • Each tower is an independent deep network that maps its inputs to a d-dimensional embedding (64 to 256), usually L2-normalised.
  • Because the towers interact only at the final dot product, item embeddings do not depend on the user, so they can be computed offline for the entire catalogue and stored in an ANN index (FAISS, ScaNN, HNSW, Vertex Matching Engine, Milvus). At request time compute the user embedding once (cheap), query the index for top-K nearest items.

Training

Data: positive interactions (clicks, purchases, watches) as (user, item) pairs. Objective: make positive pairs score higher than negatives.

  • Softmax cross-entropy with in-batch negatives: for a batch of B positive pairs (u_i, v_i), treat the other items v_j (j ≠ i) in the batch as negatives for user u_i:

L = − (1/B) Σ_i log [ exp(s(u_i, v_i)/τ) / Σ_j exp(s(u_i, v_j)/τ) ] It is efficient (B² scores from B forward passes in each tower) and standard in YouTube and Google's retrieval papers.

  • Sampling bias correction: in-batch negatives are drawn proportional to item popularity, which over-penalises popular items; apply a logQ correction (subtract log p(item) from logits) using estimated sampling probability.
  • Hard negatives: items shown but not engaged, or retrieved by the previous model, mixed with random negatives for better discrimination; avoid false negatives (unseen but relevant).
  • Alternatives: BPR/pairwise loss, sampled softmax, contrastive losses with temperature; multi-task heads (watch time plus click).
import tensorflow as tf, tensorflow_recommenders as tfrs
class TwoTower(tfrs.Model):
    def __init__(self, user_model, item_model, items_ds):
        super().__init__()
        self.user_model, self.item_model = user_model, item_model
        self.task = tfrs.tasks.Retrieval(metrics=tfrs.metrics.FactorizedTopK(items_ds.batch(256).map(item_model)))
    def compute_loss(self, features, training=False):
        return self.task(self.user_model(features["user"]), self.item_model(features["item"]))

Serving

  1. Batch job (daily or hourly) recomputes item embeddings, builds or updates the ANN index with metadata filters (availability, region).
  2. Online: fetch user features (feature store), compute the user embedding via the user tower, ANN search for top K (hundreds), apply filters, send candidates to the ranker.
  3. Real-time signals: session history in the user tower, incremental index updates for new items, embedding cache.
  4. Monitor recall@K versus offline brute force, latency, embedding drift, coverage and diversity.

Pros and cons

Pros: scales to huge catalogues, low latency, cold-start handling for items via content features, decoupled and cacheable, multiple retrieval sources can be merged. Cons: limited feature interaction (only dot product at the end, no user-item cross features), so lower accuracy than ranking models; ANN approximation loss; sensitivity to negative sampling choices; embedding staleness; popularity bias.

Extensions

Multi-interest towers, sequence-based user towers (transformers), graph-based item towers, deep retrieval with learned tree indexes, multimodal item towers, query towers for search (dual encoders as in dense retrieval).

Pitfalls

Training and serving feature mismatch, mixing normalised and unnormalised vectors with inner-product indexes, leakage of future interactions in the user history, and evaluating retrieval with random splits.

Likely follow-ups

  • Why must the towers not share cross features, and what do you lose compared to a ranking model?
  • How does in-batch negative sampling work and what is sampling bias correction?
  • How do you serve and refresh embeddings in production?
