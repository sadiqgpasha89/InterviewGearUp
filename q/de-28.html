What are open table formats (Apache Iceberg, Delta Lake, Apache Hudi) and what problems do they solve?

Data engineer · Gear 3 (Senior) · Lakehouse · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Open table formats (Apache Iceberg, Delta Lake, Apache Hudi) add a metadata layer on top of Parquet files in object storage so they behave like real tables. They provide ACID transactions, schema evolution, time travel, row-level updates and deletes, and efficient file pruning, solving the unreliability and slowness of raw files in a data lake.

Explained in depth

Problems with plain files in object storage

  • No atomic multi-file commits: a failed job leaves partial files and readers see inconsistent data.
  • Listing millions of files is slow, and there are no statistics to prune.
  • No safe updates or deletes (needed for GDPR or CDC), no schema enforcement, and concurrent writers conflict.

What a table format adds

A metadata and transaction log records exactly which data files belong to each table version. A commit atomically swaps the pointer to a new version.

  • ACID with snapshot isolation: readers see a consistent snapshot while writers commit.
  • Schema evolution (add, rename and drop columns safely) and partition evolution.
  • Time travel and rollback to earlier snapshots.
  • Upserts and deletes (MERGE INTO), enabling CDC and streaming.
  • File-level statistics for skipping data, plus compaction and clustering.

Operations

Run compaction, expire old snapshots, remove orphan files and manage a catalog (Hive metastore, Glue, REST catalog). Interoperability tools can expose one format through another's reader.
