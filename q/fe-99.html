What are synthetic events in React and how do they differ from native browser events?

Frontend engineer · Gear 2 (Mid-level) · React · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

React's synthetic events are cross-browser wrapper objects that React passes to your handlers. They normalise the native event API, are delegated to the React root container instead of each node, and since React 17 are no longer pooled. They share the common interface of native events with stopPropagation, preventDefault and nativeEvent access.

Explained in depth

What they are

onClick, onChange, onKeyDown handlers receive a SyntheticEvent that wraps the browser event and provides a consistent interface (target, currentTarget, type, preventDefault(), stopPropagation(), isDefaultPrevented()), with e.nativeEvent as the escape hatch.

function Form() {
  const onSubmit = (e) => { e.preventDefault(); console.log(e.nativeEvent instanceof Event); };
  return <form onSubmit={onSubmit}>...</form>;
}

Differences from native events

  • Delegation: React attaches one listener per event type at the root container (React 17 and later; at document in 16) and dispatches to the matching handlers through the fibre tree, which is efficient for many elements.
  • Bubbling follows the React tree, not only the DOM tree, so events in a portal bubble to React ancestors.
  • Naming and API: camelCase props (onClick), handlers receive functions rather than strings, return false does nothing; call preventDefault() explicitly.
  • onChange fires on every input change (like the native input event), not only on blur.
  • onFocus and onBlur bubble (they use focusin and focusout under the hood), unlike native focus and blur.
  • Pooling removed: before React 17 the event object was reused and nullified after the handler, so async access required e.persist(). Now it is safe to read in async code, although it is still better to copy needed values.
  • Scroll and wheel handlers may be passive; onWheel, onTouchStart registered passively by React, so preventDefault in them can fail. Add native non-passive listeners for that.
  • Some native events (onScroll) do not bubble in React 17 and later, matching the browser.

Mixing with native listeners

Native listeners attached to document or window run after React's root handler for bubbling events, and e.stopPropagation() in React stops only React propagation plus native bubbling above the root. Use e.nativeEvent.stopImmediatePropagation() carefully, or capture phase props (onClickCapture) to run earlier. For outside-click detection attach a pointerdown listener in useEffect and compare with ref.current.contains(e.target).

Practical tips

Use e.currentTarget for the element that owns the handler and e.target for the origin of the event. Type handlers in TypeScript with React.MouseEvent<HTMLButtonElement>. Prefer a single delegated handler with data-* attributes for very large lists only when profiling shows a problem, since React already delegates internally.
