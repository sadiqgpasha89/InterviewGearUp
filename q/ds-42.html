How do you do a power analysis and choose the sample size and duration for an experiment?

Data scientist · Gear 3 (Senior) · Experimentation · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Fix the primary metric, baseline and variance, the minimum detectable effect that matters to the business, significance level and power, then compute the per-arm sample size, typically n = 2 (z_alpha/2 + z_beta)^2 sigma^2 / delta^2. Convert to days using eligible traffic, round up to whole weeks to capture weekly cycles, and decide the stopping rule in advance.

Explained in depth

Inputs

  1. Primary metric and its baseline value and variance (from historical data, using the same unit of randomisation).
  2. Minimum detectable effect (MDE): the smallest change that would change a decision (cost to build, value gained). Not "what we hope to see".
  3. Significance level alpha (usually 0.05, two-sided): tolerated false-positive rate.
  4. Power (1 - beta) (usually 0.8, or 0.9 for important decisions): probability of detecting an effect of size MDE if it exists.
  5. Allocation ratio, number of variants, and one- or two-sided test.

Formulas

For comparing two means with equal allocation: n per arm = 2 (z_{1-alpha/2} + z_{1-beta})^2 sigma^2 / delta^2. With alpha 0.05 and power 0.8, (1.96 + 0.84)^2 = 7.85, so n = 15.7 sigma^2 / delta^2. For proportions: use p1 and p2 = p1 + delta with variance p(1 - p). A quick rule: n per arm is about 16 p (1 - p) / delta^2. Example: baseline conversion 10 percent, want to detect an absolute lift of 1 point: n is about 16 x 0.1 x 0.9 / 0.0001 = 14,400 per arm. Detect 0.5 point: 57,600, four times as many (n scales with 1 / delta^2).

from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize
es = proportion_effectsize(0.11, 0.10)
n = NormalIndPower().solve_power(effect_size=es, alpha=0.05, power=0.8, ratio=1.0)
print(round(n))

Converting to duration

Duration = (n per arm x number of arms) / eligible daily users who enter the experiment. Adjust for:

  • Weekly seasonality: run full weeks (at least 1 to 2).
  • Novelty and primacy effects: early behaviour may not represent steady state.
  • Users appear repeatedly: if you randomise by user, each user counts once; sessions are not independent.
  • Ramp-up (1 percent to 50 percent) for safety.
  • For metrics with long maturity (retention at 28 days) the experiment must include that follow-up.

Levers when the sample is too small

  • Reduce variance: CUPED, stratification, triggered analysis, winsorising, a less noisy metric.
  • Increase the MDE (accept only larger effects), the traffic share, or the duration.
  • Relax power or alpha knowingly, or switch to a one-sided test if only improvement matters (document).
  • Use a sequential or Bayesian design so you can stop early when the effect is large.
  • Combine related tests or move to a quasi-experiment for low-traffic situations.

Related considerations

  • Multiple metrics and variants: apply corrections or pre-specify the primary metric; power drops with more comparisons.
  • Cluster randomisation (by store, city, classroom): the design effect = 1 + (m - 1) ICC inflates the needed sample.
  • Report confidence intervals, not just significance; an underpowered "not significant" result is inconclusive, not evidence of no effect.
  • Pre-register the plan: metric, MDE, stopping rule, analysis method, guardrails (latency, crash rate, revenue).
  • Peeking inflates false positives unless you use group-sequential or always-valid methods.

Pitfalls

Choosing the MDE after seeing results, using the observed effect for "post-hoc power", sizing the test on sessions instead of users, and stopping the test the moment p dips below 0.05.

Likely follow-ups

  • How does the sample size change if you halve the minimum detectable effect?
  • Why should you run experiments for full weeks and consider novelty effects when setting duration?
  • What do you do when the required sample size exceeds the traffic you have?
