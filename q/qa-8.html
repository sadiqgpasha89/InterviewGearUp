Compare Black-Box, White-Box, and Gray-Box testing methodologies with concrete examples.

QA / SDET · Gear 1 (Junior) · Fundamentals · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Black-box testing checks behaviour through inputs and outputs without looking at the code. White-box testing uses knowledge of the internal structure to design tests such as branch coverage. Gray-box testing mixes both: the tester knows some internals, such as the data model or API design, but tests mainly from the outside.

Explained in depth

Black-box

  • Based on requirements and specifications; the code is invisible.
  • Techniques: equivalence partitioning, boundary value analysis, decision tables, state transition testing and exploratory testing.
  • Example: for a login form, test valid and invalid passwords, empty fields and lockout after five failures, without knowing how the code is written.
  • Strength: reflects the user's view and finds missing requirements. Weakness: may miss untested code paths.

White-box

  • Based on the source code and design.
  • Techniques: statement, branch and path coverage, and mutation testing. Developers' unit tests are mostly white-box.
  • Example: ensure each branch of a discount function (for example a premium user, a coupon and an expired coupon) is executed by at least one test.
  • Strength: finds dead code and unexercised branches. Weakness: needs code access and skill, and it cannot find missing features.

Gray-box

  • Partial knowledge, such as the database schema, API contracts or logs.
  • Example: submit an order through the UI, then query the database to verify the correct rows and check the logs for errors; or test an API using knowledge of its validation rules.

In practice

Teams combine them: developers write white-box unit tests, QA writes black-box functional tests and gray-box integration checks.

Likely follow-ups

  • Which techniques belong to each approach (equivalence partitioning, statement coverage, and so on)?
  • Which approach do unit tests use?
  • How would you combine them on one feature?
