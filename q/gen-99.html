Explain the Boyer-Moore Majority Vote algorithm to find the majority element in $O(N)$ time and $O(1)$ space.

Software engineer (core) · Gear 2 (Mid-level) · Algorithms · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Boyer-Moore voting keeps one candidate and a counter: matching elements increment it, others decrement it, and at zero a new candidate is chosen. If a majority element (more than n/2 occurrences) exists it must survive. It runs in O(n) time with O(1) space; a second pass verifies the candidate.

Explained in depth

Problem

Given an array of n items, find the element that appears more than n/2 times, if it exists. Alternatives: counting with a hash map (O(n) time, O(n) space) or sorting and taking the middle element (O(n log n)).

Algorithm

def majority(nums):
    cand, count = None, 0
    for x in nums:
        if count == 0:
            cand = x
        count += 1 if x == cand else -1
    # verification pass (needed unless the majority is guaranteed)
    return cand if nums.count(cand) > len(nums) // 2 else None

Intuition: cancelling pairs

Think of each decrement as pairing one occurrence of the candidate with a different element and removing both. A true majority element has more than n/2 copies, so it cannot be completely cancelled by the at most n - (copies) other elements: at least one copy survives. When the counter returns to zero, the prefix processed so far consists of pairs of distinct elements plus matching candidate copies, in which the candidate has exactly half of the prefix, so removing that prefix leaves the majority property intact for the suffix.

The final candidate is 2, which appears 4 times out of 7, so it is the majority.

Why verify

The algorithm's guarantee is one-directional: if a majority exists, it is returned. For [1, 2, 3] it returns 3, which is not a majority. A second linear pass counting the candidate confirms it.

Generalisation (Misra-Gries)

To find all elements occurring more than n/k times, keep up to k - 1 candidate counters; when a new element has no counter and none is free, decrement all counters. At most k - 1 elements can exceed n/k, and a verification pass filters false candidates. For k = 3 use two candidates. This also underlies streaming heavy-hitter estimation with fixed memory.

Complexity and use

Time O(n), space O(1), single pass over a stream. Useful when data does not fit in memory or comes as a stream (log analysis, votes, telemetry), and when it can be merged across partitions (combine candidate and count pairs).

Pitfalls

Skipping verification, handling empty input, and applying it when the "majority" threshold is smaller than n/2 (needs the generalised version).

Likely follow-ups

  • How do you generalise this to find all elements appearing more than n/3 times?
  • Why is the verification pass needed when no majority is guaranteed?
  • Why does the pairing-off argument prove correctness?
