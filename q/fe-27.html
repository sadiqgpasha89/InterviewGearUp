What are CSS Container Queries and how do they differ from viewport Media Queries?

Frontend engineer · Gear 3 (Senior) · CSS · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Container queries apply styles based on the size of a component's containing element, not the viewport. You mark a parent with container-type and then write @container rules, so a card can switch layout depending on the space it is given wherever it is placed. Media queries only know the viewport, so they cannot adapt a reusable component to its context.

Explained in depth

Why they exist

A card in a wide main column and the same card in a narrow sidebar need different layouts, but the viewport width is identical. Media queries cannot distinguish them; container queries can.

Usage

.card-wrapper {
  container-type: inline-size;   /* make this element a query container */
  container-name: card;          /* optional */
}

.card { display: grid; gap: 8px; }

@container card (min-width: 480px) {
  .card { grid-template-columns: 160px 1fr; }   /* side-by-side when there is room */
}

Details

  • container-type: inline-size lets descendants query the container's width (the inline axis). The container's own size must not depend on its contents along that axis, which is why the property creates containment.
  • Container query units (cqw, cqh, cqi) size things relative to the container.
  • Style queries (@container style(--theme: dark)) are a newer, separate feature with narrower support.
  • Support is broad in current browsers; older ones need a fallback layout.

Media versus container

  • Media queries: page-level decisions such as navigation layout, global typography and user preferences (prefers-color-scheme, print).
  • Container queries: component-level responsiveness in design systems, where placement varies.
