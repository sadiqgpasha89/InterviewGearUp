What are structured, semi-structured and unstructured data? Give examples and how each is stored and queried.

Data engineer · Gear 1 (Junior) · Fundamentals · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Structured data fits fixed rows and columns, like relational tables. Semi-structured data has tags or keys but a flexible schema, such as JSON, XML and logs. Unstructured data has no predefined model, such as text, images, audio and video. Each needs a different storage and processing approach, from SQL warehouses to document stores and object storage with specialised tools.

Explained in depth

Structured data

  • Organised in a fixed schema: tables with typed columns and rows.
  • Examples: customers, orders, transactions, spreadsheets, CSV exports.
  • Stored in relational databases and warehouses (PostgreSQL, Snowflake, BigQuery); queried with SQL. Schema is enforced on write (schema-on-write).

Semi-structured data

  • Has self-describing structure (keys, tags, nesting) but not a rigid, uniform schema; fields can vary or be optional.
  • Examples: JSON from APIs, XML, Avro and Parquet files (with embedded schema), event and application logs, clickstream.
  • Stored as files in a lake, in document databases (MongoDB), or in warehouse columns of type VARIANT (Snowflake), JSON (PostgreSQL) or STRUCT and ARRAY (BigQuery). Queried with SQL JSON functions or by flattening nested fields. Often schema-on-read: you decide the structure when reading.

Unstructured data

  • No predefined model or uniform fields; most real-world data by volume.
  • Examples: documents and emails, PDFs, images, audio, video, social posts.
  • Stored in object storage (S3, GCS, Blob) with metadata catalogues; processed with specialised tools: NLP and OCR, speech-to-text, computer vision, and embeddings stored in vector databases for semantic search.

Practical approach

Land everything in a lake, then extract structure: parse JSON into columns, generate text from documents, create embeddings, and produce tables used for analytics. Key issues to manage: schema evolution, data quality, cost of storing big files, privacy (documents often contain personal data) and metadata for discovery.
