Explain binary search: Classic exact match implementation and avoiding integer overflow in midpoint calculation.

Software engineer (core) · Gear 1 (Junior) · Algorithms · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

Binary search repeatedly halves a sorted range: compare the middle element with the target and discard the half that cannot contain it. It runs in O(log N). Compute the midpoint as lo + (hi - lo) / 2 instead of (lo + hi) / 2, because the sum can overflow a fixed-width integer.

Explained in depth

Implementation

def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

Midpoint overflow

In languages with 32-bit ints, lo + hi can exceed 2^31 - 1 for large arrays and wrap to a negative number. This bug sat in the Java standard library for years. lo + (hi - lo) / 2 never exceeds hi, so it is safe. (Python has arbitrary-precision ints, so it does not overflow there.)

Details that matter

  • The array must be sorted and support O(1) random access.
  • Be consistent about the range: with lo <= hi and hi = len - 1, use mid + 1 and mid - 1. Mixing conventions causes off-by-one bugs and infinite loops.
  • Each iteration halves the range, so at most about log2(N) steps. For one billion elements that is roughly 30 comparisons.
  • It can also search on an answer space, for example the smallest value that satisfies a monotonic condition.
