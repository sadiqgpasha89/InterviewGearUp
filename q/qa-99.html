How do you automate interactions with native OS file dialogs and authentication popups in Playwright?

QA / SDET · Gear 2 (Mid-level) · UI Automation · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Playwright does not drive native OS dialogs, so avoid them by using browser-level APIs: file chooser events or setInputFiles for uploads, httpCredentials in the context for HTTP basic or NTLM auth, dialog events for alert and confirm, and download events for save prompts. For anything truly native, use OS-level tools or a different driver sparingly.

Explained in depth

Why native dialogs are a problem

Browser automation protocols (CDP, WebDriver BiDi) control web content. Operating system file pickers, HTTP authentication prompts, print dialogs and some permission bubbles are browser chrome or OS windows outside the page, so selectors cannot reach them. Playwright provides purpose-built hooks that bypass the UI while triggering the same application behaviour.

File dialogs

// 1) Set files directly on the input, even if hidden
await page.setInputFiles('input[type=file]', 'fixtures/report.pdf');
// 2) When the page opens a chooser from a custom button (no visible input)
const [chooser] = await Promise.all([page.waitForEvent('filechooser'), page.getByRole('button', { name: 'Upload' }).click()]);
await chooser.setFiles(['fixtures/a.png', 'fixtures/b.png']);
// 3) Directory upload and in-memory files
await page.setInputFiles('input[webkitdirectory]', 'fixtures/folder');
await page.setInputFiles('input[type=file]', { name: 'x.txt', mimeType: 'text/plain', buffer: Buffer.from('data') });
// Save-as: use download events, not the dialog
const [dl] = await Promise.all([page.waitForEvent('download'), page.click('text=Export')]);
await dl.saveAs('tmp/export.csv');

The File System Access API (showOpenFilePicker, showSaveFilePicker) is not controllable via filechooser; stub it with page.addInitScript to return in-memory handles in tests.

Authentication popups

Basic, Digest and NTLM/Negotiate challenges trigger a browser prompt. Supply credentials ahead of time:

const context = await browser.newContext({ httpCredentials: { username: 'qa', password: process.env.BASIC_PASS!, origin: 'https://intranet.example.com' } });

Alternatives: embed credentials in the URL (https://user:pass@host, deprecated and often blocked), or send an Authorization header via page.setExtraHTTPHeaders or route.continue({ headers }). For Windows integrated auth (Kerberos or NTLM) configure the browser (--auth-server-allowlist for Chromium, Firefox policies) and run on an authenticated machine, or bypass authentication in test environments with API tokens. SSO popups are normal web pages: use waitForEvent('popup') or API-based login with storageState.

JavaScript dialogs

alert, confirm, prompt and beforeunload are exposed as events: register the handler before the triggering action, otherwise Playwright auto-dismisses.

page.once('dialog', async d => { expect(d.message()).toContain('Delete this item?'); await d.accept(); });
await page.click('text=Delete');

Permission prompts and other browser UI

  • Camera, microphone, geolocation, notifications, clipboard: grant or deny through the context (permissions: ['geolocation'], context.grantPermissions, clearPermissions), and use Chromium fake media flags (--use-fake-device-for-media-stream --use-fake-ui-for-media-stream --use-file-for-fake-video-capture=clip.y4m).
  • Print dialog (window.print()): stub window.print and assert it was called, or generate PDFs with page.pdf() (Chromium headless) and validate content.
  • Download bubbles and "open with" prompts: use the download event; configure the browser profile to avoid prompts.
  • Popups and new tabs: popup event; new windows: context.on('page').
  • Certificate errors: ignoreHTTPSErrors: true in test environments; client certificates via clientCertificates option.
  • Autofill, password manager and save-card prompts: disabled in clean contexts; test through the web form logic instead.
  • Extensions and browser settings pages (chrome://): launch persistent contexts with flags or preconfigure profiles.

When native automation is unavoidable

Desktop applications, Electron app menus, OS-level dialogs in hybrid apps, and legacy plugins may require AutoIt, pywinauto, WinAppDriver or Windows Application Driver successors, xdotool, robotjs, SikuliX, macOS Accessibility APIs, or Appium desktop drivers. Playwright also supports Electron (_electron.launch) and exposes its main process and windows. Drawbacks of OS-level automation: needs a real display (virtual framebuffer Xvfb in CI), timing and focus fragility, platform-specific code, slower runs, harder parallelism, and weak reporting. Isolate it in a small adapter layer and prefer test hooks or alternative app paths first.

Pitfalls

Registering the dialog handler after the click, using sleep instead of waiting for events, testing real SSO prompts in every test, relying on headed mode in CI, and hard-coding absolute paths for upload fixtures.
