How do you implement code splitting at the route level versus component level in React?

Frontend engineer · Gear 3 (Senior) · React · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Route-level code splitting lazy-loads one chunk per page with React.lazy and dynamic import at the router, giving the biggest, simplest win. Component-level splitting lazy-loads heavy widgets (charts, editors, modals) used only on interaction or below the fold. Wrap lazy components in Suspense with a fallback and add error boundaries.

Explained in depth

Why split

A single bundle makes every user download and parse code for pages they never visit. Splitting reduces initial JavaScript, improves LCP, TBT and INP, and keeps caches effective since unchanged chunks keep hashed names.

Route level

import { lazy, Suspense } from 'react';
import { createBrowserRouter, RouterProvider } from 'react-router-dom';

const Dashboard = lazy(() => import('./pages/Dashboard'));
const Settings  = lazy(() => import('./pages/Settings'));

const router = createBrowserRouter([
  { path: '/', element: <Home /> },
  { path: '/dashboard', element: <Suspense fallback={<PageSkeleton />}><Dashboard /></Suspense> },
  { path: '/settings',  element: <Suspense fallback={<PageSkeleton />}><Settings /></Suspense> },
]);

React Router's route.lazy and Next.js (file-system routes, App Router) split automatically per route, which is usually the best default. Components must be the default export for React.lazy.

Component level

Split large, conditionally used pieces: rich text editor, chart library, map, PDF viewer, syntax highlighter, admin-only panels, modal contents.

const Chart = lazy(() => import('./Chart'));
function Report({ show }) {
  return show ? <Suspense fallback={<Spinner />}><Chart /></Suspense> : null;
}

Also lazy import libraries inside handlers: const { default: html2pdf } = await import('html2pdf.js') when the user clicks "Export".

Tuning

  • Preload on intent: call the import on hover, focus or when idle (onMouseEnter={() => import('./pages/Settings')}); bundlers supply magic comments (/* webpackPrefetch: true */, webpackPreload) and Vite has modulepreload.
  • Prefer skeleton fallbacks with the final dimensions to prevent layout shift; keep fallbacks light.
  • Use error boundaries to handle failed chunk loads (network, deploy changed hashes) with a retry or reload.
  • Use startTransition so navigation keeps the old screen visible while the new chunk loads instead of flashing the fallback.
  • Avoid waterfalls: a lazy component that fetches data after loading doubles latency; start data fetching in route loaders in parallel with the chunk.
  • Analyse the result with source-map-explorer, webpack-bundle-analyzer or vite-bundle-visualizer; extract shared vendor chunks sensibly (too many tiny chunks hurt over HTTP/1, fine over HTTP/2).

Server components and SSR

With SSR, lazy components are supported with streaming Suspense (React 18+). Server Components reduce client JavaScript at the source by never shipping server-only code.

Pitfalls

Splitting tiny components (overhead exceeds savings), a fallback that appears for a blink and flickers, forgetting error handling on deploys, and importing a lazy module's code statically elsewhere which defeats splitting.
