What is a cache stampede (thundering herd) and how do single-flight locks and XFetch prevent it?

Backend engineer · Gear 3 (Senior) · Caching · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

A cache stampede (thundering herd) happens when a popular key expires and many requests miss at once, all hitting the database to rebuild it. Prevent it by letting only one request recompute (single-flight or a lock), serving slightly stale data while refreshing, and refreshing early with probabilistic XFetch before expiry.

Explained in depth

The problem

A hot key (home page data, 10,000 requests per second) expires. In the next milliseconds every request sees a miss, and all of them run the expensive query. The database spikes, slows down, the rebuild takes longer and more requests pile up, which can cause an outage.

Solutions

  1. Single-flight (request coalescing): the first request for a missing key takes a lock (in-process, or a Redis SET key NX PX lock across servers) and recomputes; others wait for its result or briefly serve stale data.
def get(key):
    v = cache.get(key)
    if v is not None:
        return v
    if cache.set(key + ':lock', 1, nx=True, px=5000):     # we won the lock
        try:
            v = load_from_db(key)
            cache.set(key, v, ex=300)
        finally:
            cache.delete(key + ':lock')
        return v
    time.sleep(0.05)                                      # someone else is loading
    return get(key)                                       # (add a retry limit in real code)
  1. Serve stale while revalidating: keep a soft TTL in the value; when it passes, return the old value and refresh in the background.
  2. Probabilistic early expiration (XFetch): each request may decide to refresh before expiry, with probability that grows as expiry nears and with the cost of recomputing, so refreshes are spread out and one usually completes before the key expires.
  3. Jitter TTLs so many keys do not expire together.
  4. Pre-warm or refresh hot keys with a background job.

Notes

Always set a lock timeout, protect against a failing loader (negative caching or backoff), and monitor miss rates for hot keys.
