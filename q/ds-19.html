Compare random forests and gradient boosting. When would you choose each for tabular data?

Data scientist · Gear 2 (Mid-level) · Modeling · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Random forests average many deep, decorrelated trees trained in parallel on bootstrap samples, which reduces variance and is robust with little tuning. Gradient boosting builds shallow trees sequentially, each correcting the errors of the previous ones, which usually achieves higher accuracy but needs careful tuning and early stopping to avoid overfitting.

Explained in depth

Random forest (bagging)

  • Trains many trees independently on bootstrap samples, and at each split considers a random subset of features (max_features). The prediction is the average (regression) or majority vote (classification).
  • Trees are grown deep (low bias, high variance); averaging decorrelated trees reduces variance.
  • Out-of-bag (OOB) samples give a built-in validation estimate.
  • Strengths: strong baseline, few critical hyperparameters (n_estimators, max_features, min_samples_leaf), parallelisable, robust to outliers and noisy features, rarely overfits as trees increase.
  • Weaknesses: usually a bit less accurate than tuned boosting, large models, predictions cannot extrapolate beyond training range, slow inference with many deep trees.

Gradient boosting (boosting)

  • Trains shallow trees sequentially; each new tree fits the negative gradient (residuals) of the loss of the current ensemble, scaled by a learning rate. Formally gradient descent in function space.
  • Implementations: XGBoost, LightGBM, CatBoost, HistGradientBoosting. Features: regularisation of leaf weights, subsampling, column sampling, histogram-based splits, native missing-value handling, categorical support (CatBoost, LightGBM).
  • Strengths: often state-of-the-art accuracy on tabular data, flexible loss functions (ranking, Poisson, quantile), handles mixed feature types and missing values.
  • Weaknesses: more hyperparameters, sensitive to overfitting and noisy labels, sequential training, needs early stopping and tuning.

Key boosting hyperparameters

learning_rate (0.01 to 0.1; lower needs more trees), n_estimators (choose with early stopping on validation), max_depth or num_leaves, min_child_weight or min_data_in_leaf, subsample, colsample_bytree, reg_lambda and reg_alpha, gamma. Tune with random search or Bayesian optimisation (Optuna), using cross-validation that respects groups or time.

import lightgbm as lgb
m = lgb.LGBMClassifier(n_estimators=5000, learning_rate=0.03, num_leaves=31, subsample=0.8, colsample_bytree=0.8, min_child_samples=50)
m.fit(X_tr, y_tr, eval_set=[(X_va, y_va)], eval_metric="auc", callbacks=[lgb.early_stopping(100)])

Choosing

  • Quick, robust baseline, small team, noisy data: random forest.
  • Maximum predictive performance, enough data, willingness to tune: gradient boosting.
  • Very small data: simpler models, regularised linear models.
  • High-dimensional sparse text or images: linear models or neural networks.
  • Latency or memory constraints: smaller boosted models, distillation.

Interpretation caveats

Impurity-based importance is biased towards high-cardinality features; prefer permutation importance or SHAP on held-out data. Correlated features split importance.

Pitfalls

Using too many boosting rounds without validation, target leakage through ID-like features, and comparing models without the same CV scheme.
