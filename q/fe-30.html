What are the rules of React Hooks and why must hooks be called at the top level?

Frontend engineer · Gear 2 (Mid-level) · React · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Call hooks only at the top level of a component or custom hook, never inside loops, conditions or nested functions, and only from React function components or other hooks. React identifies each hook by the order of calls during a render, so the order must be identical every time or state gets attached to the wrong hook.

Explained in depth

The two rules

  1. Only call hooks at the top level: not in if statements, loops, after an early return, or inside callbacks.
  2. Only call hooks from React functions: function components or custom hooks (functions whose names start with use).

Why

React does not know hook names. Per component, it stores hook state in an ordered list (a linked list on the fiber). Each useState or useEffect call takes the next slot in that list during a render.

function Bad({ show }) {
  if (show) {
    const [a, setA] = useState(0);   // slot 1 only sometimes
  }
  const [b, setB] = useState('');    // slot 1 or 2: mismatched state
}

If the condition changes between renders, b would read the slot that belonged to a. React cannot tell, so state and effects would be corrupted. React warns about this in development.

How to follow the rules

  • Put the condition inside the hook or effect: useEffect(() => { if (show) ... }, [show]).
  • If a branch needs its own state, move it into a child component.
  • Place early returns after all hooks.
  • Use the ESLint plugin eslint-plugin-react-hooks (rules-of-hooks and exhaustive-deps), which catches violations and missing dependencies.

Exception

The newer use API, which reads a promise or context, can be called conditionally. The classic hooks (useState, useEffect, useMemo and so on) cannot.
