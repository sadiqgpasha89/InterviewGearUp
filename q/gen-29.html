Walk through Dijkstra's shortest path algorithm using a priority queue and explain why it fails with negative weights.

Software engineer (core) · Gear 2 (Mid-level) · Graphs · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Dijkstra keeps a priority queue of vertices by tentative distance. It repeatedly pops the closest unfinalised vertex and relaxes its edges, in O((V+E) log V) with a binary heap. It fails with negative edges because it assumes a popped vertex's distance can never improve later.

Explained in depth

import heapq
def dijkstra(graph, src):            # graph[u] = [(v, w), ...]
    dist = {src: 0}
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float('inf')):
            continue                  # stale queue entry
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float('inf')):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

Why it works

With non-negative weights, the unfinalised vertex with the smallest tentative distance cannot be improved: any other path to it must pass through some unfinalised vertex that is at least as far away, plus a non-negative edge. So each vertex is final when popped.

Why negative weights break it

Take A to B with weight 2, A to C with weight 5, and C to B with weight -4. Dijkstra pops B at distance 2 and finalises it, but the real shortest path A, C, B costs 1. The greedy 'popped means final' argument no longer holds.

Fixes and variants

  • Use Bellman-Ford when negative edges exist (and it can detect negative cycles), or Johnson's algorithm for all pairs on sparse graphs.
  • Adding a constant to every edge does not work, because paths with more edges are penalised more.
  • The queue-with-stale-entries version above avoids decrease-key. A Fibonacci heap gives O(E + V log V) in theory.
  • A* is Dijkstra guided by a heuristic.
