How do you tune `spark.sql.shuffle.partitions` to avoid small files and spill-to-disk?

Data engineer · Gear 3 (Senior) · Spark · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

spark.sql.shuffle.partitions sets how many partitions a shuffle (join or aggregation) produces; the default of 200 is often wrong. Too few partitions create huge partitions that spill to disk or run out of memory; too many create tiny tasks and small output files. Aim for roughly 100 to 200 MB per partition, or let adaptive query execution coalesce them automatically.

Explained in depth

What the setting controls

After a wide transformation, rows are redistributed into spark.sql.shuffle.partitions partitions (default 200). Each becomes one task in the next stage, and it also determines how many output files a write may produce.

Symptoms

  • Too few (partitions larger than about 1 GB): executors spill to disk or fail with out-of-memory, tasks run long, and cores sit idle. Look in the Spark UI for high shuffle spill and long, uneven task times.
  • Too many (partitions of a few KB): scheduling overhead dominates, thousands of tiny tasks, and a flood of small output files.

Sizing

A common target is 100 to 200 MB of shuffle data per partition: partitions ~ total shuffle size / 128 MB Also keep it at roughly 2 to 3 times the total executor cores, so all cores stay busy. For a 500 GB shuffle that suggests about 4,000 partitions; for a 2 GB shuffle, about 16.

Easier: adaptive query execution (Spark 3.2+, on by default)

spark.conf.set('spark.sql.adaptive.enabled', 'true')
spark.conf.set('spark.sql.adaptive.coalescePartitions.enabled', 'true')
spark.conf.set('spark.sql.shuffle.partitions', '2000')    # set high as an upper bound

AQE measures real shuffle output sizes and coalesces small partitions toward advisoryPartitionSizeInBytes (64 MB by default), and can split skewed ones.

Related techniques

repartition(n) or coalesce(n) for write layout, salting for skewed keys, broadcasting small tables to avoid a shuffle entirely, and using compact formats.
