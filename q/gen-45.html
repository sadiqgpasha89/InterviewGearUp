Solve the 0/1 Knapsack problem with 2D dynamic programming and optimize it to 1D array space.

Software engineer (core) · Gear 3 (Senior) · Dynamic programming · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

0/1 knapsack: dp[i][w] is the best value using the first i items with capacity w, equal to the max of skipping item i or taking it. That is O(N*W) time and space. Since row i only needs row i-1, you can use a 1D array if you loop capacity downwards so each item is used once.

Explained in depth

Recurrence

dp[i][w] = dp[i-1][w]                                     if weight[i] > w
dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i])  otherwise

Base case: dp[0][w] = 0. The answer is dp[N][W]. Time O(N*W), which is pseudo-polynomial because W is a number, not the input length.

1D optimisation

function knapsack(weights, values, W) {
  const dp = new Array(W + 1).fill(0);
  for (let i = 0; i < weights.length; i++) {
    for (let w = W; w >= weights[i]; w--) {      // downwards!
      dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
    }
  }
  return dp[W];
}

Why the direction matters

Going from high capacity to low means dp[w - weight] still holds the value from the previous item, so each item is used at most once. Going upwards would reuse the current item and solve the unbounded knapsack instead.

Extras

  • To recover which items were chosen, keep the 2D table (or a bit table) and walk back from dp[N][W].
  • Space is O(W) in the 1D version.
  • When W is huge but values are small, swap the dimensions: dp over value, storing minimum weight.
  • The problem is NP-hard in general; this DP is not a polynomial-time algorithm in the input size.

Likely follow-ups

  • How do you reconstruct the chosen items?
  • How does the code change for unbounded knapsack?
  • Why is the DP pseudo-polynomial and not truly polynomial?
