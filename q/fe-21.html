Implement and compare debounce and throttle functions with cancellation support.

Frontend engineer · Gear 2 (Mid-level) · JavaScript · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Debounce delays a function until the calls stop for a given time, so it runs once after the burst, which suits search-as-you-type. Throttle lets a function run at most once per interval, which suits scroll and resize handlers. Both should expose a cancel method so pending work can be dropped on cleanup.

Explained in depth

Debounce

function debounce(fn, wait) {
  let timer;
  function debounced(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), wait);
  }
  debounced.cancel = () => clearTimeout(timer);
  return debounced;
}
const search = debounce((q) => fetchResults(q), 300);

Every call resets the timer, so the function runs only after 300 ms of silence.

Throttle

function throttle(fn, interval) {
  let last = 0, timer;
  function throttled(...args) {
    const now = Date.now();
    const remaining = interval - (now - last);
    clearTimeout(timer);
    if (remaining <= 0) {
      last = now;
      fn.apply(this, args);
    } else {
      timer = setTimeout(() => { last = Date.now(); fn.apply(this, args); }, remaining);
    }
  }
  throttled.cancel = () => clearTimeout(timer);
  return throttled;
}

It runs immediately, then at most once per interval, with a trailing call so the last event is not lost.

Practical notes

  • Provide cancel (and ideally flush) and call it when a component unmounts.
  • In React, create the function once (useMemo or useRef), because a new debounced function on each render has no memory of previous calls.
  • For visual updates, requestAnimationFrame is a natural throttle at the display rate.
