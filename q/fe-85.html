How do you implement internationalization (i18n) and RTL layout support in a large web app?

Frontend engineer · Gear 3 (Senior) · Architecture · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Internationalisation means externalising strings into message catalogs with ICU message formatting for plurals and gender, using Intl APIs for dates, numbers and currency, lazy-loading locale bundles, and building layouts with CSS logical properties and dir attributes so right-to-left languages mirror correctly.

Explained in depth

Building blocks

  • Locale detection: URL segment or domain (best for SEO), user preference, then Accept-Language and navigator.languages; persist the choice. Add <html lang dir>, hreflang links and a locale-aware sitemap.
  • Message catalogs: keys mapped to translations per locale (JSON, XLIFF, PO). Use a library: i18next, FormatJS (react-intl), LinguiJS, Fluent, or framework-native (Angular, Vue i18n).
  • ICU MessageFormat for grammar:
{count, plural, =0 {No messages} one {# message} other {# messages}}
{gender, select, female {She replied} male {He replied} other {They replied}}

Never build sentences with concatenation ("You have " + n + " items") because word order, plural categories (Arabic has six, Polish has few and many) and gender vary.

  • Formatting with Intl: Intl.NumberFormat, DateTimeFormat, RelativeTimeFormat, ListFormat, PluralRules, Collator (locale-aware sort). Store dates as UTC ISO and format at the edge.
  • Lazy loading: split catalogs per locale and per route; keep a fallback chain (pt-BR to pt to en).

RTL support

  • Set dir="rtl" on <html> for Arabic, Hebrew, Persian, Urdu.
  • Use CSS logical properties: margin-inline-start, padding-inline, inset-inline-end, text-align: start, border-start-start-radius, and flexbox/grid (which mirror automatically with direction). Avoid hardcoded left and right.
  • Mirror directional icons (arrows, back chevrons, progress) but not logos, media controls or clocks; use :dir(rtl) or [dir=rtl] selectors and transform: scaleX(-1) for icons.
  • Bidirectional text: wrap user content in <bdi> or dir="auto", isolate embedded LTR (numbers, URLs, code) to avoid punctuation jumping.
  • Test fonts for script coverage and line-height (Arabic and Thai need more height); avoid letter-spacing on cursive scripts.

Process and tooling

  • Extract keys automatically, use stable key ids and context notes for translators, integrate a TMS (Crowdin, Lokalise, Phrase) with CI.
  • Lint for missing or unused keys and ICU syntax errors; use pseudo-localisation (accented, expanded text) to find hardcoded strings and overflow; allow about 30 to 40 percent text growth.
  • Snapshot or visual tests per locale, including RTL.

Pitfalls

Hardcoded strings in images and SVG, truncating text, assuming 12/24 hour formats, sorting with default sort(), name and address formats, currency versus locale confusion, and flash of untranslated content during hydration.
