Explain Apache Parquet internal layout: Row Groups, Column Chunks, and Pages.

Data engineer · Gear 2 (Mid-level) · Storage · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

A Parquet file is split into row groups (horizontal chunks of rows). Within each row group, every column is stored as a column chunk, which is divided into pages, the unit of encoding and compression. The footer holds the schema and metadata, including per-chunk min and max statistics that let engines skip data they do not need.

Explained in depth

Layout

File
 |- Row group 1 (for example 128 MB of rows)
 |    |- Column chunk: user_id  -> pages (data pages, optional dictionary page)
 |    |- Column chunk: country  -> pages
 |    |- Column chunk: amount   -> pages
 |- Row group 2
 |- Footer: schema, row group and column metadata, statistics, offsets
  • Row group: a set of rows, written and read as a unit; it is the usual granularity for parallelism (one task per row group or split).
  • Column chunk: all the values of one column within a row group, stored contiguously.
  • Page (roughly 1 MB): the smallest unit for encoding and compression, with its own header. Pages can be dictionary-encoded, run-length encoded or bit-packed, then compressed with Snappy or Zstd.
  • Footer: read first; holds the schema, offsets and min, max and null-count statistics per column chunk (and optional page indexes and Bloom filters).

Why this helps queries

  • Column pruning: SELECT amount reads only that column's chunks.
  • Predicate pushdown: with WHERE country = 'IN', the engine checks statistics and skips row groups whose min and max exclude the value.
  • Similar values stored together compress very well, so I/O is lower.

Nested data

Parquet stores nested structures using definition and repetition levels, so it can represent lists and structs while staying columnar.

Tuning

Row groups that are too small increase metadata and overhead; too large reduce parallelism and memory use becomes heavy. Sort or cluster data by commonly filtered columns so min and max statistics are selective, and avoid many tiny files.
