How does the browser Same-Origin Policy (SOP) enforce isolation, and how does CORS relax it safely?

Frontend engineer · Gear 2 (Mid-level) · Security · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

The same-origin policy (an origin is scheme, host and port) stops a page from reading responses, DOM or storage belonging to a different origin, while still allowing it to embed or send requests to them. CORS lets a server opt in to specific cross-origin reads by sending Access-Control-Allow-* headers that the browser enforces.

Explained in depth

What the policy isolates

Two URLs are same-origin only if scheme, host and port all match. Script on https://a.com cannot:

  • Read the response of a fetch or XMLHttpRequest to https://b.com.
  • Access the DOM of a cross-origin iframe or window, or its localStorage and IndexedDB (these are per origin).

What is still allowed: embedding images, scripts, stylesheets and frames from other origins, and sending form posts and simple requests cross-origin. That is why CSRF exists and why SOP is not a defence against it. Cookies follow different rules: they are scoped by domain and path, not port, and SameSite controls whether they are sent cross-site.

How CORS relaxes it

The browser asks, and the server decides. A response with Access-Control-Allow-Origin: https://a.com allows script on that origin to read it. For requests that could have side effects (non-simple methods or headers), the browser first sends a preflight OPTIONS request and proceeds only if the server approves the method and headers. Cookies and auth need Access-Control-Allow-Credentials: true and a specific origin, not *.

Safe practice

  • Allow-list trusted origins and add Vary: Origin; never reflect any origin back when credentials are allowed.
  • CORS is enforced only by browsers. It does not protect an API from curl or other servers, so keep authentication and authorisation on the server.
  • A CORS error is fixed on the server (or by a same-origin proxy), not in the front-end code. mode: 'no-cors' only gives an opaque response you cannot read.

Other cross-origin tools

window.postMessage for controlled messaging between windows (always check event.origin), and headers such as COOP, COEP and CORP for stronger isolation against side-channel attacks.
