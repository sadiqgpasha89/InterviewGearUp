How do font loading strategies (`font-display: swap/optional`) eliminate Flash of Invisible Text (FOIT)?

Frontend engineer · Gear 2 (Mid-level) · CSS · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

FOIT is invisible text while a web font loads. The font-display descriptor controls it: swap shows a fallback immediately and swaps when the font arrives, optional uses the font only if it loads almost instantly, fallback and block sit in between. Pair it with preload and size-adjusted fallbacks to avoid layout shift.

Explained in depth

Default behaviour

Browsers hide text that uses a custom font until it loads (up to about 3 s in Chromium), then show it: Flash of Invisible Text (FOIT). That delays content paint, hurting First Contentful Paint and LCP when the text is the largest element. The opposite, FOUT (flash of unstyled text), shows a fallback first and then swaps.

The font-display values

@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-var.woff2") format("woff2");
  font-weight: 100 900;
  font-display: swap;
}
ValueBlock periodSwap periodBehaviour
autobrowser defaultusually like block
blockabout 3 sinfiniteinvisible text, then swap (use for icon fonts)
swapabout 0infinitefallback immediately, swap whenever loaded (small shift)
fallbackabout 100 msabout 3 sbrief invisibility, swap only if loaded quickly, otherwise keep fallback
optionalabout 100 msnoneuse the web font only if it is available almost immediately (cache); no swap, so no shift

swap suits brand fonts where text must appear fast. optional yields the best stability (zero shift) and works well with preload and a warm cache.

Reducing the shift when swapping

Fallback and web font have different metrics, so the swap moves lines around (CLS). Match metrics with descriptors:

@font-face {
  font-family: "Inter Fallback";
  src: local("Arial");
  size-adjust: 107%;
  ascent-override: 90%;
  descent-override: 22%;
  line-gap-override: 0%;
}
body { font-family: "Inter", "Inter Fallback", sans-serif; }

Tools such as Next.js next/font, Fontaine and Capsize generate these values.

Loading faster

  • <link rel="preload" href="/fonts/inter-var.woff2" as="font" type="font/woff2" crossorigin> (the crossorigin attribute is required even for same origin).
  • Self-host, use WOFF2, subset to needed glyphs (unicode-range), and prefer variable fonts to cut file count.
  • Limit weights and styles; use system-ui stacks for UI where acceptable.
  • Cache aggressively (Cache-Control: immutable).
  • font-display plus preconnect for third-party font hosts (Google Fonts supports &display=swap).

Pitfalls

Preloading fonts that are not used on the page (wasted bandwidth), omitting crossorigin (the font is fetched twice), icon fonts with swap (shows wrong glyph letters), and many weights loaded eagerly.
