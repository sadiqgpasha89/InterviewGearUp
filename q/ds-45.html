How would you build a text classification system, comparing TF-IDF with linear models, pretrained embeddings and fine-tuned transformers?

Data scientist · Gear 3 (Senior) · Natural language processing · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Start with a TF-IDF plus logistic regression baseline, then try frozen sentence embeddings with a simple classifier, and fine-tune a transformer when accuracy justifies the cost. Invest in labelling quality, stratified time-aware evaluation, error analysis, and consider zero-shot or few-shot LLMs when labels are scarce, weighing latency, cost and privacy.

Explained in depth

Frame the problem

Define classes (single or multi-label), business cost of errors, latency and volume, languages, data privacy, and how labels will be obtained. Example: routing support tickets into 12 categories with a 200 ms budget.

Data and labels

  • Collect representative text; deduplicate; split by time or by group (customer, thread) to avoid leakage (near-duplicate messages in train and test inflate scores).
  • Label quality dominates model choice: write clear guidelines, double-label a sample and measure inter-annotator agreement (Cohen's kappa), resolve disagreements, and review label noise with tools such as cleanlab.
  • Use active learning to label the most informative examples, weak supervision (rules, distant labels), and LLMs for pre-labelling with human review.
  • Handle class imbalance with class weights, stratified sampling, and per-class metrics.

Modelling ladder

StageApproachWhen
1TF-IDF (word and character n-grams) + logistic regression or linear SVMfast, strong baseline, interpretable, cheap
2Pretrained sentence embeddings (SBERT, E5, OpenAI-type embeddings) + logistic regression or gradient boostinglittle labelled data, semantic similarity, easy
3Fine-tune a transformer (BERT, RoBERTa, DeBERTa, domain models)best accuracy with a few thousand labels, nuanced language
4Zero-shot or few-shot LLM prompts (structured output)no labels, changing taxonomy, prototype; check cost and consistency
5Distil an LLM or large model into a small student for productionLLM-quality at low latency and cost

Also consider rules or keyword features for rare high-precision classes, and a hybrid where cheap models handle easy cases and uncertain ones escalate to a larger model or human.

from sklearn.pipeline import make_pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
clf = make_pipeline(TfidfVectorizer(ngram_range=(1, 2), min_df=3, sublinear_tf=True),
                    LogisticRegression(C=4, max_iter=2000, class_weight="balanced"))
clf.fit(train_text, train_y)

Preprocessing

Light cleaning (lowercasing may hurt for transformers; keep cased models if casing matters), handling URLs, emojis, numbers, multilingual text, truncation of long documents (chunk, then aggregate), and privacy scrubbing (PII).

Evaluation and error analysis

Use macro and per-class precision, recall and F1, a confusion matrix, calibration for confidence thresholds, and slice metrics (language, channel, length). Read misclassified examples: many errors reveal ambiguous labels, missing classes or taxonomy overlap rather than model weakness. For LLM classifiers, build a fixed test set, measure consistency across prompt versions and temperature, and watch for prompt sensitivity.

Deployment

Latency and cost (batching, quantisation, ONNX, distillation, caching), confidence thresholds with human fallback, drift monitoring (new topics and slang), periodic relabelling and retraining, versioned taxonomy, and feedback capture from agents. For LLMs: guardrails against prompt injection, output schema validation, and logging.

Pitfalls

Jumping to a large model before a baseline, random splits with near-duplicates, ignoring label noise, and reporting accuracy on imbalanced classes.
