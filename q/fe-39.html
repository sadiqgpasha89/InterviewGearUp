How do server-state libraries like TanStack Query (React Query) handle caching, deduplication, and stale data?

Frontend engineer · Gear 3 (Senior) · State · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

TanStack Query treats server data as a cache keyed by a query key. It deduplicates identical in-flight requests, returns cached data immediately and refetches in the background when data is stale, based on staleTime, with options for retries, window-focus refetching, invalidation after mutations and garbage collection of unused entries.

Explained in depth

Mental model

Server state is data you do not own: it lives remotely and can change without you knowing. TanStack Query manages it as a cache.

const { data, isPending, isError } = useQuery({
  queryKey: ['todos', { status }],      // identifies the cache entry
  queryFn: () => fetchTodos(status),
  staleTime: 60_000,                    // fresh for one minute
});

How caching works

  • Query key uniquely identifies data. Changing the key (for example the filter) is a different cache entry.
  • Fresh data (within staleTime) is returned without a request. Stale data is returned instantly and then refetched in the background, so the UI updates when new data arrives (stale-while-revalidate).
  • gcTime (formerly cacheTime): how long unused entries stay in memory before removal.
  • Deduplication: if ten components request the same key at once, one network request is made.
  • Refetch triggers: window refocus, network reconnect, mount, interval or manual invalidation.

Mutations

const mutation = useMutation({
  mutationFn: addTodo,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['todos'] }),
});

invalidateQueries marks matching entries stale so active ones refetch. For optimistic updates, write to the cache in onMutate and roll back in onError.

Other features

Retries with backoff, pagination and infinite queries, prefetching, request cancellation and Suspense support.
