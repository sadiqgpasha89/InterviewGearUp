Explain Bayesian A/B testing and multi-armed bandits. When would you use Thompson sampling instead of a classic fixed-horizon test?

Data scientist · Gear 3 (Senior) · Experimentation · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Bayesian A/B testing updates a prior with data to give a posterior over each variant's rate, so you report the probability that B beats A and expected loss. Multi-armed bandits such as Thompson sampling shift traffic towards better variants as evidence accumulates, which cuts regret when the cost of showing poor variants is high, at the price of weaker inference.

Explained in depth

Bayesian A/B test

Treat each variant's conversion rate as an unknown with a prior and update with data. For binary outcomes use Beta-Binomial: prior Beta(a, b); after s successes and f failures the posterior is Beta(a + s, b + f). Sample from both posteriors to compute:

  • P(B > A): probability that B has the higher rate.
  • Distribution of the lift (credible interval).
  • Expected loss: the expected conversion lost if you choose a variant and it is actually worse (decision-oriented stopping rule: stop when expected loss falls below a tolerance).
import numpy as np
rng = np.random.default_rng(0)
a = rng.beta(1 + sA, 1 + nA - sA, 200_000)
b = rng.beta(1 + sB, 1 + nB - sB, 200_000)
print("P(B>A) =", (b > a).mean(), "expected loss choosing B =", np.maximum(a - b, 0).mean())

Benefits: direct probability statements, natural use of prior knowledge, flexible decision rules. Caveats: results depend on the prior (use weakly informative ones, check sensitivity); repeated peeking still has frequentist error rates unless you calibrate the stopping rule by simulation; "P(B > A) above 95 percent" is not a p-value, and the lift estimate is still subject to winner's curse (shrink with hierarchical priors).

Multi-armed bandits

In a classic test you split traffic evenly until the end. A bandit treats allocation as sequential decision-making: explore to learn which arm is best, exploit by sending traffic to the apparent best, minimising cumulative regret (value lost to showing worse arms).

AlgorithmIdea
Epsilon-greedyexploit with probability 1 - epsilon, explore randomly otherwise
UCBchoose the arm with the highest upper confidence bound
Thompson samplingsample a rate from each arm's posterior and play the arm with the highest sample; arms with high uncertainty are tried more naturally
Contextual banditschoose arm using context features (LinUCB, contextual Thompson) for personalisation
import numpy as np
alpha, beta = np.ones(K), np.ones(K)
for t in range(T):
    arm = np.argmax(np.random.beta(alpha, beta))
    reward = pull(arm)
    alpha[arm] += reward; beta[arm] += 1 - reward

When bandits fit

  • The opportunity cost is high and short-lived: headline testing on news, promotions with an expiry, ad creatives, many variants (10+), recommendation slates.
  • Outcomes arrive quickly (click or conversion within minutes).
  • You care about maximising reward during the test rather than precisely estimating each effect.

When to prefer a fixed-horizon (or sequential) test

  • You need unbiased effect estimates and clean confidence intervals for decision making or reporting (bandits bias estimates for under-sampled arms).
  • Delayed or long-term outcomes (retention, lifetime value): the bandit adapts on short-term proxies.
  • Non-stationarity (day-of-week, novelty effects) can mislead adaptive allocation; use discounting or sliding windows if you must.
  • Guardrail metrics and multiple metrics need monitoring, and stakeholder trust in standard methodology matters.
  • Interference and network effects.

Practical hybrid

Run a bandit for exploration with a minimum traffic floor per arm, and a confirmatory holdout test for the winner; log propensities for later off-policy evaluation.

Pitfalls

Declaring victory with a posterior probability after peeking continuously, ignoring delayed conversions, and using bandits where the reward is a noisy proxy for what the business values.
