What is the difference between Kubernetes Deployments, StatefulSets, and DaemonSets?

DevOps / SRE / Cloud · Gear 2 (Mid-level) · Kubernetes · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

A Deployment runs interchangeable stateless pods and handles rolling updates. A StatefulSet gives each pod a stable name, stable network identity and its own persistent volume, with ordered start and update, for databases and clustered systems. A DaemonSet runs one pod on every node (or a chosen subset), for agents such as log collectors.

Explained in depth

Deployment

Manages ReplicaSets. A rolling update creates a new ReplicaSet and shifts pods gradually (maxSurge, maxUnavailable), and a rollback restores the previous one.

StatefulSet

If db-1 is rescheduled, it comes back as db-1 and re-attaches to its volume, so a cluster member keeps its identity and data. A headless Service (clusterIP: None) gives each pod a DNS name such as db-1.db.default.svc. Caveats: volumes are not deleted when the StatefulSet is deleted, and scaling or upgrading a stateful system safely still needs application knowledge, which is why operators are common.

DaemonSet

New nodes automatically get the pod, and removed nodes lose it. Use node selectors or tolerations to restrict it (for example only GPU nodes, or to run on tainted control-plane nodes).

For one-off or scheduled work use Job and CronJob instead.
