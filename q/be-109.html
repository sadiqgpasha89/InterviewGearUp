What are primary keys, foreign keys and constraints, and why do they matter?

Backend engineer · Gear 1 (Junior) · Databases · Difficulty: easy · AI-drafted, not yet reviewed by a person

In 30 seconds

A primary key uniquely identifies each row, a foreign key references a row in another table to enforce referential integrity, and constraints such as NOT NULL, UNIQUE and CHECK make the database reject invalid data. Putting rules in the schema protects data integrity even when application code has bugs or several services write to the same tables.

Explained in depth

Primary key

  • Uniquely identifies a row; cannot be null; automatically indexed.
  • Surrogate keys (auto-increment integers, UUIDs) are meaningless and never change. Natural keys (email, ISBN) carry meaning but can change or be reused. Most designs use a surrogate primary key plus a UNIQUE constraint on natural attributes.
  • Composite keys combine columns, common in join tables.

Foreign key

CREATE TABLE orders (
  id          BIGSERIAL PRIMARY KEY,
  customer_id BIGINT NOT NULL REFERENCES customers(id) ON DELETE RESTRICT,
  total       NUMERIC(10,2) CHECK (total >= 0),
  status      TEXT NOT NULL DEFAULT 'new'
);

The database guarantees every order points to an existing customer, so orphan rows cannot appear. Actions on delete or update: RESTRICT or NO ACTION (block), CASCADE (delete children too), SET NULL.

Other constraints

  • NOT NULL: value required.
  • UNIQUE: no duplicates (for example email), also backed by an index.
  • CHECK: domain rules such as positive amounts or allowed statuses.
  • DEFAULT: sensible values.

Why they matter

  • Integrity at the lowest layer: application validation can be bypassed by bugs, scripts, concurrent requests or other services. A unique constraint is the only reliable way to prevent duplicate rows under race conditions.
  • Documentation of relationships, and optimisers can use the information.
  • Safer migrations and fewer data-cleanup projects.

Trade-offs

Foreign keys add overhead on writes and complicate sharding, bulk loads and some online migrations, so some large-scale systems enforce relationships in application code and with periodic consistency checks. Index foreign key columns to keep joins and deletes fast. Be careful with CASCADE since an accidental delete can remove large amounts of data.
