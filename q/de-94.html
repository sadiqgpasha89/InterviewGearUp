How do you efficiently ingest and flatten semi-structured nested JSON arrays into tabular warehouses?

Data engineer · Gear 2 (Mid-level) · Ingestion · Difficulty: medium · AI-drafted, not yet reviewed by a person

In 30 seconds

Land the raw JSON in a variant, JSON or string column, then flatten with the engine's native functions: explode or inline in Spark, FLATTEN or LATERAL in Snowflake, UNNEST in BigQuery and Postgres, and OPENJSON or JSON_TABLE elsewhere. Create one row per array element in child tables keyed to the parent, project typed columns, and handle schema drift and nulls.

Explained in depth

Strategy

  1. Land raw first: store the payload as-is in bronze with metadata (ingest time, source) so you can reprocess.
  2. Parse and type in silver: extract known fields with explicit types.
  3. Flatten arrays into child tables (normalisation) or keep as nested types when consumers use nested queries.

Example payload

{"order_id": "A1", "customer": {"id": 7, "email": "a@x.com"},
 "items": [{"sku": "S1", "qty": 2, "price": 9.5}, {"sku": "S2", "qty": 1, "price": 20}],
 "tags": ["gift", "express"]}

Snowflake

CREATE TABLE raw.orders (payload VARIANT, loaded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP);
-- parent
SELECT payload:order_id::STRING AS order_id, payload:customer.id::NUMBER AS customer_id, payload:customer.email::STRING AS email FROM raw.orders;
-- child rows, one per item
SELECT o.payload:order_id::STRING AS order_id, i.index AS line_no, i.value:sku::STRING AS sku, i.value:qty::INT AS qty, i.value:price::DECIMAL(10,2) AS price
FROM raw.orders o, LATERAL FLATTEN(input => o.payload:items) i;

FLATTEN(..., OUTER => TRUE) keeps parents whose array is empty; RECURSIVE => TRUE descends nested levels.

BigQuery

SELECT JSON_VALUE(p, '$.order_id') AS order_id, JSON_VALUE(item, '$.sku') AS sku, CAST(JSON_VALUE(item, '$.qty') AS INT64) AS qty
FROM raw.orders, UNNEST(JSON_QUERY_ARRAY(p, '$.items')) AS item;

Native STRUCT and ARRAY<STRUCT> columns can be queried with UNNEST and avoid joins entirely.

Spark

from pyspark.sql.functions import from_json, explode_outer, col
schema = "order_id STRING, customer STRUCT<id: BIGINT, email: STRING>, items ARRAY<STRUCT<sku: STRING, qty: INT, price: DOUBLE>>, tags ARRAY<STRING>"
df = raw.select(from_json("payload", schema).alias("o")).select("o.*")
orders = df.select("order_id", col("customer.id").alias("customer_id"))
items  = df.select("order_id", explode_outer("items").alias("item")).select("order_id", "item.*")

Use schema_of_json or a schema registry rather than relying on full inference in production. Auto Loader and Delta schema evolution handle new fields with _rescued_data.

Design considerations

  • Grain and keys: each child table has (parent_id, line_no) as key; keep ordering through array index. Joining children back to parents avoids duplication in facts.
  • Avoid cartesian explosion: flattening two independent arrays (items and tags) in one query multiplies rows. Flatten each array into its own child table instead.
  • Keep nested types when consumers benefit (BigQuery, Parquet and Spark columns) because nested columns reduce joins and storage; flatten for BI tools that need tabular data.
  • Nulls and missing fields: use try-style casts (TRY_CAST, SAFE_CAST), defaults, and OUTER flattening to avoid dropping rows.
  • Schema drift: monitor new keys, keep the raw column, and use contracts; avoid blindly materialising every key into columns (columns explosion with sparse data).
  • Performance: persist flattened results as tables (incremental models in dbt) rather than flattening on every query; partition by ingest date; prune with filters on extracted columns; pushdown on Parquet nested fields.
  • Security: mask PII (email) during flattening.
  • Use dbt (dbt_utils JSON helpers) or Dataform for maintainable flattening models, with tests for uniqueness of (order_id, line_no).

Pitfalls

Parsing JSON repeatedly in views, exploding multiple arrays together, losing parents with empty arrays, and number precision issues when JSON numbers become doubles (parse money as decimal strings).
