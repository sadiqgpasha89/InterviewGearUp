Explain Cypress in-browser execution architecture and its constraints regarding multiple tabs and origins.

QA / SDET · Gear 3 (Senior) · Frameworks · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Cypress runs the test code in the same browser run loop as the application, with a Node server in the background, so it sees DOM events and network traffic directly, auto-retries commands and offers time-travel debugging. The trade-offs are no true multi-tab support, same-origin limits (relaxed by cy.origin), and tests written only in JavaScript or TypeScript.

Explained in depth

Execution model

Selenium drives the browser from outside; Cypress loads the test spec inside the browser next to your application, in an iframe of its runner page. Commands are queued and run asynchronously with built-in retries, and a proxy in the Node process lets Cypress observe and modify network traffic (cy.intercept).

Benefits

  • Direct access to the page and application state, which gives fast, consistent runs.
  • Automatic waiting and retrying of assertions, no explicit sleeps.
  • A visual runner with snapshots for each command, plus videos and screenshots.
  • Easy network stubbing and spying.

Constraints

  • Multiple tabs and windows: Cypress cannot control a second tab. Work-arounds include removing target="_blank" or checking the link's href and visiting it directly.
  • Origins: a single test traditionally stays on one superdomain because of browser security. cy.origin() allows commands on a second origin within a test, with limits on sharing variables.
  • Languages: JavaScript and TypeScript only.
  • No native events: it simulates events in JavaScript; for OS-level behaviours such as real file dialogs it needs plugins.
  • Browser coverage and parallelism: a smaller set of browsers than Selenium, and parallel runs rely on the paid dashboard or custom CI splitting.

Typical workaround for authentication

Log in through the API (cy.request) and set cookies or tokens directly, instead of driving the identity provider's pages, which also makes tests faster.

Likely follow-ups

  • How does cy.origin help with login flows through another domain?
  • How does Cypress stub network requests?
  • What does Cypress do about iframes and file downloads?
