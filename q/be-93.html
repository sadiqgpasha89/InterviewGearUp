How does clock skew affect distributed systems, and how do TrueTime and logical clocks address it?

Backend engineer · Gear 4 (Lead / Staff) · Distributed systems · Difficulty: hard · AI-drafted, not yet reviewed by a person

In 30 seconds

Physical clocks on different machines drift and jump when synced, so timestamps cannot reliably order events across nodes, which breaks last-write-wins, lock leases and log ordering. Spanner's TrueTime exposes a bounded uncertainty interval and waits it out; logical clocks (Lamport, vector, hybrid) order events by causality instead of wall time.

Explained in depth

What goes wrong with clock skew

  • Last-write-wins by timestamp can discard a newer write that came from a node with a slow clock.
  • Leases and TTLs: a node that thinks its lease is still valid (because its clock or its process paused) can act while another node holds the lock. Use fencing tokens, increasing numbers checked by the resource.
  • Ordering of logs and transactions across machines is wrong, and expiring certificates or tokens can behave inconsistently.
  • NTP corrections can make the clock jump forwards or backwards. Use monotonic clocks to measure durations.

TrueTime (Google Spanner)

TrueTime returns an interval [earliest, latest] that is guaranteed to contain the real time, with an uncertainty of a few milliseconds thanks to GPS receivers and atomic clocks in each data centre. When a transaction commits, Spanner assigns a timestamp and then waits out the uncertainty (commit wait) before making it visible. That guarantees external consistency: if one transaction finishes before another starts, it has the smaller timestamp.

Logical clocks

  • Lamport clocks: a counter increased on each event and merged on message receipt. If A happened before B, then clock(A) < clock(B), but the reverse is not true, so it cannot detect concurrency.
  • Vector clocks: one counter per node. They can tell whether two events are causally ordered or concurrent, at the cost of size growing with the number of nodes (used by Dynamo-style systems to surface conflicts).
  • Hybrid logical clocks: physical time plus a logical counter, staying close to wall time while preserving causality. CockroachDB and MongoDB use variants.

Practical advice

Monitor NTP offset, avoid wall-clock comparisons for correctness, use versions or fencing tokens, and treat last-write-wins as lossy.
